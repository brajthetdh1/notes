Introduction to Kubernetes

What is Kubernetes?

Kubernetes (often abbreviated as K8s) is an open-source container orchestration platform that automates the deployment, scaling, and management of containerized applications. Originally developed by Google, it's now maintained by the Cloud Native Computing Foundation (CNCF).

Why Kubernetes for Java Applications?

Java applications, especially microservices, benefit from Kubernetes through:

  • Automatic scaling based on traffic load
  • Self-healing capabilities (auto-restart failed containers)
  • Service discovery and load balancing
  • Rolling updates and rollbacks
  • Resource optimization across cluster nodes

Control Plane Components

  • API Server: Front-end for the Kubernetes control plane, exposes REST API
  • etcd: Consistent and highly-available key-value store for cluster data
  • Scheduler: Assigns Pods to Nodes based on resource availability
  • Controller Manager: Runs controller processes that regulate cluster state

Node Components

  • Kubelet: Agent that runs on each node, ensures containers are running
  • Kube Proxy: Maintains network rules on nodes for pod communication
  • Container Runtime: Software that runs containers (Docker, containerd, etc.)
  • Pod: Smallest deployable unit containing one or more containers

4. Dockerfile for Containerization

1# Multi-stage build for optimized image size
2FROM maven:3.8.4-openjdk-11 AS builder
3
4WORKDIR /app
5COPY pom.xml .
6COPY src ./src
7
8# Build the application
9RUN mvn clean package -DskipTests
10
11# Runtime stage
12FROM openjdk:11-jre-slim
13
14# Create non-root user for security
15RUN groupadd -r java-user && useradd -r -g java-user java-user
16
17WORKDIR /app
18
19# Copy JAR from builder stage
20COPY --from=builder /app/target/java-kubernetes-app-1.0.0.jar app.jar
21
22# Switch to non-root user
23USER java-user
24
25# Expose application port
26EXPOSE 8080
27
28# JVM options optimized for containers
29ENV JAVA_OPTS="-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0"
30
31# Run the application
32ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
Explanation:
  • Line 2: Multi-stage build starts with Maven for building
  • Lines 4-9: Copy source and build the application
  • Line 12: Second stage uses smaller JRE-only image
  • Lines 15-23: Security: create and use non-root user
  • Line 26: Expose port 8080 (Spring Boot default)
  • Line 29: JVM options optimized for container environments
  • Line 32: Command to run the application

Explanation:

Deployment Process

Step-by-Step Deployment

Step 1: Build and Push Docker Image

1# Build the application JAR
2mvn clean package
3
4# Build Docker image
5docker build -t your-registry/java-kubernetes-app:1.0.0 .
6
7# Push to container registry
8docker push your-registry/java-kubernetes-app:1.0.0

Step 2: Apply Kubernetes Resources

1# Apply all resources in order
2kubectl apply -f namespace.yaml
3kubectl apply -f configmap.yaml
4kubectl apply -f deployment.yaml
5kubectl apply -f service.yaml
6kubectl apply -f hpa.yaml

Or apply all files at once:

1kubectl apply -f k8s/

Step 3: Verify Deployment

1# Check pods
2kubectl get pods -n java-app
3
4# Check services
5kubectl get svc -n java-app
6
7# Check deployment status
8kubectl get deployment -n java-app
9
10# View pod logs
11kubectl logs -n java-app <pod-name>

Step 4: Test the Application

1# Get the external IP of the service
2kubectl get svc java-app-service -n java-app
3
4# Test the endpoint
5curl http://<EXTERNAL-IP>/hello
6
7# Test health endpoint
8curl http://<EXTERNAL-IP>/health
