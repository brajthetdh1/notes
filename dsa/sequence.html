1. Problem Statement

Given an unsorted array of integers nums, return the length of the longest consecutive elements sequence.

You must write an algorithm that runs in O(n) time.

Constraints

  • 0 ≤ nums.length ≤ 105
  • -109 ≤ nums[i] ≤ 109

2. Examples

Example 1

Input: nums = [100, 4, 200, 1, 3, 2]

Output: 4

Explanation: The longest consecutive sequence is [1, 2, 3, 4]. Length = 4.

Example 2

Input: nums = [0, 3, 7, 2, 5, 8, 4, 6, 0, 1]

Output: 9

Explanation: The longest sequence is [0, 1, 2, 3, 4, 5, 6, 7, 8]. Length = 9. (Duplicate 0 is ignored.)

Example 3

Input: nums = []

Output: 0

3. Key Insight & Approach

❌ Why Naive Approaches Fail

  • Brute force O(n³): For each number, linear-scan for x+1, x+2, etc.
  • Sorting O(n log n): Sort, then scan for runs. Correct but violates the O(n) requirement.
  • HashSet + "always walk forward" O(n²): If you walk forward from every element, you'll re-walk the same sequence many times.

✅ The O(n) Trick — Only Start From Sequence Beginnings

A number x is the start of a sequence if and only if x - 1 is not in the set.

  1. Put every unique number into a HashSet<Integer>.
  2. For each number x in the set:
    • If set.contains(x - 1) → skip (x is not a start; it'll be counted when we start from its true beginning).
    • Otherwise → walk forward: x+1, x+2, ... counting how many exist in the set.
  3. Track the maximum count seen.

🧠 Why Is This Amortized O(n)?

The inner while loop runs only for elements that are the true start of a sequence. For a run of length k, we walk it exactly once — from its beginning. Every element is visited at most twice total (once in the outer loop, once inside a walk). So total work = O(2n) = O(n).

4. Complete Java Solution

import java.util.HashSet;
import java.util.Set;

public class Main {

    public int longestConsecutive(int[] nums) {
        if (nums == null || nums.length == 0) return 0;

        // 1. Deduplicate: build a HashSet in O(n)
        Set<Integer> set = new HashSet<>(nums.length * 2);
        for (int n : nums) set.add(n);

        int best = 0;

        // 2. Only walk from sequence starts
        for (int x : set) {
            // Skip if x has a predecessor → not the true start
            if (set.contains(x - 1)) continue;

            int len = 1;
            int cur = x;

            // Walk forward, counting consecutive elements
            while (set.contains(cur + 1)) {
                cur++;
                len++;
            }

            best = Math.max(best, len);
        }

        return best;
    }

    public static void void main(String[] args) {
        Main m = new Main();
        System.out.println(m.longestConsecutive(new int[]{100, 4, 200, 1, 3, 2}));  // 4
        System.out.println(m.longestConsecutive(new int[]{0,3,7,2,5,8,4,6,0,1})); // 9
        System.out.println(m.longestConsecutive(new int[]{}));                              // 0
    }
}

6. Complexity Analysis

MetricComplexityWhy
Time O(n) Building the set is O(n). Outer loop iterates n times; each inner walk is bounded by the length of the sequence it starts, and each sequence is walked at most once. Total work amortized to O(n).
Space O(n) HashSet stores at most n distinct values.
Why not O(n²)? A common worry is that the inner while is O(n), and the outer loop is O(n), suggesting O(n²). But the inner loop only runs for elements without predecessors, and the walk stops at the end of the run. Each element is visited at most once inside a walk. Therefore the total work is n + n = O(n).

7. Common Pitfalls

❌ Pitfall 1 — Forgetting the "is start?" check
Without if (set.contains(x - 1)) continue;, you walk the sequence from every element, giving O(n²) worst case.
❌ Pitfall 2 — Using the array instead of a Set
Duplicate values cause redundant work. Also, checking nums.contains(...) is O(n) per check.
❌ Pitfall 3 — Sorting the array first
Sorting gives an O(n log n) algorithm — correct output, but fails the O(n) interview requirement.
❌ Pitfall 4 — Integer overflow on x - 1
If nums[i] == Integer.MIN_VALUE, then x - 1 wraps to MAX_VALUE. Guard it explicitly.
❌ Pitfall 5 — Using Integer vs int in the walk
The while (set.contains(cur + 1)) is safe — but if cur is an Integer and you do cur == otherInteger, Java compares references. Always use .equals() or unbox to int.

8. Follow-Up Questions (with Dry Runs & Solutions)

🔁 Follow-Up 1: Return the actual sequence, not just its length

Variant: Given nums, return [start, end] of the longest consecutive sequence.

Solution

public int[] longestConsecutiveRange(int[] nums) {
    if (nums == null || nums.length == 0) return new int[]{};

    Set<Integer> set = new HashSet<>();
    for (int n : nums) set.add(n);

    int bestLen = 0;
    int bestStart = 0;

    for (int x : set) {
        if (set.contains(x - 1)) continue;
        int len = 1, cur = x;
        while (set.contains(cur + 1)) { cur++; len++; }
        if (len > bestLen) { bestLen = len; bestStart = x; }
    }
    return new int[]{bestStart, bestStart + bestLen - 1};
}

🔁 Follow-Up 2: Find ALL sequences of maximal length

Variant: Return every consecutive sequence whose length equals the maximum.

Solution

public List<List<Integer>> allLongestSequences(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    if (nums == null || nums.length == 0) return result;

    Set<Integer> set = new HashSet<>();
    for (int n : nums) set.add(n);

    // First pass: find max length
    int maxLen = 0;
    for (int x : set) {
        if (set.contains(x - 1)) continue;
        int len = 1, cur = x;
        while (set.contains(cur + 1)) { cur++; len++; }
        maxLen = Math.max(maxLen, len);
    }

    // Second pass: collect all sequences of length maxLen
    for (int x : set) {
        if (set.contains(x - 1)) continue;
        List<Integer> seq = new ArrayList<>();
        int cur = x;
        while (set.contains(cur)) { seq.add(cur); cur++; }
        if (seq.size() == maxLen) result.add(seq);
    }
    return result;
}

🔁 Follow-Up 3: What if the array is a stream (can't fit in memory)?

Variant: Numbers arrive one at a time. After each insert, return the current longest consecutive run.

Solution — Union-Find (Disjoint Set Union)

Union-find with path compression + union by size gives near-O(1) per insertion.

class StreamingConsecutive {
    private Map<Integer, Integer> parent = new HashMap<>();
    private Map<Integer, Integer> size = new HashMap<>();
    private int best = 0;

    public int add(int num) {
        if (parent.containsKey(num)) return best;

        parent.put(num, num);
        size.put(num, 1);

        if (parent.containsKey(num - 1)) union(num, num - 1);
        if (parent.containsKey(num + 1)) union(num, num + 1);

        return best;
    }

    private void union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return;
        if (size.get(ra) < size.get(rb)) { int t = ra; ra = rb; rb = t; }
        parent.put(rb, ra);
        int newSize = size.get(ra) + size.get(rb);
        size.put(ra, newSize);
        best = Math.max(best, newSize);
    }

    private int find(int x) {
        if (parent.get(x) != x) parent.put(x, find(parent.get(x)));
        return parent.get(x);
    }
}

🔁 Follow-Up 4: Longest Consecutive Sequence in a Binary Tree

Variant: LeetCode #298 (premium). Given a binary tree, find the longest consecutive path (parent → child, each child = parent + 1).

Solution — DFS with "current run length" parameter

class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int v) { val = v; }
}

class Solution {
    private int maxLen = 0;

    public int longestConsecutive(TreeNode root) {
        dfs(root, null, 0);
        return maxLen;
    }

    private void dfs(TreeNode node, TreeNode parent, int curLen) {
        if (node == null) return;

        if (parent != null && node.val == parent.val + 1) curLen++;
        else curLen = 1;

        maxLen = Math.max(maxLen, curLen);

        dfs(node.left, node, curLen);
        dfs(node.right, node, curLen);
    }
}

🔁 Follow-Up 5: Sorted array — can we do better?

Variant: If nums is already sorted, what's the optimal approach?

Solution — Single pass, O(n) time, O(1) space

public int longestConsecutiveSorted(int[] nums) {
    if (nums == null || nums.length == 0) return 0;

    int best = 1, len = 1;
    for (int i = 1; i < nums.length; i++) {
        if (nums[i] == nums[i - 1]) {
            // duplicate — no change
        } else if (nums[i] == nums[i - 1] + 1) {
            len++;
            best = Math.max(best, len);
        } else {
            len = 1;
        }
    }
    return best;
}

🔁 Follow-Up 6: Duplicates are very common — optimize memory

Variant: The array contains many duplicates. Can you shrink the HashSet?

Solution — Still O(n) memory, but HashSet already dedups for free

The HashSet approach already deduplicates during insertion — set.add(n) ignores duplicates. So if nums = [1,1,1,...,1] (a million 1s), the set has size 1, not a million. No further optimization needed for the set size, but the input traversal is still O(n).

If memory is the absolute constraint and duplicates are heavy, consider:
  • Approximate: use a Bloom filter for membership, then verify hits with a disk scan.
  • External sort: if data doesn't fit in memory, sort on disk (merge sort), then scan — O(n log n) but O(1) RAM.

🔁 Follow-Up 7: What if we need to find the longest run in TWO arrays?

Variant: Given two arrays, find the longest consecutive sequence present in both.

Solution — Intersect first, then apply HashSet algorithm

public int longestCommonConsecutive(int[] a, int[] b) {
    Set<Integer> sa = new HashSet<>();
    for (int x : a) sa.add(x);

    Set<Integer> common = new HashSet<>();
    for (int x : b) if (sa.contains(x)) common.add(x);

    int best = 0;
    for (int x : common) {
        if (common.contains(x - 1)) continue;
        int len = 1, cur = x;
        while (common.contains(cur + 1)) { cur++; len++; }
        best = Math.max(best, len);
    }
    return best;
}

✅ Key takeaways:
  1. Detect sequence starts using !set.contains(x - 1).
  2. Walk forward only from starts → amortized O(n).
  3. Always deduplicate via HashSet.
  4. Guard against integer overflow at Integer.MIN_VALUE.
  5. For streams: use union-find. For trees: use DFS with run-length state.
