Spring Boot AutoConfiguration - Complete Guide

AutoConfiguration is Spring Boot's magic that automatically configures your Spring application based on the jar dependencies that you have added.

Tip: AutoConfiguration is what makes Spring Boot "opinionated" - it provides sensible defaults that you can override when needed.

How AutoConfiguration Works

Spring Boot AutoConfiguration works by scanning the classpath for specific dependencies and automatically configuring beans based on those dependencies.

AutoConfiguration Flow
1
Classpath Scanning
Spring Boot scans the classpath for specific libraries and dependencies
2
spring.factories Lookup
Looks for META-INF/spring.factories files that list AutoConfiguration classes
3
Condition Evaluation
Evaluates @Conditional annotations to determine which configurations to apply
4
Bean Creation
Creates and configures beans based on the evaluated conditions
5
Application Ready
Your application starts with all necessary beans configured automatically
Example: DataSource AutoConfiguration

When Spring Boot finds a database driver in the classpath, it automatically configures a DataSource:


// Simplified version of what happens internally
@Configuration
@ConditionalOnClass(DataSource.class)
@ConditionalOnProperty(name = "spring.datasource.url")
public class DataSourceAutoConfiguration {
    
    @Bean
    @ConditionalOnMissingBean
    public DataSource dataSource(DataSourceProperties properties) {
        return properties.initializeDataSourceBuilder().build();
    }
}

Conditional Annotations

Spring Boot uses various @Conditional annotations to determine when to apply AutoConfiguration.

Common Conditional Annotations
Annotation Purpose Example
@ConditionalOnClass When specified class is in classpath @ConditionalOnClass(DataSource.class)
@ConditionalOnMissingClass When specified class is NOT in classpath @ConditionalOnMissingClass("com.example.ExternalService")
@ConditionalOnBean When specified bean exists @ConditionalOnBean(DataSource.class)
@ConditionalOnMissingBean When specified bean does NOT exist @ConditionalOnMissingBean(DataSource.class)
@ConditionalOnProperty When property has specific value @ConditionalOnProperty(name="app.feature.enabled", havingValue="true")
@ConditionalOnExpression When SpEL expression evaluates to true @ConditionalOnExpression("${app.feature.enabled:false} and ${app.mode:dev} == 'prod'")
@ConditionalOnWebApplication When application is a web application @ConditionalOnWebApplication
@ConditionalOnNotWebApplication When application is NOT a web application @ConditionalOnNotWebApplication
@ConditionalOnResource When specified resource exists @ConditionalOnResource(resources="classpath:config.properties")
@ConditionalOnJava When running on specific Java version @ConditionalOnJava(JavaVersion.ELEVEN)
Practical Examples

@Configuration
public class ConditionalConfigurationExamples {
    
    // Only create if Jackson is in classpath
    @Bean
    @ConditionalOnClass(name = "com.fasterxml.jackson.databind.ObjectMapper")
    public JacksonMapper jacksonMapper() {
        return new JacksonMapper();
    }
    
    // Only create if no other CacheManager exists
    @Bean
    @ConditionalOnMissingBean(CacheManager.class)
    public SimpleCacheManager cacheManager() {
        return new SimpleCacheManager();
    }
    
    // Only create if property is set to true
    @Bean
    @ConditionalOnProperty(prefix = "app.feature", name = "advanced-logging", havingValue = "true")
    public AdvancedLogger advancedLogger() {
        return new AdvancedLogger();
    }
    
    // Only in web applications
    @Bean
    @ConditionalOnWebApplication(type = ConditionalOnWebApplication.Type.SERVLET)
    public WebMvcConfigurer webConfigurer() {
        return new CustomWebConfig();
    }
    
    // Complex condition using SpEL
    @Bean
    @ConditionalOnExpression("#{environment.getProperty('app.mode') == 'prod' && environment.getProperty('app.feature.cache') == 'true'}")
    public RedisCacheManager redisCacheManager() {
        return new RedisCacheManager();
    }
}

spring.factories Mechanism

The META-INF/spring.factories file is the key mechanism that Spring Boot uses to discover AutoConfiguration classes.

spring.factories Structure

# META-INF/spring.factories
# Auto Configure
org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
com.example.MyAutoConfiguration,\
com.example.AnotherAutoConfiguration

# AutoConfiguration Import Candidates
org.springframework.boot.autoconfigure.AutoConfigurationImportSelector=\
com.example.MyAutoConfiguration

# Application Context Initializer
org.springframework.context.ApplicationContextInitializer=\
com.example.MyInitializer

# Application Listener
org.springframework.context.ApplicationListener=\
com.example.MyListener
How Spring Boot Processes spring.factories
  1. Spring Boot scans all JARs for META-INF/spring.factories files
  2. Reads all classes listed under org.springframework.boot.autoconfigure.EnableAutoConfiguration
  3. Processes each AutoConfiguration class in order
  4. Evaluates @Conditional annotations on each configuration
  5. Applies configurations that meet all conditions
Note: In Spring Boot 2.7+, the recommendation is to use META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports instead of spring.factories for AutoConfiguration classes.
New Approach (Spring Boot 2.7+)

# META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
com.example.MyAutoConfiguration
com.example.AnotherAutoConfiguration
com.example.ThirdAutoConfiguration

    @ConditionalOnMissingBean({ DataSource.class, XADataSource.class })

    }

Creating Custom AutoConfiguration

You can create your own AutoConfiguration classes to automatically configure custom components or third-party libraries.

Basic Custom AutoConfiguration

@Configuration
@ConditionalOnClass(MyService.class)
@EnableConfigurationProperties(MyServiceProperties.class)
@AutoConfigureAfter(DataSourceAutoConfiguration.class)
public class MyServiceAutoConfiguration {
    
    @Bean
    @ConditionalOnMissingBean
    public MyService myService(MyServiceProperties properties) {
        return new MyService(properties.getUrl(), properties.getTimeout());
    }
    
    @Bean
    @ConditionalOnProperty(name = "app.feature.advanced", havingValue = "true")
    public MyAdvancedService myAdvancedService() {
        return new MyAdvancedService();
    }
}

// Configuration properties
@ConfigurationProperties(prefix = "my.service")
public class MyServiceProperties {
    private String url;
    private int timeout = 5000;
    
    // getters and setters
    public String getUrl() { return url; }
    public void setUrl(String url) { this.url = url; }
    
    public int getTimeout() { return timeout; }
    public void setTimeout(int timeout) { this.timeout = timeout; }
}
Registering AutoConfiguration

Create META-INF/spring.factories or META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports:


# META-INF/spring.factories

Or for Spring Boot 2.7+:


# META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
com.example.autoconfig.MyServiceAutoConfiguration
