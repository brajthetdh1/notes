Installation & Setup

1. Installing Docker on Linux

# Update package index
sudo apt-get update

# Install prerequisites
sudo apt-get install \
    apt-transport-https \
    ca-certificates \
    curl \
    gnupg \
    lsb-release

# Add Docker's official GPG key
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

# Add Docker repository
echo \
  "deb [arch=amd64 signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Install Docker Engine
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io

# Add user to docker group
sudo usermod -aG docker $USER

# Start Docker service
sudo systemctl start docker
sudo systemctl enable docker
2. Installing Docker on Windows

Basic Docker Concepts

Containers

A container is a runnable instance of an image. You can create, start, stop, move, or delete a container using the Docker API or CLI.

Images

An image is a read-only template with instructions for creating a Docker container. Often, an image is based on another image with additional customization.

Registry

A Docker registry stores Docker images. Docker Hub is a public registry that anyone can use, and Docker is configured to look for images on Docker Hub by default.

Dockerfile

A Dockerfile is a text document that contains all the commands a user could call on the command line to assemble an image.

Essential Docker Commands

1. Container Management
Basic Container Operations
# Run a container docker run -d --name my-container nginx:latest # List running containers docker ps # List all containers (including stopped) docker ps -a # Stop a container docker stop my-container # Start a stopped container docker start my-container # Restart a container docker restart my-container # Remove a container docker rm my-container # Remove all stopped containers docker container prune
2. Image Management
Image Operations
# Pull an image from registry docker pull nginx:latest # List images docker images # Remove an image docker rmi nginx:latest # Remove unused images docker image prune # Build image from Dockerfile docker build -t my-app:latest . # Tag an image docker tag my-app:latest my-registry/my-app:1.0 # Push image to registry docker push my-registry/my-app:1.0
3. Container Interaction
Interacting with Running Containers
# Run container interactively docker run -it ubuntu:latest /bin/bash # Execute command in running container docker exec -it my-container /bin/bash # View container logs docker logs my-container # Follow container logs docker logs -f my-container # Copy files to/from container docker cp file.txt my-container:/path/in/container docker cp my-container:/path/file.txt ./ # Inspect container details docker inspect my-container # View resource usage docker stats my-container
4. Advanced Container Operations
Advanced Commands
# Run with environment variables docker run -e "ENV_VAR=value" my-app # Run with port mapping docker run -p 8080:80 nginx # Run with volume mounting docker run -v /host/path:/container/path my-app # Run with custom network docker run --network my-network my-app # Set container resource limits docker run --memory=512m --cpus=1.0 my-app # Run with restart policy docker run --restart unless-stopped my-app # View container processes docker top my-container # Save container as image docker commit my-container my-new-image
5. System Management
Docker System Commands
# View system-wide information docker system info # Show disk usage docker system df # Remove unused data docker system prune # Remove all unused data (including volumes) docker system prune -a --volumes # View events in real-time docker events # Show version information docker version

Dockerfile Guide

A Dockerfile is a text document that contains all the commands to assemble a Docker image.

1. Basic Dockerfile Structure

# Base image
FROM ubuntu:20.04

# Set maintainer
LABEL maintainer="developer@company.com"

# Set working directory
WORKDIR /app

# Copy files
COPY . .

# Install dependencies
RUN apt-get update && apt-get install -y \
    python3 \
    python3-pip

# Install Python packages
RUN pip3 install -r requirements.txt

# Expose port
EXPOSE 8000

# Set environment variables
ENV PYTHONUNBUFFERED=1
ENV DEBUG=False

# Define entry point
CMD ["python3", "app.py"]
2. Dockerfile Instructions
Instruction Description Example
FROM Base image for the build FROM node:16
RUN Execute commands in a new layer RUN npm install
COPY Copy files from host to container COPY . /app
ADD Copy files with URL and tar extraction ADD https://example.com/file.tar.gz /
CMD Default command to run CMD ["node", "app.js"]
ENTRYPOINT Configure container to run as executable ENTRYPOINT ["python3"]
ENV Set environment variables ENV NODE_ENV=production
ARG Build-time variables ARG APP_VERSION=1.0
EXPOSE Document which ports are exposed EXPOSE 3000
WORKDIR Set working directory WORKDIR /app
USER Set user for subsequent instructions USER node
VOLUME Create mount point VOLUME /data
HEALTHCHECK Check container health HEALTHCHECK --interval=30s CMD curl -f http://localhost/
3. Multi-stage Dockerfile Example

# Build stage
FROM node:16 as builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production

# Runtime stage
FROM node:16-alpine
RUN addgroup -g 1001 -S nodejs
RUN adduser -S nextjs -u 1001
WORKDIR /app
COPY --from=builder --chown=nextjs:nodejs /app/node_modules ./node_modules
COPY --chown=nextjs:nodejs . .
USER nextjs
EXPOSE 3000
CMD ["npm", "start"]
4. Spring Boot Application Dockerfile

# Build stage
FROM maven:3.8.4-openjdk-11 as builder
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn clean package -DskipTests

# Runtime stage
FROM openjdk:11-jre-slim
RUN addgroup --system --gid 1000 appuser && \
    adduser --system --uid 1000 --ingroup appuser appuser
USER appuser
WORKDIR /app
COPY --from=builder /app/target/*.jar app.jar
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=3s \
  CMD curl -f http://localhost:8080/actuator/health || exit 1
ENTRYPOINT ["java", "-jar", "/app.jar"]
5. Building and Running

# Build image from Dockerfile
docker build -t my-app:latest .

# Build with build arguments
docker build --build-arg APP_VERSION=1.0 -t my-app:1.0 .

# Run the built image
docker run -d -p 8080:8080 --name my-app-container my-app:latest

# View build history
docker history my-app:latest

Docker Compose

Docker Compose is a tool for defining and running multi-container Docker applications.

1. Basic docker-compose.yml

version: '3.8'

services:
  web:
    image: nginx:latest
    ports:
      - "80:80"
    volumes:
      - ./html:/usr/share/nginx/html
    networks:
      - app-network

  database:
    image: postgres:13
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
    volumes:
      - db_data:/var/lib/postgresql/data
    networks:
      - app-network

  redis:
    image: redis:6-alpine
    networks:
      - app-network

volumes:
  db_data:

networks:
  app-network:
    driver: bridge
2. Advanced Docker Compose Example

version: '3.8'

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        APP_VERSION: 1.0
    ports:
      - "8080:8080"
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - DB_URL=jdbc:postgresql://database:5432/myapp
    depends_on:
      - database
      - redis
    networks:
      - backend
    deploy:
      resources:
        limits:
          memory: 512M
          cpus: '0.5'
        reservations:
          memory: 256M
          cpus: '0.25'

  database:
    image: postgres:13
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - db_data:/var/lib/postgresql/data
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - backend

  redis:
    image: redis:6-alpine
    command: redis-server --appendonly yes
    volumes:
      - redis_data:/data
    networks:
      - backend

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
    depends_on:
      - app
    networks:
      - backend

volumes:
  db_data:
  redis_data:

networks:
  backend:
    driver: bridge
3. Docker Compose Commands
Compose Operations
# Start services in background docker-compose up -d # Start specific services docker-compose up -d app database # View running services docker-compose ps # View service logs docker-compose logs # Follow service logs docker-compose logs -f app # Scale services docker-compose up -d --scale app=3 # Stop services docker-compose down # Stop and remove volumes docker-compose down -v # Build images docker-compose build # Execute command in service docker-compose exec app bash # View service configuration docker-compose config
4. Environment Variables in Compose

# docker-compose.yml
services:
  app:
    image: my-app:latest
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - REDIS_URL=redis://redis:6379
    env_file:
      - .env
      - .env.production

# .env file
DATABASE_URL=postgresql://user:pass@localhost:5432/myapp
APP_SECRET=mysecretkey
DEBUG=false

Docker Networking

Docker provides various networking options to connect containers together and to the outside world.

1. Network Types
Network Type Description Use Case
Bridge Default network for standalone containers Single host communication
Host Remove network isolation between container and host High-performance applications
Overlay Connect multiple Docker daemons Swarm services
Macvlan Assign MAC addresses to containers Legacy applications
None Disable all networking Isolated containers
2. Network Management Commands
Network Operations
# List networks docker network ls # Create a network docker network create my-network # Inspect a network docker network inspect my-network # Connect container to network docker network connect my-network my-container # Disconnect container from network docker network disconnect my-network my-container # Remove a network docker network rm my-network # Remove unused networks docker network prune
3. Practical Network Examples

# Create custom bridge network
docker network create --driver bridge app-network

# Run containers on custom network
docker run -d --name web --network app-network nginx
docker run -d --name database --network app-network postgres

# Connect existing container to network
docker network connect app-network existing-container

# Use host networking
docker run -d --name web --network host nginx

# Use none networking (completely isolated)
docker run -d --name isolated --network none alpine sleep 3600
4. Docker Compose Networking

version: '3.8'

services:
  web:
    image: nginx
    networks:
      - frontend
      - backend

  api:
    image: my-api
    networks:
      - backend

  database:
    image: postgres
    networks:
      - backend

networks:
  frontend:
    driver: bridge
    ipam:
      config:
        - subnet: 172.20.0.0/16
  backend:
    driver: bridge

Volumes & Storage

Docker provides several ways to persist data and share files between containers and the host system.

1. Storage Types
Storage Type Description Use Case
Volumes Managed by Docker, stored in host filesystem Persistent data, backups
Bind Mounts Mount host directory into container Development, host configuration
tmpfs Mounts Stored in host memory only Temporary files, sensitive data
2. Volume Management Commands
Volume Operations
# List volumes docker volume ls # Create a volume docker volume create my-volume # Inspect a volume docker volume inspect my-volume # Remove a volume docker volume rm my-volume # Remove unused volumes docker volume prune # Backup volume data docker run --rm -v my-volume:/source -v $(pwd):/backup alpine \ tar czf /backup/backup.tar.gz -C /source . # Restore volume data docker run --rm -v my-volume:/target -v $(pwd):/backup alpine \ tar xzf /backup/backup.tar.gz -C /target
3. Practical Volume Examples

# Use named volume
docker run -d --name db -v db_data:/var/lib/postgresql/data postgres

# Use bind mount
docker run -d --name web -v /host/path:/container/path nginx

# Use read-only bind mount
docker run -d --name web -v /host/path:/container/path:ro nginx

# Use tmpfs mount
docker run -d --name tmp -v /tmp --tmpfs /tmp alpine

# Multiple volume types
docker run -d --name app \
  -v named_volume:/data \
  -v /host/config:/config:ro \
  --tmpfs /tmp \
  my-app
4. Docker Compose Volumes

version: '3.8'

services:
  database:
    image: postgres:13
    volumes:
      - db_data:/var/lib/postgresql/data
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql:ro

  web:
    image: nginx:alpine
    volumes:
      - static_volume:/var/www/static
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - ./html:/usr/share/nginx/html

  app:
    image: my-app:latest
    volumes:
      - logs_volume:/app/logs
      - ./config:/app/config:ro
    tmpfs:
      - /tmp

volumes:
  db_data:
    driver: local
  static_volume:
    driver: local
  logs_volume:
    driver: local
    driver_opts:
      type: nfs
      o: addr=192.168.1.1,rw
      device: ":/path/to/nfs"

Multi-stage Builds

Multi-stage builds help create optimized Docker images by separating build environment from runtime environment.

1. Why Multi-stage Builds?
  • Reduce final image size
  • Improve security by excluding build tools
  • Separate build dependencies from runtime
  • Optimize caching and build times
2. Node.js Multi-stage Example

# Build stage
FROM node:16 as builder

WORKDIR /app

# Copy package files
COPY package*.json ./

# Install dependencies
RUN npm ci --only=production

# Copy source code
COPY . .

# Build application
RUN npm run build

# Production stage
FROM node:16-alpine

RUN addgroup -g 1001 -S nodejs
RUN adduser -S nextjs -u 1001

WORKDIR /app

# Copy built application and dependencies
COPY --from=builder --chown=nextjs:nodejs /app/.next ./.next
COPY --from=builder --chown=nextjs:nodejs /app/node_modules ./node_modules
COPY --from=builder --chown=nextjs:nodejs /app/package.json ./package.json
COPY --from=builder --chown=nextjs:nodejs /app/public ./public

USER nextjs

EXPOSE 3000

CMD ["npm", "start"]
3. Java Spring Boot Multi-stage

# Build stage
FROM maven:3.8.4-openjdk-11 as builder

WORKDIR /app

# Copy pom.xml for dependency resolution
COPY pom.xml .

# Download dependencies (cached unless pom.xml changes)
RUN mvn dependency:go-offline

# Copy source code
COPY src ./src

# Build application
RUN mvn clean package -DskipTests

# Runtime stage
FROM openjdk:11-jre-slim

# Create non-root user
RUN addgroup --system --gid 1000 appuser && \
    adduser --system --uid 1000 --ingroup appuser appuser

USER appuser
WORKDIR /app

# Copy built JAR from builder stage
COPY --from=builder /app/target/*.jar app.jar

EXPOSE 8080

# Health check
HEALTHCHECK --interval=30s --timeout=3s \
  CMD curl -f http://localhost:8080/actuator/health || exit 1

ENTRYPOINT ["java", "-jar", "/app.jar"]
4. Python Multi-stage Example

# Build stage
FROM python:3.9 as builder

WORKDIR /app

# Copy requirements
COPY requirements.txt .

# Install dependencies to local directory
RUN pip install --user -r requirements.txt

# Runtime stage
FROM python:3.9-slim

WORKDIR /app

# Copy installed dependencies
COPY --from=builder /root/.local /root/.local

# Copy application code
COPY . .

# Make sure scripts in .local are usable
ENV PATH=/root/.local/bin:$PATH

# Create non-root user
RUN adduser --disabled-password --gecos '' myuser
USER myuser

EXPOSE 8000

CMD ["python", "app.py"]
5. Multi-stage with Multiple Builders

# Frontend builder
FROM node:16 as frontend-builder
WORKDIR /app/frontend
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ .
RUN npm run build

# Backend builder
FROM golang:1.17 as backend-builder
WORKDIR /app/backend
COPY backend/go.mod backend/go.sum ./
RUN go mod download
COPY backend/ .
RUN CGO_ENABLED=0 GOOS=linux go build -a -installsuffix cgo -o main .

# Final stage
FROM alpine:latest
RUN apk --no-cache add ca-certificates
WORKDIR /root/

# Copy frontend build
COPY --from=frontend-builder /app/frontend/dist ./static

# Copy backend binary
COPY --from=backend-builder /app/backend/main .

EXPOSE 8080
CMD ["./main"]

Docker Security

1. Container Security Principles
Security Considerations
  • Run containers as non-root users
  • Use minimal base images
  • Keep images updated
  • Scan images for vulnerabilities
  • Limit container capabilities
  • Use read-only filesystems when possible
2. Security Scanning

# Scan image for vulnerabilities
docker scan my-app:latest

# Scan with specific output format
docker scan --format table my-app:latest

# Scan with dependency tree
docker scan --dependency-tree my-app:latest

# Exclude specific vulnerabilities
docker scan --exclude-base my-app:latest

# Using Trivy (alternative)
trivy image my-app:latest

# Using Grype (alternative)
grype my-app:latest
3. Secure Container Configuration

# Run as non-root user
docker run --user 1000:1000 my-app

# Read-only root filesystem
docker run --read-only my-app

# Drop capabilities
docker run --cap-drop=ALL --cap-add=NET_BIND_SERVICE my-app

docker run --security-opt=no-new-privileges my-app

# AppArmor profile
docker run --security-opt apparmor=my-profile my-app

# Seccomp profile
docker run --security-opt seccomp=my-seccomp.json my-app

Problem Solution
Container exits immediately Check logs: docker logs container_name
Port already in use Change port: -p 8081:8080 or stop existing container
Permission denied Run as correct user or fix volume permissions
Out of memory Set memory limits: --memory=512m
Image not found Check image name/tag or pull image first
Build context too large Use .dockerignore file
Network connectivity issues Check network configuration and DNS
