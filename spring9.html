Spring Dependency Injection by Type

Understanding how Spring injects dependencies using annotations

Question

Which annotation is used to inject a dependency by type in Spring?

  • A. @Autowired
  • B. @Inject
  • C. @Resource
  • D. All of the above
Answer: D ✅

Explanation

  • @Autowired → Spring’s type-based injection
  • @Inject → JSR-330 standard, also type-based
  • @Resource → JSR-250, injects by name by default but can also work by type

Spring Dependency Injection Annotations

Detailed explanation of @Autowired, @Inject, and @Resource

1. @Autowired – Spring’s Type-Based Injection

Injects a bean by type. If multiple beans exist, use @Qualifier to specify the bean. 

@Component
public class CarService {
}

@Component
public class CarController {

    @Autowired
    private CarService carService;

    public void showService() {
        System.out.println(carService);
    }
}

Spring scans the context, finds a bean of type CarService, and injects it into CarController.

2. @Inject – JSR-330 Standard (Type-Based)

Works like @Autowired, injecting by type. Standard annotation supported by Spring. 

import javax.inject.Inject;
import org.springframework.stereotype.Component;

@Component
public class EngineService {
}

@Component
public class VehicleController {

    @Inject
    private EngineService engineService;

    public void displayEngine() {
        System.out.println(engineService);
    }
}

Standard annotation from JSR-330. Can use @Named if multiple beans of same type exist.

3. @Resource – JSR-250 Standard (Name-Based by Default)

Injects by name first, then by type if name is not found. 

import javax.annotation.Resource;
import org.springframework.stereotype.Component;

@Component("wheelService")
public class WheelService {
}

@Component
public class GarageController {

    @Resource(name = "wheelService")
    private WheelService ws;

    public void displayWheel() {
        System.out.println(ws);
    }
}

Spring tries to inject a bean matching the field name or specified name. Falls back to type if no name matches.

Summary Table

Annotation Injection Type Standard Default Behavior Supports Qualifier
@Autowired By type No Type-based Yes (@Qualifier)
@Inject By type Yes Type-based Yes (@Named)
@Resource By name → type Yes Name-based No

Difference Between @Autowired, @Inject, and @Resource

Understanding the key differences in Spring dependency injection annotations

1. @Autowired – Spring-Specific Type-Based Injection

Behavior: Injects dependency by type. If multiple beans exist, use @Qualifier to specify the bean.

Package: org.springframework.beans.factory.annotation.Autowired

@Autowired
private CarService carService;

2. @Inject – JSR-330 Standard (Type-Based)

Behavior: Similar to @Autowired, injects dependency by type. Standard annotation supported by multiple frameworks.

Package: javax.inject.Inject

@Inject
private EngineService engineService;

3. @Resource – JSR-250 Standard (Name-Based by Default)

Behavior: Injects dependency by name first, then falls back to type if no name match is found.

Package: javax.annotation.Resource

@Resource(name = "wheelService")
private WheelService ws;

Dependency Injection: By Type vs. By Name

Understanding how Spring injects beans differently by type and by name

Injection by Type

Spring injects a bean based on its class type. Field name does not matter.

@Autowired
private CarService carService;

Spring finds a bean of type CarService and injects it automatically.

Injection by Name

Spring injects a bean based on its name. Type is secondary.

@Resource(name = "myCarService")
private CarService carService;

Spring finds the bean named myCarService and injects it. If the name does not match, it falls back to type.

Spring Boot Application Startup Order

Understanding the correct sequence of steps when a Spring Boot application starts

Question

What is the correct order of Spring Boot application startup?

  • A. Load configuration → Initialize beans → Auto-configuration → Start Tomcat
  • B. Auto-configuration → Load configuration → Initialize beans → Start Tomcat
  • C. Load configuration → Auto-configuration → Initialize beans → Start embedded server
  • D. Initialize beans → Load configuration → Start embedded server → Auto-configuration
Answer: C ✅

Explanation

  • Load configuration → Spring Boot reads application properties (application.properties / application.yml) and environment variables.
  • Auto-configuration → Spring Boot detects classpath dependencies and automatically configures beans for you.
  • Initialize beans → Beans annotated with @Component, @Service, @Repository, etc., are instantiated and dependency injection occurs.
  • Start embedded server → Finally, the embedded server (Tomcat, Jetty, or Undertow) starts and the application begins listening for requests.

Changing the Default Server Port in Spring Boot

How to configure Spring Boot to run on a different port

Question

How do you change the default server port in Spring Boot?

  • A. application.properties: server.port=9090 ✅
  • B. application.yml: server.port: 9090 ✅
  • C. Programmatically via SpringApplication.setPort()
  • D. Only via command-line arguments
Answer: A & B ✅

Explanation

  • application.properties: Add server.port=9090 to set the port.
  • application.yml: Add server.port: 9090 under the root configuration.
  • Command-line override: You can also override the port at runtime with --server.port=9090.
  • Programmatic changes: While possible via custom code, Spring Boot does not provide a built-in SpringApplication.setPort() method, so the recommended ways are properties, YAML, or command-line arguments.

Binding Properties to POJO in Spring Boot

Understanding how to use @ConfigurationProperties for type-safe configuration

Question

Which annotation is used to bind properties to a POJO in Spring Boot?

  • A. @Value
  • B. @ConfigurationProperties ✅
  • C. @PropertySource
  • D. @EnableConfigurationProperties
Answer: B ✅

Explanation

@ConfigurationProperties binds a group of properties from application.properties or application.yml to a POJO. This allows for type-safe configuration and better organization of related properties.

1. Example Properties

# application.properties
app.name=SpringDemo
app.version=1.0.0
app.description=Demo application

2. POJO Class

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.stereotype.Component;

@Component
@ConfigurationProperties(prefix = "app")
public class AppProperties {
    private String name;
    private String version;
    private String description;

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public String getVersion() { return version; }
    public void setVersion(String version) { this.version = version; }

    public String getDescription() { return description; }
    public void setDescription(String description) { this.description = description; }
}

3. Usage in a Service

import org.springframework.stereotype.Service;

@Service
public class AppService {
    private final AppProperties appProperties;

    public AppService(AppProperties appProperties) {
        this.appProperties = appProperties;
    }

    public void printAppInfo() {
        System.out.println("App Name: " + appProperties.getName());
        System.out.println("Version: " + appProperties.getVersion());
        System.out.println("Description: " + appProperties.getDescription());
    }
}

4. Key Points

  • Use prefix to map related properties.
  • Annotate the POJO with @Component or enable it via @EnableConfigurationProperties.
  • Supports nested properties and type conversion.
  • Provides a cleaner and type-safe alternative to multiple @Value annotations.

Enabling Spring Security Method-Level Annotations

Understanding how to secure individual methods in Spring applications

Question

Which annotation is used to enable Spring Security method-level annotations?

  • A. @EnableSecurity
  • B. @EnableGlobalMethodSecurity ✅
  • C. @EnableWebSecurity
  • D. @EnableAuthorization
Answer: B ✅

Explanation

The @EnableGlobalMethodSecurity annotation enables method-level security in Spring applications. This allows the use of annotations such as @PreAuthorize, @PostAuthorize, and @Secured to secure individual methods.

Example Usage

import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.method.configuration.EnableGlobalMethodSecurity;

@Configuration
@EnableGlobalMethodSecurity(prePostEnabled = true, securedEnabled = true)
public class MethodSecurityConfig {
}

Securing Methods

import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    @PreAuthorize("hasRole('ADMIN')")
    public void createProduct() {
        System.out.println("Product created");
    }

    @Secured("ROLE_USER")
    public void viewProduct() {
        System.out.println("Viewing product");
    }
}

Key Points

  • Use @EnableGlobalMethodSecurity(prePostEnabled = true) to enable @PreAuthorize and @PostAuthorize.
  • Use securedEnabled = true to enable @Secured annotations.
  • Method-level security allows fine-grained control over who can access specific service methods.

<dependency>

# Expose specific actuator endpoints
management.endpoints.web.exposure.include=health,info,metrics

# Set actuator server port (optional)

# Show detailed health info
management.endpoint.health.show-details=always

# Configure Spring Security user for actuator
spring.security.user.name=admin
spring.security.user.password=admin123

This ensures that sensitive endpoints like /actuator/metrics are protected. You can also secure endpoints programmatically using Spring Security configuration.

  • http://localhost:8080/actuator/health – Shows application health status
  • http://localhost:8080/actuator/info – Shows application info
  • http://localhost:8080/actuator/metrics – Shows metrics like memory and CPU usage

5. Add Custom Info Properties

# application.properties
info.app.name=MyApp
info.app.version=1.0.0
info.app.description=Demo Spring Boot App

This adds custom information that can be accessed via /actuator/info.

import org.springframework.boot.actuate.info.Info;

This allows dynamic info to be shown in the /actuator/info endpoint.

Caching in Spring Framework

How to use caching to improve performance in Spring applications

1. Enable Caching

To use caching in Spring, you need to enable it in your configuration class using @EnableCaching. 

import org.springframework.cache.annotation.EnableCaching;
import org.springframework.context.annotation.Configuration;

@Configuration
@EnableCaching
public class CacheConfig {
}

2. Add a Cache Provider (Optional)

Spring Boot supports several caching providers like ConcurrentMapCache, EhCache, Redis, and Caffeine. For simple applications, the default ConcurrentMapCache is sufficient.

3. Use Caching Annotations

  • @Cacheable – Caches the result of a method; subsequent calls with the same arguments return cached data.
  • @CachePut – Updates the cache without skipping method execution.
  • @CacheEvict – Removes data from the cache.
  • @Caching – Combines multiple cache operations on a single method.

4. Example: Caching a Service Method

import org.springframework.cache.annotation.Cacheable;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    @Cacheable(value = "products", key = "#id")
    public Product getProductById(Long id) {
        System.out.println("Fetching product from DB for id: " + id);
        // Simulate database access
        return new Product(id, "Product " + id);
    }

    @CacheEvict(value = "products", key = "#id")
    public void removeProductFromCache(Long id) {
        System.out.println("Removing product from cache for id: " + id);
    }

    @CachePut(value = "products", key = "#product.id")
    public Product updateProduct(Product product) {
        System.out.println("Updating product in DB and cache: " + product.getName());
        return product;
    }
}

5. application.properties Configuration (Optional)

# For example, using simple in-memory cache manager
spring.cache.type=simple

# For Redis cache
# spring.cache.type=redis
# spring.redis.host=localhost
# spring.redis.port=6379

6. Key Points

  • Enable caching with @EnableCaching.
  • Use @Cacheable to cache method results automatically.
  • Use @CacheEvict to remove stale data from the cache.
  • Use @CachePut to update the cache without skipping method execution.
  • Choose the appropriate cache provider based on your application needs (in-memory, Redis, etc.).
  • Cache keys are important; you can use SpEL expressions to define them precisely.

Understanding CacheManager in Spring

How Spring manages caches using CacheManager and different providers

1. What is CacheManager?

CacheManager is the central interface in Spring’s caching abstraction. It manages one or more caches and provides methods to retrieve or interact with them. Spring uses it to handle caching transparently when you use annotations like @Cacheable, @CachePut, and @CacheEvict.

2. Built-in CacheManager Implementations

  • ConcurrentMapCacheManager: Default in-memory cache, suitable for simple applications.
  • EhCacheCacheManager: Uses EhCache for more advanced caching features.
  • RedisCacheManager: Uses Redis for distributed caching across multiple instances.
  • CaffeineCacheManager: High-performance in-memory cache.

3. Configuring a CacheManager

You can define a CacheManager bean in a Spring configuration class:

import org.springframework.cache.CacheManager;
import org.springframework.cache.concurrent.ConcurrentMapCacheManager;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class CacheConfig {

    @Bean
    public CacheManager cacheManager() {
        return new ConcurrentMapCacheManager("products", "users");
    }
}

This creates two caches named products and users. When a method annotated with @Cacheable("products") is called, Spring will use this CacheManager to store and retrieve values from the products cache.

4. Using CacheManager Programmatically

You can interact with caches directly if needed:

import org.springframework.cache.Cache;
import org.springframework.cache.CacheManager;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    private final CacheManager cacheManager;

    public ProductService(CacheManager cacheManager) {
        this.cacheManager = cacheManager;
    }

    public void clearProductCache(Long id) {
        Cache cache = cacheManager.getCache("products");
        if (cache != null) {
            cache.evict(id);
        }
    }

    public void clearAllProductCache() {
        Cache cache = cacheManager.getCache("products");
        if (cache != null) {
            cache.clear();
        }
    }
}

5. Key Points

  • CacheManager is central to Spring’s caching abstraction.
  • All @Cacheable, @CachePut, and @CacheEvict annotations delegate to the CacheManager.
  • You can configure multiple caches with a single CacheManager.
  • Supports in-memory, distributed, and third-party caching solutions (EhCache, Redis, Caffeine, etc.).
  • Programmatic access allows clearing or updating caches manually when needed.

Spring Cache: @CachePut Annotation

How to update cache values without skipping method execution

Question

Which annotation marks a method to always update the cache even if it already exists?

  • A. @Cacheable
  • B. @CachePut ✅
  • C. @CacheEvict
  • D. @EnableCaching
Answer: B ✅

Explanation

@CachePut is used to **update the cache for a method result** without skipping the method execution. Unlike @Cacheable, which checks the cache first and may skip method execution if data exists, @CachePut always runs the method and updates the cache with the returned value.

Example Usage

import org.springframework.cache.annotation.CachePut;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    @CachePut(value = "products", key = "#product.id")
    public Product updateProduct(Product product) {
        System.out.println("Updating product in DB and cache: " + product.getName());
        // Save or update product in database
        return product;
    }
}

Key Points

  • Always executes the method, even if the cache contains the key.
  • Updates the cache with the returned value of the method.
  • Useful for write/update operations where cached data must be refreshed.
  • Works alongside @Cacheable and @CacheEvict in the same cache namespace.

Spring Security: Multiple Role Access

How to allow multiple roles to access a method using Spring Security annotations

Question

Which annotation allows multiple roles to access a method?

  • A. @PreAuthorize("hasRole('ROLE_USER')")
  • B. @Secured({"ROLE_USER","ROLE_ADMIN"})
  • C. @RolesAllowed({"ROLE_USER","ROLE_ADMIN"})
  • D. B and C ✅
Answer: D – B and C

Explanation

Both @Secured and @RolesAllowed allow specifying multiple roles for method-level security. When a user has any of the listed roles, access to the method is granted.

Example with @Secured

import org.springframework.security.access.annotation.Secured;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    @Secured({"ROLE_USER", "ROLE_ADMIN"})
    public void viewProducts() {
        System.out.println("Access granted to USER or ADMIN");
    }
}

Example with @RolesAllowed

import jakarta.annotation.security.RolesAllowed;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    @RolesAllowed({"ROLE_USER", "ROLE_ADMIN"})
    public void viewProducts() {
        System.out.println("Access granted to USER or ADMIN");
    }
}

Key Points

  • @Secured and @RolesAllowed allow multiple roles.
  • @PreAuthorize can also be used with SpEL expressions for more complex conditions but does not natively accept an array of roles.
  • Use @EnableGlobalMethodSecurity(securedEnabled = true) to enable @Secured.
  • Use @EnableGlobalMethodSecurity(jsr250Enabled = true) to enable @RolesAllowed.

Spring Security: Authenticated Principal

Understanding how Spring Security stores and accesses the authenticated user

Question

Which class stores the authenticated principal in Spring Security?

  • A. SecurityContext
  • B. SecurityContextHolder ✅
  • C. AuthenticationManager
  • D. Principal
Answer: B – SecurityContextHolder

Explanation

SecurityContextHolder is the central class that stores the SecurityContext for the current execution thread. The SecurityContext contains the Authentication object, which holds the authenticated principal (user details) and authorities (roles/permissions).

Example Usage

import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;

public class SecurityExample {

    public void printCurrentUser() {
        Authentication authentication = SecurityContextHolder.getContext().getAuthentication();
        Object principal = authentication.getPrincipal();
        System.out.println("Authenticated principal: " + principal);
    }
}

Key Points

  • SecurityContextHolder is thread-bound by default using ThreadLocal.
  • The Authentication object contains principal (user info) and authorities (roles/permissions).
  • Use SecurityContextHolder.getContext().getAuthentication() to access the current authenticated user anywhere in the code.
  • For web applications, Spring Security automatically populates the SecurityContext during authentication.

Spring Security: Password Storage & Login URL

Best practices for storing passwords and default login behavior in Spring Security

Q1: Password Storage

Which of the following is true about password storage in Spring Security?

  • A. Plain text passwords are recommended
  • B. PasswordEncoder should be used to hash passwords
  • C. BCryptPasswordEncoder is commonly used
  • D. B and C ✅
Answer: D – B and C

Explanation

Passwords should never be stored in plain text. Instead, use a PasswordEncoder to hash passwords before storing them. BCryptPasswordEncoder is commonly used as it provides strong hashing along with a random salt for each password, making it highly secure.

Example Usage

import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;

public class PasswordExample {

    public static void main(String[] args) {
        PasswordEncoder encoder = new BCryptPasswordEncoder();
        String rawPassword = "mySecret123";
        String encodedPassword = encoder.encode(rawPassword);

        System.out.println("Encoded password: " + encodedPassword);
    }
}

Q2: Default Login URL

What is the default login URL provided by Spring Security?

  • A. /login ✅
  • B. /signin
  • C. /authenticate
  • D. /user/login
Answer: A – /login

Explanation

Spring Security auto-configures a default login page at /login when form login is enabled and no custom login page is provided. This page includes a username and password form and handles authentication automatically.

Example: Customizing Login Page

import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth.anyRequest().authenticated())
            .formLogin(form -> form.loginPage("/custom-login").permitAll());
        return http.build();
    }
}

Spring Security: Authentication Filter

Understanding which filter handles username/password authentication in Spring Security

Question

Which filter in Spring Security is responsible for username/password authentication?

  • A. UsernamePasswordAuthenticationFilter ✅
  • B. BasicAuthenticationFilter
  • C. SecurityContextPersistenceFilter
  • D. AuthenticationManagerFilter
Answer: A – UsernamePasswordAuthenticationFilter

Explanation

UsernamePasswordAuthenticationFilter handles authentication via form login using a username and password. It intercepts login requests, extracts the credentials, and passes them to the AuthenticationManager for authentication.

Example Usage

import org.springframework.context.annotation.Bean;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .addFilterBefore(new UsernamePasswordAuthenticationFilter(), 
                             BasicAuthenticationFilter.class)
            .authorizeHttpRequests(auth -> auth.anyRequest().authenticated());
        return http.build();
    }
}

Key Points

  • Intercepts login requests at /login by default.
  • Extracts username and password parameters from the request.
  • Delegates authentication to AuthenticationManager.
  • Other filters, like BasicAuthenticationFilter, handle different authentication mechanisms (e.g., HTTP Basic).

Spring Security: CSRF Protection

Understanding default CSRF behavior in Spring Security

Question

What is the default CSRF protection behavior in Spring Security?

  • A. Disabled
  • B. Enabled for all non-GET requests ✅
  • C. Enabled only for POST requests
  • D. Must be configured manually
Answer: B – Enabled for all non-GET requests

Explanation

By default, Spring Security enables CSRF (Cross-Site Request Forgery) protection for all state-changing HTTP methods, such as POST, PUT, DELETE, and PATCH. GET requests are considered safe and do not require CSRF tokens.

Key Points

  • CSRF tokens prevent malicious requests from other sites from performing actions on behalf of authenticated users.
  • Spring Security automatically generates and validates CSRF tokens for applicable requests.
  • Tokens are typically included as a hidden field in HTML forms or as a header in AJAX requests.

Example: Disabling CSRF (if needed)

import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth.anyRequest().authenticated());
        return http.build();
    }
}

Spring Security: Disabling CSRF for Specific Endpoints

How to selectively disable CSRF protection in Spring Security

Question

Which annotation can be used to disable CSRF for a specific endpoint?

  • A. @DisableCSRF
  • B. csrf().disable() in HttpSecurity configuration ✅
  • C. @NoCSRF
  • D. @PermitAll
Answer: B – csrf().disable() in HttpSecurity configuration

Explanation

Spring Security does not provide a specific annotation to disable CSRF. Instead, you can use the HttpSecurity configuration to disable CSRF globally or for specific endpoints.

Example: Disable CSRF for a specific endpoint

import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.ignoringRequestMatchers("/api/public/**"))
            .authorizeHttpRequests(auth -> auth.anyRequest().authenticated());
        return http.build();
    }
}

Key Points

  • Use csrf().disable() to completely disable CSRF protection (not recommended for production).
  • Use csrf().ignoringRequestMatchers(...) to disable CSRF for specific endpoints while keeping it enabled for others.
  • Disabling CSRF is typically required for stateless APIs or endpoints accessed via tokens (e.g., JWT).

Spring Security: Custom Authentication

Using AuthenticationProvider to implement custom authentication logic

Question

Which interface is used to configure custom authentication logic in Spring Security?

  • A. UserDetails
  • B. AuthenticationProvider ✅
  • C. AuthenticationManager
  • D. UserService
Answer: B – AuthenticationProvider

Explanation

The AuthenticationProvider interface allows you to implement custom authentication logic in Spring Security. You can validate credentials against a database, LDAP, JWT, or any other authentication mechanism. Once authenticated, it returns an Authentication object containing the principal and authorities.

Example: Custom AuthenticationProvider

import org.springframework.security.authentication.AuthenticationProvider;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.AuthenticationException;
import org.springframework.stereotype.Component;

@Component
public class CustomAuthProvider implements AuthenticationProvider {

    @Override
    public Authentication authenticate(Authentication authentication) throws AuthenticationException {
        String username = authentication.getName();
        String password = authentication.getCredentials().toString();

        // Custom authentication logic (e.g., check database or LDAP)
        if ("user".equals(username) && "password".equals(password)) {
            return new UsernamePasswordAuthenticationToken(username, password, List.of());
        } else {
            return null;
        }
    }

    @Override
    public boolean supports(Class authentication) {
        return UsernamePasswordAuthenticationToken.class.isAssignableFrom(authentication);
    }
}

Key Points

  • Implement AuthenticationProvider to customize authentication logic.
  • Return a valid Authentication object when credentials are correct.
  • Configure multiple providers if needed; Spring Security iterates through them.
  • The supports() method ensures the provider is used for the correct authentication type.

                                    HttpServletResponse response,

        filterChain.doFilter(request, response);
    }

Spring Security: Preventing Session Fixation Attacks

How Spring Security protects against session fixation attacks

Question

How can Spring Security prevent session fixation attacks?

  • A. By enabling CSRF
  • B. By using sessionManagement().sessionFixation().migrateSession() ✅
  • C. By enabling HTTPS only
  • D. By using JWT tokens only
Answer: B – By using sessionManagement().sessionFixation().migrateSession()

Explanation

Session fixation attacks occur when an attacker sets or predicts a user's session ID and then uses it after the user logs in. Spring Security prevents this by **migrating the session ID** upon authentication. The old session is invalidated, and a new session ID is generated for the authenticated user.

Example: Configuring Session Fixation Protection

import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .sessionManagement(session -> 
                session.sessionFixation(fixation -> fixation.migrateSession())
            )
            .authorizeHttpRequests(auth -> auth.anyRequest().authenticated())
            .formLogin();
        return http.build();
    }
}

Key Points

  • migrateSession() creates a new session after login while preserving existing attributes.
  • Prevents attackers from using a pre-authentication session ID.
  • Other options include none(), newSession(), and changeSessionId().

Spring Security: CSRF Protection

Understanding CSRF (Cross-Site Request Forgery) in Spring Security

Question

Which of the following is true about CSRF in Spring Security?

  • B. Protects state-changing requests like POST, PUT, DELETE ✅
  • C. Can be disabled using HttpSecurity ✅
  • D. All of the above ✅
Answer: D – All of the above

Explanation

CSRF (Cross-Site Request Forgery) protection is an important security feature in Spring Security:

  • Enabled by default to protect your application from malicious cross-site requests.
  • Automatically protects state-changing HTTP requests such as POST, PUT, DELETE, and PATCH.
  • Can be selectively disabled using http.csrf().disable() for specific endpoints or testing purposes.

import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;

@Configuration
public class SecurityConfig {

    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {

            .csrf(csrf -> csrf.disable()) // Disables CSRF protection
            .authorizeHttpRequests(auth -> auth.anyRequest().authenticated())
            .formLogin();
        return http.build();
    }
}

Key Points

  • CSRF protection is enabled by default for web applications with form login.
  • It is designed to prevent unauthorized actions triggered from other websites.
  • Can be safely disabled for stateless APIs or when using JWT authentication.
