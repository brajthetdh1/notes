Section 6.1: CountDownLatch – The One-Shot Synchronizer

CountDownLatch is a simple but powerful utility that allows one or more threads to wait until a set of operations in other threads completes.

Subsection 6.1.1: What is CountDownLatch?

public class CountDownLatch {
            public CountDownLatch(int count);
            public void await() throws InterruptedException;
            public boolean await(long timeout, TimeUnit unit) throws InterruptedException;
            public void countDown();
            public long getCount();
        }

How it works:

  • You initialize the latch with a count (e.g., number of tasks to wait for).
  • Each thread calls countDown() when it completes its work, decrementing the count.
  • The waiting thread(s) call await(), which blocks until the count reaches zero.

Is CountDownLatch reusable? No! Once the count reaches zero, the latch cannot be reset. If you need a reusable barrier, use CyclicBarrier.

Use Case 1: Waiting for Multiple Tasks to Complete

public class CountDownLatchExample {

                int numberOfTasks = 5;
                CountDownLatch latch = new CountDownLatch(numberOfTasks);

                        } catch (InterruptedException e) {
                            Thread.currentThread().interrupt();

            }

Subsection 6.1.3: The "Doubt Clarifier" – Can multiple threads call await()?

Yes! Multiple threads can call await(). They will all block until the count reaches zero. Once the count reaches zero, all waiting threads are released simultaneously.

Subsection 6.1.4: The "Doubt Clarifier" – What if a thread calls countDown() more than once?

Each call decrements the count. If a thread accidentally calls countDown() twice, the latch may reach zero earlier than expected. Always call countDown() exactly once per task.

What if a thread calls countDown() after the latch is already zero? It has no effect. The count cannot go below zero.

Semaphore is a counting semaphore that controls access to a limited number of resources.

Section 6.4: Exchanger – Exchanging Data Between Threads

Exchanger is a synchronization point where two threads can exchange objects.

  • Two threads call exchange() with an object.

  • When both have arrived, they exchange objects.

A: Yes, using future.cancel(mayInterruptIfRunning). However, cancellation only works if the task supports interruption.

Q42: What is the difference between complete() and completeExceptionally()?

A: complete() completes the future with a normal value. completeExceptionally() completes the future with an exception. Both set isDone() to true.

Q43: What is a CompletionStage?

Q49: Write a connection pool using Semaphore to limit concurrent connections to 5.

A:

public class ConnectionPool {
            private final Semaphore semaphore = new Semaphore(5);
            private final List<Connection> connections = new ArrayList<>();
            
            public ConnectionPool() {
                for (int i = 0; i < 5; i++) {
                    connections.add(new Connection());
                }
            }
            
            public Connection getConnection() throws InterruptedException {
                semaphore.acquire();
                synchronized (connections) {
                    return connections.remove(connections.size() - 1);
                }
            }
            
            public void returnConnection(Connection conn) {
                synchronized (connections) {
                    connections.add(conn);
                }
                semaphore.release();
            }
        }

                protected boolean onAdvance(int phase, int registeredParties) {

                }

                for (int i = 0; i < 3; i++) {
                    phaser.register();
                    new Thread(new Task(i)).start();
                }

                    phaser.awaitAdvance(phaser.getPhase());
                }
            }

                @Override
                public void run() {

                        // Phase 1
                        phaser.arriveAndAwaitAdvance();
                        // Phase 2
                        phaser.arriveAndAwaitAdvance();
                        // Phase 3
                        phaser.arriveAndDeregister();
                    } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
                }
            }

Q53: What is wrong with this code?

public class WrongLatch {
            public static void main(String[] args) throws InterruptedException {
                CountDownLatch latch = new CountDownLatch(3);
                for (int i = 0; i < 4; i++) {

                System.out.println("All tasks done!");
            }
        }

A: The latch is initialized with 3, but 4 threads call countDown(). The latch reaches zero after 3 threads. The 4th thread is unnecessary. Better to initialize the latch with 4.

Q54: What is wrong with this code?

public class WrongBarrier {
            public static void main(String[] args) {
                CyclicBarrier barrier = new CyclicBarrier(3);
                for (int i = 0; i < 2; i++) {
                    new Thread(() -> {
                        try { barrier.await(); }
                        catch (Exception e) { e.printStackTrace(); }
                    }).start();
                }
            }
        }

A: The barrier is created with 3 parties, but only 2 threads call await(). The barrier will never be tripped, and the threads will block indefinitely. Fix: initialize the barrier with 2, or add a third thread.

Q55: What is wrong with this code?

public class WrongSemaphore {

                // Critical section
                // Forgot to call release()!
            }

A: The thread acquires a permit but never releases it. The semaphore becomes exhausted, and other threads will block forever. Fix: always call release() in a finally block.
