What is a Deadlock?

A deadlock is a situation in concurrent programming where two or more threads are blocked forever, each waiting for the other to release a resource. This results in a permanent blocking state where no progress can be made.

Real-World Analogy

Imagine two people trying to cross a narrow bridge from opposite directions. Both need to cross, but neither can proceed because the other is in the way. This is similar to a deadlock in programming.

Why Deadlocks Matter
  • They can cause entire systems to hang or become unresponsive
  • They are difficult to detect and reproduce
  • They can occur in various environments (databases, operating systems, distributed systems)
  • They impact system reliability and user experience
The Four Coffman Conditions

For a deadlock to occur, all four of these conditions must hold simultaneously:

1. Mutual Exclusion

At least one resource must be held in a non-sharable mode. Only one process can use the resource at a time.

Example

// Only one thread can hold the lock at a time
synchronized(lockObject) {
    // Critical section
}
2. Hold and Wait

A process must be holding at least one resource and waiting to acquire additional resources that are currently being held by other processes.

Example

// Thread holds lock1 and waits for lock2
synchronized(lock1) {
    // Some code
    synchronized(lock2) {  // Waiting for lock2 while holding lock1
        // Critical section
    }
}
3. No Preemption

Resources cannot be forcibly taken away from a process; they must be explicitly released by the process holding them.

Example

// In Java, there's no way to force a thread to release a lock
// The thread must voluntarily release it
synchronized(lock) {
    // No other thread can preempt this lock
    // It will be released only when this block exits
}
4. Circular Wait

There must be a circular chain of processes where each process is waiting for a resource held by the next process in the chain.

Example

// Thread1: holds lock1, wants lock2
// Thread2: holds lock2, wants lock1
// This creates a circular wait
Key Insight: To prevent deadlocks, we need to ensure that at least one of these conditions cannot hold.
Deadlock Examples in Code
Classic Java Deadlock Example
DeadlockDemo.java

public class DeadlockDemo {
    private static final Object lock1 = new Object();
    private static final Object lock2 = new Object();
    
    public static void main(String[] args) {
        Thread thread1 = new Thread(() -> {
            synchronized (lock1) {
                System.out.println("Thread1: Holding lock1...");
                
                try { Thread.sleep(100); } 
                catch (InterruptedException e) {}
                
                System.out.println("Thread1: Waiting for lock2...");
                synchronized (lock2) {
                    System.out.println("Thread1: Acquired lock2!");
                }
            }
        });
        
        Thread thread2 = new Thread(() -> {
            synchronized (lock2) {
                System.out.println("Thread2: Holding lock2...");
                
                try { Thread.sleep(100); } 
                catch (InterruptedException e) {}
                
                System.out.println("Thread2: Waiting for lock1...");
                synchronized (lock1) {
                    System.out.println("Thread2: Acquired lock1!");
                }
            }
        });
        
        thread1.start();
        thread2.start();
        
        // Wait for threads to finish (which they won't due to deadlock)
        try {
            thread1.join();
            thread2.join();
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
        
        System.out.println("This line will never be reached due to deadlock!");
    }
}

Dining Philosophers Problem

A classic synchronization problem that demonstrates deadlocks:

DiningPhilosophers.java

public class DiningPhilosophers {
    private static final int NUM_PHILOSOPHERS = 5;
    private static Object[] forks = new Object[NUM_PHILOSOPHERS];
    
    static {
        for (int i = 0; i < NUM_PHILOSOPHERS; i++) {
            forks[i] = new Object();
        }
    }
    
    static class Philosopher implements Runnable {
        private int id;
        
        public Philosopher(int id) {
            this.id = id;
        }
        
        private void think() throws InterruptedException {
            System.out.println("Philosopher " + id + " is thinking");
            Thread.sleep((long) (Math.random() * 1000));
        }
        
        private void eat() throws InterruptedException {
            System.out.println("Philosopher " + id + " is eating");
            Thread.sleep((long) (Math.random() * 1000));
        }
        
        @Override
        public void run() {
            try {
                while (true) {
                    think();
                    
                    // Pick up forks
                    synchronized (forks[id]) {  // Left fork
                        synchronized (forks[(id + 1) % NUM_PHILOSOPHERS]) {  // Right fork
                            eat();
                        }
                    }
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
    
    public static void main(String[] args) {
        for (int i = 0; i < NUM_PHILOSOPHERS; i++) {
            new Thread(new Philosopher(i)).start();
        }
    }
}

This implementation can lead to deadlock when all philosophers pick up their left forks simultaneously.

Deadlock Prevention Techniques

Prevention strategies ensure that at least one of the four Coffman conditions cannot occur.

1. Breaking Mutual Exclusion

Use shared resources or make resources non-blocking when possible:

Using atomic variables instead of locks

import java.util.concurrent.atomic.AtomicInteger;

public class AtomicExample {
    private AtomicInteger counter = new AtomicInteger(0);
    
    public void increment() {
        counter.incrementAndGet();  // No locking required
    }
    
    public int getValue() {
        return counter.get();
    }
}
2. Breaking Hold and Wait

Acquire all required resources at once, or don't hold resources while waiting:

Acquire all locks atomically

public void transfer(Account from, Account to, int amount) {
    // Acquire locks in a consistent order
    Object firstLock = from.getId() < to.getId() ? from : to;
    Object secondLock = from.getId() < to.getId() ? to : from;
    
    synchronized (firstLock) {
        synchronized (secondLock) {
            from.withdraw(amount);
            to.deposit(amount);
        }
    }
}
3. Breaking No Preemption

Use timeout mechanisms or try-lock patterns:

Using tryLock with timeout

import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class TryLockExample {
    private Lock lock1 = new ReentrantLock();
    private Lock lock2 = new ReentrantLock();
    
    public boolean tryTransfer() {
        boolean gotLock1 = false;
        boolean gotLock2 = false;
        
        try {
            // Try to acquire both locks with timeout
            gotLock1 = lock1.tryLock(100, TimeUnit.MILLISECONDS);
            if (gotLock1) {
                gotLock2 = lock2.tryLock(100, TimeUnit.MILLISECONDS);
            }
            
            if (gotLock1 && gotLock2) {
                // Perform transfer
                return true;
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            // Release locks if acquired
            if (gotLock2) lock2.unlock();
            if (gotLock1) lock1.unlock();
        }
        
        return false;
    }
}
4. Breaking Circular Wait

Establish a total ordering of resources and always acquire locks in that order:

Consistent lock ordering

public class OrderedLocking {
    public void method1(Object a, Object b) {
        Object first = System.identityHashCode(a) < System.identityHashCode(b) ? a : b;
        Object second = System.identityHashCode(a) < System.identityHashCode(b) ? b : a;
        
        synchronized (first) {
            synchronized (second) {
                // Critical section
            }
        }
    }
    
    public void method2(Object c, Object d) {
        // Uses the same ordering logic
        Object first = System.identityHashCode(c) < System.identityHashCode(d) ? c : d;
        Object second = System.identityHashCode(c) < System.identityHashCode(d) ? d : c;
        
        synchronized (first) {
            synchronized (second) {
                // Critical section
            }
        }
    }
}
Deadlock Avoidance Algorithms
Banker's Algorithm

A resource allocation and deadlock avoidance algorithm that tests for safe states:

Key Concepts:
  • Available: Number of available resources of each type
  • Max: Maximum demand of each process
  • Allocation: Resources currently allocated to each process
  • Need: Remaining resources needed by each process (Max - Allocation)
Safe State Check
Banker's Algorithm Implementation

public class BankersAlgorithm {
    private int[] available;
    private int[][] max;
    private int[][] allocation;
    private int[][] need;
    private int numProcesses;
    private int numResources;
    
    public BankersAlgorithm(int[] available, int[][] max, int[][] allocation) {
        this.available = available.clone();
        this.max = max;
        this.allocation = allocation;
        this.numProcesses = max.length;
        this.numResources = available.length;
        
        // Calculate need matrix
        this.need = new int[numProcesses][numResources];
        for (int i = 0; i < numProcesses; i++) {
            for (int j = 0; j < numResources; j++) {
                need[i][j] = max[i][j] - allocation[i][j];
            }
        }
    }
    
    public boolean isSafe() {
        boolean[] finished = new boolean[numProcesses];
        int[] work = available.clone();
        int count = 0;
        
        while (count < numProcesses) {
            boolean found = false;
            
            for (int i = 0; i < numProcesses; i++) {
                if (!finished[i] && canGrant(i, work)) {
                    // Process i can be granted resources
                    for (int j = 0; j < numResources; j++) {
                        work[j] += allocation[i][j];
                    }
                    finished[i] = true;
                    found = true;
                    count++;
                }
            }
            
            if (!found) {
                // No process found that can be granted resources
                return false; // Unsafe state
            }
        }
        
        return true; // Safe state
    }
    
    private boolean canGrant(int process, int[] work) {
        for (int j = 0; j < numResources; j++) {
            if (need[process][j] > work[j]) {
                return false;
            }
        }
        return true;
    }
    
    public synchronized boolean requestResources(int process, int[] request) {
        // Check if request is valid
        for (int j = 0; j < numResources; j++) {
            if (request[j] > need[process][j] || request[j] > available[j]) {
                return false;
            }
        }
        
        // Try to allocate resources temporarily
        for (int j = 0; j < numResources; j++) {
            available[j] -= request[j];
            allocation[process][j] += request[j];
            need[process][j] -= request[j];
        }
        
        // Check if system remains in safe state
        if (isSafe()) {
            return true; // Grant the request
        } else {
            // Rollback the allocation
            for (int j = 0; j < numResources; j++) {
                available[j] += request[j];
                allocation[process][j] -= request[j];
                need[process][j] += request[j];
            }
            return false; // Deny the request
        }
    }
}
Deadlock Recovery Strategies

When prevention and avoidance fail, recovery mechanisms can resolve deadlocks.

1. Process Termination
  • Abort all deadlocked processes: Simple but costly
  • Abort one process at a time: Check if deadlock persists after each termination
  • Cost factors: Priority, execution time, resources held
2. Resource Preemption
  • Select a victim: Choose which resource to preempt
  • Rollback: Restore process to safe state
  • Starvation prevention: Ensure same process isn't always victim
Java-Specific Recovery Techniques
Using Thread.interrupt() for recovery

public class InterruptRecovery {
    private final Object lock1 = new Object();
    private final Object lock2 = new Object();
    
    public void potentialDeadlockMethod() {
        Thread worker = new Thread(() -> {
            synchronized (lock1) {
                try {
                    Thread.sleep(100); // Simulate work
                    synchronized (lock2) {
                        System.out.println("Acquired both locks");
                    }
                } catch (InterruptedException e) {
                    System.out.println("Thread interrupted, releasing locks");
                    // The synchronized blocks will release locks automatically
                    // when we exit due to interruption
                    return;
                }
            }
        });
        
        worker.start();
        
        // Set a timeout to interrupt if deadlock suspected
        Timer timer = new Timer();
        timer.schedule(new TimerTask() {
            @Override
            public void run() {
                if (worker.isAlive()) {
                    worker.interrupt();
                    System.out.println("Interrupted worker thread to prevent deadlock");
                }
            }
        }, 5000); // Timeout after 5 seconds
    }
}

Most databases automatically detect and resolve deadlocks:

Handling database deadlocks

public class DatabaseService {
    public boolean transferWithRetry(Account from, Account to, int amount) {
        int retries = 3;
        
        while (retries > 0) {
            try {
                return executeTransfer(from, to, amount);
            } catch (DeadlockLoserDataAccessException e) {
                retries--;
                if (retries == 0) throw e;
                
                // Wait with exponential backoff
                try {
                    Thread.sleep(100 * (4 - retries));
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    throw new RuntimeException("Transfer interrupted", ie);
                }
            }
        }
        return false;
    }

        // Database operation that might cause deadlock

        return true;
    }
}
Best Practices and Design Patterns
Preventive Coding Practices
  • Lock ordering: Always acquire locks in a consistent global order
  • Lock timeouts: Use tryLock with timeouts instead of unconditional locking
  • Minimize lock scope: Hold locks for the shortest time possible
  • Use higher-level abstractions: Prefer concurrent collections over manual synchronization
Design Patterns for Deadlock Prevention
1. Resource Ordering Pattern

Always acquire resources in a predetermined order:


public class ResourceOrdering {
    public static void orderedLock(Object a, Object b, Runnable task) {
        Object first = a;
        Object second = b;
        
        // Establish consistent ordering
        if (System.identityHashCode(a) > System.identityHashCode(b)) {
            first = b;
            second = a;
        }
        
        synchronized (first) {
            synchronized (second) {
                task.run();
            }
        }
    }
}
2. Try-Lock Pattern

Attempt to acquire locks with timeout and backoff:


public class TryLockPattern {
    public boolean tryWithLocks(Lock lock1, Lock lock2, long timeout, TimeUnit unit) {
        long stopTime = System.nanoTime() + unit.toNanos(timeout);
        
        while (System.nanoTime() < stopTime) {
            if (lock1.tryLock()) {
                try {
                    if (lock2.tryLock()) {
                        try {
                            return true; // Successfully acquired both locks
                        } finally {
                            lock2.unlock();
                        }
                    }
                } finally {
                    lock1.unlock();
                }
            }
            
            // Backoff before retry
            try {
                Thread.sleep(10);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return false;
            }
        }
        
        return false; // Timeout
    }
}
