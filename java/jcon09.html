Section 9.1: Overview of Executor and ExecutorService

The Executor Framework provides a clean separation between task submission and task execution. Instead of creating threads manually, you submit tasks to an executor that manages the threads.

Subsection 9.1.1: The Executor Interface – The Foundation

public interface Executor {
            void execute(Runnable command);
        }

Why is Executor so simple? It decouples task submission from task execution. The caller doesn't need to know how the task will be executed.

// Synchronous executor (runs in the caller's thread)
        Executor directExecutor = Runnable::run;
        
        // Thread-per-task executor
        Executor threadPerTaskExecutor = command -> new Thread(command).start();
        
        // Thread pool executor
        Executor poolExecutor = Executors.newFixedThreadPool(10);

Subsection 9.1.2: The ExecutorService Interface – Adding Lifecycle Management

public interface ExecutorService extends Executor {
            // Shutdown
            void shutdown();
            List<Runnable> shutdownNow();
            boolean isShutdown();
            boolean isTerminated();
            boolean awaitTermination(long timeout, TimeUnit unit) throws InterruptedException;
            
            // Task submission
            <T> Future<T> submit(Callable<T> task);
            <T> Future<T> submit(Runnable task, T result);
            Future<?> submit(Runnable task);
            
            // Batch submission
            <T> List<Future<T>> invokeAll(Collection<? extends Callable<T>> tasks) throws InterruptedException;
            <T> T invokeAny(Collection<? extends Callable<T>> tasks) throws InterruptedException, ExecutionException;
        }

execute() vs submit(): execute() is fire-and-forget for Runnable. submit() returns a Future for result handling and cancellation.

Subsection 9.1.3: The "Doubt Clarifier" – What is the lifecycle of an ExecutorService?

  • Running: Accepting new tasks.
  • Shutting Down: shutdown() called. No new tasks accepted.
  • Terminated: All tasks completed.

Subsection 9.3.2: The "Doubt Clarifier" – How does the pool decide to create a new thread?

  • If threads < corePoolSize: New thread created for each task.
  • If threads between corePoolSize and maximumPoolSize: New thread created only if queue is full.
  • If threads = maximumPoolSize: Task is rejected (or handled by rejection policy).

Example: core=5, max=10, queue=100. First 5 tasks create threads. Next 100 tasks queue. Next 5 tasks create 5 more threads (total=10). Remaining 40 tasks rejected.

Section 9.6: Fork/Join Framework – Parallel Decomposition

The Fork/Join framework is designed for parallel processing of large datasets using divide-and-conquer.

Subsection 9.6.1: What is Fork/Join?

  • Fork: Split a large task into smaller subtasks.
  • Join: Wait for subtasks to complete and combine their results.

Key Classes:

  • ForkJoinPool: The thread pool used for Fork/Join tasks.
  • RecursiveTask<V>: A task that returns a result.
  • RecursiveAction: A task that does not return a result.

When to use Fork/Join? CPU-bound tasks that can be divided into independent subtasks. Don't use for I/O-bound tasks.

11 / 37

Subsection 9.6.2: Example – Parallel Sum

public class ParallelSum extends RecursiveTask<Long> {
            private static final int THRESHOLD = 1000;
            private final int[] array;
            private final int start;
            private final int end;
            
            @Override
            protected Long compute() {
                if (end - start <= THRESHOLD) {
                    long sum = 0;
                    for (int i = start; i < end; i++) {
                        sum += array[i];
                    }
                    return sum;
                } else {
                    int mid = (start + end) / 2;
                    ParallelSum left = new ParallelSum(array, start, mid);
                    ParallelSum right = new ParallelSum(array, mid, end);
                    
                    left.fork();  // Asynchronously execute left
                    long rightResult = right.compute();  // Execute right synchronously
                    long leftResult = left.join();  // Wait for left to complete
                    
                    return leftResult + rightResult;
                }
            }
            
            public static void main(String[] args) {
                int[] array = new int[10_000_000];
                Arrays.fill(array, 1);
                ForkJoinPool pool = ForkJoinPool.commonPool();
                long result = pool.invoke(new ParallelSum(array, 0, array.length));
                System.out.println("Sum: " + result);
            }
        }

Section 9.7: Virtual Threads (Java 21+) – The Future

Virtual threads are lightweight threads managed by the JVM, not the OS.

Subsection 9.7.1: Creating Virtual Threads

// Method 1: Using Thread.startVirtualThread()

            System.out.println("Running in a virtual thread");
        });
        
        // Method 2: Using Thread.ofVirtual()
        Thread virtualThread = Thread.ofVirtual()
            .name("virtual-thread-1")
            .start(() -> {
                System.out.println("Running in a virtual thread");
            });
        
        // Method 3: Using Executors.newVirtualThreadPerTaskExecutor()
        ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor();
        executor.submit(() -> {
            System.out.println("Running in a virtual thread");
        });

When to use Virtual Threads? I/O-bound tasks with high concurrency. CPU-bound tasks should use platform threads.

Subsection 9.7.2: Pinning – The Virtual Thread Limitation

When a virtual thread enters a synchronized block, it may become "pinned" to the carrier thread, reducing scalability.

The Fix: Use ReentrantLock instead of synchronized in code that will run on virtual threads.

// Bad: May cause pinning
        synchronized (lock) {
            // Blocking operation
        }
        
        // Good: No pinning
        lock.lock();
        try {
            // Blocking operation
        } finally {
            lock.unlock();
        }

Q1: What is the Executor Framework and why was it introduced?

Q3: What is the difference between execute() and submit()?

A: execute() is fire-and-forget for Runnable. submit() returns a Future that can be used to get the result, check completion, or cancel the task. One-liner: "execute() is fire-and-forget for Runnable tasks. submit() returns a Future for result handling and cancellation."

A: Three states: Running (accepting tasks), Shutting Down (shutdown() called, no new tasks), Terminated (all tasks complete).

ExecutorService executor = Executors.newFixedThreadPool(10);

A: newCachedThreadPool() creates threads as needed with no upper limit. This code will create unlimited threads, causing OutOfMemoryError or OS thread exhaustion. Fix: use newFixedThreadPool().
