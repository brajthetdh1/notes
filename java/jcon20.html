wait() and notify() Overview

The wait() and notify() methods in Java provide a mechanism for inter-thread communication, allowing threads to coordinate their activities and avoid busy waiting.

Key Points

  • Defined in java.lang.Object class
  • Used for inter-thread communication and coordination
  • Must be called from synchronized context
  • Thread releases monitor lock when waiting
  • Alternative to polling and busy waiting

Thread Coordination Flow

Thread 1

Calls wait() - releases lock and waits

Thread 2

Calls notify() - wakes up waiting thread

Thread 1

Resumes execution after reacquiring lock

Basic Wait-Notify Pattern

public class BasicWaitNotify {
    private boolean condition = false;
    private final Object lock = new Object();
    
    public void waitForCondition() throws InterruptedException {
        synchronized (lock) {
            // Always use wait() in a loop to handle spurious wakeups
            while (!condition) {
                System.out.println(Thread.currentThread().getName() + " is waiting...");
                lock.wait(); // Releases lock and waits for notification
            }
            // Condition is true, proceed with work
            System.out.println(Thread.currentThread().getName() + " is proceeding with work");
            condition = false; // Reset condition for next time
        }
    }
    
    public void setCondition() {
        synchronized (lock) {
            condition = true;
            System.out.println(Thread.currentThread().getName() + " is notifying waiting threads");
            lock.notify(); // Wakes up one waiting thread
            // lock.notifyAll(); // Use this to wake up all waiting threads
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        BasicWaitNotify example = new BasicWaitNotify();
        
        // Thread that waits for condition
        Thread waiter = new Thread(() -> {
            try {
                example.waitForCondition();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, "Waiter-Thread");
        
        // Thread that sets condition
        Thread notifier = new Thread(() -> {
            try {
                Thread.sleep(2000); // Simulate some work before notifying
                example.setCondition();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, "Notifier-Thread");
        
        waiter.start();
        notifier.start();
        
        waiter.join();
        notifier.join();
        
        System.out.println("Basic wait-notify example completed");
    }
}

Method Deep Dive

wait()

Causes current thread to wait until another thread invokes notify() or notifyAll().

Signature:

public final void wait() throws InterruptedException

Behavior:

  • Releases the object's monitor lock
  • Thread moves to WAITING state
  • Waits indefinitely for notification
  • Can be interrupted
synchronized (lockObject) {
    while (!condition) {
        lockObject.wait(); // Releases lock and waits
    }
    // Proceed when condition is true
}

wait(long timeout)

Waits for specified milliseconds or until notified.

Signature:

public final void wait(long timeout) throws InterruptedException

Behavior:

  • Waits up to specified milliseconds
  • Returns if timeout expires
  • Still need to check condition after wait
  • Prevents indefinite blocking
synchronized (lockObject) {
    long timeout = 5000; // 5 seconds
    long startTime = System.currentTimeMillis();
    
    while (!condition) {
        long remaining = timeout - (System.currentTimeMillis() - startTime);
        if (remaining <= 0) {
            throw new TimeoutException("Condition not met within timeout");
        }
        lockObject.wait(remaining);
    }
}

notify() & notifyAll()

Wakes up waiting thread(s).

Signatures:

public final void notify() public final void notifyAll()

Behavior:

  • notify(): Wakes one arbitrary waiting thread
  • notifyAll(): Wakes all waiting threads
  • Waiting threads compete for the lock
  • Doesn't release lock immediately
synchronized (lockObject) {
    condition = true;
    lockObject.notify(); // Wake one thread
    // OR
    lockObject.notifyAll(); // Wake all threads
}

Method Comparison

Method Parameters Behavior When to Use Throws
wait() None Waits indefinitely for notification When you can wait forever InterruptedException
wait(long timeout) milliseconds Waits up to specified time When you need timeout InterruptedException
wait(long timeout, int nanos) ms + nanoseconds More precise timeout High precision timing InterruptedException
notify() None Wakes one waiting thread Single consumer or don't care which -
notifyAll() None Wakes all waiting threads Multiple consumers or specific ordering needed -

Producer-Consumer Pattern

Classic Producer-Consumer with Bounded Buffer

The producer-consumer pattern demonstrates how wait() and notify() coordinate multiple threads sharing a bounded buffer with capacity constraints.

Producer Thread

  • Produces items and adds to buffer
  • Waits if buffer is full
  • Notifies consumers when adding items

Consumer Thread

  • Consumes items from buffer
  • Waits if buffer is empty
  • Notifies producers when removing items
import java.util.LinkedList;
import java.util.Queue;

public class ProducerConsumerExample {
    private final Queue buffer = new LinkedList<>();
    private final int capacity;
    private final Object lock = new Object();
    
    public ProducerConsumerExample(int capacity) {
        this.capacity = capacity;
    }
    
    // Producer method
    public void produce(int item) throws InterruptedException {
        synchronized (lock) {
            // Wait while buffer is full
            while (buffer.size() == capacity) {
                System.out.println("Buffer full, producer waiting...");
                lock.wait();
            }
            
            // Add item to buffer
            buffer.offer(item);
            System.out.println("Produced: " + item + ", Buffer size: " + buffer.size());
            
            // Notify consumers that buffer is not empty
            lock.notifyAll();
        }
    }
    
    // Consumer method
    public int consume() throws InterruptedException {
        synchronized (lock) {
            // Wait while buffer is empty
            while (buffer.isEmpty()) {
                System.out.println("Buffer empty, consumer waiting...");
                lock.wait();
            }
            
            // Remove item from buffer
            int item = buffer.poll();
            System.out.println("Consumed: " + item + ", Buffer size: " + buffer.size());
            
            // Notify producers that buffer is not full
            lock.notifyAll();
            
            return item;
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        ProducerConsumerExample pc = new ProducerConsumerExample(5);
        
        // Create multiple producers
        Thread[] producers = new Thread[3];
        for (int i = 0; i < producers.length; i++) {
            final int producerId = i;
            producers[i] = new Thread(() -> {
                try {
                    for (int j = 0; j < 5; j++) {
                        int item = producerId * 10 + j;
                        pc.produce(item);
                        Thread.sleep(100); // Simulate production time
                    }
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }, "Producer-" + producerId);
        }
        
        // Create multiple consumers
        Thread[] consumers = new Thread[2];
        for (int i = 0; i < consumers.length; i++) {
            final int consumerId = i;
            consumers[i] = new Thread(() -> {
                try {
                    for (int j = 0; j < 7; j++) { // Consume more than produced by single producer
                        pc.consume();
                        Thread.sleep(150); // Simulate consumption time
                    }
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }, "Consumer-" + consumerId);
        }
        
        // Start all threads
        for (Thread producer : producers) {
            producer.start();
        }
        for (Thread consumer : consumers) {
            consumer.start();
        }
        
        // Wait for completion
        for (Thread producer : producers) {
            producer.join();
        }
        for (Thread consumer : consumers) {
            consumer.join();
        }
        
        System.out.println("Producer-Consumer example completed");
    }
}

Conditions & Spurious Wakeups

Spurious Wakeups

Threads can sometimes wake up from wait() without being notified. This is called a "spurious wakeup" and must be handled properly. 

public class SpuriousWakeupHandling {
    private boolean condition = false;
    private final Object lock = new Object();
    
    // ❌ WRONG - susceptible to spurious wakeups
    public void wrongWait() throws InterruptedException {
        synchronized (lock) {
            if (!condition) {
                lock.wait(); // May wake up without notification!
            }
            // Proceed assuming condition is true (may be false!)
        }
    }
    
    // ✅ CORRECT - handles spurious wakeups
    public void correctWait() throws InterruptedException {
        synchronized (lock) {
            // Always use wait() in a while loop
            while (!condition) {
                lock.wait(); // If spurious wakeup occurs, check condition again
            }
            // Condition is guaranteed to be true here
            System.out.println("Condition is true, proceeding...");
        }
    }
    
    public void setCondition() {
        synchronized (lock) {
            condition = true;
            lock.notifyAll();
        }
    }
}

Why Spurious Wakeups Happen

Due to underlying OS and JVM implementation details. Always assume they can occur.

Multiple Conditions

When multiple conditions need to be waited upon, use different lock objects or implement condition checking. 

public class MultipleConditionsExample {
    private boolean condition1 = false;
    private boolean condition2 = false;
    private final Object lock = new Object();
    
    public void waitForCondition1() throws InterruptedException {
        synchronized (lock) {
            while (!condition1) {
                lock.wait();
            }
            condition1 = false; // Reset for next use
            System.out.println("Condition 1 satisfied");
        }
    }
    
    public void waitForCondition2() throws InterruptedException {
        synchronized (lock) {
            while (!condition2) {
                lock.wait();
            }
            condition2 = false; // Reset for next use
            System.out.println("Condition 2 satisfied");
        }
    }
    
    public void setCondition1() {
        synchronized (lock) {
            condition1 = true;
            lock.notifyAll(); // Wake all to check their conditions
        }
    }
    
    public void setCondition2() {
        synchronized (lock) {
            condition2 = true;
            lock.notifyAll(); // Wake all to check their conditions
        }
    }
    
    // More efficient approach with selective notification
    public void efficientWaitForCondition1() throws InterruptedException {
        synchronized (lock) {
            while (!condition1) {
                lock.wait();
            }
        }
    }
    
    // But we can't selectively notify with basic wait/notify
    // For selective notification, use java.util.concurrent.locks.Condition
}

Advanced: Wait with Timeout Pattern

import java.util.concurrent.TimeUnit;
import java.util.concurrent.TimeoutException;

public class TimedWaitExample {
    private boolean condition = false;
    private final Object lock = new Object();
    
    /**
     * Waits for condition to be true, with timeout
     * @param timeout the maximum time to wait
     * @param unit the time unit of the timeout argument
     * @return true if condition became true, false if timeout occurred
     * @throws InterruptedException if thread is interrupted
     */
    public boolean waitForCondition(long timeout, TimeUnit unit) 
            throws InterruptedException {
        
        long nanosTimeout = unit.toNanos(timeout);
        long startTime = System.nanoTime();
        
        synchronized (lock) {
            while (!condition) {
                if (nanosTimeout <= 0) {
                    return false; // Timeout occurred
                }
                
                // Wait for remaining time or until notified
                long waitStart = System.nanoTime();
                lock.wait(nanosTimeout / 1_000_000, (int) (nanosTimeout % 1_000_000));
                long waitEnd = System.nanoTime();
                
                // Update remaining time
                nanosTimeout -= (waitEnd - waitStart);
                
                // Check if condition was set while we were waiting
                if (condition) {
                    return true;
                }
            }
            return true; // Condition was already true
        }
    }
    
    /**
     * Alternative implementation that throws exception on timeout
     */
    public void waitForConditionOrThrow(long timeout, TimeUnit unit) 
            throws InterruptedException, TimeoutException {
        
        if (!waitForCondition(timeout, unit)) {
            throw new TimeoutException("Condition not met within " + timeout + " " + unit);
        }
    }
    
    public void setCondition() {
        synchronized (lock) {
            condition = true;
            lock.notifyAll();
        }
    }
    
    public void resetCondition() {
        synchronized (lock) {
            condition = false;
        }
    }
    
    public static void main(String[] args) {
        TimedWaitExample example = new TimedWaitExample();
        
        Thread waiter = new Thread(() -> {
            try {
                System.out.println("Waiting for condition with 3 second timeout...");
                boolean success = example.waitForCondition(3, TimeUnit.SECONDS);
                
                if (success) {
                    System.out.println("Condition met within timeout!");
                } else {
                    System.out.println("Timeout occurred before condition was met");
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        
        Thread setter = new Thread(() -> {
            try {
                Thread.sleep(2000); // Set condition after 2 seconds
                example.setCondition();
                System.out.println("Condition set by setter thread");
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        
        waiter.start();
        setter.start();
        
        try {
            waiter.join();
            setter.join();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

Best Practices

Always Use While Loop

Protect against spurious wakeups by checking condition in a while loop.

while (!condition) { wait(); }

Synchronized Context

Always call wait() and notify() from synchronized blocks/methods.

synchronized(lock) { wait(); }

Prefer notifyAll()

Use notifyAll() unless you have specific performance requirements.

notifyAll() // over notify()

Use Timeouts

Prevent indefinite blocking with wait(timeout) in production code.

wait(5000) // 5 second timeout

Handle Interruption

Always handle InterruptedException properly by restoring interrupt status.

catch (InterruptedException e) { Thread.currentThread().interrupt(); }

Document Assumptions

Clearly document which thread is responsible for notifications.

Common Issues & Solutions

IllegalMonitorStateException

Thrown when wait() or notify() is called without holding the object's monitor.

public class MonitorStateExample {
    private final Object lock = new Object();
    
    // ❌ WRONG - not synchronized
    public void wrongWait() throws InterruptedException {
        lock.wait(); // Throws IllegalMonitorStateException!
    }
    
    // ❌ WRONG - synchronized on wrong object
    public void wrongSyncWait() throws InterruptedException {
        synchronized (this) { // Synchronizing on 'this' but waiting on 'lock'
            lock.wait(); // Throws IllegalMonitorStateException!
        }
    }
    
    // ✅ CORRECT - synchronized on the same object
    public void correctWait() throws InterruptedException {
        synchronized (lock) {
            lock.wait(); // This works correctly
        }
    }
    
    // ✅ CORRECT - synchronized method using 'this'
    public synchronized void correctSyncMethodWait() throws InterruptedException {
        this.wait(); // Synchronized method uses 'this' as lock
    }
}

Lost Notifications

Occurs when notify() is called before wait(), causing the notification to be lost.

public class LostNotificationExample {
    private boolean condition = false;
    private final Object lock = new Object();
    
    // Scenario that can cause lost notification
    public void demonstrateLostNotification() throws InterruptedException {
        // Thread 1: Sets condition and notifies (but no one is waiting yet)
        Thread notifier = new Thread(() -> {
            synchronized (lock) {
                condition = true;
                lock.notify(); // Notification is lost!
                System.out.println("Notification sent, but no one was waiting");
            }
        });
        
        // Thread 2: Waits after notification was already sent
        Thread waiter = new Thread(() -> {
            synchronized (lock) {
                try {
                    while (!condition) {
                        lock.wait(); // Waits forever because notification was lost
                    }
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
        });
        
        notifier.start();
        Thread.sleep(100); // Ensure notifier runs first
        waiter.start();
        
        notifier.join();
        waiter.join(); // This may never complete!
    }
    
    // Solution: Use proper state management and consider notifyAll()
    public void fixedVersion() {
        // Proper design ensures notifications aren't timing-dependent
        // Or use java.util.concurrent components instead
    }
}

  • CyclicBarrier - For repeated synchronization points
  • Phaser - For reusable synchronization barriers

Lock and Condition

For more advanced scenarios, use java.util.concurrent.locks:

import java.util.concurrent.locks.*;

// Modern alternative to wait/notify
Lock lock = new ReentrantLock();
Condition condition = lock.newCondition();

// Waiting
lock.lock();
try {
    while (!someCondition) {
        condition.await(); // Similar to wait()
    }
} finally {
    lock.unlock();
}

// Notifying
lock.lock();
try {
    someCondition = true;
    condition.signalAll(); // Similar to notifyAll()
} finally {
    lock.unlock();
}
