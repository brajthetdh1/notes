Introduction to Concurrent Collections

Concurrent collections in Java are thread-safe implementations of collection interfaces designed for use in multi-threaded environments. They provide better performance than synchronized wrappers (like Collections.synchronizedList()) by using advanced concurrency control techniques.

Why Use Concurrent Collections?
  • Thread Safety: Can be safely accessed by multiple threads simultaneously
  • Performance: Better performance than synchronized collections in high-contention scenarios
  • Scalability: Designed to scale well with increasing numbers of threads
  • Atomic Operations: Provide atomic compound operations (like put-if-absent)

// Traditional synchronized collection
List<String> syncList = Collections.synchronizedList(new ArrayList<>());

// Concurrent collection (better performance)
List<String> concurrentList = new CopyOnWriteArrayList<>();
Blocking Queues

Blocking queues are thread-safe queues that support operations that wait for the queue to become non-empty when retrieving an element, and wait for space to become available when storing an element.

Key Implementations:
  • ArrayBlockingQueue: Bounded blocking queue backed by an array
  • LinkedBlockingQueue: Optionally bounded queue based on linked nodes
  • PriorityBlockingQueue: Unbounded blocking priority queue
  • SynchronousQueue: Queue with zero capacity
  • DelayQueue: Queue where elements can only be taken when their delay has expired

↓ put()
Blocking Queue
[Element 1][Element 2]...

Example: Producer-Consumer with ArrayBlockingQueue

import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;

public class ProducerConsumerExample {
    public static void main(String[] args) {
        // Create a blocking queue with capacity of 10
        BlockingQueue<String> queue = new ArrayBlockingQueue<>(10);
        
        // Producer thread
        Thread producer = new Thread(() -> {
            try {
                for (int i = 0; i < 20; i++) {
                    String item = "Item " + i;
                    queue.put(item); // Blocks if queue is full
                    System.out.println("Produced: " + item);
                    Thread.sleep(100);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        
        // Consumer thread
        Thread consumer = new Thread(() -> {
            try {
                for (int i = 0; i < 20; i++) {
                    String item = queue.take(); // Blocks if queue is empty
                    System.out.println("Consumed: " + item);
                    Thread.sleep(200);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        
        producer.start();
        consumer.start();
    }
}
Concurrent Maps

Concurrent maps provide thread-safe implementations of the Map interface with better performance than synchronized maps.

Key Implementations:
  • ConcurrentHashMap: Highly concurrent hash map implementation
  • ConcurrentSkipListMap: Concurrent map with sorted keys
ConcurrentHashMap Features:
  • Uses lock striping for better concurrency
  • Provides atomic operations (putIfAbsent, replace, etc.)
  • Supports parallel bulk operations
  • Doesn't allow null keys or values
ConcurrentHashMap Internal Structure
Segment 1
Bucket 1 → Bucket 2 → ...
Segment 2
Bucket 1 → Bucket 2 → ...
Segment N
Bucket 1 → Bucket 2 → ...
Multiple threads can operate on different segments concurrently
Example: Using ConcurrentHashMap

import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ConcurrentMap;

public class ConcurrentMapExample {
    public static void main(String[] args) {
        ConcurrentMap<String, Integer> map = new ConcurrentHashMap<>();
        
        // Multiple threads can safely update the map
        Runnable task = () -> {
            for (int i = 0; i < 1000; i++) {
                // Atomic operation - thread-safe
                map.merge("key", 1, Integer::sum);
            }
        };
        
        Thread t1 = new Thread(task);
        Thread t2 = new Thread(task);
        
        t1.start();
        t2.start();
        
        try {
            t1.join();
            t2.join();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        
        System.out.println("Final value: " + map.get("key")); // Should be 2000
    }
}
ConcurrentHashMap vs Synchronized HashMap

Copy-On-Write Collections

Copy-on-write collections maintain thread safety by creating a new copy of the underlying array whenever the collection is modified. They are ideal for read-heavy scenarios.

Key Implementations:
  • CopyOnWriteArrayList: Thread-safe variant of ArrayList
  • CopyOnWriteArraySet: Thread-safe Set implementation backed by CopyOnWriteArrayList
When to Use Copy-On-Write Collections:
  • Read operations greatly outnumber write operations
  • Collection size is small to moderate
  • You need to avoid synchronization overhead during iteration

↓ get()

+

↓ add()

Example: Using CopyOnWriteArrayList

import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;

public class CopyOnWriteExample {
    public static void main(String[] args) {
        List<String> list = new CopyOnWriteArrayList<>();
        
        // Add initial elements
        list.add("A");
        list.add("B");
        list.add("C");
        
        // Start a thread that iterates over the list
        Thread reader = new Thread(() -> {
            // This iterator works on a snapshot of the list
            for (String item : list) {
                System.out.println("Read: " + item);
                try {
                    Thread.sleep(100);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    break;
                }
            }
        });
        
        // Start a thread that modifies the list
        Thread writer = new Thread(() -> {
            try {
                Thread.sleep(50); // Let reader start first
                list.add("D");
                System.out.println("Added: D");
                list.remove("A");
                System.out.println("Removed: A");
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        
        reader.start();
        writer.start();
        
        try {
            reader.join();
            writer.join();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        
        System.out.println("Final list: " + list);
    }
}
Other Concurrent Collections
ConcurrentLinkedQueue

An unbounded, thread-safe queue based on linked nodes. This queue orders elements FIFO (first-in-first-out).


import java.util.Queue;
import java.util.concurrent.ConcurrentLinkedQueue;

public class ConcurrentQueueExample {
    public static void main(String[] args) {
        Queue<String> queue = new ConcurrentLinkedQueue<>();
        
        // Multiple producers
        for (int i = 0; i < 3; i++) {
            final int producerId = i;
            new Thread(() -> {
                for (int j = 0; j < 5; j++) {
                    String item = "P" + producerId + "-Item" + j;
                    queue.offer(item);
                    System.out.println("Produced: " + item);
                }
            }).start();
        }
        
        // Consumer
        new Thread(() -> {
            int consumed = 0;
            while (consumed < 15) {
                String item = queue.poll();
                if (item != null) {
                    System.out.println("Consumed: " + item);
                    consumed++;
                }
            }
        }).start();
    }
}
ConcurrentSkipListSet

A scalable concurrent NavigableSet implementation based on a ConcurrentSkipListMap.


import java.util.Set;
import java.util.concurrent.ConcurrentSkipListSet;

public class ConcurrentSetExample {
    public static void main(String[] args) {
        Set<Integer> set = new ConcurrentSkipListSet<>();
        
        // Multiple threads adding elements
        Runnable addTask = () -> {
            for (int i = 0; i < 100; i++) {
                set.add((int) (Math.random() * 1000));
            }
        };
        
        Thread t1 = new Thread(addTask);
        Thread t2 = new Thread(addTask);
        
        t1.start();
        t2.start();
        
        try {
            t1.join();
            t2.join();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        
        System.out.println("Set size: " + set.size());
        System.out.println("First element: " + set.stream().findFirst().orElse(-1));
    }
}
Performance Comparison

Performance characteristics of concurrent collections vary based on the use case. Here's a general comparison:

Collection Read Performance Write Performance Memory Overhead Best Use Case
ConcurrentHashMap High High Medium General-purpose concurrent map
CopyOnWriteArrayList High Low High Read-heavy, rarely modified lists
ConcurrentLinkedQueue High High Medium Unbounded producer-consumer scenarios
ArrayBlockingQueue Medium Medium Low Bounded producer-consumer with backpressure
ConcurrentSkipListMap Medium Medium High Sorted concurrent maps
Performance Tips:
  • Choose the right collection for your access pattern (read-heavy vs write-heavy)
  • For maps, set appropriate initial capacity and concurrency level for ConcurrentHashMap
  • Avoid using CopyOnWriteArrayList for frequently modified large collections
  • Consider using ConcurrentHashMap instead of synchronized maps for better scalability
  • Use appropriate queue implementations based on your bounded/unbounded needs
Best Practices
Choosing the Right Concurrent Collection
  • For Maps: Use ConcurrentHashMap for general cases, ConcurrentSkipListMap when you need sorted keys
  • For Lists: Use CopyOnWriteArrayList for read-heavy scenarios, synchronized list for write-heavy scenarios
  • For Queues: Use ArrayBlockingQueue for bounded scenarios, ConcurrentLinkedQueue for unbounded scenarios
  • For Sets: Use ConcurrentHashMap.newKeySet() for general cases, CopyOnWriteArraySet for read-heavy scenarios
Common Pitfalls to Avoid
  • Don't assume compound operations are atomic - use atomic methods provided by the collections
  • Be aware of the memory overhead of CopyOnWrite collections
  • Understand the difference between blocking and non-blocking operations
  • Remember that iterators for concurrent collections are weakly consistent
  • Don't use null keys or values with ConcurrentHashMap
Atomic Operations Example

import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ConcurrentMap;

public class AtomicOperationsExample {
    public static void main(String[] args) {
        ConcurrentMap<String, Integer> map = new ConcurrentHashMap<>();
        
        // Non-atomic approach (NOT thread-safe)
        // if (!map.containsKey("key")) {
        //     map.put("key", 1);
        // }
        
        // Atomic approach (thread-safe)
        map.putIfAbsent("key", 1);
        
        // Atomic update
        map.compute("key", (k, v) -> v == null ? 1 : v + 1);
        
        // Atomic conditional update
        map.replace("key", 2, 3); // Only replaces if current value is 2
        
        System.out.println("Value: " + map.get("key"));
    }
}
When to Use Which Collection
Use Case Recommended Collection Reason
High-frequency updates to key-value pairs ConcurrentHashMap Excellent write scalability
Frequent iteration, rare modifications CopyOnWriteArrayList No ConcurrentModificationException, fast reads
Producer-consumer with backpressure ArrayBlockingQueue Bounded capacity blocks producers when full
Simple thread-safe set ConcurrentHashMap.newKeySet() Better performance than CopyOnWriteArraySet for writes
Need sorted concurrent map ConcurrentSkipListMap Maintains keys in sorted order
