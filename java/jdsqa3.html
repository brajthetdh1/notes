Q101: Trie

Advanced DS
What is a Trie? What are its applications?

A Trie (also called a prefix tree) is a tree-like data structure used to store a dynamic set of strings, where each node represents a character. It allows efficient prefix-based operations.

Key Properties:

  • Each node contains an array of child pointers (26 for lowercase English letters).
  • Common prefixes are shared, making it memory efficient for many strings.
  • Root represents the empty string.

Applications:

  • Autocomplete: Find all words with a given prefix.
  • Spell Checker: Find words in a dictionary.
  • IP Routing: Longest prefix matching.
  • Dictionary Compression.
  • Word Games: Boggle, Scrabble.
// Trie node structure
class TrieNode {
    TrieNode[] children = new TrieNode[26];
    boolean isEndOfWord;
}

// Searching a word
boolean search(String word) {
    TrieNode node = root;
    for (char c : word.toCharArray()) {
        if (node.children[c - 'a'] == null) return false;
        node = node.children[c - 'a'];
    }
    return node.isEndOfWord;
}

Time Complexity: O(L) where L is the length of the string.

Space Complexity: O(ALPHABET_SIZE * N * L) in worst case.

Q102: Segment Tree

Advanced DS
What is a Segment Tree? When would you use it?

A Segment Tree is a tree data structure used for storing intervals or segments. It allows efficient querying and updating of array ranges.

Use Cases:

  • Range Sum Queries: Sum of elements in a range.
  • Range Minimum/Maximum Queries.
  • Range Updates: Adding a value to all elements in a range.
  • Computational Geometry.

Key Features:

  • Build: O(n) time.
  • Query: O(log n) time.
  • Update: O(log n) time.
  • Can be implemented as an array (heap-like).
// Segment tree for range sum
int build(int[] arr, int tree[], int node, int l, int r) {
    if (l == r) return tree[node] = arr[l];
    int mid = (l + r) / 2;
    return tree[node] = build(arr, tree, node*2, l, mid) +
        build(arr, tree, node*2+1, mid+1, r);
}

Space Complexity: O(4n) for array-based implementation.

Q103: Fenwick Tree

Advanced DS
What is a Fenwick Tree (Binary Indexed Tree)? How does it work?

A Fenwick Tree (BIT) is a data structure that provides efficient prefix sum queries and point updates. It uses the concept of binary indexing.

How it works:

  • Uses an array of size n+1.
  • Each index stores the sum of a range of elements.
  • The range is determined by the lowest set bit (LSB).
  • update(i, delta): Add delta to index i, then i += i & -i.
  • query(i): Sum from 1 to i, then i -= i & -i.
int[] bit;
void update(int i, int delta) {
    while (i <= n) { bit[i] += delta; i += i & -i; }
}

int query(int i) {
    int sum = 0;
    while (i > 0) { sum += bit[i]; i -= i & -i; }
    return sum;
}

Time Complexity: O(log n) for both update and query.

Space Complexity: O(n).

Use Cases: Prefix sums, frequency counting, order statistics.

Q104: Disjoint Set (Union-Find)

Advanced DS
What is a Disjoint Set (Union-Find) data structure?

A Disjoint Set (Union-Find) is a data structure that keeps track of a set of elements partitioned into disjoint (non-overlapping) subsets. It supports two operations:

  • Find: Determine which subset a particular element is in.
  • Union: Merge two subsets into a single subset.

Optimizations:

  • Union by Rank/Size: Attach smaller tree under larger tree.
  • Path Compression: Flatten the tree structure for faster find operations.
int[] parent, rank;

int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);
    return parent[x];
}

void union(int x, int y) {
    int rx = find(x), ry = find(y);
    if (rx == ry) return;
    if (rank[rx] < rank[ry]) parent[rx] = ry;
    else if (rank[rx] > rank[ry]) parent[ry] = rx;
    else { parent[ry] = rx; rank[rx]++; }
}

Time Complexity: O(α(n)) ≈ O(1) amortized.

Use Cases: Kruskal's algorithm, connected components, cycle detection.

Q105: Bloom Filter

Advanced DS
What is a Bloom Filter? What are its advantages and disadvantages?

A Bloom Filter is a space-efficient probabilistic data structure used to test whether an element is a member of a set. It can return false positives but never false negatives.

How it works:

  • Uses a bit array of size m and k hash functions.
  • To insert: set bits at positions returned by hash functions to 1.
  • To check: verify all k bits are set to 1.

Advantages:

  • Extremely memory efficient.
  • Constant time insertion and lookup.
  • Can handle large datasets.

Disadvantages:

  • False positives are possible.
  • Cannot delete elements.
  • Cannot retrieve elements.

Use Cases: Web caching, spell checkers, database query optimization, Google Bigtable.

Q106: Skip List

Advanced DS
What is a Skip List? How does it compare to a balanced BST?

A Skip List is a probabilistic data structure that allows fast search, insertion, and deletion in an ordered sequence of elements.

How it works:

  • Consists of multiple levels of linked lists.
  • Level 0 contains all elements.
  • Level 1 contains a subset of elements, level 2 a subset of level 1, etc.
  • Element promotion is random (like a coin toss).

Comparison with Balanced BST:

Time Complexity: O(log n) expected.

Use Cases: Concurrent systems, in-memory databases (Redis).

Q107: Suffix Tree

Advanced DS
What is a Suffix Tree? What are its applications?

A Suffix Tree is a compressed trie of all suffixes of a given string. It contains all suffixes as paths from root to leaves.

Key properties:

  • Each node represents a substring.
  • Leaves represent the suffix index.
  • Paths from root to leaf represent suffixes.

Applications:

  • Pattern Matching: Find occurrences of a pattern in O(m) time.
  • Longest Common Substring: Find common substrings between two strings.
  • DNA Sequence Analysis.
  • Data Compression.
  • Bioinformatics.

Space Complexity: O(n) for the string.

Note: Suffix trees are memory-intensive and are often replaced by suffix arrays in practice.

Q108: B-Tree

Advanced DS
What is a B-Tree? Why is it used in databases?

A B-Tree is a self-balancing tree data structure that maintains sorted data and allows searches, sequential access, insertions, and deletions in logarithmic time.

Key properties:

  • All leaves at the same level.
  • Internal nodes have between ceil(m/2) and m children.
  • Each node contains keys that separate child subtrees.

Why used in databases:

  • Optimized for disk I/O: Nodes can be large (block size).
  • Balanced: Consistent O(log n) operations.
  • Low height: Fewer disk reads.
  • Range queries: Efficient due to sorted order.

Time Complexity: O(log n) for search, insert, delete.

Order (m): Maximum number of children per node.

Q110: Red-Black Tree Properties

Advanced DS
What is a Red-Black Tree? What are its properties?

A Red-Black Tree is a self-balancing BST where each node has a color (red or black) that maintains balance.

Properties:

  • Every node is either red or black.
  • The root is always black.
  • All leaves (null nodes) are black.
  • Red nodes cannot have red children (no two consecutive reds).
  • Every path from a node to its descendant leaves has the same number of black nodes (black height).

Why use Red-Black Tree?

  • Guarantees O(log n) operations.
  • Fewer rotations than AVL (better for insertion/deletion).
  • Used in Java's TreeMap and TreeSet.
  • Used in C++ STL std::map and std::set.

Time Complexity: O(log n) for search, insert, delete.

Q112: Splay Tree

Advanced DS
What is a Splay Tree? What is the concept of splaying?

A Splay Tree is a self-adjusting binary search tree that moves recently accessed elements closer to the root through a series of rotations called splaying.

Splaying:

  • Zig-Zig: Rotate node with its grandparent when both are left or both are right children.
  • Zig-Zag: Rotate node with its parent, then with grandparent (opposite directions).
  • Zig: Simple rotation when node is at depth 1.

Advantages:

  • Amortized O(log n) complexity.
  • Excellent locality of reference.
  • No need for balance information.

Use Cases:

  • Cache implementations.
  • Data structures with locality of access.
  • Garbage collection.

Q113: Treap

Advanced DS
What is a Treap? How does it combine properties of BST and Heap?

A Treap is a randomized binary search tree that combines a BST (ordered by key) with a heap (ordered by priority).

Properties:

  • BST Property: In-order traversal yields sorted keys.
  • Heap Property: Priorities follow min-heap or max-heap order.
  • Priorities are randomly assigned.

Operations:

  • Insert: Insert as BST node, then rotate up to maintain heap property.
  • Delete: Rotate node down until it becomes a leaf, then remove.
  • Search: Standard BST search.
// Treap node
class TreapNode {
    int key, priority;
    TreapNode left, right;
}

Time Complexity: O(log n) expected due to random priorities.

Advantages: Simple implementation, randomized balance, no rotations needed.

Q115: Fibonacci Heap

Advanced DS
What is a Fibonacci Heap? What are its advantages?

A Fibonacci Heap is a collection of heap-ordered trees with a lazy consolidation strategy.

Key Features:

  • It's a min-heap ordered forest.
  • Uses lazy deletion – elements are marked for deletion but not removed immediately.
  • Consolidation happens during extract-min operation.

Advantages:

  • O(1) amortized time for insert, decrease-key, and merge.
  • O(log n) amortized time for extract-min.
  • Excellent for algorithms with many decrease-key operations (Dijkstra, Prim).

Disadvantages:

  • Complex implementation.
  • High constant factors.
  • Not suitable for small datasets.

Use Cases: Graph algorithms, computational geometry, operations research.

Q117: Master Theorem

Complexity
What is the Master Theorem? How is it used in complexity analysis?

The Master Theorem provides a cookbook solution for recurrence relations of the form:

T(n) = aT(n/b) + f(n), where a ≥ 1, b > 1.

Three cases:

  • Case 1: If f(n) = O(nlogba - ε), then T(n) = Θ(nlogba).
  • Case 2: If f(n) = Θ(nlogba), then T(n) = Θ(nlogba log n).
  • Case 3: If f(n) = Ω(nlogba + ε) and af(n/b) ≤ cf(n), then T(n) = Θ(f(n)).

Example: Merge Sort: T(n) = 2T(n/2) + O(n) → Case 2 → T(n) = Θ(n log n).

Limitations: Only works for specific recurrence forms.

Q119: NP-Complete vs NP-Hard

Complexity
Difference between NP-Complete and NP-Hard problems?
  • NP (Nondeterministic Polynomial): Problems whose solution can be verified in polynomial time.
  • NP-Hard: Problems that are at least as hard as the hardest problems in NP. All NP problems can be reduced to an NP-Hard problem.
  • NP-Complete: Problems that are both in NP and NP-Hard.
// NP-Complete examples
• Traveling Salesman Problem (decision version)
• Boolean Satisfiability (SAT)
• Knapsack Problem (decision version)
• Graph Coloring

Key difference: NP-Complete problems can be verified in polynomial time (in NP). NP-Hard problems may not be verifiable in polynomial time.

Q120: NP-Completeness

Complexity
What is the concept of NP-Completeness? Why is it important?

NP-Completeness is a classification of problems that are both in NP and NP-Hard. If any NP-Complete problem can be solved in polynomial time, then all NP problems can be solved in polynomial time.

Why it's important:

  • Helps identify problems that are computationally difficult.
  • Guides algorithm design – if a problem is NP-Complete, focus on approximation algorithms or heuristics.
  • Helps in understanding the limits of computation.

Key Insight: No polynomial-time algorithm has been found for any NP-Complete problem, but none has been proven impossible either.

Examples: SAT, TSP, Knapsack, Graph Coloring, Hamiltonian Path.

Q121: P vs NP

Complexity
What is the P vs NP problem?

The P vs NP problem is one of the most important unsolved problems in computer science. It asks:

"Is every problem whose solution can be quickly verified (NP) also quickly solvable (P)?"

  • P (Polynomial Time): Problems that can be solved in polynomial time.
  • NP (Nondeterministic Polynomial Time): Problems whose solution can be verified in polynomial time.

Implications:

  • If P = NP, all NP-Complete problems have polynomial-time solutions.
  • If P ≠ NP, some problems are inherently difficult.

Most computer scientists believe P ≠ NP, but it remains unproven.

Millennium Prize Problem: $1 million reward for a solution.

Q122: Deterministic vs Non-deterministic

Complexity
Difference between deterministic and non-deterministic algorithms?
  • Deterministic Algorithm: Given the same input, it always produces the same output and follows the same sequence of steps. Standard algorithms are deterministic.
  • Non-deterministic Algorithm: Can make different choices at various points (like multiple possible paths). It is a theoretical model used in complexity theory.
// Deterministic: Binary Search
int binarySearch(int[] arr, int x) {
    int l = 0, r = arr.length - 1;
    while (l <= r) {
        int mid = (l + r) / 2;
        if (arr[mid] == x) return mid;
        if (arr[mid] < x) l = mid + 1;
        else r = mid - 1;
    }
    return -1;
}

Key difference: Deterministic algorithms have a single path of execution; non-deterministic algorithms can explore multiple paths simultaneously (theoretical concept).

Q124: Randomized Algorithms

Complexity
What is the concept of randomized algorithms?

Randomized algorithms use random numbers to make decisions during execution. They can provide better performance or simpler implementations than deterministic algorithms.

Types:

  • Las Vegas: Always gives the correct answer, but runtime can vary (e.g., QuickSort randomized).
  • Monte Carlo: May give incorrect answer with some probability, but has guaranteed runtime (e.g., Randomized Primality Testing).

Advantages:

  • Simpler implementation.
  • Better average-case performance.
  • Avoids worst-case inputs.
// Randomized QuickSort
int partition(int[] arr, int l, int r) {
    int random = l + rand.nextInt(r - l + 1);
    swap(arr, random, r);
    // ... normal partition logic
}

Q126: Memoization vs Tabulation

Complexity
What is the concept of memoization vs tabulation in DP?
  • Memoization: Top-down approach. Recursively solve subproblems and cache results. Only computes subproblems that are needed.
  • Tabulation: Bottom-up approach. Iteratively fill a table in a specific order (usually from smallest to largest subproblem).
AspectMemoizationTabulation
ApproachTop-down (recursion)Bottom-up (iteration)
MemoryUses recursion stackNo recursion stack
SpeedSlower (recursion overhead)Faster
When to useWhen not all subproblems are neededWhen all subproblems are needed
// Memoization (Fibonacci)
int fibMemo(int n, int[] memo) {
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];
    return memo[n] = fibMemo(n-1, memo) + fibMemo(n-2, memo);
}

// Tabulation (Fibonacci)
int fibTab(int n) {
    if (n <= 1) return n;
    int[] dp = new int[n+1];
    dp[0] = 0; dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = dp[i-1] + dp[i-2];
    return dp[n];
}

Q138: Spell Checker

Application
Which data structure would you use for a spell checker?

A Trie is the most suitable data structure for a spell checker.

Why?

  • Efficient prefix matching for word suggestions.
  • Can check if a word exists in O(L) time (L = word length).
  • Memory efficient for shared prefixes.
  • Easy to implement autocomplete and suggestions.

Alternative approaches:

  • Bloom Filter: For fast membership testing (but can have false positives).
  • HashSet: For exact word lookup (O(1)), but no prefix support.
  • B-Tree: For dictionary storage in databases.

Spell Checker Workflow:

  • Build a Trie from the dictionary.
  • For each word, check if it exists.
  • If not, suggest words with similar prefixes or edit distance.

Q139: Autocomplete

Application
Which data structure would you use for autocomplete feature?

A Trie (prefix tree) is the most common data structure for autocomplete.

Why Trie?

Q145: Shortest Path

Application
Which data structure would you use for shortest path finding?

Shortest path algorithms use different data structures:

  • Dijkstra's Algorithm: Uses Priority Queue (min-heap) to extract the vertex with minimum distance.
  • Bellman-Ford: Uses Queue or list of edges.
  • Floyd-Warshall: Uses 2D Array (Adjacency Matrix).
  • A* Algorithm: Uses Priority Queue with heuristic.
// Dijkstra's Algorithm
int[] dijkstra(Graph g, int src) {
    PriorityQueue<Node> pq = new PriorityQueue<>(
        (a, b) -> a.dist - b.dist);
    int[] dist = new int[g.V];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    pq.add(new Node(src, 0));
    while (!pq.isEmpty()) {
        Node curr = pq.poll();
        for (Edge e : g.adj[curr.id]) {
            if (dist[e.to] > dist[curr.id] + e.weight) {
                dist[e.to] = dist[curr.id] + e.weight;
                pq.add(new Node(e.to, dist[e.to]));
            }
        }
    }
    return dist;
}

Key Insight: Priority Queue (heap) is essential for efficient shortest path algorithms.

Q146: Undo/Redo

Application
Which data structure would you use for implementing undo/redo functionality?

Two Stacks (or two lists) are used for undo/redo functionality.

How it works:

  • Undo Stack: Stores actions that can be undone.
  • Redo Stack: Stores actions that can be redone.
  • On undo: pop from undo stack, push to redo stack.
  • On redo: pop from redo stack, push to undo stack.
  • On new action: clear redo stack, push to undo stack.
// Undo/Redo implementation
class UndoRedo {
    Stack<Action> undoStack = new Stack<>();
    Stack<Action> redoStack = new Stack<>();

    void perform(Action action) {
        action.execute();
        undoStack.push(action);
        redoStack.clear();
    }

    void undo() {
        Action a = undoStack.pop();
        a.undo();
        redoStack.push(a);
    }

    void redo() {
        Action a = redoStack.pop();
        a.execute();
        undoStack.push(a);
    }
}

Use Cases: Text editors, image editors, version control systems.

Q147: Data Abstraction

Fundamentals
What is the concept of data abstraction in data structures?

Data Abstraction is the concept of hiding implementation details and exposing only the essential features of a data structure.

Key aspects:

  • Abstract Data Type (ADT): A mathematical model for data types where the behavior is defined by the operations, not the implementation. Examples: Stack, Queue, List.
  • Implementation Hiding: The user only interacts with the interface; the internal implementation is hidden.
  • Encapsulation: Bundling data and methods that operate on that data.

Difference between a node and a pointer?
  • Node: A fundamental unit in a data structure that contains data and references to other nodes. It is a container for data and links.

}

Key difference: A node is an object that holds data and references; a pointer is a variable that holds a memory address.
