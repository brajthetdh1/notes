What is Synchronization?

Synchronization in Java is the capability to control the access of multiple threads to shared resources. Without synchronization, threads can interfere with each other, leading to inconsistent data.

Why Synchronization?

  • Prevent thread interference
  • Avoid consistency problems
  • Control access to shared resources
  • Ensure thread safety

Problems Without Synchronization

Race Condition

When multiple threads access and modify shared data concurrently, leading to unpredictable results.

class Counter {
    private int count = 0;
    
    // Not thread-safe - race condition
    public void increment() {
        count++; // This is NOT atomic
    }
    
    public int getCount() {
        return count;
    }
}

public class RaceConditionExample {
    public static void main(String[] args) throws InterruptedException {
        Counter counter = new Counter();
        
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });
        
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });
        
        t1.start();
        t2.start();
        
        t1.join();
        t2.join();
        
        // May not print 2000!
        System.out.println("Final count: " + counter.getCount());
    }
}

The Problem

count++ is actually three operations: read, increment, write. Threads can interleave these operations.

Data Inconsistency

Threads may see stale or inconsistent values due to caching and memory visibility issues.

class SharedData {
    private boolean flag = false;
    private int data = 0;
    
    public void write() {
        data = 42;          // Step 1
        flag = true;        // Step 2
    }
    
    public void read() {
        if (flag) {         // Step 3
            System.out.println("Data: " + data); // Step 4
        }
    }
}

public class VisibilityProblem {
    public static void main(String[] args) {
        SharedData shared = new SharedData();
        
        Thread writer = new Thread(() -> {
            shared.write();
        });
        
        Thread reader = new Thread(() -> {
            shared.read(); // Might see flag=true but data=0!
        });
        
        writer.start();
        reader.start();
    }
}

Visibility Issue

Due to CPU caching, the reader thread might not see the updated values immediately.

Synchronized Keyword

Synchronized Method

Synchronized methods lock on the object instance (for instance methods) or class (for static methods).

class SynchronizedCounter {
    private int count = 0;
    
    // Synchronized instance method
    // Locks on 'this' object
    public synchronized void increment() {
        count++;
    }
    
    // Synchronized static method
    // Locks on Class object
    public static synchronized void staticIncrement() {
        // static counter increment
    }
    
    public int getCount() {
        return count;
    }
}

public class SynchronizedMethodExample {
    public static void main(String[] args) throws InterruptedException {
        SynchronizedCounter counter = new SynchronizedCounter();
        
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });
        
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });
        
        t1.start();
        t2.start();
        
        t1.join();
        t2.join();
        
        // Always prints 2000
        System.out.println("Final count: " + counter.getCount());
    }
}

Thread Safety

Only one thread can execute synchronized methods on the same object at a time.

Synchronized Block

Synchronized blocks provide finer-grained control by locking on specific objects.

class FineGrainedCounter {
    private int count1 = 0;
    private int count2 = 0;
    
    // Use separate lock objects for different resources
    private final Object lock1 = new Object();
    private final Object lock2 = new Object();
    
    public void increment1() {
        // Synchronized block with custom lock
        synchronized(lock1) {
            count1++;
        }
    }
    
    public void increment2() {
        // Synchronized block with different lock
        synchronized(lock2) {
            count2++;
        }
    }
    
    // Method that needs to lock both counters
    public void incrementBoth() {
        // To avoid deadlock, always acquire locks in same order
        synchronized(lock1) {
            synchronized(lock2) {
                count1++;
                count2++;
            }
        }
    }
    
    public void printCounts() {
        synchronized(lock1) {
            synchronized(lock2) {
                System.out.println("Count1: " + count1 + ", Count2: " + count2);
            }
        }
    }
}

public class SynchronizedBlockExample {
    public static void main(String[] args) {
        FineGrainedCounter counter = new FineGrainedCounter();
        
        // Multiple threads can increment count1 and count2 concurrently
        // because they use different locks
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment1();
            }
        });
        
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment2();
            }
        });
        
        t1.start();
        t2.start();
        
        try {
            t1.join();
            t2.join();
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
        
        counter.printCounts(); // Both will be 1000
    }
}

Advantage

Better performance through finer-grained locking and reduced contention.

Synchronized Details

Lock Objects

  • Instance methods: Lock on this object
  • Static methods: Lock on Class object
  • Synchronized blocks: Lock on specified object
  • Intrinsic locks: Reentrant (thread can acquire same lock multiple times)

Best Practices

  • Keep synchronized blocks as small as possible
  • Use separate locks for independent resources
  • Avoid nested synchronized blocks to prevent deadlocks
  • Document locking strategy clearly
class ReentrantExample {
    public synchronized void methodA() {
        System.out.println("In methodA");
        methodB(); // This works - lock is reentrant
    }
    
    public synchronized void methodB() {
        System.out.println("In methodB");
    }
    
    public void demonstrateReentrancy() {
        synchronized(this) {
            System.out.println("First synchronized block");
            // Reentrant - same thread can acquire lock again
            synchronized(this) {
                System.out.println("Nested synchronized block");
            }
        }
    }
}

public class ReentrantLockDemo {
    public static void main(String[] args) {
        ReentrantExample example = new ReentrantExample();
        example.methodA(); // No deadlock - lock is reentrant
        example.demonstrateReentrancy();
    }
}

Lock Interface

java.util.concurrent.locks Package

The Lock interface provides more flexible and sophisticated locking operations than synchronized methods/blocks.

ReentrantLock

import java.util.concurrent.locks.ReentrantLock;
import java.util.concurrent.locks.Lock;

class LockBasedCounter {
    private int count = 0;
    private final Lock lock = new ReentrantLock();
    
    public void increment() {
        lock.lock(); // Acquire the lock
        try {
            count++;
        } finally {
            lock.unlock(); // Always release in finally block
        }
    }
    
    // TryLock example - non-blocking
    public boolean tryIncrement() {
        if (lock.tryLock()) { // Try without waiting
            try {
                count++;
                return true;
            } finally {
                lock.unlock();
            }
        }
        return false; // Lock wasn't available
    }
    
    // Lock with timeout
    public boolean incrementWithTimeout() throws InterruptedException {
        if (lock.tryLock(1, TimeUnit.SECONDS)) { // Wait up to 1 second
            try {
                count++;
                return true;
            } finally {
                lock.unlock();
            }
        }
        return false; // Couldn't acquire lock within timeout
    }
    
    public int getCount() {
        lock.lock();
        try {
            return count;
        } finally {
            lock.unlock();
        }
    }
}

public class ReentrantLockExample {
    public static void main(String[] args) throws InterruptedException {
        LockBasedCounter counter = new LockBasedCounter();
        
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });
        
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });
        
        t1.start();
        t2.start();
        
        t1.join();
        t2.join();
        
        System.out.println("Final count: " + counter.getCount()); // 2000
    }
}

ReadWriteLock

import java.util.concurrent.locks.ReadWriteLock;
import java.util.concurrent.locks.ReentrantReadWriteLock;

class ThreadSafeDictionary {
    private final Map dictionary = new HashMap<>();
    private final ReadWriteLock rwLock = new ReentrantReadWriteLock();
    
    // Multiple threads can read concurrently
    public String get(String key) {
        rwLock.readLock().lock();
        try {
            return dictionary.get(key);
        } finally {
            rwLock.readLock().unlock();
        }
    }
    
    // Only one thread can write at a time
    public void put(String key, String value) {
        rwLock.writeLock().lock();
        try {
            dictionary.put(key, value);
        } finally {
            rwLock.writeLock().unlock();
        }
    }
    
    // Multiple readers, exclusive writer
    public boolean containsKey(String key) {
        rwLock.readLock().lock();
        try {
            return dictionary.containsKey(key);
        } finally {
            rwLock.readLock().unlock();
        }
    }
}

public class ReadWriteLockExample {
    public static void main(String[] args) {
        ThreadSafeDictionary dictionary = new ThreadSafeDictionary();
        
        // Multiple readers can access concurrently
        Thread reader1 = new Thread(() -> {
            for (int i = 0; i < 100; i++) {
                dictionary.get("key" + i);
            }
        });
        
        Thread reader2 = new Thread(() -> {
            for (int i = 0; i < 100; i++) {
                dictionary.get("key" + i);
            }
        });
        
        // Writer has exclusive access
        Thread writer = new Thread(() -> {
            for (int i = 0; i < 100; i++) {
                dictionary.put("key" + i, "value" + i);
            }
        });
        
        writer.start();
        reader1.start();
        reader2.start();
        
        try {
            writer.join();
            reader1.join();
            reader2.join();
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
    }
}

synchronized vs Lock Interface

Feature synchronized Lock Interface
Acquisition Automatic, implicit Explicit with lock()/unlock()
Try Lock No Yes, with tryLock()
Timeout No Yes, with tryLock(timeout)
Interruption No (blocks indefinitely) Yes, with lockInterruptibly()
Fairness No guaranteed order Configurable fairness policy
Read/Write No distinction Separate read and write locks

Volatile Keyword

Visibility Guarantees

The volatile keyword ensures that changes to a variable are immediately visible to all threads. It prevents thread caching and ensures reads/writes go directly to main memory.

Important Notes

  • Volatile provides visibility but NOT atomicity
  • Use for simple flag variables or status indicators
  • Not suitable for compound operations (like count++)
  • Prevents instruction reordering
class VolatileExample {
    // Without volatile, changes might not be visible to other threads
    private volatile boolean running = true;
    private volatile int counter = 0; // NOT atomic for increment!
    
    public void start() {
        Thread worker = new Thread(() -> {
            while (running) { // Always sees the latest value
                // Do some work
                counter++; // This is NOT thread-safe!
            }
            System.out.println("Worker stopped");
        });
        worker.start();
    }
    
    public void stop() {
        running = false; // Immediately visible to worker thread
    }
    
    // Correct usage - status flag
    public void correctUsage() {
        volatile boolean shutdownRequested = false;
        
        Thread worker = new Thread(() -> {
            while (!shutdownRequested) {
                // Process tasks
            }
            System.out.println("Shutting down...");
        });
        worker.start();
        
        // Later, from another thread
        shutdownRequested = true; // Immediately visible
    }
}

public class VolatileDemo {
    public static void main(String[] args) throws InterruptedException {
        VolatileExample example = new VolatileExample();
        example.start();
        
        Thread.sleep(1000);
        example.stop(); // Worker thread will see this change immediately
        
        Thread.sleep(100);
    }
}

When to Use Volatile

Good for Volatile
  • Status flags (running, shutdown, initialized)
  • Publish immutable objects safely
  • One-time initialization flags
  • Read-only variables after initialization
Not for Volatile
  • Compound operations (check-then-act)
  • Counter increments/decrements
  • Multiple related variables that need consistent updates
  • Complex state transitions

Atomic Classes

java.util.concurrent.atomic Package

Atomic classes provide lock-free, thread-safe programming on single variables using compare-and-swap (CAS) operations.

Basic Atomic Types

import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.atomic.AtomicLong;
import java.util.concurrent.atomic.AtomicBoolean;
import java.util.concurrent.atomic.AtomicReference;

public class AtomicExamples {
    public static void main(String[] args) throws InterruptedException {
        // Atomic counter - lock-free and thread-safe
        AtomicInteger counter = new AtomicInteger(0);
        
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.incrementAndGet(); // Atomic operation
            }
        });
        
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.incrementAndGet();
            }
        });
        
        t1.start();
        t2.start();
        
        t1.join();
        t2.join();
        
        System.out.println("Final count: " + counter.get()); // Always 2000
        
        // Atomic boolean for flags
        AtomicBoolean flag = new AtomicBoolean(true);
        
        // Atomic reference for object references
        AtomicReference message = new AtomicReference<>("Hello");
        
        // Compare and set example
        String oldValue = message.get();
        String newValue = "World";
        boolean updated = message.compareAndSet(oldValue, newValue);
        System.out.println("Update successful: " + updated);
        
        // Complex atomic operations
        AtomicInteger value = new AtomicInteger(10);
        
        // Atomic update with function
        int result = value.updateAndGet(x -> x * 2 + 1);
        System.out.println("Updated value: " + result); // 21
        
        // Accumulate values
        value.accumulateAndGet(5, (x, y) -> x + y);
        System.out.println("After accumulate: " + value.get()); // 26
    }
}

Advanced Atomic Operations

import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.atomic.LongAdder;

class AtomicCounter {
    private final AtomicInteger count = new AtomicInteger(0);
    
    public void increment() {
        count.incrementAndGet();
    }
    
    public void decrement() {
        count.decrementAndGet();
    }
    
    public int get() {
        return count.get();
    }
    
    // Complex atomic operation
    public boolean compareAndSet(int expected, int newValue) {
        return count.compareAndSet(expected, newValue);
    }
    
    // Atomic update with transformation
    public int multiplyAndGet(int multiplier) {
        return count.updateAndGet(x -> x * multiplier);
    }
}

// High-performance counter for high contention scenarios
class HighPerformanceCounter {
    private final LongAdder adder = new LongAdder();
    
    public void increment() {
        adder.increment();
    }
    
    public long get() {
        return adder.sum();
    }
}

public class AdvancedAtomicOperations {
    public static void main(String[] args) throws InterruptedException {
        // Standard atomic counter
        AtomicCounter counter = new AtomicCounter();
        
        Thread[] threads = new Thread[10];
        for (int i = 0; i < threads.length; i++) {
            threads[i] = new Thread(() -> {
                for (int j = 0; j < 1000; j++) {
                    counter.increment();
                }
            });
            threads[i].start();
        }
        
        for (Thread t : threads) {
            t.join();
        }
        
        System.out.println("Atomic counter: " + counter.get()); // 10000
        
        // High-performance counter
        HighPerformanceCounter hpCounter = new HighPerformanceCounter();
        
        for (int i = 0; i < threads.length; i++) {
            threads[i] = new Thread(() -> {
                for (int j = 0; j < 1000; j++) {
                    hpCounter.increment();
                }
            });
            threads[i].start();
        }
        
        for (Thread t : threads) {
            t.join();
        }
        
        System.out.println("LongAdder counter: " + hpCounter.get()); // 10000
        
        // Demonstrate CAS operation
        AtomicInteger value = new AtomicInteger(100);
        
        // This will succeed
        boolean success1 = value.compareAndSet(100, 200);
        System.out.println("First CAS: " + success1 + ", value: " + value.get());
        
        // This will fail because value is now 200, not 100
        boolean success2 = value.compareAndSet(100, 300);
        System.out.println("Second CAS: " + success2 + ", value: " + value.get());
    }
}

Synchronization Best Practices

Minimize Lock Scope

Keep synchronized blocks as small as possible to reduce contention and improve performance.

Avoid Nested Locks

Prevent deadlocks by acquiring locks in a consistent order or using timeout mechanisms.

Use ReadWriteLock

For read-heavy workloads, use ReadWriteLock to allow multiple concurrent readers.

Prefer Atomic Classes

Use atomic classes for simple counters and flags to avoid lock contention.

Document Thread Safety

Clearly document the thread safety guarantees and synchronization strategies of your classes.

Test Thoroughly

Use stress testing and thread analysis tools to identify concurrency issues.
