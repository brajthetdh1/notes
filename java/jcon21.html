Lock Interface Overview

The java.util.concurrent.locks.Lock interface provides a more flexible and powerful locking mechanism than intrinsic synchronization. It offers explicit lock acquisition and release, timeout support, and interruptible locking.

Key Advantages

  • Explicit lock acquisition and release
  • Try-lock with timeout support
  • Interruptible lock acquisition
  • Non-block-structured locking
  • Multiple condition variables per lock

Lock Hierarchy

Lock Interface

Base interface for all locks

ReentrantLock

Most commonly used implementation

ReadWriteLock

Separate read and write locks

Basic Lock Usage Pattern

import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class BasicLockExample {
    private final Lock lock = new ReentrantLock();
    private int sharedResource = 0;
    
    public void criticalSection() {
        lock.lock();  // Acquire the lock
        try {
            // Critical section - thread-safe operations
            sharedResource++;
            System.out.println("Thread " + Thread.currentThread().getName() + 
                             " updated resource to: " + sharedResource);
        } finally {
            lock.unlock();  // Always release in finally block
        }
    }
    
    public static void main(String[] args) {
        BasicLockExample example = new BasicLockExample();
        
        // Create multiple threads accessing the critical section
        Thread[] threads = new Thread[5];
        for (int i = 0; i < threads.length; i++) {
            threads[i] = new Thread(() -> {
                for (int j = 0; j < 3; j++) {
                    example.criticalSection();
                    try {
                        Thread.sleep(100); // Simulate some work
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                    }
                }
            });
            threads[i].start();
        }
        
        // Wait for all threads to complete
        for (Thread thread : threads) {
            try {
                thread.join();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
        
        System.out.println("Final resource value: " + example.sharedResource);
    }
}

ReentrantLock Deep Dive

Reentrancy

A thread can acquire the same lock multiple times without deadlocking itself. Each lock acquisition must be matched with a release. 

import java.util.concurrent.locks.ReentrantLock;

public class ReentrancyExample {
    private final ReentrantLock lock = new ReentrantLock();
    
    public void outerMethod() {
        lock.lock();
        try {
            System.out.println("Outer method - Lock count: " + lock.getHoldCount());
            innerMethod(); // Reentrant call - same thread can acquire lock again
        } finally {
            lock.unlock();
        }
    }
    
    public void innerMethod() {
        lock.lock(); // This works - lock is reentrant
        try {
            System.out.println("Inner method - Lock count: " + lock.getHoldCount());
            // The lock will only be released when unlock() is called as many times as lock()
        } finally {
            lock.unlock();
        }
    }
    
    public void demonstrateReentrancy() {
        System.out.println("Initial - isLocked: " + lock.isLocked() + 
                         ", Hold count: " + lock.getHoldCount());
        
        outerMethod();
        
        System.out.println("Final - isLocked: " + lock.isLocked() + 
                         ", Hold count: " + lock.getHoldCount());
    }
    
    public static void main(String[] args) {
        ReentrancyExample example = new ReentrancyExample();
        example.demonstrateReentrancy();
    }
}

Reentrancy in Action

The lock maintains a hold count. It's only released when unlock() is called as many times as lock().

Fairness Policy

ReentrantLock can be configured with a fairness policy. When fair, locks are granted to the longest-waiting thread. 

import java.util.concurrent.locks.ReentrantLock;

public class FairnessExample {
    // Fair lock - grants access to the longest-waiting thread
    private final ReentrantLock fairLock = new ReentrantLock(true);
    
    // Non-fair lock - no guarantee about acquisition order
    private final ReentrantLock nonFairLock = new ReentrantLock(false);
    
    public void accessWithFairLock(String threadName) {
        fairLock.lock();
        try {
            System.out.println(threadName + " acquired fair lock");
            Thread.sleep(100); // Simulate work
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            fairLock.unlock();
        }
    }
    
    public void accessWithNonFairLock(String threadName) {
        nonFairLock.lock();
        try {
            System.out.println(threadName + " acquired non-fair lock");
            Thread.sleep(100);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            nonFairLock.unlock();
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        FairnessExample example = new FairnessExample();
        
        System.out.println("=== Fair Lock Test ===");
        Thread[] fairThreads = new Thread[5];
        for (int i = 0; i < fairThreads.length; i++) {
            final int threadId = i;
            fairThreads[i] = new Thread(() -> {
                example.accessWithFairLock("FairThread-" + threadId);
            });
        }
        
        // Start threads in order
        for (Thread t : fairThreads) {
            t.start();
            Thread.sleep(10); // Small delay to ensure ordering
        }
        
        for (Thread t : fairThreads) {
            t.join();
        }
        
        System.out.println("\n=== Non-Fair Lock Test ===");
        Thread[] nonFairThreads = new Thread[5];
        for (int i = 0; i < nonFairThreads.length; i++) {
            final int threadId = i;
            nonFairThreads[i] = new Thread(() -> {
                example.accessWithNonFairLock("NonFairThread-" + threadId);
            });
        }
        
        for (Thread t : nonFairThreads) {
            t.start();
            Thread.sleep(10);
        }
        
        for (Thread t : nonFairThreads) {
            t.join();
        }
    }
}

Fairness Trade-off

Fair locks prevent starvation but have higher overhead. Non-fair locks are faster but may cause starvation.

Lock Monitoring

import java.util.concurrent.locks.ReentrantLock;

public class LockMonitoringExample {
    private final ReentrantLock lock = new ReentrantLock();
    
    public void demonstrateMonitoring() {
        System.out.println("=== Lock State Information ===");
        System.out.println("isLocked: " + lock.isLocked());
        System.out.println("isHeldByCurrentThread: " + lock.isHeldByCurrentThread());
        System.out.println("getHoldCount: " + lock.getHoldCount());
        System.out.println("isFair: " + lock.isFair());
        System.out.println("hasQueuedThreads: " + lock.hasQueuedThreads());
        System.out.println("getQueueLength: " + lock.getQueueLength());
        
        lock.lock();
        try {
            System.out.println("\n=== After acquiring lock ===");
            System.out.println("isLocked: " + lock.isLocked());
            System.out.println("isHeldByCurrentThread: " + lock.isHeldByCurrentThread());
            System.out.println("getHoldCount: " + lock.getHoldCount());
            
            // Nested lock acquisition
            lock.lock();
            System.out.println("After nested lock - getHoldCount: " + lock.getHoldCount());
            lock.unlock();
            
        } finally {
            lock.unlock();
            System.out.println("\n=== After releasing lock ===");
            System.out.println("isLocked: " + lock.isLocked());
            System.out.println("getHoldCount: " + lock.getHoldCount());
        }
    }
    
    public static void main(String[] args) {
        LockMonitoringExample example = new LockMonitoringExample();
        example.demonstrateMonitoring();
    }
}

TryLock with Timeout

import java.util.concurrent.TimeUnit;
import java.util.concurrent.locks.ReentrantLock;

public class TryLockExample {
    private final ReentrantLock lock = new ReentrantLock();
    
    public boolean attemptTaskWithTimeout(long timeout, TimeUnit unit) {
        boolean locked = false;
        try {
            // Try to acquire lock with timeout
            locked = lock.tryLock(timeout, unit);
            if (locked) {
                System.out.println(Thread.currentThread().getName() + 
                                 " acquired lock successfully");
                // Perform critical section work
                Thread.sleep(500); // Simulate work
                return true;
            } else {
                System.out.println(Thread.currentThread().getName() + 
                                 " could not acquire lock within timeout");
                return false;
            }
        } catch (InterruptedException e) {
            System.out.println(Thread.currentThread().getName() + " was interrupted");
            Thread.currentThread().interrupt();
            return false;
        } finally {
            if (locked) {
                lock.unlock();
            }
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        TryLockExample example = new TryLockExample();
        
        // Thread that holds the lock for a while
        Thread holder = new Thread(() -> {
            example.lock.lock();
            try {
                System.out.println("Holder thread acquired lock, sleeping...");
                Thread.sleep(2000); // Hold lock for 2 seconds
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            } finally {
                example.lock.unlock();
                System.out.println("Holder thread released lock");
            }
        });
        
        // Thread that tries to acquire with timeout
        Thread attemptor = new Thread(() -> {
            boolean success = example.attemptTaskWithTimeout(1, TimeUnit.SECONDS);
            System.out.println("Attemptor result: " + success);
        });
        
        holder.start();
        Thread.sleep(100); // Ensure holder gets lock first
        attemptor.start();
        
        holder.join();
        attemptor.join();
    }
}

Lock Interface Methods

Complete Method Reference

Method Description Usage
void lock() Acquires the lock, blocking if necessary Standard lock acquisition
void lockInterruptibly() Acquires lock unless current thread is interrupted Interruptible locking
boolean tryLock() Acquires lock only if available immediately Non-blocking attempt
boolean tryLock(long time, TimeUnit unit) Acquires lock within given waiting time Timeout-based acquisition
void unlock() Releases the lock Always call in finally block
Condition newCondition() Returns new Condition bound to this lock Advanced thread coordination

Practical Method Usage Examples

import java.util.concurrent.TimeUnit;
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class LockMethodsExample {
    private final Lock lock = new ReentrantLock();
    private int counter = 0;
    
    // Example 1: Basic lock() and unlock()
    public void basicLockExample() {
        lock.lock();
        try {
            counter++;
            System.out.println("Counter: " + counter);
        } finally {
            lock.unlock();
        }
    }
    
    // Example 2: tryLock() for non-blocking access
    public boolean tryIncrement() {
        if (lock.tryLock()) {
            try {
                counter++;
                System.out.println("Incremented to: " + counter);
                return true;
            } finally {
                lock.unlock();
            }
        } else {
            System.out.println("Could not acquire lock, skipping increment");
            return false;
        }
    }
    
    // Example 3: tryLock with timeout
    public boolean timedIncrement() throws InterruptedException {
        if (lock.tryLock(1, TimeUnit.SECONDS)) {
            try {
                counter++;
                System.out.println("Timed increment to: " + counter);
                return true;
            } finally {
                lock.unlock();
            }
        } else {
            System.out.println("Timeout acquiring lock");
            return false;
        }
    }
    
    // Example 4: lockInterruptibly() for responsive locking
    public void interruptibleIncrement() throws InterruptedException {
        lock.lockInterruptibly();
        try {
            // Simulate long operation
            Thread.sleep(2000);
            counter++;
            System.out.println("Interruptible increment to: " + counter);
        } finally {
            lock.unlock();
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        LockMethodsExample example = new LockMethodsExample();
        
        // Test basic lock
        example.basicLockExample();
        
        // Test tryLock
        example.tryIncrement();
        
        // Test timed tryLock
        example.timedIncrement();
        
        // Test interruptible lock
        Thread interrupter = new Thread(() -> {
            try {
                example.interruptibleIncrement();
            } catch (InterruptedException e) {
                System.out.println("Thread was interrupted during lock acquisition");
            }
        });
        
        interrupter.start();
        Thread.sleep(100); // Let thread start
        interrupter.interrupt(); // Interrupt the thread
        interrupter.join();
    }
}

ReadWriteLock

Optimized for Read-Heavy Workloads

ReadWriteLock maintains a pair of locks: one for read-only operations and one for writing. Multiple readers can hold the read lock simultaneously, but only one writer can hold the write lock.

When to Use ReadWriteLock

  • Read-heavy data structures (caches, configuration)
  • Frequently read, rarely written data
  • When readers significantly outnumber writers
  • When read operations are time-consuming
import java.util.concurrent.locks.ReadWriteLock;
import java.util.concurrent.locks.ReentrantReadWriteLock;
import java.util.HashMap;
import java.util.Map;

public class ReadWriteLockExample {
    private final Map data = new HashMap<>();
    private final ReadWriteLock rwLock = new ReentrantReadWriteLock();
    
    // Read operation - multiple threads can read concurrently
    public String read(String key) {
        rwLock.readLock().lock();
        try {
            System.out.println(Thread.currentThread().getName() + " reading: " + key);
            Thread.sleep(100); // Simulate read operation
            return data.get(key);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            return null;
        } finally {
            rwLock.readLock().unlock();
        }
    }
    
    // Write operation - exclusive access
    public void write(String key, String value) {
        rwLock.writeLock().lock();
        try {
            System.out.println(Thread.currentThread().getName() + " writing: " + key);
            Thread.sleep(200); // Simulate write operation
            data.put(key, value);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            rwLock.writeLock().unlock();
        }
    }
    
    // Upgrade read lock to write lock (not directly supported)
    public void upgradeDemo(String key, String newValue) {
        // This demonstrates why you can't directly upgrade
        rwLock.readLock().lock();
        try {
            if (data.containsKey(key)) {
                // Can't upgrade read lock to write lock directly
                // Must release read lock and acquire write lock
                rwLock.readLock().unlock();
                rwLock.writeLock().lock();
                try {
                    data.put(key, newValue);
                } finally {
                    // Downgrade: acquire read lock before releasing write lock
                    rwLock.readLock().lock();
                    rwLock.writeLock().unlock();
                }
            }
        } finally {
            rwLock.readLock().unlock();
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        ReadWriteLockExample example = new ReadWriteLockExample();
        
        // Initialize some data
        example.write("key1", "value1");
        example.write("key2", "value2");
        
        // Create multiple reader threads
        Thread[] readers = new Thread[5];
        for (int i = 0; i < readers.length; i++) {
            final int readerId = i;
            readers[i] = new Thread(() -> {
                for (int j = 0; j < 3; j++) {
                    example.read("key1");
                }
            }, "Reader-" + readerId);
        }
        
        // Create writer thread
        Thread writer = new Thread(() -> {
            for (int i = 0; i < 2; i++) {
                example.write("key3", "value" + i);
            }
        }, "Writer");
        
        // Start all threads
        for (Thread reader : readers) {
            reader.start();
        }
        writer.start();
        
        // Wait for completion
        for (Thread reader : readers) {
            reader.join();
        }
        writer.join();
        
        System.out.println("All operations completed");
    }
}

Condition Objects

Advanced Thread Coordination

Condition objects provide sophisticated thread coordination similar to wait()/notify() but with more flexibility. Each Lock can have multiple Condition objects. 

import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;
import java.util.LinkedList;
import java.util.Queue;

public class ConditionExample {
    private final Lock lock = new ReentrantLock();
    private final Condition notEmpty = lock.newCondition();
    private final Condition notFull = lock.newCondition();
    private final Queue queue = new LinkedList<>();
    private final int capacity = 5;
    
    // Producer method
    public void produce(String item) throws InterruptedException {
        lock.lock();
        try {
            // Wait while queue is full
            while (queue.size() == capacity) {
                System.out.println("Queue full, producer waiting...");
                notFull.await(); // Releases lock and waits
            }
            
            queue.offer(item);
            System.out.println("Produced: " + item + ", Queue size: " + queue.size());
            
            // Signal consumers that queue is not empty
            notEmpty.signal();
        } finally {
            lock.unlock();
        }
    }
    
    // Consumer method
    public String consume() throws InterruptedException {
        lock.lock();
        try {
            // Wait while queue is empty
            while (queue.isEmpty()) {
                System.out.println("Queue empty, consumer waiting...");
                notEmpty.await(); // Releases lock and waits
            }
            
            String item = queue.poll();
            System.out.println("Consumed: " + item + ", Queue size: " + queue.size());
            
            // Signal producers that queue is not full
            notFull.signal();
            
            return item;
        } finally {
            lock.unlock();
        }
    }
    
    // Timed await example
    public String consumeWithTimeout() throws InterruptedException {
        lock.lock();
        try {
            long waitTime = 2000; // 2 seconds
            while (queue.isEmpty()) {
                System.out.println("Queue empty, waiting with timeout...");
                if (!notEmpty.await(waitTime, java.util.concurrent.TimeUnit.MILLISECONDS)) {
                    System.out.println("Timeout occurred, returning null");
                    return null;
                }
            }
            
            String item = queue.poll();
            notFull.signal();
            return item;
        } finally {
            lock.unlock();
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        ConditionExample example = new ConditionExample();
        
        // Producer thread
        Thread producer = new Thread(() -> {
            try {
                for (int i = 1; i <= 10; i++) {
                    example.produce("Item-" + i);
                    Thread.sleep(100);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        
        // Consumer thread
        Thread consumer = new Thread(() -> {
            try {
                for (int i = 0; i < 10; i++) {
                    example.consume();
                    Thread.sleep(150);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        
        producer.start();
        consumer.start();
        
        producer.join();
        consumer.join();
        
        System.out.println("Producer-consumer example completed");
    }
}

Condition Methods

await()

Causes current thread to wait until signaled or interrupted

void await() throws InterruptedException
awaitUninterruptibly()

Causes current thread to wait until signaled (not interruptible)

void awaitUninterruptibly()
awaitNanos(long nanosTimeout)

Waits until signaled, interrupted, or timeout

long awaitNanos(long nanosTimeout)
signal()

Wakes up one waiting thread

void signal()
signalAll()

Wakes up all waiting threads

void signalAll()

Condition Best Practices

  • Always use await() in a while loop to handle spurious wakeups
  • Use different Condition objects for different wait conditions
  • Always call await() with the lock held
  • Use signal() instead of signalAll() when possible for better performance

Best Practices & Common Patterns

Always Use try-finally

Ensure locks are always released by using try-finally blocks.

lock.lock(); try { ... } finally { lock.unlock(); }

Use Timeouts

Prevent deadlocks by using tryLock with timeouts in production code.

lock.tryLock(timeout, unit)

Choose Right Lock

Use ReadWriteLock for read-heavy scenarios, ReentrantLock for write-heavy.

Consider Fairness

Use fair locks only when thread starvation is a real concern.

Avoid Nested Locks

Acquire locks in a consistent order to prevent deadlocks.

Monitor Performance

Use getQueueLength() and other monitoring methods to detect contention.

Common Anti-patterns to Avoid

❌ Forgetting to Unlock

// WRONG - may cause deadlock if exception occurs
lock.lock();
sharedResource++;  // If exception here, lock never released!
lock.unlock();

// CORRECT - use try-finally
lock.lock();
try {
    sharedResource++;
} finally {
    lock.unlock();
}

❌ Calling unlock() Without Lock

// WRONG - IllegalMonitorStateException
if (condition) {
    lock.unlock();  // Never called lock()!
}

// CORRECT - check lock ownership
if (lock.tryLock()) {
    try {
        // critical section
    } finally {
        lock.unlock();
    }
}
