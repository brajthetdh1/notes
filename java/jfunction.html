Functional Programming Overview

Functional Programming (FP) in Java, introduced in Java 8, revolutionized how we write code by enabling more concise, readable, and maintainable programs. FP focuses on pure functions, immutability, and declarative programming style.

Key Concepts

  • Lambda Expressions
  • Functional Interfaces
  • Streams API
  • Method References
  • Optional Class

Benefits

  • More concise code
  • Better readability
  • Easier parallelization
  • Reduced side effects

Quick Example 

// Traditional approach
List names = Arrays.asList("Alice", "Bob", "Charlie");
List filtered = new ArrayList<>();
for (String name : names) {
    if (name.startsWith("A")) {
        filtered.add(name.toUpperCase());
    }
}

// Functional approach
List filtered = names.stream()
    .filter(name -> name.startsWith("A"))
    .map(String::toUpperCase)
    .collect(Collectors.toList());

Lambda Expressions

Lambda expressions are anonymous functions that provide a clear and concise way to represent one method interface using an expression. They enable functional programming in Java.

Syntax & Examples

Basic Syntax

(parameters) -> expression
(parameters) -> { statements; }

Parameter Rules

  • • Zero parameters: () ->
  • • One parameter: s -> or (s) ->
  • • Multiple parameters: (a, b) ->

Practical Examples

Runnable Example

// Traditional
new Thread(new Runnable() {
    @Override
    public void run() {
        System.out.println("Running");
    }
}).start();

// Lambda
new Thread(() -> System.out.println("Running")).start();

Comparator Example

// Traditional
Collections.sort(names, new Comparator() {
    @Override
    public int compare(String s1, String s2) {
        return s1.compareTo(s2);
    }
});

// Lambda
Collections.sort(names, (s1, s2) -> s1.compareTo(s2));

Introduction to Lambda Expressions

What are Lambda Expressions?

Lambda expressions are anonymous functions - functions without a name that can be treated as values. Introduced in Java 8, they enable functional programming by allowing you to write more concise, readable, and maintainable code.

Key Characteristics

  • Anonymous (no explicit name)
  • Can be passed as method arguments
  • Can be stored in variables
  • Implement functional interfaces

Benefits

  • Reduces boilerplate code
  • Improves code readability
  • Enables functional programming
  • Facilitates parallel processing

Syntax and Structure

Basic Syntax

General Form:

(parameters) -> expression
(parameters) -> { statements; }

Components:

  • Parameter List: Input parameters
  • Arrow Token: ->
  • Body: Expression or code block

Parameter Variations

Zero Parameters
() -> System.out.println("Hello")
One Parameter
s -> s.toUpperCase()
(s) -> s.toUpperCase()
Multiple Parameters
(a, b) -> a + b
(int a, int b) -> a * b

Body Variations

Expression Body
s -> s.length()
(a, b) -> a + b

Single expression, automatic return

Block Body
s -> {
    String result = s.trim();
    return result.toUpperCase();
}

Multiple statements, explicit return

Relationship with Functional Interfaces

The Fundamental Connection

Lambda expressions implement functional interfaces. A functional interface is an interface with exactly one abstract method. The lambda expression provides the implementation for that single abstract method.

How It Works

1
Interface Definition

Define a functional interface with one abstract method

2
Lambda Creation

Create lambda that matches the method signature

3
Assignment

Assign lambda to interface type variable

Practical Example

// Functional Interface
@FunctionalInterface
interface MathOperation {
    int operate(int a, int b);
}

// Lambda implementations
MathOperation addition = (a, b) -> a + b;
MathOperation subtraction = (a, b) -> a - b;
MathOperation multiplication = (a, b) -> a * b;

// Usage
int result = addition.operate(5, 3); // 8

Type Inference

The Java compiler can infer the types of lambda parameters from the context (the functional interface it's being assigned to). This allows for more concise syntax.

With Type Declaration
(String s) -> s.length()
(int a, int b) -> a + b
Without Type Declaration
s -> s.length()
(a, b) -> a + b

Variable Capture

Accessing Variables from Enclosing Scope

Lambda expressions can access variables from their enclosing scope, but with important restrictions to maintain functional programming principles and avoid concurrency issues.

Effectively Final Variables

Lambda expressions can access effectively final variables from the enclosing scope. A variable is effectively final if it's not modified after initialization. 

String prefix = "Hello "; // effectively final
Function greeter = 
    name -> prefix + name; // ✅ Can access

// prefix = "Hi "; // ❌ Would break effectively final

Restrictions

  • Cannot modify captured variables
  • Cannot access non-final instance variables directly
  • Cannot use 'this' to refer to enclosing instance

Variable Capture Examples

✅ Valid Capture
final int multiplier = 2;
Function doubler = 
    n -> n * multiplier; // ✅ Works
❌ Invalid Capture
int counter = 0;
Runnable incrementer = 
    () -> counter++; // ❌ Compilation error

Function obj = s -> s.length();

Proper Type Context

Functional Interfaces in Java

Functional interfaces are interfaces with exactly one abstract method. They serve as the foundation for lambda expressions and method references in Java's functional programming.

What are Functional Interfaces?

Definition

A functional interface is an interface that contains exactly one abstract method. It can contain multiple default or static methods, but only one abstract method. 

@FunctionalInterface
interface MyFunctionalInterface {
    // Single abstract method
    void execute();
    
    // Default methods are allowed
    default void log(String message) {
        System.out.println("Log: " + message);
    }
    
    // Static methods are allowed
    static void utility() {
        System.out.println("Utility method");
    }
}

@FunctionalInterface Annotation

  • Optional but recommended
  • Provides compile-time checking
  • Documents intent clearly
  • Prevents accidental addition of abstract methods 
// Compilation error - multiple abstract methods
@FunctionalInterface
interface InvalidInterface {
    void method1();
    void method2(); // ❌ Compile error
}

@FunctionalInterface
interface StringProcessor {

Advanced Custom Interface

@FunctionalInterface
interface Validator<T> {
    ValidationResult validate(T item);
    
    // Default method for combining validators
    default Validator<T> and(Validator<? super T> other) {
        return item -> {
            ValidationResult first = this.validate(item);
            return !first.isValid() ? first : other.validate(item);
        };
    }
    
    // Static factory method
    static <T> Validator<T> alwaysValid() {
        return item -> ValidationResult.valid();
    }
}

class ValidationResult {
    private final boolean valid;
    private final String message;
    
    // constructor, getters, static methods
}

// Usage
Validator<String> notEmpty = s -> 
    s == null || s.trim().isEmpty() ? 
        ValidationResult.invalid("Cannot be empty") : 
        ValidationResult.valid();

Validator<String> minLength = s -> 
    s.length() >= 5 ? 
        ValidationResult.valid() : 
        ValidationResult.invalid("Too short");

Validator<String> combined = notEmpty.and(minLength);

Supplier Interface in Java

The Supplier<T> interface represents a supplier of results. It has a single method get() that returns a value without taking any input. Suppliers are perfect for lazy initialization, object creation, and value generation.

Memoization

class MemoizingSupplier<T> implements Supplier<T> {
    private final Supplier<T> delegate;
    private volatile T value;
    private volatile boolean initialized = false;
    
    public MemoizingSupplier(Supplier<T> delegate) {
        this.delegate = delegate;
    }
    
    @Override
    public T get() {
        if (!initialized) {
            synchronized (this) {
                if (!initialized) {
                    value = delegate.get();
                    initialized = true;
                }
            }
        }
        return value;
    }
}

// Usage

    System.out.println("Performing expensive operation...");
    try { Thread.sleep(1000); } catch (InterruptedException e) {}
    return "Result";
};

// Second call - returns cached result

Supplier Composition

class SupplierUtils {
    // Transform supplier output
    public static <T, R> Supplier<R> map(
            Supplier<T> supplier, Function<T, R> mapper) {
        return () -> mapper.apply(supplier.get());
    }
    
    // Combine two suppliers
    public static <T, U, R> Supplier<R> combine(
            Supplier<T> s1, Supplier<U> s2, BiFunction<T, U, R> combiner) {
        return () -> combiner.apply(s1.get(), s2.get());
    }
    
    // Conditional supplier
    public static <T> Supplier<T> conditional(
            Supplier<Boolean> condition, 
            Supplier<T> trueCase, 
            Supplier<T> falseCase) {
        return () -> condition.get() ? trueCase.get() : falseCase.get();
    }
}

// Usage

Supplier<String> upperCaseName = SupplierUtils.map(nameSupplier, String::toUpperCase);

Supplier<Integer> random1 = () -> (int)(Math.random() * 100);
Supplier<Integer> random2 = () -> (int)(Math.random() * 100);
Supplier<Integer> sumSupplier = SupplierUtils.combine(random1, random2, (a, b) -> a + b);

Supplier<String> greetingSupplier = SupplierUtils.conditional(
    () -> LocalTime.now().getHour() < 12,
    () -> "Good Morning",
    () -> "Good Afternoon"
);

            .productId(item.getProductId())
            .quantity(item.getQuantity())

            stream = stream.filter(p ->

        }
        
        if (criteria.getMinPrice() != null) {
            stream = stream.filter(p -> 
                p.getPrice().compareTo(criteria.getMinPrice()) >= 0);
        }
        
        if (criteria.getMaxPrice() != null) {
            stream = stream.filter(p -> 
                p.getPrice().compareTo(criteria.getMaxPrice()) <= 0);
        }
        
        if (criteria.getInStock() != null && criteria.getInStock()) {
            stream = stream.filter(p -> p.getStockQuantity() > 0);
        }
        
        if (criteria.getSearchTerm() != null) {
            String searchTerm = criteria.getSearchTerm().toLowerCase();
            stream = stream.filter(p -> 
                p.getName().toLowerCase().contains(searchTerm) ||
                p.getDescription().toLowerCase().contains(searchTerm));
        }
        
        // Sorting
        if (criteria.getSortBy() != null) {
            stream = applySorting(stream, criteria.getSortBy(), 
                criteria.getSortDirection());
        }
        
        return stream
            .map(this::convertToDTO)
            .collect(Collectors.toList());
    }
    
    private Stream applySorting(Stream stream, 
                                       String sortBy, 
                                       SortDirection direction) {
        Comparator comparator = switch (sortBy) {
            case "name" -> Comparator.comparing(Product::getName);
            case "price" -> Comparator.comparing(Product::getPrice);
            case "rating" -> Comparator.comparing(Product::getAverageRating);
            default -> Comparator.comparing(Product::getId);
        };
        
        if (direction == SortDirection.DESC) {
            comparator = comparator.reversed();
        }
        
        return stream.sorted(comparator);
    }
}

Streams API

The Streams API allows functional-style operations on streams of elements. Streams support sequential and parallel aggregate operations with lazy evaluation.

Introduction to Streams

What are Streams?

Streams are a sequence of elements supporting sequential and parallel aggregate operations.

  • Not a data structure
  • Functional in nature
  • Lazy evaluation
  • Can be unbounded

Key Characteristics

  • No storage - elements are computed on-demand
  • Source can be collections, arrays, or I/O channels
  • Supports functional programming operations
  • Automatic parallelization support

Best Practices & Common Pitfalls

✅ Best Practices

  • Use method references for better readability
  • Prefer immutable operations
  • Use parallel streams for large datasets
  • Close resources with try-with-resources
  • Use primitive streams for better performance

❌ Common Pitfalls

  • Modifying source collection during stream operations
  • Ignoring terminal operations (streams are lazy)
  • Using parallel streams for small datasets
  • Forgetting to close I/O streams
  • Using stateful lambda expressions

Introduction to Optional

What is Optional?

Optional is a container object that may or may not contain a non-null value. Introduced in Java 8, it provides a better alternative to null references and helps avoid NullPointerException.

The Null Problem

  • NullPointerException is common
  • No clear intent about nullable returns
  • Forces defensive null checks everywhere
  • Error-prone and hard to maintain

Optional Benefits

  • Explicit nullability in API design
  • No more NullPointerException
  • Functional-style operations
  • Cleaner, more expressive code
