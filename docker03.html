What is a Dockerfile?

A Dockerfile is a text document that contains all the commands a user could call on the command line to assemble an image. Using docker build, users can create an automated build that executes several command-line instructions in succession.

Dockerfile Structure

Base Image

Every Dockerfile starts with a FROM instruction specifying the base image

Configuration

Set environment variables, working directory, and install dependencies

Application Code

Copy your application code and files into the image

Runtime Configuration

Define how to run the application with CMD or ENTRYPOINT

Basic Dockerfile Example

# Start from a base image
FROM node:18-alpine

# Set environment variables
ENV NODE_ENV=production
ENV PORT=3000

# Set working directory
WORKDIR /app

# Copy package files
COPY package*.json ./

# Install dependencies
RUN npm ci --only=production

# Copy application code
COPY . .

# Expose the application port
EXPOSE 3000

# Define the runtime command
CMD ["node", "server.js"]

Dockerfile Instructions Reference

FROM

FROM

Initializes a new build stage and sets the Base Image for subsequent instructions.

FROM ubuntu:20.04
FROM node:18-alpine
FROM python:3.9-slim

Note: Must be the first non-comment instruction in the Dockerfile.

RUN

RUN

Executes commands in a new layer on top of the current image and commits the results.

RUN apt-get update && apt-get install -y curl
RUN npm install
RUN pip install -r requirements.txt

Best Practice: Combine multiple RUN commands to reduce layers.

COPY

COPY

Copies new files or directories from the source and adds them to the filesystem of the container.

COPY package.json .
COPY src/ /app/src/
COPY --chown=node:node . .

Tip: Use .dockerignore to exclude files from being copied.

WORKDIR

WORKDIR

Sets the working directory for any RUN, CMD, ENTRYPOINT, COPY, and ADD instructions that follow it.

WORKDIR /app
WORKDIR /usr/src/app

Note: Creates the directory if it doesn't exist.

ENV

ENV

Sets environment variables that will be available in the container.

ENV NODE_ENV=production
ENV APP_PORT=3000
ENV DB_HOST=localhost
ARG

ARG

Defines a variable that users can pass at build-time to the builder with docker build --build-arg.

ARG VERSION=latest
FROM ubuntu:${VERSION}

ARG USERNAME=appuser
RUN useradd -m ${USERNAME}
VOLUME

VOLUME

Creates a mount point and marks it as holding externally mounted volumes.

VOLUME /data
VOLUME ["/var/log", "/var/db"]
USER

USER

Sets the user name (or UID) and optionally the user group (or GID) to use when running the image.

USER node
USER 1000:1000
USER nobody
CMD

CMD

Provides defaults for an executing container. There can only be one CMD instruction in a Dockerfile.

CMD ["npm", "start"]
CMD ["python", "app.py"]
CMD nginx -g 'daemon off;'

Note: Can be overridden when starting the container.

ENTRYPOINT

ENTRYPOINT

Configures a container that will run as an executable. Command-line arguments are appended.

ENTRYPOINT ["python"]
CMD ["app.py"]

# docker run my-app --help
# executes: python app.py --help
EXPOSE

EXPOSE

Informs Docker that the container listens on the specified network ports at runtime.

EXPOSE 80
EXPOSE 3000
EXPOSE 5432/tcp

Note: Doesn't actually publish the port. Use docker run -p to publish.

HEALTHCHECK

HEALTHCHECK

Tells Docker how to test a container to check that it is still working.

HEALTHCHECK --interval=30s --timeout=3s \
CMD curl -f http://localhost/ || exit 1

Real-World Dockerfile Examples

Node.js Application

# Use official Node.js runtime
FROM node:18-alpine

# Install dumb-init for proper signal handling
RUN apk add --no-cache dumb-init

# Set working directory
WORKDIR /app

# Copy package files
COPY package*.json ./

# Install dependencies
RUN npm ci --only=production

# Copy application code
COPY . .

# Create non-root user
RUN adduser -D myuser
USER myuser

# Expose port
EXPOSE 3000

# Use dumb-init as entrypoint
ENTRYPOINT ["dumb-init", "--"]

# Start the application
CMD ["node", "server.js"]

Python Flask API

# Use official Python runtime
FROM python:3.11-slim

# Set environment variables
ENV PYTHONUNBUFFERED=1
ENV PYTHONDONTWRITEBYTECODE=1

# Install system dependencies
RUN apt-get update && apt-get install -y \
    gcc \
    && rm -rf /var/lib/apt/lists/*

# Set working directory
WORKDIR /app

# Copy requirements and install dependencies
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY . .

# Create non-root user
RUN useradd --create-home --shell /bin/bash app
USER app

# Expose port
EXPOSE 5000

# Run the application
CMD ["gunicorn", "--bind", "0.0.0.0:5000", "app:app"]
Production ready

Nginx Static Site

# Use official Nginx image
FROM nginx:alpine

# Remove default nginx website
RUN rm -rf /usr/share/nginx/html/*

# Copy custom nginx configuration
COPY nginx.conf /etc/nginx/nginx.conf

# Copy static website files
COPY dist/ /usr/share/nginx/html/

# Create a non-root user (nginx user already exists in base image)
RUN chown -R nginx:nginx /usr/share/nginx/html

# Expose port 80
EXPOSE 80

# Start nginx
CMD ["nginx", "-g", "daemon off;"]
Simple & efficient

Java Spring Boot

# Build stage
FROM maven:3.8-openjdk-17 AS builder
WORKDIR /app
COPY pom.xml .
COPY src ./src
RUN mvn clean package -DskipTests

# Runtime stage
FROM openjdk:17-jdk-slim

# Install curl for health checks
RUN apt-get update && apt-get install -y curl

# Create application user
RUN groupadd -r spring && useradd -r -g spring spring
USER spring

# Copy jar from build stage
COPY --from=builder /app/target/*.jar app.jar

# Expose application port
EXPOSE 8080

# Health check
HEALTHCHECK --interval=30s --timeout=3s \
  CMD curl -f http://localhost:8080/actuator/health || exit 1

# Run the application
ENTRYPOINT ["java", "-jar", "/app.jar"]

Dockerfile Best Practices

Minimize Layers

Combine multiple RUN commands and use multi-stage builds to reduce image size and build time.

Use Non-Root User

Always run containers as non-root users to improve security and follow principle of least privilege.

Clean Up Apt Cache

Remove apt cache and temporary files in the same RUN command to avoid storing them in layers.

Use .dockerignore

Create a .dockerignore file to exclude unnecessary files from being copied into the image.

Use Specific Tags

Avoid using the 'latest' tag. Use specific version tags for reproducible builds.

Add Health Checks

Use HEALTHCHECK instruction to let Docker know how to test if your container is still working.

Example .dockerignore File

The .dockerignore file prevents unnecessary files from being copied into your Docker image, reducing build time and image size.

  • Excludes node_modules (will be installed during build)
  • Ignores Git and IDE files
  • Excludes logs and temporary files
  • Prevents environment files from being included

node_modules/
npm-debug.log*
yarn-debug.log*
yarn-error.log*

# Environment files
.env
.env.local
.env.production

# Logs
logs
*.log

# Runtime data
pids
*.pid
*.seed
*.pid.lock

# Coverage directory
coverage/

# IDE files
.vscode/
.idea/
*.swp
*.swo

# OS files
.DS_Store
Thumbs.db

# Git
.git/

Multi-Stage Builds

Why Use Multi-Stage Builds?

Multi-stage builds allow you to use multiple FROM statements in your Dockerfile. Each FROM instruction can use a different base, and each begins a new stage of the build.

Smaller Final Images

Only include what's needed for runtime

Better Security

Build tools don't end up in production

Faster Builds

Leverage build cache more effectively

Multi-Stage Example

# Build stage
FROM node:18 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Production stage
FROM node:18-alpine
RUN addgroup -g 1001 -S nodejs
RUN adduser -S nextjs -u 1001
WORKDIR /app
COPY --from=builder --chown=nextjs:nodejs /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next ./.next
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./
USER nextjs
EXPOSE 3000
CMD ["npm", "start"]

Building and Testing

Building Your Image

# Build with a tag
docker build -t my-app:1.0 .

# Build with build args
docker build --build-arg NODE_ENV=production -t my-app .

# Build from different Dockerfile
docker build -f Dockerfile.prod -t my-app:prod .

Testing and Debugging

# Run built image
docker run -p 3000:3000 my-app

# Run with environment variables
docker run -e NODE_ENV=development my-app

# Debug: Run with shell access
docker run -it my-app /bin/sh

# Check image layers
docker history my-app
