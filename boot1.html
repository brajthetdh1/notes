Spring Boot Configuration Externalization: Complete Guide

Configuration Externalization Fundamentals

Spring Boot uses a powerful and flexible approach to externalize configuration, allowing you to work with the same application code in different environments. Instead of hardcoding configuration values, Spring Boot lets you externalize them through various sources that follow a specific order of precedence.

Core Principle: Spring Boot uses a property resolution order where properties defined in higher-priority sources override those in lower-priority sources. This enables environment-specific configurations without code changes.

Property Resolution Order

Highest to Lowest Priority: Properties are loaded in a specific order where later sources can override properties from earlier sources. This creates a powerful inheritance and override mechanism.

Priority Configuration Source Description Example
1 (Highest) DevTools global settings Home directory devtools properties ~/.spring-boot-devtools.properties
2 @TestPropertySource Test-specific properties @TestPropertySource annotation
3 Command Line Arguments Properties passed at runtime --server.port=8081
4 SPRING_APPLICATION_JSON Inline JSON environment variable SPRING_APPLICATION_JSON
5 Servlet Config Init Parameters Web application init parameters web.xml init-param
6 Servlet Context Init Parameters Servlet context parameters context-param in web.xml
7 JNDI Attributes Java Naming and Directory Interface java:comp/env
8 Java System Properties System.getProperties() -Dserver.port=8081
9 OS Environment Variables System environment variables SERVER_PORT=8081
10 RandomValuePropertySource random.* properties only ${random.value}
11 Profile-specific Properties application-{profile}.properties application-prod.properties
12 Profile-specific YAML application-{profile}.yml application-prod.yml
13 Application Properties Packaged application.properties application.properties
14 Application YAML Packaged application.yml application.yml
15 Default Properties SpringApplication.setDefaultProperties() setDefaultProperties()
16 (Lowest) @PropertySource Custom property sources on @Configuration @PropertySource

Key Insight: Properties defined later in this list override those defined earlier. This means command line arguments override environment variables, which override properties files, giving you fine-grained control over configuration precedence.

// Custom PropertySource for database configuration
@Component
public class DatabasePropertySource extends PropertySource<Map<String, String>> {
    
    private final JdbcTemplate jdbcTemplate;
    private Map<String, String> properties;
    
    public DatabasePropertySource(JdbcTemplate jdbcTemplate) {
        super("databaseProperties");
        this.jdbcTemplate = jdbcTemplate;
        loadPropertiesFromDatabase();
    }
    
    private void loadPropertiesFromDatabase() {
        properties = jdbcTemplate.query(
            "SELECT prop_key, prop_value FROM app_properties",
            (rs, rowNum) -> {
                String key = rs.getString("prop_key");
                String value = rs.getString("prop_value");
                return new AbstractMap.SimpleEntry<>(key, value);
            })
            .stream()
            .collect(Collectors.toMap(Map.Entry::getKey, Map.Entry::getValue));
    }
    
    @Override
    public Object getProperty(String name) {
        return properties.get(name);
    }
}

Configuration Best Practices

Do's

  • Use environment variables for secrets (passwords, API keys)
  • Use profiles for environment-specific configurations
  • Externalize all configuration from code
  • Use @ConfigurationProperties for complex configurations
  • Provide sensible default values
  • Use YAML for complex hierarchical configurations
  • Validate configuration properties with @Validated
  • Use Spring Cloud Config for distributed configurations

Don'ts

  • Don't commit secrets to version control
  • Don't hardcode configuration values
  • Don't use @Value for complex object graphs
  • Don't mix configuration styles unnecessarily
  • Don't ignore configuration validation
  • Don't use system properties for cloud deployments
  • Don't create too many fine-grained profiles
  • Don't forget to document configuration properties

Security Considerations

  • Use environment variables or secure vaults for sensitive data
  • Consider using Spring Cloud Vault or AWS Parameter Store for secrets
  • Use configuration encryption for sensitive properties in files
  • Regularly audit and rotate configuration secrets
  • Use different credentials for different environments

Health Status Hierarchy & Aggregation

Health indicators return specific statuses that are aggregated into an overall application health status. Understanding this hierarchy is crucial for proper health monitoring.

Health Status Aggregation

DOWN
Highest Priority
▼
OUT_OF_SERVICE
▼
UP
▼
UNKNOWN
Lowest Priority

Aggregation Rule: The overall health status is derived from the worst status returned by all health indicators. If any component is DOWN, the overall status is DOWN.

package com.example.health;

import org.springframework.boot.actuate.health.Health;
import org.springframework.boot.actuate.health.HealthIndicator;

@Component
public class CustomServiceHealthIndicator implements HealthIndicator {
    
    private final CustomService customService;
    
    public CustomServiceHealthIndicator(CustomService customService) {
        this.customService = customService;
    }
    
    @Override
    public Health health() {
        try {
            // Check if our custom service is healthy
            boolean isHealthy = customService.isHealthy();
            
            if (isHealthy) {
                return Health.up()
                    .withDetail("service", "custom-service")
                    .withDetail("status", "operational")
                    .withDetail("responseTime", customService.getResponseTime() + "ms")

                return Health.down()
                    .withDetail("service", "custom-service")
                    .withDetail("status", "degraded")
                    .withDetail("error", customService.getLastError())
                    .build();
            }
            
        } catch (Exception e) {
            return Health.down(e)
                .withDetail("service", "custom-service")
                .withDetail("status", "unreachable")
                .build();
        }
    }
}

@Component
public class ExternalApiHealthIndicator 
    extends AbstractHealthIndicator {
    
    private final RestTemplate restTemplate;
    private final ApiProperties apiProperties;
    
    public ExternalApiHealthIndicator(RestTemplate restTemplate, 
                                    ApiProperties apiProperties) {
        this.restTemplate = restTemplate;
        this.apiProperties = apiProperties;
    }
    
    @Override
    protected void doHealthCheck(Health.Builder builder) throws Exception {
        try {
            long startTime = System.currentTimeMillis();
            
            ResponseEntity<String> response = restTemplate.getForEntity(
                apiProperties.getHealthUrl(), String.class);
                
            long responseTime = System.currentTimeMillis() - startTime;
            
            if (response.getStatusCode().is2xxSuccessful()) {
                builder.up()
                    .withDetail("api", apiProperties.getName())
                    .withDetail("statusCode", response.getStatusCodeValue())
                    .withDetail("responseTime", responseTime + "ms")
                    .withDetail("message", "API is responsive");
                    
                // Check response time thresholds
                if (responseTime > apiProperties.getSlowThreshold()) {
                    builder.withDetail("warning", "High response time");
                }
            } else {
                builder.down()
                    .withDetail("api", apiProperties.getName())
                    .withDetail("statusCode", response.getStatusCodeValue())
                    .withDetail("error", "Non-200 response");
            }
        } catch (ResourceAccessException e) {
            builder.down(e)
                .withDetail("api", apiProperties.getName())
                .withDetail("error", "Connection timeout or refused");
        } catch (Exception e) {
            builder.down(e)
                .withDetail("api", apiProperties.getName())
                .withDetail("error", "Unexpected error: " + e.getMessage());
        }
    }
}

@Component

    implements HealthIndicator {
    
    private final CircuitBreakerRegistry circuitBreakerRegistry;
    
    public CircuitBreakerHealthIndicator(CircuitBreakerRegistry registry) {
        this.circuitBreakerRegistry = registry;
    }
    
    @Override
    public Health health() {
        Health.Builder builder = new Health.Builder();
        boolean allUp = true;
        
        circuitBreakerRegistry.getAllCircuitBreakers()
            .forEach(circuitBreaker -> {
                CircuitBreaker.State state = circuitBreaker.getState();
                CircuitBreaker.Metrics metrics = circuitBreaker.getMetrics();
                
                builder.withDetail(circuitBreaker.getName(), 
                    Map.of(
                        "state", state,
                        "failureRate", metrics.getFailureRate() + "%",
                        "bufferedCalls", metrics.getNumberOfBufferedCalls(),
                        "failedCalls", metrics.getNumberOfFailedCalls()
                    ));
            });
            
        // Determine overall status
        boolean anyOpen = circuitBreakerRegistry.getAllCircuitBreakers()
            .stream()
            .anyMatch(cb -> cb.getState() == CircuitBreaker.State.OPEN);
            
        if (anyOpen) {
            return builder.down().build();
        } else {
            return builder.up().build();
        }
    }
}

                totalCaches++;
                var cache = Objects.requireNonNull(cacheManager.getCache(cacheName));

                    String testKey = "health-check-" + System.currentTimeMillis();
                    String testValue = "test-value";

                    String retrievedValue = cache.get(testKey, String.class);
                    cache.evict(testKey);

                        healthyCaches++;
                        builder.withDetail("cache." + cacheName, "OPERATIONAL");
                    } else {
                        builder.withDetail("cache." + cacheName, "DEGRADED");
                    }
                } catch (Exception e) {
                    builder.withDetail("cache." + cacheName, 
                        "ERROR: " + e.getMessage());
                }
            }
            
            // Overall cache health
            builder.withDetail("totalCaches", totalCaches)
                   .withDetail("healthyCaches", healthyCaches)
                   .withDetail("healthPercentage", 
                       totalCaches > 0 ? (healthyCaches * 100 / totalCaches) + "%" : "100%");
            
            if (healthyCaches < totalCaches) {
                return builder.down().build();
            }
            
            return builder.build();
            
        } catch (Exception e) {
            return Health.down(e)
                .withDetail("error", "Cache health check failed: " + e.getMessage())
                .build();
        }

@Component
@ConfigurationProperties(prefix = "app.health.external-services")
public class ConfigurableExternalServiceHealthIndicator implements HealthIndicator {
    
    private Map<String, ServiceConfig> services = new ConcurrentHashMap<>();
    private final RestTemplate restTemplate;
    
    // Configuration properties
    public static class ServiceConfig {
        private String healthUrl;
        private long timeoutMs = 5000;
        private int slowThresholdMs = 1000;
        
        // getters and setters
        public String getHealthUrl() { return healthUrl; }
        public void setHealthUrl(String healthUrl) { this.healthUrl = healthUrl; }
        
        public long getTimeoutMs() { return timeoutMs; }
        public void setTimeoutMs(long timeoutMs) { this.timeoutMs = timeoutMs; }
        
        public int getSlowThresholdMs() { return slowThresholdMs; }
        public void setSlowThresholdMs(int slowThresholdMs) { 
            this.slowThresholdMs = slowThresholdMs; 
        }
    }
    
    public ConfigurableExternalServiceHealthIndicator(RestTemplate restTemplate) {
        this.restTemplate = restTemplate;
    }
    
    public Map<String, ServiceConfig> getServices() {
        return services;
    }
    
    public void setServices(Map<String, ServiceConfig> services) {
        this.services = services;
    }
    
    @Override
    public Health health() {
        Health.Builder builder = Health.up();
        boolean allHealthy = true;
        
        for (Map.Entry<String, ServiceConfig> entry : services.entrySet()) {
            String serviceName = entry.getKey();
            ServiceConfig config = entry.getValue();
            
            try {
                long startTime = System.currentTimeMillis();
                
                // Configure timeout
                restTemplate.getForEntity(config.getHealthUrl(), String.class);
                
                long responseTime = System.currentTimeMillis() - startTime;
                
                Map<String, Object> details = Map.of(
                    "status", "UP",
                    "responseTime", responseTime + "ms",
                    "healthUrl", config.getHealthUrl()
                );
                
                if (responseTime > config.getSlowThresholdMs()) {
                    details.put("warning", "Slow response");
                }
                
                builder.withDetail(serviceName, details);
                
            } catch (Exception e) {
                allHealthy = false;
                builder.withDetail(serviceName, 
                    Map.of(
                        "status", "DOWN",
                        "error", e.getMessage(),
                        "healthUrl", config.getHealthUrl()
                    ));
            }
        }
        
        if (!allHealthy) {
            return builder.down().build();
        }
        
        return builder.build();
    }

Spring Boot Auto-Configuration: Complete Internal Mechanism Guide

What is Spring Boot Auto-Configuration?

Spring Boot Auto-Configuration is a powerful feature that automatically configures Spring applications based on the dependencies present on the classpath. It eliminates the need for manual bean configuration and boilerplate code by intelligently detecting what components are available and configuring them appropriately.

Core Philosophy: "Opinionated Defaults" - Spring Boot makes assumptions about what you need based on your dependencies and automatically configures those components with sensible defaults, while allowing complete override when needed.

Auto-Configuration Fundamentals

How It Works at High Level

  • Classpath Scanning: Detects specific classes and dependencies
  • Conditional Configuration: Uses conditions to determine what to configure
  • Automatic Bean Registration: Creates and configures beans automatically
  • Property-Driven: Customizable through application.properties
  • Override Capable: User configurations take precedence

Handling Multiple Database Transactions in a Single Service Method

Multiple Transactions Overview

There are several scenarios where you might need multiple transactions within a single service method: partial commits, independent operations, error isolation, or mixed read-write patterns. Each approach has different trade-offs and use cases.

Key Concept: Multiple transactions can be achieved through different propagation behaviors, programmatic transaction management, or asynchronous processing. The choice depends on your consistency requirements and error handling strategy.

Method 1: REQUIRES_NEW Propagation

Using REQUIRES_NEW for Independent Transactions

Use @Transactional(propagation = Propagation.REQUIRES_NEW) to create completely independent transactions that commit separately from the main transaction. 


@Service
@Transactional
public class OrderProcessingService {
    
    @Autowired
    private OrderRepository orderRepository;
    
    @Autowired
    private AuditService auditService;
    
    @Autowired
    private NotificationService notificationService;
    
    @Autowired
    private InventoryService inventoryService;
    
    public Order processOrder(OrderRequest request) {
        try {
            // TRANSACTION 1: Main order processing
            Order order = createOrder(request);
            orderRepository.save(order);
            
            // TRANSACTION 2: Independent audit log (commits even if main fails)
            auditService.logOrderCreation(order);
            
            // TRANSACTION 3: Inventory update (independent)
            inventoryService.updateStock(order.getItems());
            
            // Continue with main transaction
            order.setStatus(OrderStatus.PROCESSING);
            orderRepository.save(order);
            
            return order;
            
        } catch (Exception e) {
            // Main transaction will rollback, but audit and inventory may have committed
            throw new OrderProcessingException("Order processing failed", e);
        }
    }
    
    private Order createOrder(OrderRequest request) {
        // Order creation logic
        return new Order(request);
    }
}

@Service
public class InventoryService {
    
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void updateStock(List<OrderItem> items) {
        for (OrderItem item : items) {
            Product product = productRepository.findById(item.getProductId())
                .orElseThrow(() -> new ProductNotFoundException("Product not found"));
            
            if (product.getStock() < item.getQuantity()) {
                throw new InsufficientStockException("Insufficient stock for product: " + product.getName());
            }
            
            product.decreaseStock(item.getQuantity());
            productRepository.save(product);
        }
        // This commits independently, even if order creation fails later
    }
}

public class NotificationService {

        emailService.sendConfirmation(order);
    }

When to Use REQUIRES_NEW
  • Audit logging that must persist even on failure
  • Independent operations that should commit separately
  • Operations that might fail but shouldn't affect main flow
  • External system integrations
REQUIRES_NEW Risks
  • Partial commits can leave inconsistent state
  • Connection pool exhaustion with many nested transactions
  • Deadlocks if not properly ordered
  • Complex error handling scenarios

Method 2: Programmatic Transaction Management

Using TransactionTemplate for Fine-grained Control

TransactionTemplate provides programmatic control over transactions, allowing you to define multiple transaction boundaries within a single method with custom configurations. 


@Service
public class ProgrammaticTransactionService {
    
    @Autowired
    private TransactionTemplate transactionTemplate;
    
    @Autowired
    private OrderRepository orderRepository;
    
    @Autowired
    private AuditRepository auditRepository;
    
    @Autowired
    private InventoryRepository inventoryRepository;
    
    // Basic multiple transactions
    public void processOrderWithMultipleTransactions(Order order) {
        // TRANSACTION 1: Create order
        Long orderId = transactionTemplate.execute(status -> {
            Order savedOrder = orderRepository.save(order);
            return savedOrder.getId();
        });
        
        // TRANSACTION 2: Log audit
        transactionTemplate.execute(status -> {
            auditRepository.save(new AuditLog("ORDER_CREATED", orderId));
            return null;
        });
        
        // TRANSACTION 3: Update inventory
        transactionTemplate.execute(status -> {
            updateInventoryForOrder(order);
            return null;
        });
        
        // TRANSACTION 4: Final status update
        transactionTemplate.execute(status -> {
            orderRepository.updateStatus(orderId, OrderStatus.COMPLETED);
            return null;
        });
    }
    
    // Custom transaction configurations
    public void processWithCustomConfigurations(Order order) {
        // Create custom TransactionTemplate with specific settings
        TransactionTemplate quickTransaction = new TransactionTemplate(
            transactionTemplate.getTransactionManager());
        quickTransaction.setTimeout(10); // 10 second timeout
        quickTransaction.setReadOnly(false);
        
        TransactionTemplate longTransaction = new TransactionTemplate(
            transactionTemplate.getTransactionManager());
        longTransaction.setTimeout(60); // 60 second timeout
        longTransaction.setIsolationLevel(TransactionDefinition.ISOLATION_READ_COMMITTED);
        
        // Use different templates for different operations
        quickTransaction.execute(status -> {
            // Quick validation operations
            validateOrder(order);
            return null;
        });
        
        longTransaction.execute(status -> {
            // Long-running processing
            processComplexOrder(order);
            return null;
        });
    }
    
    // Handling failures in individual transactions
    public void robustMultiTransactionProcessing(Order order) {
        List<String> errors = new ArrayList<>();
        
        // Transaction 1: Always attempt order creation
        try {
            transactionTemplate.execute(status -> {
                return orderRepository.save(order);
            });
        } catch (Exception e) {
            errors.add("Order creation failed: " + e.getMessage());
            throw new OrderProcessingException("Critical failure", e);
        }
        
        // Transaction 2: Attempt audit logging (non-critical)
        try {
            transactionTemplate.execute(status -> {
                auditRepository.save(new AuditLog("ORDER_CREATED", order.getId()));
                return null;
            });
        } catch (Exception e) {
            errors.add("Audit logging failed: " + e.getMessage());
            // Continue despite audit failure
        }
        
        // Transaction 3: Attempt inventory update
        try {
            transactionTemplate.execute(status -> {
                updateInventoryForOrder(order);
                return null;
            });
        } catch (InsufficientStockException e) {
            errors.add("Inventory update failed: " + e.getMessage());
            // Compensating action: mark order as needing restock
            transactionTemplate.execute(status -> {
                order.setStatus(OrderStatus.NEEDS_RESTOCK);
                orderRepository.save(order);
                return null;
            });
        } catch (Exception e) {
            errors.add("Unexpected inventory error: " + e.getMessage());
            // Log but continue
        }
        
        if (!errors.isEmpty()) {
            logger.warn("Order processed with warnings: {}", errors);
        }
    }
    
    // Conditional transactions
    public void conditionalTransactionExecution(Order order, boolean processInventory, boolean sendNotification) {
        // Always create order
        transactionTemplate.execute(status -> {
            return orderRepository.save(order);
        });
        
        // Conditional inventory processing
        if (processInventory) {
            transactionTemplate.execute(status -> {
                updateInventoryForOrder(order);
                return null;
            });
        }
        
        // Conditional notification
        if (sendNotification) {
            transactionTemplate.execute(status -> {
                sendOrderNotification(order);
                return null;
            });
        }
    }
    
    // Chained transactions with data passing
    public Order processOrderChain(OrderRequest request) {
        // Step 1: Validate and create order
        Order order = transactionTemplate.execute(status -> {
            Order newOrder = createAndValidateOrder(request);
            return orderRepository.save(newOrder);
        });
        
        // Step 2: Process payment (depends on order ID)
        PaymentResult payment = transactionTemplate.execute(status -> {
            return paymentService.processPayment(order.getId(), order.getTotal());
        });
        
        // Step 3: Update order with payment result
        transactionTemplate.execute(status -> {
            order.setPaymentStatus(payment.getStatus());
            orderRepository.save(order);
            return null;
        });
        
        return order;
    }
    
    private void updateInventoryForOrder(Order order) {
        // Inventory update logic
        for (OrderItem item : order.getItems()) {
            Product product = inventoryRepository.findById(item.getProductId())
                .orElseThrow(() -> new ProductNotFoundException("Product not found"));
            product.decreaseStock(item.getQuantity());
            inventoryRepository.save(product);
        }
    }
    
    private void sendOrderNotification(Order order) {
        // Notification logic
        notificationRepository.save(new Notification(order.getCustomerEmail(), "ORDER_PROCESSED"));
    }
}

Method 3: NESTED Propagation & Savepoints

Using NESTED Propagation for Partial Rollbacks

Propagation.NESTED creates savepoints that allow partial rollbacks within a larger transaction. This is supported by some databases (not all). 


@Service
@Transactional
public class NestedTransactionService {
    
    @Autowired
    private OrderRepository orderRepository;
    
    @Autowired
    private ItemRepository itemRepository;
    
    @Autowired
    private PaymentRepository paymentRepository;
    
    // Using NESTED propagation for partial commits
    public void processOrderWithNestedTransactions(Order order) {
        // Main transaction starts
        
        // Save order - this is part of main transaction
        orderRepository.save(order);
        
        try {
            // NESTED transaction for items - can rollback independently
            processOrderItems(order.getId(), order.getItems());
        } catch (ItemProcessingException e) {
            // Only item processing is rolled back, order remains
            logger.error("Item processing failed, but order was saved", e);
            order.setStatus(OrderStatus.ITEMS_FAILED);
            orderRepository.save(order);
        }
        
        try {
            // Another NESTED transaction for payment
            processPayment(order.getId(), order.getTotal());
        } catch (PaymentException e) {
            // Only payment is rolled back
            logger.error("Payment processing failed", e);
            order.setStatus(OrderStatus.PAYMENT_FAILED);
            orderRepository.save(order);
            // Main transaction continues
        }
        
        // If we reach here, main transaction commits
        order.setStatus(OrderStatus.COMPLETED);
        orderRepository.save(order);
    }
    
    @Transactional(propagation = Propagation.NESTED)
    public void processOrderItems(Long orderId, List<OrderItem> items) {
        for (OrderItem item : items) {
            Item savedItem = itemRepository.save(item);
            
            // Simulate item processing that might fail
            if (item.getProductId().equals("RISKY_PRODUCT")) {
                throw new ItemProcessingException("Risky product processing failed");
            }
        }
    }
    
    @Transactional(propagation = Propagation.NESTED)
    public void processPayment(Long orderId, BigDecimal amount) {
        Payment payment = new Payment(orderId, amount);
        paymentRepository.save(payment);
        
        // Simulate payment processing that might fail
        if (amount.compareTo(new BigDecimal("1000")) > 0) {
            throw new PaymentException("Large payment requires manual review");
        }
    }
    
    // Alternative: Using TransactionTemplate with NESTED behavior
    @Autowired
    private TransactionTemplate transactionTemplate;
    
    public void processWithSavepoints(Order order) {
        transactionTemplate.execute(status -> {
            // Main transaction
            orderRepository.save(order);
            
            // Create savepoint
            Object savepoint = status.createSavepoint();
            
            try {
                // Process items - can rollback to savepoint
                processItems(order.getItems());
            } catch (Exception e) {
                // Rollback only the items processing
                status.rollbackToSavepoint(savepoint);
                logger.error("Items processing failed, rolling back to savepoint", e);
                // Main transaction continues
            }
            
            // Continue with main transaction
            order.setStatus(OrderStatus.PROCESSED);
            orderRepository.save(order);
            
            return null;
        });
    }
    
    private void processItems(List<OrderItem> items) {
        for (OrderItem item : items) {
            itemRepository.save(item);
            // Business logic that might fail
            validateItem(item);
        }
    }
    
    private void validateItem(OrderItem item) {
        if (item.getQuantity() <= 0) {
            throw new ValidationException("Item quantity must be positive");
        }
    }
}

Method 4: Chunk Processing for Large Datasets

Processing Large Datasets in Chunks

For large datasets, process data in chunks with separate transactions to avoid long-running transactions and memory issues. 


@Service
public class ChunkProcessingService {
    
    @Autowired
    private TransactionTemplate transactionTemplate;
    
    @Autowired
    private CustomerRepository customerRepository;
    
    @Autowired
    private OrderRepository orderRepository;
    
    @Autowired
    private AuditRepository auditRepository;
    
    // Basic chunk processing
    public void processLargeCustomerBatch(List<Customer> customers) {
        List<List<Customer>> chunks = partitionList(customers, 100); // 100 per chunk
        
        for (int i = 0; i < chunks.size(); i++) {
            final int chunkNumber = i + 1;
            List<Customer> chunk = chunks.get(i);
            
            transactionTemplate.execute(status -> {
                logger.info("Processing chunk {}/{}", chunkNumber, chunks.size());
                
                for (Customer customer : chunk) {
                    processCustomer(customer);
                }
                
                // Each chunk is its own transaction
                return null;
            });
            
            // Optional: Small delay between chunks
            if (i < chunks.size() - 1) {
                try {
                    Thread.sleep(100); // 100ms between chunks
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    throw new ProcessingInterruptedException("Chunk processing interrupted");
                }
            }
        }
    }
    
    // Chunk processing with error handling
    public ChunkProcessingResult processCustomersWithErrorHandling(List<Customer> customers) {
        List<List<Customer>> chunks = partitionList(customers, 100);
        List<String> errors = new ArrayList<>();
        int successCount = 0;
        
        for (int i = 0; i < chunks.size(); i++) {
            final int chunkNumber = i + 1;
            List<Customer> chunk = chunks.get(i);
            
            try {
                Integer chunkSuccess = transactionTemplate.execute(status -> {
                    int chunkSuccessCount = 0;
                    
                    for (Customer customer : chunk) {
                        try {
                            processCustomer(customer);
                            chunkSuccessCount++;
                        } catch (CustomerProcessingException e) {
                            // Log but continue with other customers in same chunk
                            logger.warn("Failed to process customer: {}", customer.getId(), e);
                            // Don't rollback entire chunk for single customer failure
                        }
                    }
                    
                    return chunkSuccessCount;
                });
                
                successCount += chunkSuccess;
                logger.info("Chunk {}/{} processed successfully", chunkNumber, chunks.size());
                
            } catch (Exception e) {
                String error = String.format("Chunk %d failed: %s", chunkNumber, e.getMessage());
                errors.add(error);
                logger.error("Chunk processing failed", e);
                // Continue with next chunk despite failure
            }
        }
        
        return new ChunkProcessingResult(successCount, errors);
    }
    
    // Parallel chunk processing
    @Async
    public CompletableFuture<Void> processChunkAsync(List<Customer> chunk, int chunkNumber) {
        return CompletableFuture.runAsync(() -> {
            transactionTemplate.execute(status -> {
                for (Customer customer : chunk) {
                    processCustomer(customer);
                }
                logger.info("Async chunk {} completed", chunkNumber);
                return null;
            });
        });
    }
    
    public void processLargeBatchInParallel(List<Customer> customers) {
        List<List<Customer>> chunks = partitionList(customers, 100);
        List<CompletableFuture<Void>> futures = new ArrayList<>();
        
        for (int i = 0; i < chunks.size(); i++) {
            CompletableFuture<Void> future = processChunkAsync(chunks.get(i), i + 1);
            futures.add(future);
        }
        
        // Wait for all chunks to complete
        CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join();
    }
    
    // Mixed operations in chunks
    public void processOrdersInChunks(List<Order> orders) {
        List<List<Order>> chunks = partitionList(orders, 50);
        
        for (List<Order> chunk : chunks) {
            transactionTemplate.execute(status -> {
                // TRANSACTION 1: Save orders
                orderRepository.saveAll(chunk);
                
                // TRANSACTION 2: Update inventory for this chunk
                updateInventoryForOrders(chunk);
                
                // TRANSACTION 3: Create audit entries
                createAuditEntries(chunk);
                
                return null;
            });
            
            // External call outside transaction
            sendBatchNotifications(chunk);
        }
    }
    
    private void updateInventoryForOrders(List<Order> orders) {
        for (Order order : orders) {
            for (OrderItem item : order.getItems()) {
                // Inventory update logic
            }
        }
    }
    
    private void createAuditEntries(List<Order> orders) {
        for (Order order : orders) {
            auditRepository.save(new AuditLog("ORDER_PROCESSED", order.getId()));
        }
    }
    
    private void sendBatchNotifications(List<Order> orders) {
        // External notification service call
        notificationService.sendBatchConfirmation(orders);
    }
    
    // Utility method for partitioning
    private <T> List<List<T>> partitionList(List<T> list, int size) {
        List<List<T>> partitions = new ArrayList<>();
        for (int i = 0; i < list.size(); i += size) {
            partitions.add(list.subList(i, Math.min(i + size, list.size())));
        }
        return partitions;
    }
    
    private void processCustomer(Customer customer) {
        // Customer processing logic
        customerRepository.save(customer);
        
        // Validate business rules
        if (customer.getEmail() == null || !customer.getEmail().contains("@")) {
            throw new CustomerProcessingException("Invalid email for customer: " + customer.getId());
        }
    }
}

Best Practices & Method Comparison

Method Comparison

Method Use Case Pros Cons
REQUIRES_NEW Independent operations Clean separation, error isolation Connection pool usage, partial commits
TransactionTemplate Fine-grained control Flexible, explicit control Verbose, manual management
NESTED Partial rollbacks Savepoints, partial commits Database dependency, limited support
Chunk Processing Large datasets Memory efficient, progress tracking More complex, potential gaps

Best Practices Summary

  • Choose based on requirements: Use REQUIRES_NEW for true independence, TransactionTemplate for control
  • Monitor connection usage: Multiple transactions consume more connections
  • Implement proper error handling: Different strategies for different failures
  • Use chunking for large datasets: Prevent memory issues and timeouts
  • Test with production data volumes: Ensure performance under load
  • Consider database limitations: Not all databases support all features
  • Implement compensation logic: Handle partial failures gracefully
