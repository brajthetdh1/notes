What is Docker?

Docker is a platform that enables developers to build, ship, and run applications in containers. Containers allow you to package an application with all of its dependencies into a standardized unit for software development.

Why Use Docker?

Consistency

Containers ensure that your application works the same way in development, testing, and production

Isolation

Applications run in isolated environments, preventing conflicts between dependencies

Portability

Containers can run on any system that has Docker installed

Efficiency

Containers share the host system's kernel, making them lightweight and fast

Docker vs Virtual Machines

Docker Containers
  • • Share the host OS kernel
  • • Start in seconds
  • • Lightweight (MBs)
  • • Less isolation
Virtual Machines
  • • Each VM has its own OS
  • • Start in minutes
  • • Heavyweight (GBs)
  • • Full isolation

Core Docker Concepts

Understand the fundamental building blocks of Docker

Docker Images

Read-only templates used to create containers. Images are built from Dockerfiles and contain everything needed to run an application.

# Pull an image from Docker Hub
docker pull nginx:latest

Docker Containers

Running instances of Docker images. Containers are isolated and contain everything needed to run the application.

# Run a container
docker run -d -p 80:80 nginx

Dockerfile

A text document containing commands to assemble a Docker image. It defines the environment and application setup.

FROM node:18
WORKDIR /app
COPY . .
RUN npm install

Docker Registry

A storage and distribution system for Docker images. Docker Hub is the default public registry.

# Push to registry
docker push myusername/my-app

Docker Volumes

Persistent data storage that survives container restarts and removals. Used for data that needs to persist.

# Create a volume
docker volume create my-data

Docker Network

Enables communication between containers and with the outside world. Different network drivers available.

# Create a network
docker network create my-network

Docker Architecture

Docker Client

The primary way users interact with Docker (CLI). Sends commands to the Docker daemon.

Docker Daemon

Listens for API requests and manages Docker objects (images, containers, networks, volumes).

Docker Registry

Stores Docker images. Docker Hub is the default public registry.

$ docker run -d -p 80:80 nginx
# Client sends command to Daemon
# Daemon checks local images, pulls from Registry if needed
# Daemon creates and starts container
$ curl http://localhost:80
<!DOCTYPE html>
<html>
<title>Welcome to nginx!</title>

Essential Docker Commands

Image Commands

docker pull nginx Pull image from registry
docker images List all images
docker build -t my-app . Build image from Dockerfile
docker rmi image_id Remove an image

Container Commands

docker run -d -p 80:80 nginx Run container in background
docker ps List running containers
docker stop container_id Stop a container
docker logs container_id View container logs

System & Info Commands

docker --version Check Docker version
docker info System-wide information
docker stats Live container statistics
docker system prune Clean up unused data

Network & Volume Commands

docker network ls List networks
docker volume create my-vol Create a volume
docker volume ls List volumes
docker exec -it container_id bash Execute command in container

Practical Examples

Simple Nginx Web Server

Run a basic web server using the official Nginx image:

$ docker run -d --name my-nginx -p 8080:80 nginx
# Access at http://localhost:8080

Command Breakdown:

  • -d - Run in detached mode (background)
  • --name - Give the container a name
  • -p 8080:80 - Map host port 8080 to container port 80
  • nginx - The image to use

Interactive Ubuntu Container

Run an interactive Ubuntu container and explore:

$ docker run -it ubuntu /bin/bash
# You're now inside the container!
root@container-id: apt update
root@container-id: apt install curl
root@container-id: exit
# Container stops when you exit

Command Breakdown:

  • -it - Interactive mode with terminal
  • ubuntu - The base image
  • /bin/bash - Command to run inside container

Your First Dockerfile

Simple Node.js Application

Create a Dockerfile for a basic Node.js application:

# Use official Node.js runtime
FROM node:18-alpine

# Set working directory
WORKDIR /app

# Copy package files
COPY package*.json ./

# Install dependencies
RUN npm install

# Copy application code
COPY . .

# Expose port
EXPOSE 3000

# Start the application
CMD ["npm", "start"]

Build and Run

$ docker build -t my-node-app .
$ docker run -d -p 3000:3000 my-node-app
# Your app is running at http://localhost:3000
Dockerfile Instructions:
  • FROM - Base image
  • WORKDIR - Working directory inside container
  • COPY - Copy files from host to container
  • RUN - Execute commands during build
  • EXPOSE - Document which ports the app uses
  • CMD - Command to run when container starts
