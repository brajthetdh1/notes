Important Note on Spot Pricing

⚠️ AWS does NOT recommend setting a maximum price for Spot Instances.

If you do not specify a maximum price, you pay the current Spot price. Specifying a maximum price can lead to increased interruptions because if the Spot price exceeds your bid (which can happen during demand spikes), your instance will be reclaimed even if capacity is still available.

For modern Spot usage: The recommended approach is not to set a maximum price and instead use allocation strategies like price-capacity-optimized to balance cost and availability.

P5.1 Request a Spot Instance

Without Maximum Price
📖 Theory: Modern Spot Instance Request
In the current AWS model, you request Spot capacity and pay the current Spot price. The "bid" concept is legacy, and setting a maximum price is discouraged.

Option 1: Using the AWS Management Console
  1. Navigate to EC2 → Spot Requests
  2. Click Request Spot Instances
  3. Configure: AMI (Amazon Linux 2023), Instance type (t3.micro), Key pair, VPC/Subnet
  4. Do NOT set a maximum price — leave it blank
  5. Set Interruption behavior to terminate (or stop)
  6. Click Launch

Option 2: Using the AWS CLI (Without Max Price)
aws ec2 request-spot-instances \ --spot-price "0.005" \ --instance-count 1 \ --type "one-time" \ --launch-specification "{ \"ImageId\": \"ami-0abcdef1234567890\", \"InstanceType\": \"t3.micro\", \"KeyName\": \"MyKeyPair\", \"SubnetId\": \"subnet-08fc749671b2d077c\", \"SecurityGroupIds\": [\"sg-0b0384b66d7d692f9\"], \"IamInstanceProfile\": {\"Name\": \"SSM-Role-For-EC2\"} }"
📌 Note on --spot-price: The spot-price parameter is still supported for backward compatibility, but specifying it can lead to increased interruptions. In practice, AWS recommends omitting this parameter entirely.

Verification:
# Check Spot request status aws ec2 describe-spot-instance-requests --query 'SpotInstanceRequests[*].[SpotInstanceRequestId,State,Status.Code]' --output table
✅ Verification Checklist
  • □ Spot request submitted successfully
  • □ Instance is in running state
  • □ No maximum price specified
  • □ Interruption behavior configured

P5.2 Configure a Termination Notice Hook

📖 Theory: The Termination Notice
When AWS needs to reclaim your Spot Instance, it issues a two-minute interruption notice via:
  • Instance Metadata Service (IMDSv2) — accessible from within the instance
  • Amazon EventBridge — emits an EC2 Spot Instance Interruption Warning event

Step 1: Create a Termination Hook Script
#!/bin/bash # /opt/scripts/spot-termination-hook.sh # Set up IMDSv2 token TOKEN=$(curl -s -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600") # Check for interruption notice HTTP_CODE=$(curl -H "X-aws-ec2-metadata-token: $TOKEN" -s -w %{http_code} -o /dev/null http://169.254.169.254/latest/meta-data/spot/instance-action) if [[ "$HTTP_CODE" -eq 200 ]]; then echo "⚠️ Spot interruption notice received. Starting graceful shutdown..." # Step 1: Stop accepting new work # Step 2: Deregister from load balancer # Step 3: Save application state echo "✅ Graceful shutdown complete." else echo "No interruption notice. Continuing..." fi

Step 2: Set Up a Systemd Service
sudo tee /etc/systemd/system/spot-monitor.service > /dev/null <<'EOF' [Unit] Description=Spot Instance Termination Monitor After=network.target [Service] Type=simple ExecStart=/opt/scripts/spot-termination-hook.sh Restart=always RestartSec=5 [Install] WantedBy=multi-user.target EOF sudo systemctl daemon-reload sudo systemctl enable spot-monitor.service sudo systemctl start spot-monitor.service
✅ Verification Checklist
  • □ Bash script created in /opt/scripts/
  • □ Systemd service enabled and running
  • □ Script detects interruption notices

P5.3 Write Python Script to Poll for Interruption Warnings

📖 Theory: Python-Based Polling
A Python script running on the Spot Instance can poll the IMDSv2 endpoint periodically to detect interruption warnings. When a warning is detected, the script triggers a graceful shutdown procedure.

Step 1: Create the Python Script
#!/usr/bin/env python3 # /opt/scripts/spot-monitor.py import requests import time import subprocess import json import logging import sys logging.basicConfig( level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s', handlers=[logging.StreamHandler(sys.stdout)] ) logger = logging.getLogger("spot-monitor") METADATA_URL = "http://169.254.169.254/latest/meta-data/spot/instance-action" TOKEN_URL = "http://169.254.169.254/latest/api/token" POLL_INTERVAL = 5 # seconds def get_imds_token(): try: response = requests.put( TOKEN_URL, headers={"X-aws-ec2-metadata-token-ttl-seconds": "21600"}, timeout=2 ) response.raise_for_status() return response.text except requests.exceptions.RequestException as e: logger.error(f"Failed to get IMDS token: {e}") sys.exit(1) def check_for_interruption(token): try: response = requests.get( METADATA_URL, headers={"X-aws-ec2-metadata-token": token}, timeout=2 ) if response.status_code == 200: return json.loads(response.text) return None except requests.exceptions.RequestException as e: logger.error(f"Error checking interruption notice: {e}") return None def graceful_shutdown(action): logger.warning(f"⚠️ Interruption notice received: {action}") # Step 1: Stop accepting new work # Step 2: Deregister from load balancer # Step 3: Save application state logger.info("✅ Graceful shutdown complete") def main(): token = get_imds_token() logger.info("Spot interruption monitor started") while True: action = check_for_interruption(token) if action: graceful_shutdown(action) break time.sleep(POLL_INTERVAL) if __name__ == "__main__": main()

Step 2: Install Dependencies
sudo dnf install -y python3 python3-pip pip3 install requests

Step 3: Test the Script
# Make script executable chmod +x /opt/scripts/spot-monitor.py sudo python3 /opt/scripts/spot-monitor.py
✅ Verification Checklist
  • □ Python script created
  • □ Requests library installed
  • □ Script polls IMDSv2 successfully
  • □ Graceful shutdown logic implemented

P5.4 EventBridge + Lambda

Automatic Termination Handling
📖 Theory: Event-Driven Handling
Amazon EventBridge can detect EC2 Spot Instance Interruption Warning events and trigger a Lambda function to handle the interruption, such as deregistering the instance from a load balancer or launching a replacement.

Step 1: Create the Lambda Function
# lambda_function.py import json import boto3 import logging logger = logging.getLogger() logger.setLevel(logging.INFO) def lambda_handler(event, context): logger.info(f"Received event: {json.dumps(event)}") detail = event.get('detail', {}) instance_id = detail.get('instance-id') if not instance_id: logger.error("No instance-id found") return {'statusCode': 400} logger.info(f"Processing interruption for instance: {instance_id}") # Check if instance is tagged for handling ec2 = boto3.client('ec2') response = ec2.describe_instances(InstanceIds=[instance_id]) instance = response['Reservations'][0]['Instances'][0] tags = instance.get('Tags', []) should_handle = any( tag['Key'] == 'SpotInterruptionHandler' and tag['Value'] == 'enabled' for tag in tags ) if not should_handle: logger.info(f"Instance {instance_id} not tagged") return {'statusCode': 200} # Detach from Auto Scaling group asg_name = None for tag in tags: if tag['Key'] == 'aws:autoscaling:groupName': asg_name = tag['Value'] break if asg_name: autoscaling = boto3.client('autoscaling') autoscaling.detach_instances( InstanceIds=[instance_id], AutoScalingGroupName=asg_name, ShouldDecrementDesiredCapacity=False ) logger.info(f"Detached {instance_id} from {asg_name}") return {'statusCode': 200}

Step 2: Create the EventBridge Rule
# Create the EventBridge rule aws events put-rule \ --name spot-interruption-handler \ --event-pattern '{ "source": ["aws.ec2"], "detail-type": ["EC2 Spot Instance Interruption Warning"] }' # Add Lambda as target aws events put-targets \ --rule spot-interruption-handler \ --targets "Id"="1","Arn"="arn:aws:lambda:us-east-1:123456789012:function:spot-interruption-handler"
✅ Verification Checklist
  • □ Lambda function created
  • □ EventBridge rule created
  • □ Lambda triggered by EventBridge
  • □ Instances tagged with SpotInterruptionHandler: enabled
📡 EventBridge ⚡ Lambda 🔄 automatic

P5.5 Spot Fleet with Mixed Instance Types

t3.micro + t4g.micro
📖 Theory: Mixed Instance Spot Fleet
Spot Fleet allows you to diversify across multiple instance types and Availability Zones, increasing your chances of getting capacity and reducing the impact of interruptions. The price-capacity-optimized allocation strategy is recommended for most workloads.

Step 1: Create a Launch Template
aws ec2 create-launch-template \ --launch-template-name spot-launch-template \ --launch-template-data '{ "ImageId": "ami-0abcdef1234567890", "InstanceType": "t3.micro", "KeyName": "MyKeyPair", "SecurityGroupIds": ["sg-0b0384b66d7d692f9"], "TagSpecifications": [ { "ResourceType": "instance", "Tags": [ {"Key": "Name", "Value": "spot-fleet-instance"}, {"Key": "SpotInterruptionHandler", "Value": "enabled"} ] } ] }'

Step 2: Create the Spot Fleet Configuration
# spot-fleet-config.json { "AllocationStrategy": "priceCapacityOptimized", "OnDemandAllocationStrategy": "prioritized", "SpotMaintenanceStrategies": { "CapacityRebalance": { "ReplacementStrategy": "launch" } }, "LaunchTemplateConfigs": [ { "LaunchTemplateSpecification": { "LaunchTemplateName": "spot-launch-template", "Version": "1" }, "Overrides": [ {"InstanceType": "t3.micro", "WeightedCapacity": 1.0, "Priority": 2.0}, {"InstanceType": "t4g.micro", "WeightedCapacity": 1.0, "Priority": 1.0} ] } ], "TargetCapacity": 4, "OnDemandTargetCapacity": 1, "Type": "maintain", "ReplaceUnhealthyInstances": true }

Step 3: Create the Spot Fleet
aws ec2 request-spot-fleet --spot-fleet-request-config file://spot-fleet-config.json

Step 4: Monitor the Fleet
# Check Spot Fleet status aws ec2 describe-spot-fleet-requests --query 'SpotFleetRequestConfigs[*].[SpotFleetRequestId,SpotFleetRequestState]' --output table # List instances in the fleet aws ec2 describe-instances --filters "Name=tag:Name,Values=spot-fleet-instance" --query 'Reservations[*].Instances[*].[InstanceId,InstanceType,State.Name]' --output table

  • □ Instances tagged with SpotInterruptionHandler: enabled

Key Takeaways

  • Setting a maximum price for Spot Instances is discouraged — it can lead to increased interruptions. AWS recommends paying the current Spot price.

  • IMDSv2 provides the most immediate way to detect interruption notices from within the instance, with a two-minute warning before termination.

  • EventBridge + Lambda enables event-driven handling of interruptions, allowing you to detach instances from Auto Scaling groups and launch replacements.

  • Spot Fleets with mixed instance types improve capacity availability. Using t3.micro and t4g.micro diversifies across Intel/AMD and Graviton architectures.

  • Allocation strategies like price-capacity-optimized balance cost and availability by selecting the most available pools with the lowest price.

  • Capacity Rebalancing proactively replaces Spot Instances at elevated risk of interruption before they are terminated.

Troubleshooting

Spot request not fulfilled
Check if the instance type is available in your AZ. Try a different AZ or instance type.
IMDSv2 returns 401
Token expired — refresh the token by making a new PUT request.
Lambda not triggered
Verify the EventBridge rule's IAM role has permission to invoke the Lambda function.
Instance not detaching from ASG
Ensure the instance has the SpotInterruptionHandler: enabled tag.
