9.3 Elastic Network Interfaces (ENIs)

📖 Complete Theory: The Virtual Network Card

An Elastic Network Interface (ENI) is a logical, virtual networking component in a VPC that represents a virtual network card. It decouples network configuration from compute instances, allowing you to move an interface — with all its associated settings such as IP addresses, security groups, and more — across different instances.
🔌 ENI 🌐 virtual network card 🔄 decoupled
💡

What is an ENI?

Think of an ENI as a virtual network card that you can plug into an EC2 instance. Each ENI has its own set of attributes that define its network identity:

  • A primary private IPv4 address from the subnet's CIDR block
  • Optionally, one or more secondary private IPv4 addresses
  • Optionally, a primary IPv6 address
  • One or more Elastic IP addresses (for IPv4)
  • A unique MAC address
  • One or more security groups
  • A description
  • Source/destination check flag

When you launch an EC2 instance, it automatically receives a primary ENI (typically named eth0). This primary ENI has special characteristics:

💡 Real-World Insight: The primary ENI is permanently linked to its instance. Secondary ENIs, however, can be detached and reattached, making them ideal for scenarios like network appliances or management networks.

Source/Destination Checking:
An important attribute of an ENI is the source/destination check flag, which is enabled by default. This ensures that the instance is either the source or destination of any traffic it receives. You must disable this flag if the instance runs services such as Network Address Translation (NAT), routing, or firewalls.

⚠️ Critical: Disable source/destination check for NAT instances, routers, and firewall appliances.

9.3.1 What is an ENI?

📖 Complete Theory: The Virtual Network Card

An Elastic Network Interface (ENI) is a logical networking component in a VPC that represents a virtual network card. It decouples network configurations from compute instances, enabling you to attach an interface — with all its associated settings such as IP addresses, security groups, and more — to an instance, detach it, and reattach it to another instance while preserving all of its attributes.

The Decoupling Concept:
The power of an ENI lies in its independence. Before ENIs, network attributes were tightly coupled to an instance. Now, you can create an ENI ahead of time and attach it to an instance at launch, or even perform a "hot attach" — attaching it to a running instance.

💡 Analogy: Think of an ENI like a physical network card you can unplug from one computer and plug into another. All its settings (IP address, MAC address, firewall rules) stay with the card, not the computer.

ENI Limits:
The number of ENIs you can attach to an instance depends on the instance type. For example, larger instances support more ENIs to handle higher network performance requirements.

⚠️ Key Insight: The primary ENI is permanently linked to its instance. Secondary ENIs, however, can be detached and reattached.

📝 Review Questions
Q1: What is an Elastic Network Interface (ENI)?
An ENI is a logical, virtual networking component in a VPC that represents a virtual network card. It can be attached to EC2 instances and includes attributes such as private IP addresses, a MAC address, security groups, and subnet association.
Q2: What is the difference between a primary ENI and a secondary ENI?
The primary ENI is automatically created when an instance launches, cannot be detached, and is deleted when the instance terminates. Secondary ENIs can be created independently and attached/detached on demand, persist independently of instances, and each can have its own security groups.
Q3: What is the purpose of the source/destination check flag?
The source/destination check flag ensures that an instance is either the source or destination of any traffic it receives. It must be disabled for instances that perform network address translation, routing, or firewall services.

9.3.2 Attaching Multiple ENIs to an Instance

📖 Complete Theory: Extending Network Capabilities

Attaching multiple Elastic Network Interfaces (ENIs) to a single EC2 instance is a powerful technique that decouples network configuration from compute. By adding secondary ENIs, you can enable complex networking scenarios such as separating management and application traffic, building network appliances, or achieving high-availability architectures.

The Core Concept: One Instance, Multiple Network Cards
Think of each ENI as a separate network card. An EC2 instance can have multiple "virtual network cards," each with its own IP addresses, security groups, and subnet association.

Critical Rules and Limitations:
RuleExplanation
Same Availability ZoneThe secondary ENI must be in the same AZ as the instance
Same VPCThe ENI must be in the same VPC as the instance
Instance Type LimitsThe number of ENIs is determined by the instance type
Primary ENI is ImmovableThe primary ENI (eth0) cannot be detached
Primary ENI Counts in LimitThe primary ENI counts toward the total ENI limit
Auto-Assign Public IPOnly works for the primary ENI; secondary ENIs require an Elastic IP

🛠️ Step-by-Step: Attaching a Secondary ENI
# Step 1: Create the Secondary ENI aws ec2 create-network-interface \ --subnet-id subnet-12345678 \ --description "Secondary ENI for management" \ --groups sg-12345678 \ --private-ip-address 10.0.2.10 # Step 2: Attach the ENI to the Instance aws ec2 attach-network-interface \ --network-interface-id eni-0dc56a8d4640ad10a \ --instance-id i-1234567890abcdef0 \ --device-index 1 # Step 3: Verify inside the instance ip addr

ENI Trunking (ECS awsvpc):
For Amazon ECS workloads using the awsvpc network mode, you can increase ENI density by enabling the awsvpcTrunking account setting. For example, a c5.large instance with ENI trunking has an increased limit of twelve ENIs, allowing you to run significantly more tasks on a single instance.
📝 Review Questions
Q1: What are the key requirements for attaching a secondary ENI to an EC2 instance?
The secondary ENI must be in the same VPC and the same Availability Zone as the instance. The instance type must support the number of ENIs being attached, and the primary ENI counts toward the ENI limit.
Q2: Why does a secondary ENI not get a public IP address automatically?
Auto-assign public IP works only for the primary ENI. Secondary ENIs require an Elastic IP to be reachable from the internet.
Q3: What is ENI trunking in Amazon ECS and when would you use it?
ENI trunking increases the ENI limit on container instances by adding a "trunk" network interface. It is used for workloads using the awsvpc network mode to run more tasks on a single instance. For example, a c5.large instance goes from 3 ENIs to 12 ENIs with trunking enabled.

9.3.3 ENI Migration

Live Migration Between Instances
📖 Complete Theory: Moving the Virtual Network Card

An Elastic Network Interface (ENI) can be detached from one EC2 instance and reattached to another, effectively migrating its entire network identity — including private IP addresses, Elastic IPs, MAC address, and security groups — from one instance to another.

When you move a network interface from one instance to another, network traffic is automatically redirected from the original instance to the new one. This migration can be performed without stopping either instance, enabling rapid failover and minimizing downtime.

Critical Constraints for Migration:
RuleExplanation
Same Availability ZoneBoth instances must be in the same AZ as the ENI
Same VPCThe ENI must be in the same VPC as both instances
Primary ENI is ImmovableThe primary ENI (eth0) cannot be detached
Secondary ENIs OnlyOnly secondary ENIs (eth1, eth2, etc.) can be migrated
Attachment LimitsThe target instance must have capacity for the additional ENI
Why ENI Migration Matters — Key Use Cases:
  • High Availability with Minimal Downtime: Move a secondary ENI from a failed instance to a standby instance. Traffic is seamlessly redirected without DNS updates.
  • Zero-Downtime Deployments: Automate within ASG lifecycle hooks. Preserves stable interface mapping (eth0, eth1, etc.) during instance refreshes.
  • Network Appliance Failover: NAT instances, firewalls, load balancers can have their ENIs moved to backup instances.
  • License Management: Some software licenses are tied to a MAC address. Moving the ENI preserves the MAC address.

🛠️ Step-by-Step: Migrating a Secondary ENI
# Step 1: Identify the ENI and current attachment aws ec2 describe-network-interfaces --network-interface-ids eni-0dc56a8d4640ad10a # Step 2: Detach the ENI from the Source Instance aws ec2 detach-network-interface --attachment-id eni-attach-01a8fc87363f07cf9 # Step 3: Attach the ENI to the Target Instance aws ec2 attach-network-interface \ --network-interface-id eni-0dc56a8d4640ad10a \ --instance-id i-standby-instance-id \ --device-index 1 # Step 4: (Optional) Bring interface up on Linux sudo ip link set dev eth1 up sudo dhclient -v eth1

📝 Review Questions
Q1: What is ENI migration and what is its primary benefit?
ENI migration is the process of detaching a secondary ENI from one EC2 instance and reattaching it to another, moving its entire network identity with it. The primary benefit is enabling rapid failover and high availability with minimal downtime — because the IP address remains the same, traffic is automatically redirected without requiring DNS updates.
Q2: Can the primary ENI be migrated between instances?
No. The primary ENI (eth0) that is automatically created when an instance launches cannot be detached from its instance. Only secondary ENIs (eth1, eth2, etc.) can be migrated.
Q3: What are the constraints for migrating an ENI between instances?
The key constraints are: both instances must be in the same Availability Zone and same VPC as the ENI; only secondary ENIs can be migrated; the target instance must have capacity for the additional ENI.
Q4: How can ENI migration be used for zero-downtime deployments?
ENI migration can be automated within Auto Scaling Group lifecycle hooks using AWS Lambda. This approach deterministically attaches ENIs and Elastic IPs to new instances during rolling refreshes, preserving stable ethX interface mapping and eliminating unpredictable ordering issues. The old instances are only terminated after the new instances are fully healthy.
