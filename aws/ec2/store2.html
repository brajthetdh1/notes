11.2.1 What is an EBS Snapshot?

📖 Complete Theory: Point-in-Time Backup for Your Volumes

An Amazon EBS Snapshot is a point-in-time copy of your Amazon EBS volume that serves as a durable backup for data protection, disaster recovery, and data migration. Think of it as a photograph of your entire volume at a specific moment.

The Core Concept: A Snapshot is Not a Volume
An EBS volume is a live, active storage device — you can read and write data to it in real-time. A snapshot, by contrast, is a static image of that volume frozen at a point in time. You cannot directly write data to a snapshot; instead, you use it as a source to create new EBS volumes.

Where Are Snapshots Stored?
EBS snapshots are stored in Amazon S3, but you cannot access them directly — you can only manage them through the Amazon EC2 console or the EC2 API. Snapshot data is automatically replicated across all Availability Zones in the Region.

💡 Key Insight: Because snapshots are incremental, deleting a snapshot might not reduce your data storage costs. Data referenced exclusively by a snapshot is removed, but data also referenced by other snapshots is preserved. You can safely delete any snapshot with no impact on previous or subsequent snapshots.
📝 Review Questions
Q1: What is an EBS snapshot and what is its primary purpose?
An EBS snapshot is a point-in-time copy of an EBS volume that is used for data protection, disaster recovery, and data migration. It is a static image of your volume frozen at the moment of creation.
Q2: How do EBS snapshots store data to minimize costs?
EBS snapshots are incremental. Only the data blocks that have changed since the last snapshot are saved in each new snapshot. This minimizes storage costs by not duplicating data.
Q3: Where are EBS snapshots stored?
EBS snapshots are stored in Amazon S3, but they are not accessible directly through the S3 console or API. You can only manage them through the Amazon EC2 console, CLI, or API.
Q4: Can you safely delete a snapshot without affecting other snapshots?
Yes, you can safely delete any snapshot with no impact on previous or subsequent snapshots. Data referenced by other snapshots is preserved; only data unique to the deleted snapshot is removed.
Q5: What is Data Lifecycle Manager (DLM) and how does it help with snapshots?
DLM is a service that allows you to define policies to automate the creation, retention, and deletion of EBS snapshots. This reduces operational overhead and helps enforce backup compliance.

11.2.2 Creating and Restoring Snapshots

📖 Complete Theory: Creating and Restoring

Creating and restoring EBS snapshots is a fundamental operational task for backing up and recovering data. This process involves two primary actions: capturing a point-in-time copy of a volume and using that copy to restore data when needed.

🛠️ Creating an EBS Snapshot

Using the AWS CLI:
# Basic snapshot creation aws ec2 create-snapshot \ --volume-id vol-1234567890abcdef0 \ --description "Data volume backup" # Tagged snapshot aws ec2 create-snapshot \ --volume-id vol-1234567890abcdef0 \ --description 'Pre-update backup' \ --tag-specifications 'ResourceType=snapshot,Tags=[{Key=Purpose,Value=PreUpdate}]'

⚠️ Consistency Considerations:
  • Snapshots from in-use volumes only capture data already written to the volume
  • Data in application or OS caches may be excluded
  • For consistency: unmount the volume, stop the instance, or use a clustered file system

🔄 Restoring a Volume from a Snapshot
# Create volume from snapshot aws ec2 create-volume \ --availability-zone us-east-1a \ --snapshot-id snap-1234567890abcdef0 \ --volume-type gp3 \ --tag-specifications 'ResourceType=volume,Tags=[{Key=Name,Value=RestoredDataVolume}]'

💡 Important: The --availability-zone parameter is required and must match the AZ of the instance you intend to attach the new volume to.
📅 Automating with Lifecycle Manager (DLM)
For consistent backups, manual snapshot creation is not scalable. Data Lifecycle Manager (DLM) automates this process with policies that define:
  • Schedule: When to create snapshots (daily, weekly, monthly)
  • Retention: How long to keep snapshots
  • Target: Which volumes to back up (by tags)

📝 Review Questions
Q1: What is the primary CLI command for creating an EBS snapshot?
The primary CLI command is aws ec2 create-snapshot. You must specify the --volume-id of the EBS volume you are backing up.
Q2: How do you restore data from an EBS snapshot?
You restore data from a snapshot by creating a new EBS volume based on that snapshot using aws ec2 create-volume --snapshot-id. After creating the volume, you attach it to an EC2 instance and mount it.
Q3: What is the advantage of using Data Lifecycle Manager (DLM) for snapshots?
DLM automates the process of snapshot creation and deletion based on a schedule. It ensures consistent backups without manual intervention and helps manage storage costs by automatically deleting old snapshots.

11.2.3 Snapshot Lifecycle Management

📖 Complete Theory: Automating the Complete Backup Journey

Snapshot Lifecycle Management is the practice of automating the entire lifecycle of your EBS snapshots — from creation and retention to deletion. Without a management strategy, backups accumulate, storage costs spiral, and compliance becomes difficult to enforce.

🛠️ The Primary Tool: Amazon Data Lifecycle Manager (DLM)
Amazon Data Lifecycle Manager is the native AWS service that automates snapshot lifecycle management. It is an included feature of Amazon EC2 and EBS with no additional charge beyond the storage costs of the snapshots themselves.

Default Policies vs. Custom Policies:
📋 Default Policy
  • Targets all volumes without recent backups
  • 1 schedule only
  • Age-based retention (2-14 days)
  • Frequency: 1-7 days
  • No archiving
⚙️ Custom Policy
  • Targets resources with specific tags
  • Up to 4 schedules per policy
  • Age-based or count-based retention
  • Daily, weekly, monthly, yearly, or custom cron
  • Archiving supported
  • Cross-Region copy supported
  • Application-consistent snapshots
🔐 Advanced DLM Features:
  • Application-Consistent Snapshots: Pre/post scripts with SSM for databases (MySQL, PostgreSQL, Windows VSS)
  • Snapshot Archiving: Save up to 75% on storage costs for snapshots retained over 90 days
  • Cross-Region Copy: Automatically copy snapshots to other Regions for DR
  • Cross-Account Sharing: Share snapshots across accounts for centralized backup management

  • IAM Blocking: Block ec2:DeleteSnapshot and ec2:ModifySnapshotAttribute permissions

📝 Review Questions
Q1: What is Amazon Data Lifecycle Manager (DLM) and what is its primary purpose?
DLM is an AWS service that automates the creation, retention, and deletion of EBS snapshots and EBS-backed AMIs. It enforces backup schedules, manages retention, and reduces storage costs. It is available at no additional charge beyond storage costs.
Q2: What is the difference between a default policy and a custom DLM policy?
A default policy backs up all volumes without recent backups (2-14 days retention) with a single schedule. A custom policy targets only resources with specific tags, supports up to 4 schedules, and supports advanced features like archiving, cross-Region copy, and application-consistent snapshots.
Q3: What are the benefits of snapshot archiving?
Archiving moves snapshots to the Archive tier, saving up to 75% on storage costs. It is suitable for snapshots retained over 90 days. Requirements include monthly/yearly creation frequency (or cron ≥28 days) and a minimum 90-day retention period.

11.2.4 Copying Snapshots Across Regions

📖 Complete Theory: Cross-Region Backup and DR

Copying an EBS snapshot across Regions is a critical capability for disaster recovery, global application deployment, and data migration. Because EBS snapshots are inherently regional, you must copy them to a new Region before you can use them there.

The Standard Copy Mechanism:
# Basic cross-Region copy aws ec2 copy-snapshot \ --region us-east-1 \ # Destination Region --source-region us-west-2 \ # Source Region --source-snapshot-id snap-066877671789bd71b \ --description "This is my copied snapshot."

💡 Incremental Copying: Snapshot copies within the same account and Region using the same KMS key are typically incremental. Only the data that has changed since the last successful copy is transferred. If you change the encryption key, the operation becomes a full copy (higher cost and time).

⚡ Advanced Options: Time-Based Copy
For critical workloads that must meet strict Recovery Point Objectives (RPOs), you can use the Time-based Copy feature. This allows you to specify a completion duration (from 15 minutes to 48 hours) for the copy. Additional charges apply.

🔐 Encryption Considerations:
  • Encrypted snapshots remain encrypted during copy
  • Best practice: Re-encrypt shared snapshots using a KMS key you own
  • This protects you if the original key is revoked

⚠️ Prerequisite: You must have permissions for the KMS key used to encrypt the source snapshot. This typically requires the key's owner to grant you the necessary permissions in the key's policy.
📝 Review Questions
Q1: How do you copy an EBS snapshot to a different AWS Region using the CLI?
You use the aws ec2 copy-snapshot command. You must initiate the command in the destination Region (using --region) and specify the source Region (--source-region) and the source snapshot ID (--source-snapshot-id).
Q2: Are cross-Region snapshot copies always full copies?
Not necessarily. Copies are incremental if the snapshot has been copied to that destination Region previously, the most recent copy still exists, and the encryption key has not changed. Changing the encryption status makes it a full copy.
Q3: What is the Time-based Copy feature and when should you use it?
Time-based Copy allows you to specify a completion duration for the snapshot copy (15 minutes to 48 hours) to meet stringent business or compliance requirements. It is useful for disaster recovery and migration scenarios where predictable copy times are critical. Additional charges apply.
Q4: Why is it recommended to re-encrypt a shared encrypted snapshot?
It is recommended to re-encrypt a shared snapshot using a KMS key you own. This protects you from losing access to the snapshot if the original key owner revokes your access or if the key is compromised.

Key Takeaways

  • EBS Snapshots are point-in-time copies of EBS volumes, stored durably in Amazon S3 with 11 nines durability.

  • Snapshots are incremental — only changed data is stored after the first snapshot, making them cost-effective for frequent backups.

  • Amazon Data Lifecycle Manager (DLM) is the native, no-cost AWS tool for automating snapshot lifecycle management — creation, retention, and deletion.

  • Custom DLM policies support up to 4 schedules, archiving (75% savings), cross-Region copy, and application-consistent snapshots.

  • Snapshot archiving provides up to 75% cost savings for snapshots retained over 90 days.

  • Cross-Region copying is essential for disaster recovery. Copies are incremental unless the encryption key changes.

  • Re-encrypt shared snapshots using a KMS key you own to protect against key revocation.

  • Protect your backups using Recycle Bin, Backup Vault Lock, or cross-account backups.

  • Cost optimization requires clear retention policies, regular audits, and automated deletion to prevent "snapshot sprawl".

  • Application-consistent snapshots use pre/post scripts with Systems Manager for databases like MySQL, PostgreSQL, and Windows VSS.
