6.2.2 Launching via AWS CLI

The AWS Command Line Interface (AWS CLI) is a powerful tool for launching and managing EC2 instances programmatically. Many administrators prefer the CLI over the console because it provides a reliable, scalable, and consistent way to deploy infrastructure.

This section provides a comprehensive guide to launching EC2 instances using the AWS CLI's run-instances command.
💻 CLI ⚙️ run-instances 🤖 automation
📖

Command Overview

The aws ec2 run-instances command is the primary method for launching EC2 instances through the CLI. This command supports over 40 different parameters, allowing you to customize your instance configuration with granular control.

Basic Syntax:
aws ec2 run-instances \ --image-id <ami-id> \ --instance-type <instance-type> \ --key-name <key-pair-name> \ --subnet-id <subnet-id> \ --security-group-ids <sg-id> \ --count <number-of-instances>

🎯 Minimum Required Parameters:
--image-id
The ID of the AMI to launch
Example: ami-0abcdef1234567890
--instance-type
Hardware configuration
Example: t2.micro
--key-name
Key pair for SSH/RDP access
Example: MyKeyPair

💡 Notes:
  • If you do not specify --subnet-id, AWS launches the instance in the default subnet of your default VPC.
  • If you do not specify --security-group-ids, the instance uses the default security group for that VPC.
📖 overview ⚙️ parameters 🎯 minimum
🚀

Minimal Launch Examples

Example 1: Minimal Launch (Default VPC/Subnet)
aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t2.micro \ --key-name MyKeyPair
Output:
{ "Instances": [{ "InstanceId": "i-1231231230abcdef0", "State": {"Name": "pending"}, "InstanceType": "t2.micro", "LaunchTime": "2018-05-10T08:05:20.000Z", ... }] }

Example 2: Launch in a Specific VPC Subnet
aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t2.micro \ --subnet-id subnet-08fc749671b2d077c \ --security-group-ids sg-0b0384b66d7d692f9 \ --associate-public-ip-address \ --key-name MyKeyPair

Example 3: Using a Launch Template
# Launch using template aws ec2 run-instances \ --launch-template LaunchTemplateId=lt-0abcd290751193123,Version=1 # Override specific parameters aws ec2 run-instances \ --launch-template LaunchTemplateId=lt-0abcd290751193123 \ --instance-type t2.small

Essential Security Parameters

--metadata-options (Enforces IMDSv2)
For improved security, enforce IMDSv2 which provides additional protection against SSRF attacks.
aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t2.micro \ --metadata-options "HttpTokens=required,HttpEndpoint=enabled" \ ...

--block-device-mappings (Configure EBS Storage)
aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t2.micro \ --block-device-mappings "DeviceName=/dev/xvda,Ebs={VolumeSize=30,VolumeType=gp3,Encrypted=true}"

Block Device Mapping Parameters:
DeleteOnTermination
Delete volume on termination (default: true)
Iops
Provisioned IOPS for io1/io2 volumes
SnapshotId
ID of snapshot to restore from
VolumeSize
Size in GiB
VolumeType
gp2, gp3, io1, io2, st1, sc1
Encrypted
Whether volume is encrypted

--user-data (Bootstrap Configuration)
aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t2.micro \ --user-data file://my_script.txt
💡 Important: User data scripts run only on the first boot of the instance.
🛡️ security 🔐 IMDSv2 💾 block mapping 📋 user data

Tagging & IAM Roles

--tag-specifications (Resource Tagging)
Tagging is essential for organizing and managing your resources.
aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t2.micro \ --tag-specifications \ 'ResourceType=instance,Tags=[{Key=Name,Value=MyWebServer},{Key=Environment,Value=Production}]' \ 'ResourceType=volume,Tags=[{Key=CostCenter,Value=Finance}]'

--iam-instance-profile (Assign IAM Roles)
Instead of embedding credentials in the instance, assign an IAM role for security.
aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t2.micro \ --iam-instance-profile Name=my-instance-role

--disable-api-termination (Prevent Accidental Deletion)
aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t2.micro \ --disable-api-termination
🏷️ tagging 🎭 IAM role 🛡️ termination protection

Production-Ready Launch

Full Example:
aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t3.medium \ --key-name my-production-key \ --subnet-id subnet-08fc749671b2d077c \ --security-group-ids sg-0b0384b66d7d692f9 \ --associate-public-ip-address \ --count 1 \ --block-device-mappings "DeviceName=/dev/xvda,Ebs={VolumeSize=50,VolumeType=gp3,Encrypted=true,DeleteOnTermination=true}" \ --metadata-options "HttpTokens=required,HttpEndpoint=enabled" \ --iam-instance-profile Name=my-app-role \ --disable-api-termination \ --tag-specifications \ 'ResourceType=instance,Tags=[{Key=Name,Value=Production-WebServer},{Key=Environment,Value=Production},{Key=Project,Value=Ecommerce}]' \ 'ResourceType=volume,Tags=[{Key=Environment,Value=Production}]' \ --monitoring Enabled \ --credit-specification CpuCredits=unlimited

Key Parameters Explained:
  • --count 1 — Launch exactly one instance
  • --monitoring Enabled — Enable detailed CloudWatch monitoring (1-minute intervals)
  • --credit-specification CpuCredits=unlimited — Enable unlimited CPU credits for burstable instances

Viewing Instances After Launch

Get Public IP Address:
aws ec2 describe-instances \ --instance-ids i-1231231230abcdef0 \ --query 'Reservations[0].Instances[0].PublicIpAddress' \ --output text

View Instance Details:
aws ec2 describe-instances \ --instance-ids i-1231231230abcdef0 \ --query 'Reservations[0].Instances[0].{ID:InstanceId,Type:InstanceType,State:State.Name,PublicIP:PublicIpAddress,PrivateIP:PrivateIpAddress}' \ --output table

Common Command Patterns:

Finding an AMI

Official Ubuntu AMIs are published by Canonical (AWS Account ID: 099720109477).

Find the latest Ubuntu 22.04 AMI:
aws ec2 describe-images \ --owners 099720109477 \ --filters "Name=name,Values=ubuntu/images/hvm-ssd/ubuntu-22.04-amd64-server-*" \ --query 'Images | sort_by(@, &CreationDate) | [-1].ImageId' \ --output text

For Amazon Linux 2023 AMI, use the SSM Parameter Store:
aws ssm get-parameters-by-path \ --path "/aws/service/ami-amazon-linux-latest" \ --query "Parameters[?contains(Name, 'al2023-ami-kernel-default-x86_64')].Value" \ --output text | head -1

Key Takeaways

  • The run-instances command is the primary method for launching EC2 instances through the AWS CLI. It supports over 40 parameters for granular control.

  • Minimum required parameters are --image-id, --instance-type, and --key-name.

  • Security best practices include enforcing IMDSv2 (--metadata-options "HttpTokens=required"), encrypting EBS volumes, and using IAM roles.

  • Use --user-data to pass bootstrap scripts that run on the first boot of the instance, automating configuration and software installation.

  • Tagging resources with --tag-specifications is essential for managing, organizing, and tracking costs.

  • Launch templates (--launch-template) simplify instance launches by preconfiguring common parameters.

  • Use --block-device-mappings to customize storage, including volume size, type, and encryption.

  • The --count parameter allows you to launch multiple identical instances in a single command.

  • Verify launch success by using aws ec2 describe-instances to check the state and retrieve the public IP address.

Review Questions

Q1: What is the minimum set of parameters required to launch an EC2 instance using the AWS CLI?
Answer: The minimum required parameters are --image-id, --instance-type, and --key-name. If you omit --subnet-id and --security-group-ids, the default VPC and default security group are used.
Q2: How can you enforce IMDSv2 when launching an EC2 instance?
Answer: Use the --metadata-options parameter: --metadata-options "HttpTokens=required,HttpEndpoint=enabled". This enforces IMDSv2, which provides additional protection against SSRF attacks.
Q3: What is the purpose of the --user-data parameter?
Answer: The --user-data parameter passes a bootstrap script or configuration that executes when the instance starts. User data scripts run only on the first boot of the instance, making it ideal for automating configuration and software installation.
Q4: How can you prevent accidental termination of a critical EC2 instance?
Answer: Use the --disable-api-termination parameter when launching the instance. This prevents the instance from being terminated through the API, console, or CLI. To terminate a protected instance, you must first disable the termination protection.
Q5: What AWS account ID publishes official Ubuntu AMIs?
Answer: Official Ubuntu AMIs are published by Canonical under AWS Account ID 099720109477. You can use this owner ID in the --owners parameter of the describe-images command to find official Ubuntu AMIs.
