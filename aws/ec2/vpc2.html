9.2 IP Addresses

📖 Complete Theory: The Three Types of IP Addressing

When you launch an EC2 instance in a VPC, it receives IP addresses to enable communication both within your VPC and with the internet. Amazon EC2 supports both IPv4 (the default) and IPv6 addressing protocols, and you manage three distinct categories of IP addresses: Private, Public, and Elastic IP addresses.
🌐 IP addresses 📊 IPv4 📈 IPv6
🔒

1. Private IPv4 Addresses

A private IPv4 address is an IP address that is not reachable over the internet, used for communication between instances in the same VPC.

🔒 Private IPv4 Address
Allocation and Persistence:
When you launch an instance into a VPC, a primary private IP address from the IPv4 address range of the subnet is assigned to the primary network interface (eth0) of the instance. You can also specify secondary private IPv4 addresses, which can be reassigned from one instance to another.

✅ A private IPv4 address remains associated with the network interface when the instance is stopped and restarted, and is released only when the instance is terminated.

Key Characteristics:
CharacteristicDescription
ScopeInternal to the VPC. Only instances and resources inside your VPC can communicate using private IPs.
AssignmentAssigned from the IPv4 CIDR block of the subnet your instance resides in.
PersistencePersists throughout the instance's lifecycle. Remains associated when stopped and started.
ReachabilityNot reachable from the internet
🔒 private IP 🌐 internal 🔄 persistent
🌍

2. Public IPv4 Addresses

A public IP address is an IPv4 address that is reachable from the internet.

🌍 Public IPv4 Address
Ephemeral Nature:
Public IP addresses are assigned from Amazon's pool of public IP addresses and are not associated with your AWS account. They are ephemeral and are released in several scenarios:

  • ⛔ Stop/Hibernate/Terminate: The public IP address is released when the instance is stopped, hibernated, or terminated.
  • 🔄 Elastic IP Association: It is released when you associate an Elastic IP address with the instance.
  • 🔄 Start: A stopped or hibernated instance receives a new public IP address when it is started.

Key Characteristics:
CharacteristicDescription
ScopeGlobal. Public IP addresses are routable on the internet.
AssignmentAssigned from Amazon's pool of public IPv4 addresses, not associated with your account.
PersistenceTemporary and dynamic. Released when the instance is stopped.
Behavior on Stop/StartWhen started, receives a new public IP address.
Allocation ControlDefault VPCs assign public IPs by default. Nondefault subnets require enabling "Auto-assign public IP".

⚠️ Note on Public IPv4 Charges: AWS charges for all public IPv4 addresses, including those associated with running instances and Elastic IP addresses. This encourages the use of private IPs and efficient management of public IPv4 resources.
🌍 public IP 🔄 ephemeral 💰 charges apply
⭐

3. Elastic IP Addresses (EIPs)

An Elastic IP address is a static public IPv4 address that you can allocate to your account and retain until you choose to release it.

⭐ Elastic IP Address
Persistence:
Unlike a standard public IP, an Elastic IP remains associated with your instance when it is stopped, and persists across stop/start cycles. You can also reassociate it with a different instance as needed.

Use Cases:
Elastic IPs are essential for scenarios where you require a persistent, static IP address (e.g., for DNS records or IP allowlisting).

Key Characteristics:
  • Static and Persistent: An Elastic IP does not change over time. It survives instance stops, restarts, and even re-associations.
  • Region-Specific: Can only be used within the specific AWS Region where it is allocated.
  • IPv4 Only: Elastic IPs are for use with the IPv4 protocol only.
  • Reachability and DNS: When associated with an instance, the public DNS hostname resolves to the Elastic IP address.

Common Use Cases:
Use CaseDescription
EC2 InstancesAssign a persistent public IP that survives stop/start cycles.
NAT GatewayRequires an Elastic IP to provide a predictable outbound IP address for private subnets.
Network Load Balancer (NLB)Supports binding one Elastic IP per subnet for a stable, whitelistable public endpoint.

💰 Pricing and Quotas:
  • Charges: AWS charges for all public IPv4 addresses, including Elastic IPs. This applies whether the EIP is in use (associated) or idle (allocated but not associated).
  • Quota: By default, all AWS accounts have a quota of five (5) Elastic IP addresses per Region.
⭐ Elastic IP 🔄 static 💰 charges apply
📈

4. IPv6 Addresses

You can optionally assign an IPv6 CIDR block to your VPC and subnets. IPv6 addresses are globally unique and can be configured to remain private or be reachable over the internet.

📈 IPv6 Address
Why IPv6 Matters:
IPv6 usage is growing every year and is becoming the default in many new network configurations. The primary driver for IPv6 adoption is the exhaustion of public IPv4 addresses. IPv6, with its 128-bit address space, provides virtually unlimited addresses.

Key Benefits:
  • Virtually Unlimited Scalability: Assign unique IP addresses to every resource.
  • Simplified Architecture: Minimizes the need for translation mechanisms like NAT.
  • Native End-to-End Connectivity: Enables end-to-end native IPv6 connectivity.

IPv6 Persistence:
An important characteristic of IPv6 addresses in EC2 is their persistence. Unlike ephemeral public IPv4 addresses, an IPv6 address persists when you stop and start your instance, and is only released when you terminate your instance.

Public and Private IPv6 Addressing:
TypeDescription
Private IPv6IPv6 addresses that are not advertised and cannot be advertised on the internet from AWS.
Public IPv6IPv6 addresses that are advertised on the internet from AWS.

💡 Dual-Stack Configuration: You can configure your VPC and resources to operate in dual-stack mode, supporting both IPv4 and IPv6 addressing. This allows you to maintain backwards compatibility with your existing IPv4 workloads while gradually adopting IPv6.

⚠️ Important Considerations:
  • IPv6 is Optional: You cannot disable IPv4 in a VPC; IPv6 is optional and must be explicitly configured.
  • IPv6 Persists: Unlike public IPv4 addresses that change on stop/start, IPv6 addresses persist through stop/start cycles.
  • No Elastic IPv6: There is no concept of an "Elastic IPv6" address.
📈 IPv6 🌐 unlimited 🔄 persistent

9.2.1 Public IP vs. Private IP

📖 Complete Theory: The Two Faces of EC2 Networking

When you launch an EC2 instance, it is assigned two fundamental types of IP addresses: a Private IP and a Public IP. These addresses serve distinct purposes and behave differently based on their role within the AWS network architecture.

🔒 Private IPv4 Address
Internal Identity
  • Scope: Internal to the VPC
  • Assignment: From subnet CIDR block
  • Persistence: Persists throughout lifecycle
  • Reachability: Not reachable from internet
🌍 Public IPv4 Address
Internet Presence
  • Scope: Global (routable on internet)
  • Assignment: From Amazon's pool
  • Persistence: Temporary and dynamic
  • Behavior: Changes on stop/start

⚙️ How They Work Together: The NAT Mechanism
Crucially, a public IP address is not directly attached to the EC2 instance's network interface. Instead, the public IP is mapped to the instance's primary private IP address through Network Address Translation (NAT). This means that the instance itself is only aware of its private IP address. The public IP exists as a mapping on the Internet Gateway (IGW) that provides the translation.

⚠️ Why This Matters: Commands like ifconfig or ipconfig run inside the instance will only show the private IP, and never the public IP.

🔄 Key Behavioral Differences:
ActionPrivate IP BehaviorPublic IP Behavior
Stop InstanceRemains the sameReleased
Start InstanceRemains the sameChanges — new IP assigned

💡 Why This Matters:
  • For Internal Communication: Use private IPs. They are stable and don't incur data transfer costs.
  • For Stable Public Access: Public IPs change on every stop/start. Use an Elastic IP (EIP) for a persistent public IP.

9.2.1 Review Questions

Q1: What is the primary difference between a private IP and a public IP in AWS?
A private IP address is used for communication within your VPC and is not reachable over the internet. A public IP address is reachable from the internet and enables your instance to communicate with the outside world. A public IP is assigned from Amazon's pool and is not associated with your account, whereas a private IP is permanently associated with your instance's network interface.
Q2: What happens to the public IP address of an instance when it is stopped and then started?
The public IP address is released when the instance is stopped. When it is started again, AWS assigns a new public IP address. The private IP address, however, remains the same.
Q3: If you run the ifconfig command inside a Linux EC2 instance, which IP will you see?
You will only see the private IP address of the instance. The public IP is not directly attached to the network interface; it is managed by the Internet Gateway (IGW) via Network Address Translation (NAT).
Q4: Can a private IP address be used to communicate with an EC2 instance from the public internet?
No, private IP addresses are not reachable over the internet. They are only accessible from within the VPC. For internet access, a public IP address or an Elastic IP address must be used.
Q5: Why is a public IP address considered "temporary" in AWS?
A public IP is considered temporary because it is not a resource you own. It is dynamically assigned from Amazon's pool and is released back into the pool when the instance is stopped, hibernated, or terminated. When the instance is started again, a new one is assigned.

9.2.2 Elastic IPs (EIPs)

Static Public IPv4
📖 Complete Theory: Static Public IPv4

An Elastic IP address (EIP) is a static, public IPv4 address designed for dynamic cloud computing. You allocate it to your AWS account, and it remains yours until you explicitly release it. This provides a stable, persistent public endpoint for your resources, regardless of their lifecycle.

🎯 Key Characteristics of Elastic IPs:
  • Static and Persistent: An Elastic IP does not change over time. It survives instance stops, restarts, and even re-associations to different resources.
  • Region-Specific: An Elastic IP address can only be used within the specific AWS Region where it is allocated.
  • IPv4 Only: Elastic IPs are for use with the IPv4 protocol only.
  • Reachability and DNS: When associated with an instance, the public DNS hostname of the instance resolves to the Elastic IP address.

🚀 Why Use Elastic IPs?
An Elastic IP is the solution to the "changing public IP" problem. When you stop and start an EC2 instance with a standard auto-assigned public IP, it is released and a new one is assigned. For any production service where a stable public IP is required (e.g., for DNS records, allowlisting by external partners), you must use an Elastic IP.

  • Masking Failures: You can rapidly remap an Elastic IP address from a failed instance to a new, healthy one.
  • Stable Endpoints: Provides a fixed, whitelistable public endpoint for services.

📝 Managing Elastic IPs:
  • Allocation: You must first allocate an Elastic IP address to your account.
  • Association: You associate the Elastic IP with an instance or a network interface.
  • Disassociation and Release: You can disassociate an EIP from a resource and associate it with another. A disassociated EIP remains allocated to your account until you release it. Best practice: release any EIPs you no longer need to avoid unnecessary charges.

💰 Pricing and Quotas:
  • Charges: AWS charges for all public IPv4 addresses, including Elastic IPs. This applies whether the EIP is in use (associated with a running resource) or idle (allocated but not associated).
  • Quota: By default, all AWS accounts have a quota of five (5) Elastic IP addresses per Region.
⭐ EIP 🔄 static 💰 charges
❓

9.2.2 Review Questions

Q1: What is an Elastic IP address and how does it differ from a standard public IP address?
An Elastic IP address is a static, public IPv4 address allocated to your AWS account. It persists until you explicitly release it. A standard public IP address, assigned automatically by AWS, is ephemeral and will be released when the instance is stopped and a new one assigned when it starts again.
Q2: What is the default Elastic IP address quota per AWS Region?
The default quota is five (5) Elastic IP addresses per Region.
Q3: Can an Elastic IP address be moved from one AWS Region to another?
No. An Elastic IP address can only be used in the specific AWS Region where it was allocated.
Q4: Are there charges for an Elastic IP address that is allocated but not associated with a running instance?
Yes. AWS charges an hourly fee for any allocated Elastic IP address, regardless of whether it is associated with a running instance or if it is disassociated.

9.2.3 IPv6 Support

📖 Complete Theory: IPv6 in AWS

Amazon EC2 and Amazon VPC support both the IPv4 and IPv6 addressing protocols. While IPv4 remains the default and cannot be disabled, IPv6 provides a virtually unlimited address space that enables you to scale your applications without the constraints of IPv4 address exhaustion.

Why IPv6 Matters:
The primary driver for IPv6 adoption is the exhaustion of public IPv4 addresses. With the surge in internet-connected devices, the 32-bit address space of IPv4 is no longer sufficient. IPv6, with its 128-bit address space, provides virtually unlimited addresses.

Key Benefits of IPv6 on AWS:
  • Virtually Unlimited Scalability: Assign unique IP addresses to every resource without complex NAT schemes.
  • Simplified Architecture: Minimizes the need for translation mechanisms like NAT.
  • Native End-to-End Connectivity: Enables end-to-end native IPv6 connectivity, improving security posture.

How IPv6 Works in EC2:
To use IPv6 with EC2, you must first associate an IPv6 CIDR block with your VPC and subnets. By default, AWS provides a /56 IPv6 CIDR block when you add an Amazon-provided IPv6 CIDR block to your VPC. This block can be subdivided into 256 /64 subnets.

IPv6 Persistence:
An important characteristic of IPv6 addresses in EC2 is their persistence. Unlike ephemeral public IPv4 addresses, an IPv6 address persists when you stop and start your instance, and is only released when you terminate your instance.

💡 Dual-Stack Configuration: You can configure your VPC and resources to operate in dual-stack mode, supporting both IPv4 and IPv6 addressing. This allows you to maintain backwards compatibility with your existing IPv4 workloads while gradually adopting IPv6.

  • No Elastic IPv6: There is no concept of an "Elastic IPv6" address.
  • Instance Type Support: All current-generation instance types support IPv6, with the exception of C1, M1, M2, M3, and T1.

9.2.3 Review Questions

Q1: What is the primary benefit of using IPv6 in AWS?
The primary benefit of IPv6 is its virtually unlimited address space, which eliminates the constraints of IPv4 address exhaustion. This allows you to scale applications without complex NAT configurations and assign unique IP addresses to every resource in your VPC.
Q2: How does an IPv6 address behave when you stop and start an EC2 instance?
An IPv6 address persists when you stop and start your instance. It is only released when you terminate the instance. This is a key difference from ephemeral public IPv4 addresses, which are released on stop and a new one assigned on start.
Q3: What older instance types do not support IPv6 addresses?
The following instance types do not support IPv6 addresses: C1, M1, M2, M3, and T1.
Q4: What is the difference between public and private IPv6 addresses in AWS?
Private IPv6 addresses are not advertised and cannot be advertised on the internet from AWS, providing isolation and security. Public IPv6 addresses are advertised on the internet from AWS and are reachable globally. You can control reachability via routing, security groups, and network ACL rules.
