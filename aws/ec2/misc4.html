10.4 Network Access Control Lists (NACLs)

📖 Complete Theory: The Subnet-Level Stateless Firewall

A Network Access Control List (NACL) is a virtual firewall that controls traffic in and out of one or more subnets within your AWS VPC. Unlike Security Groups, which protect individual instances, NACLs operate at the subnet level and provide an additional layer of defense-in-depth for your network architecture.
🛡️ NACLs 📊 subnet-level 🔒 stateless
🔑

Key Characteristics

1. Stateless Nature
The most fundamental characteristic of a NACL is that it is stateless. This means that it does not "remember" established connections. If you allow an inbound request, the corresponding outbound response traffic is not automatically allowed. You must explicitly configure both inbound and outbound rules to permit the return traffic.

💡 Analogy: Think of a NACL like a security guard checking ID at a building entrance. If you show your ID (inbound traffic) and are allowed in, the guard at the exit doesn't automatically know you — you need to show ID again to leave (outbound traffic).

2. Allow and Deny Rules
NACLs support both ALLOW and DENY rules. This enables you to explicitly block specific IP addresses or traffic types, even if other rules might allow them.

3. Rule Evaluation Order
NACL rules are evaluated in numerical order, starting with the lowest rule number. As soon as a rule matches the traffic, it is applied, and the evaluation stops.

Key Rule Structure:
FieldDescription
Rule NumberInteger from 1–32,766, determining evaluation order
ProtocolTCP, UDP, ICMP, or ALL
Port RangeSingle port or range (e.g., 80 or 1024-65535)
CIDR BlockSource (for inbound) or destination (for outbound)
ActionALLOW or DENY

4. Subnet-Level Enforcement
NACLs are attached to subnets, not individual instances:
  • One NACL can be associated with multiple subnets
  • Each subnet can be associated with only one NACL at a time
  • Subnets are automatically assigned the default NACL if no custom NACL is associated

10.4.1 What is a NACL?

Stateless Firewall
📖 Complete Theory: The Subnet-Level Firewall

A Network Access Control List (NACL) is a stateless, subnet-level firewall that controls traffic entering and leaving one or more subnets within your Amazon Virtual Private Cloud (VPC). It acts as an additional layer of security, working alongside Security Groups to provide defense in depth.

The Core Concept: Subnet-Level Security
NACLs operate at the subnet boundary, making decisions about traffic based on a set of numbered rules. They evaluate traffic as it enters or leaves a subnet, providing a first line of defense before traffic reaches individual instances.

🔑 Key Characteristics of NACLs:
  • Stateless: Does not track connection state
  • Allow and Deny: Supports both types of rules
  • Rule Order: Evaluated in numerical order
  • Subnet-Level: Attached to subnets, not instances
  • Ephemeral Ports: Must be explicitly configured

💡 Key Insight: NACLs are evaluated before Security Groups. A DENY rule in the NACL will block traffic before it ever reaches the instance, effectively overriding any ALLOW rules in the Security Group.
📝 Review Questions
Q1: What is a Network Access Control List (NACL)?
A NACL is a stateless, subnet-level firewall that controls traffic entering and leaving one or more subnets within a VPC. It provides an additional layer of defense by enforcing security rules at the subnet boundary.
Q2: Why are NACLs considered "stateless"?
NACLs are stateless because they do not track established connections. If you allow an inbound request, the corresponding outbound response is not automatically allowed. You must explicitly define outbound rules to permit return traffic, unlike Security Groups which handle this automatically.
Q3: What is the primary difference between a NACL and a Security Group?
A NACL operates at the subnet level, is stateless, supports both ALLOW and DENY rules, and evaluates rules in numerical order. A Security Group operates at the instance level, is stateful, only supports ALLOW rules, and evaluates all rules together.
Q4: How are rules evaluated in a NACL?
NACL rules are evaluated in numerical order, starting with the lowest rule number. When traffic matches a rule, the evaluation stops, and the rule's action (ALLOW or DENY) is applied. Higher-numbered rules are not considered if a lower-numbered rule matches.
Q5: What are ephemeral ports and why are they important for NACLs?
Ephemeral ports are high-numbered TCP ports (typically 1024-65535) used by client-side applications for temporary communication. Because NACLs are stateless, you must explicitly allow these ports in both inbound and outbound directions to enable TCP communication.

10.4.2 NACL Rules (Allow/Deny)

📖 Complete Theory: The Structure of Subnet Traffic Control

A Network Access Control List (NACL) is a stateless, subnet-level firewall that defines a set of rules, each of which either ALLOWs or DENYs specific traffic. Unlike Security Groups, which only support ALLOW rules, NACLs give you the power to explicitly block traffic with DENY rules.

The Anatomy of a NACL Rule:

ProtocolTCP, UDP, ICMP, or ALLTCP, UDP, ICMP, ALL
Port RangeListening port or port range22, 80, 443, 1024-65535
Source/DestinationCIDR block203.0.113.0/24, 0.0.0.0/0

📊 Rule Evaluation Order:
NACL rules are evaluated in numerical order starting with the lowest rule number. As soon as a rule matches the traffic, the ALLOW or DENY action is applied immediately, and no further rules are evaluated.

💡 Best Practice: Start by creating rules in increments (for example, increments of 10 or 100) so that you can insert new rules later on if needed.

🚫 The Importance of Deny Rules:
One of the key differentiators of NACLs is the ability to explicitly DENY traffic. This can be used to:
  • Block Malicious IPs: Create a low-numbered DENY rule for a known bad actor's IP range
  • Emergency Lockdown: Quickly block all traffic to a subnet during a security incident
  • Enforce Policies: Explicitly deny specific protocols or ports at the subnet boundary
📝 Review Questions
Q1: How are rules in a Network ACL evaluated?
NACL rules are evaluated in numerical order, starting with the lowest rule number. When traffic matches a rule, the evaluation stops and the rule's action (ALLOW or DENY) is immediately applied. This is why a lower-numbered ALLOW rule can override a higher-numbered DENY rule.
Q2: Can a NACL deny all traffic by default?
Yes. While the default NACL that comes with a VPC allows all traffic, a custom NACL denies all inbound and outbound traffic by default. You can also add a catch-all DENY rule (*) to any NACL to block traffic that doesn't match any other numbered rule.
Q3: What happens if a DENY rule for SSH has a higher rule number than an ALLOW rule for SSH?
The DENY rule becomes ineffective. Because rules are evaluated in numerical order, traffic will match the lower-numbered ALLOW rule first, and the DENY rule will never be reached. To effectively block traffic, place the DENY rule at a lower number than the ALLOW rule.
Q4: What is the difference between inbound and outbound NACL rules?
Inbound rules control traffic entering the subnet, while outbound rules control traffic leaving the subnet. Because NACLs are stateless, you must define rules in both directions to allow the response traffic for allowed connections.
Q5: What are ephemeral ports and why are they important in NACL configuration?
Ephemeral ports are high-numbered ports (typically 1024-65535) used for temporary client-side communication. Because NACLs are stateless, you must explicitly allow these ports in both inbound and outbound directions for TCP communication to work, as they are used for response traffic.

10.4.3 Difference Between SGs and NACLs

📖 Complete Theory: Two Layers of Defense

Security Groups (SGs) and Network Access Control Lists (NACLs) are the two primary network security mechanisms in AWS VPC. While both control traffic, they operate at different layers of the networking stack and have fundamentally different characteristics.

💡 Key Insight: The security industry consensus is to use both SGs and NACLs together — SGs for fine-grained, instance-level controls and NACLs for broad, subnet-level protection. Think of it as "Security Groups secure the apartment, NACLs secure the building."

Ephemeral PortsAutomatically handledMust be explicitly configured
Rule LimitsUp to 60 rules per SG (soft limit)Up to 20 rules per NACL (soft limit)
Attach PointsUp to 5 per ENI (soft limit)One per subnet (must be associated)

The recommended security architecture uses both SGs and NACLs together:
Internet → NACL (subnet check) → Security Group (instance check) → EC2 Instance
  • NACL at subnet level: Apply broad, subnet-wide rules
  • SG at instance level: Apply fine-grained, application-specific rules
  • A DENY rule in the NACL will block traffic before it ever reaches the instance

10.4.3 Review Questions

Q1: What is the primary difference between a Security Group and a Network ACL?
A Security Group is a stateful firewall that operates at the instance/ENI level and only supports ALLOW rules. A Network ACL is a stateless firewall that operates at the subnet level and supports both ALLOW and DENY rules.
Q2: Why are NACLs considered stateless?
NACLs are stateless because they do not track established connections. If you allow an inbound request, the corresponding outbound response is not automatically allowed. You must explicitly define outbound rules to permit return traffic.
Q3: How are rules evaluated in a Security Group vs. a NACL?
In a Security Group, all rules are evaluated together — if any rule allows the traffic, it is allowed. In a NACL, rules are evaluated in numerical order — the first matching rule (lowest number) is applied, and evaluation stops.
Q4: When would you use a DENY rule in a NACL?
You would use a DENY rule to explicitly block traffic at the subnet level. Common use cases include blocking known malicious IP addresses, blocking specific protocols, implementing emergency lockdowns, or enforcing stateless compliance requirements.
Q5: Can a Security Group and a NACL be used together on the same instance?
Yes. This is a best practice for defense-in-depth. The NACL at the subnet level provides broad, first-line controls, and the Security Group at the instance level provides fine-grained, application-specific controls. A DENY rule in the NACL blocks traffic before it reaches the instance.

Key Takeaways

  • NACLs are stateless, subnet-level firewalls that support both ALLOW and DENY rules.

  • Stateless means you must explicitly configure both inbound and outbound rules for return traffic.

  • Rule evaluation is in numerical order — first match wins, and evaluation stops.

  • Custom NACLs deny all traffic by default; default NACLs allow all traffic.

  • Ephemeral ports (1024-65535) must be explicitly allowed in both directions for TCP communication.

  • DENY rules in NACLs block traffic before it reaches Security Groups — they override SG rules.

  • Security Groups are stateful (instance-level) and only support ALLOW rules; NACLs are stateless (subnet-level) and support both.

  • Use both SGs and NACLs together for defense-in-depth — SGs secure the instance, NACLs secure the subnet.

  • Best practice: Use incremental rule numbers (10, 20, 30) to allow future rule insertion.

  • Always include a catch-all DENY rule (*) to block unmatched traffic.
