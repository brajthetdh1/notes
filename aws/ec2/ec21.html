P4.1 Launch with User Data

Install Apache, Deploy Webpage
📖 Theory: What is User Data?
User Data is a script or configuration that runs automatically when an EC2 instance launches for the first time. It's used to bootstrap instances — installing software, applying configurations, and preparing the instance for use without manual intervention.

Key Characteristics:
  • Runs only on first boot (not on subsequent starts)
  • Can be up to 16 KB in size
  • Executes as root (Linux) or Administrator (Windows)
  • Supports shell scripts (Linux) or PowerShell scripts (Windows)

🛠️ Step-by-Step Instructions
Step 1: Create the User Data Script
Create a file named user-data.sh with the Apache installation script:
#!/bin/bash # Update system packages sudo dnf update -y # Install Apache web server sudo dnf install -y httpd # Start Apache and enable on boot sudo systemctl start httpd sudo systemctl enable httpd # Create a custom webpage sudo tee /var/www/html/index.html > /dev/null <<'EOF' <!DOCTYPE html> <html> <head> <title>User Data Demo</title> <style> body { font-family: Arial, sans-serif; text-align: center; padding: 50px; } h1 { color: #FF9900; } .info { background: #f4f4f4; padding: 20px; border-radius: 8px; } </style> </head> <body> <h1>🚀 User Data Demo</h1> <div class="info"> <p>This instance was launched with User Data!</p> <p>Apache is installed and running.</p> <p>Instance ID: <span id="instance-id">Loading...</span></p> </div> </body> </html> EOF
Step 2: Launch the Instance with User Data
Using the AWS Management Console:
  1. Navigate to EC2 → Launch Instance.
  2. Name: UserData-Demo.
  3. AMI: Amazon Linux 2023.
  4. Instance Type: t3.micro.
  5. Under Advanced details, scroll to User data.
  6. Copy and paste the script into the User data field.
  7. Click Launch instance.

Using the AWS CLI:
# Encode the user data script to base64 USER_DATA_BASE64=$(base64 -w0 user-data.sh) # Launch the instance with user data aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t3.micro \ --key-name MyKeyPair \ --subnet-id subnet-08fc749671b2d077c \ --security-group-ids sg-0b0384b66d7d692f9 \ --associate-public-ip-address \ --user-data "$USER_DATA_BASE64" \ --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=UserData-Demo}]'

Step 4: Verify Apache is Running
# Get the public IP INSTANCE_ID=$(aws ec2 describe-instances --filters "Name=tag:Name,Values=UserData-Demo" --query 'Reservations[0].Instances[0].InstanceId' --output text) PUBLIC_IP=$(aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].PublicIpAddress' --output text) echo "Public IP: $PUBLIC_IP" # Test the webpage curl http://$PUBLIC_IP
✅ Verification Checklist
  • □ Instance launched with UserData-Demo name
  • □ Apache installed and running
  • □ Webpage accessible via public IP
  • □ User Data logs available in /var/log/cloud-init-output.log

P4.2 Connect via SSH or EC2 Instance Connect

📖 Theory: Connection Methods
SSH (Secure Shell) is the standard protocol for connecting to Linux instances. EC2 Instance Connect is a browser-based alternative that injects a temporary SSH key for secure access.

🛠️ Step-by-Step Instructions
Method A: Connect via SSH (Linux/macOS)
# Set correct permissions for the private key chmod 400 ~/Downloads/MyKeyPair.pem # Connect to the instance ssh -i ~/Downloads/MyKeyPair.pem ec2-user@<public-ip>

Method B: Connect via SSH (Windows PuTTY)
  1. Convert .pem to .ppk using PuTTYgen.
  2. Open PuTTY, enter ec2-user@<public-ip>.
  3. Under Connection → SSH → Auth, browse to the .ppk file.
  4. Click Open.

Method C: Connect via EC2 Instance Connect
  1. Open the EC2 console.
  2. Select your UserData-Demo instance.
  3. Click Connect.
  4. Select the EC2 Instance Connect tab.
  5. Click Connect.

✅ Verification Checklist
  • □ Successfully connected to the instance
  • □ Prompt shows [ec2-user@ip-... ~]$
  • □ Can run basic commands (e.g., pwd, ls)
🔌 SSH 🌐 Instance Connect 🔑 key pair

P4.3 Query IMDSv2 for Instance Metadata

📖 Theory: What is IMDSv2?
Instance Metadata Service (IMDS) provides instance-specific information to applications running on EC2. IMDSv2 is the latest version, which adds security features to prevent SSRF attacks.

IMDSv2 Security Enhancements:
  • 🔐 Session Tokens: Every request requires a session token (PUT request)
  • ⏱️ TTL: Tokens expire after a configurable time
  • 🚫 Disable v1: You can optionally disable IMDSv1 for enhanced security

IMDSv2 WORKFLOW ┌─────────────────────────────────────────────────────────────────────────────────────┐ │ IMDSv2 WORKFLOW │ ├─────────────────────────────────────────────────────────────────────────────────────┤ │ │ │ Step 1: Request Session Token │ │ ┌─────────────────────────────────────────────────────────────────────────────────┐│ │ │ PUT http://169.254.169.254/latest/api/token ││ │ │ Header: X-aws-ec2-metadata-token-ttl-seconds: 21600 ││ │ │ Response: AAAAAAAABBBBBBBBCCCCCCCCDDDDDDDD ││ │ └─────────────────────────────────────────────────────────────────────────────────┘│ │ │ │ │ ▼ │ │ Step 2: Use Token to Retrieve Metadata │ │ ┌─────────────────────────────────────────────────────────────────────────────────┐│ │ │ GET http://169.254.169.254/latest/meta-data/<path> ││ │ │ Header: X-aws-ec2-metadata-token: AAAAAAAABBBBBBBB... ││ │ │ Response: <metadata-value> ││ │ └─────────────────────────────────────────────────────────────────────────────────┘│ │ │ └─────────────────────────────────────────────────────────────────────────────────────┘
🛠️ Step-by-Step Instructions
Step 1: Get a Session Token
TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600") echo "Token: $TOKEN"

P4.3.1: Retrieve Instance ID
INSTANCE_ID=$(curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id) echo "Instance ID: $INSTANCE_ID"

P4.3.2: Retrieve Public IPv4 Address
PUBLIC_IP=$(curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/public-ipv4) echo "Public IP: $PUBLIC_IP"

P4.3.3: Retrieve Private IPv4 Address
PRIVATE_IP=$(curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/local-ipv4) echo "Private IP: $PRIVATE_IP"

P4.3.4: Retrieve Security Groups
SECURITY_GROUPS=$(curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/security-groups) echo "Security Groups: $SECURITY_GROUPS"

📋 All Metadata in One Command
TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600") curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/
✅ Verification Checklist
  • □ Session token retrieved successfully
  • □ instance-id retrieved
  • □ public-ipv4 retrieved
  • □ local-ipv4 retrieved
  • □ security-groups retrieved

P4.4 Use JQ to Parse JSON

📖 Theory: What is JQ?
jq is a lightweight and flexible command-line JSON processor. It allows you to parse, filter, and extract data from JSON structures, making it invaluable for working with AWS CLI output and instance metadata.

🛠️ Step-by-Step Instructions
Step 1: Install JQ (if not already installed)
# Amazon Linux 2023 sudo dnf install -y jq # Ubuntu/Debian sudo apt install -y jq

Step 2: Retrieve the Instance Identity Document
TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600") curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/dynamic/instance-identity/document | jq '.'

Step 3: Extract Specific Fields with JQ
# Extract just the instance ID curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/dynamic/instance-identity/document | jq '.instanceId' # Extract instance type curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/dynamic/instance-identity/document | jq '.instanceType' # Extract region and availability zone curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/dynamic/instance-identity/document | jq '{region: .region, az: .availabilityZone}'

📋 Other Useful JQ Commands for AWS
# List all instances with name tags aws ec2 describe-instances --query 'Reservations[].Instances[].[InstanceId, Tags[?Key==`Name`].Value | [0], InstanceType, State.Name]' --output table # Count running instances aws ec2 describe-instances --query 'Reservations[].Instances[?State.Name==`running`] | length' # Get public IPs of all running instances aws ec2 describe-instances --query 'Reservations[].Instances[?State.Name==`running`].PublicIpAddress' --output text
✅ Verification Checklist
  • □ jq installed successfully
  • □ Instance identity document retrieved
  • □ Specific fields extracted with jq

P4.5 Stop & Change Instance Type

t3.micro → t3.small
📖 Theory: Changing Instance Type
Changing the instance type allows you to resize your instance to match changing performance requirements. The process requires stopping the instance, changing the type, and then starting it again.

Key Points:
  • EBS-backed instances must be stopped to change instance type
  • Instance store data is lost during stop
  • Public IP changes (unless you have an Elastic IP)
  • EBS volumes remain intact
  • Private IP remains the same

🛠️ Step-by-Step Instructions
Step 1: Get the Instance ID
INSTANCE_ID=$(aws ec2 describe-instances --filters "Name=tag:Name,Values=UserData-Demo" --query 'Reservations[0].Instances[0].InstanceId' --output text) echo "Instance ID: $INSTANCE_ID"

Step 2: Check the Current Instance Type
aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].InstanceType' --output text

Step 3: Stop the Instance
aws ec2 stop-instances --instance-ids $INSTANCE_ID aws ec2 wait instance-stopped --instance-ids $INSTANCE_ID aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].State.Name' --output text

Step 4: Change the Instance Type
aws ec2 modify-instance-attribute \ --instance-id $INSTANCE_ID \ --instance-type "{\"Value\": \"t3.small\"}"

Step 5: Verify the Change
aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].InstanceType' --output text
✅ Expected Output: t3.small
✅ Verification Checklist
  • □ Instance stopped successfully
  • □ Instance type changed to t3.small
  • □ Instance type verified via CLI
🔄 stop → change 📊 t3.micro → t3.small ⚙️ modify-instance-attribute

P4.6 Start & Observe IP Changes

📖 Theory: IP Address Changes on Stop/Start
When you stop and start an EC2 instance:
  • Private IP: Remains the same (the instance retains its ENI)
  • Public IP (non-Elastic): Changes (released on stop, new one assigned on start)
  • Elastic IP: Remains attached (if applicable)

🛠️ Step-by-Step Instructions
Step 1: Record Current Public IP (Before Start)
OLD_PUBLIC_IP=$(aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].PublicIpAddress' --output text) echo "Old Public IP (before start): $OLD_PUBLIC_IP"

Step 2: Start the Instance
aws ec2 start-instances --instance-ids $INSTANCE_ID aws ec2 wait instance-running --instance-ids $INSTANCE_ID aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].State.Name' --output text

Step 3: Record the New Public IP
NEW_PUBLIC_IP=$(aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].PublicIpAddress' --output text) echo "New Public IP (after start): $NEW_PUBLIC_IP"

Step 4: Observe the IP Change
if [[ -n "$OLD_PUBLIC_IP" && "$OLD_PUBLIC_IP" != "null" && "$OLD_PUBLIC_IP" != "$NEW_PUBLIC_IP" ]]; then echo "✅ Public IP has changed: $OLD_PUBLIC_IP → $NEW_PUBLIC_IP" else echo "ℹ️ Public IP may have changed. Check the instance manually." fi

Step 5: Verify the Web Application Still Works
curl http://$NEW_PUBLIC_IP
✅ Verification Checklist
  • □ Instance started successfully
  • □ Public IP changed (recorded both old and new)
  • □ Web application still accessible
  • □ Instance type verified as t3.small
▶️ start 🌐 IP changes ✅ verification

Troubleshooting

IMDSv2 returns 401 Unauthorized
Ensure you are using the session token correctly in the X-aws-ec2-metadata-token header.
jq command not found
Install jq: sudo dnf install -y jq (Amazon Linux) or sudo apt install -y jq (Ubuntu).
Instance stuck in stopping state
Use --force flag: aws ec2 stop-instances --instance-ids $INSTANCE_ID --force.
Unable to connect after start
Check the new public IP address. It changes after a stop/start cycle.
Apache not running after start
Check if User Data completed successfully. View logs in /var/log/cloud-init-output.log.

Key Takeaways

  • User Data is a powerful tool for bootstrapping instances without manual intervention. It runs only on the first boot.

  • IMDSv2 provides secure access to instance metadata. Always use session tokens (PUT request) for enhanced security.

  • JQ is an essential tool for parsing JSON output from AWS CLI commands and instance metadata.

  • Changing instance type requires stopping the instance. This is a three-step process: Stop → Change → Start.

  • Public IP addresses change when you stop and start an instance. Use Elastic IPs for stable public addressing.

  • Private IP addresses remain the same when you stop and start instances, as the ENI is preserved.

  • User Data scripts do not run when you start a stopped instance — they only run on the first boot.

Review Questions

Q1: Why does User Data only run on the first boot?
Answer: User Data is designed to bootstrap an instance — to perform initial setup and configuration that only needs to happen once. It runs on first boot to install software, apply configurations, and prepare the instance. If it ran on every start, it could overwrite changes or cause unintended behavior.
Q2: What security advantage does IMDSv2 provide over IMDSv1?
Answer: IMDSv2 adds a session token requirement. A client must first make a PUT request to obtain a token, which is then included in subsequent requests. This prevents SSRF attacks where an attacker tricks the server into making unauthorized metadata requests. The token also has a TTL, limiting the window of opportunity for attackers.
Q3: Why does the public IP change when you stop and start an instance?
Answer: When you stop an instance, the public IP (non-Elastic) is released back to the AWS pool. When you start the instance again, it is assigned a new public IP from the available pool. This is why you should use Elastic IPs if you need a stable public address.
Q4: What command would you use to change the instance type via the CLI?
Answer: The command is aws ec2 modify-instance-attribute with the --instance-type parameter:
aws ec2 modify-instance-attribute \ --instance-id i-1234567890abcdef0 \ --instance-type "{\"Value\": \"t3.small\"}"
The instance must be stopped first.
Q5: How can you view the User Data logs to debug issues?
Answer: On Amazon Linux, Ubuntu, and other Linux distributions, User Data logs are stored in /var/log/cloud-init-output.log. You can view them with:
sudo cat /var/log/cloud-init-output.log # or sudo tail -f /var/log/cloud-init-output.log
This log captures the output of the User Data script, including any errors.
