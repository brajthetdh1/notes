6.3 Connecting to EC2 Instances

Connecting to your EC2 instances is a fundamental skill for managing your cloud infrastructure. AWS provides several methods to establish secure connections, ranging from traditional SSH clients to modern, browser-based solutions. 6.3.1 SSH (Linux/macOS)

📖 Complete Theory
SSH (Secure Shell) is the standard protocol for securely connecting to Linux instances. For Linux and macOS users, SSH is built directly into the terminal, providing a native, powerful command-line interface for managing EC2 instances.

Prerequisites:
  • EC2 instance must have a public IP address and be reachable from the internet.
  • Security group must allow inbound SSH on port 22 from your IP address.
  • You must have access to the private key (.pem file) used to launch the instance.

The SSH Command Structure:
ssh -i /path/to/your-key-pair.pem username@instance-public-dns-name

SSH Step-by-Step

Step 1: Locate Your Private Key File
Your private key file (.pem) was downloaded when you created your key pair. AWS does not retain a copy.

Step 2: Set the Correct Permissions (Critical)
chmod 400 your-key-pair.pem
⚠️ Without this step, you will receive:
"Permissions are too open" error

Step 3: Find Your Instance's Public DNS
Copy the Public IPv4 DNS or Public IPv4 address from the instance details pane.

Step 4: Connect to the Instance
ssh -i ~/Downloads/my-key-pair.pem ec2-user@ec2-54-123-45-67.compute-1.amazonaws.com

Step 5: Accept the Host Key
The authenticity of host '...' can't be established. Are you sure you want to continue connecting (yes/no/[fingerprint])?
Type yes to continue.

Step 6: Verify the Connection
[ec2-user@ip-10-0-1-123 ~]$
You are now inside your EC2 instance!

6.3.2 PuTTY (Windows)

📖 Complete Theory
PuTTY is a free, open-source SSH client for Windows that provides secure connections to Linux EC2 instances. Unlike Linux/macOS, Windows does not have a native SSH client installed by default.

Key Step: Convert the .pem key file to PuTTY's .ppk format using the PuTTY Key Generator.

🛠️ Step-by-Step Instructions:
  1. Download and Install PuTTY from the official website.
  2. Convert .pem to .ppk:
    • Open puttygen.exe
    • Click Load → select your .pem file
    • Click Save private key → name the file with .ppk extension
  3. Configure PuTTY:
    • Host Name: username@instance-public-dns
    • Port: 22
    • Connection → SSH → Auth → Browse → select .ppk file
  4. Click Open and accept the host key.

6.3.3 EC2 Instance Connect

📖 Complete Theory
EC2 Instance Connect is a browser-based SSH client that allows you to connect directly to your Linux instances from the AWS Management Console. Instead of using a permanent key pair, Instance Connect uses a temporary, single-use SSH key that is automatically injected into the instance's ~/.ssh/authorized_keys file.

Key Benefits:
  • ✅ No Local SSH Client — Connects directly from your browser
  • ✅ No Key Management — AWS handles temporary keys
  • ✅ Simple Access — Just a few clicks from the EC2 console
  • ✅ Secure — Keys are short-lived and session-specific

Prerequisites:
  • Instance must have public IP or be reachable via EC2 Instance Connect Endpoint
  • Security group must allow inbound SSH (port 22) from EC2 Instance Connect service IP ranges
  • Instance must have the EC2 Instance Connect package installed (default on newer Amazon Linux 2 and Ubuntu AMIs)
  • IAM permissions for ec2-instance-connect:SendSSHPublicKey

6.3.4 AWS Systems Manager Session Manager

📖 Complete Theory
AWS Systems Manager Session Manager is a fully managed service that provides secure, browser-based or CLI-based shell access to your EC2 instances. It is the modern, security-first alternative to SSH that does not require a public IP address, an open inbound port, or management of SSH keys.

Key Takeaways

  • Choose the right connection method — SSH for direct CLI access, PuTTY for Windows, Instance Connect for browser convenience, or Session Manager for secure, private instances.

  • For Windows users, PuTTY is a proven SSH client. Remember to use puttygen.exe to convert your .pem file to .ppk.

  • EC2 Instance Connect provides a browser-based SSH experience without the need for a local client or SSH key management.

  • Session Manager is the security-first approach — no public IP, no open ports, no SSH keys, and built-in auditing.

  • VPC Endpoints enable private instances to use Session Manager without public IPs.

  • Always restrict SSH source IP in Security Groups to reduce attack surface.

  • Never share your .pem file — anyone with the key can access your instance.

Review Questions

Q1: What are the key differences between connecting via SSH and Session Manager?
Answer: SSH requires a public IP address, an open inbound port 22, and management of SSH key pairs. Session Manager works without a public IP, requires no open inbound ports, and authenticates via IAM without SSH keys. Session Manager also provides built-in session logging and auditing capabilities.
Q2: Why do you need to set the correct permissions (chmod 400) on a .pem file for SSH?
Answer: SSH requires the private key file to have restricted permissions (read-only for the owner) to prevent unauthorized access. If permissions are too permissive, SSH rejects the key as a security measure to protect the private key from being read by other users.
Q3: What is the purpose of converting a .pem file to .ppk for PuTTY?
Answer: PuTTY uses its own private key format (.ppk) and does not natively support the .pem format. The PuTTY Key Generator (puttygen.exe) is used to convert the .pem key into the .ppk format required by PuTTY.
Q4: How does EC2 Instance Connect handle authentication?
Answer: EC2 Instance Connect uses a temporary, single-use SSH key that is automatically injected into the instance's ~/.ssh/authorized_keys file for the duration of the session. This eliminates the need for users to store permanent SSH keys on their local machine. The service uses IAM to verify permissions and initiate the connection.
Q5: What are the prerequisites for using Session Manager to connect to an EC2 instance in a private subnet?
Answer: The prerequisites are: the SSM Agent must be installed and running on the instance, the instance must have an IAM role with the AmazonSSMManagedInstanceCore policy attached, and the instance must be able to communicate with the Systems Manager service (via VPC endpoints for ssm, ssmmessages, and ec2messages or via a NAT gateway).
