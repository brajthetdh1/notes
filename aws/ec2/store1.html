11.1 Elastic Block Store (EBS)

📖 Complete Theory: Persistent Block Storage for EC2

Amazon Elastic Block Store (Amazon EBS) is a scalable, high-performance block storage service designed specifically for use with Amazon EC2 instances. It provides persistent, durable storage volumes that you can attach to your EC2 instances, functioning like a physical hard drive in the cloud.

What is a Block Storage Device?
In computing, a "block" is a sequence of bytes or bits, usually containing a whole number of records, having a maximum length. Block storage stores data in fixed-size blocks, treating each block as a separate, individual unit. This allows a storage system to handle read and write operations quickly and efficiently, making it ideal for low-latency operations.

EBS Core Concepts

Core Concept: Persistent, Off-Instance Storage
EBS is designed to be persistent storage that exists independently of the lifecycle of an EC2 instance. This is one of its most fundamental and powerful features.

Key Features and Benefits of EBS:
  • 🔒 Data Persistence: Data remains on the volume even if you stop, terminate, or detach it
  • ✅ High Availability: Automatically replicated within Availability Zone
  • 📈 Flexible and Scalable: Volumes from 1 GiB to 64 TiB
  • 🔐 Secure: Supports encryption using AWS KMS
  • 📊 Multiple Volume Types: SSD-backed and HDD-backed options

How EBS Works with EC2:
  1. Creation: Create an EBS volume in a specific Availability Zone
  2. Attachment: Attach the volume to any EC2 instance in the same Availability Zone
  3. Using the Volume: Format with a file system, install applications, store data
  4. Detachment and Reattachment: Move data between instances
  5. Backup: Create point-in-time backups (snapshots) stored in S3

EBS Volume Types

Choosing the Right Storage for Your Workload
Amazon EBS offers a range of volume types, each designed to balance performance, cost, and durability for specific use cases. These volumes fall into two primary categories:
  • SSD-backed volumes: Transactional workloads (databases, boot volumes, virtual desktops)
  • HDD-backed volumes: Throughput-intensive workloads (big data, log processing, data warehousing)

11.1.3 Creating, Attaching, and Detaching Volumes

📖 Complete Theory: Managing EBS Volumes

Amazon EBS volumes are persistent block storage devices that you can attach to EC2 instances. The lifecycle of an EBS volume involves three primary operations: creating a volume, attaching it to an instance, and detaching it when it is no longer needed.

🛠️ Creating an EBS Volume
Critical Prerequisite: A volume must be created in the same Availability Zone as the EC2 instance you plan to attach it to.
# Create an empty gp3 volume of 100 GiB aws ec2 create-volume \ --volume-type gp3 \ --size 100 \ --availability-zone us-east-1a # Create a volume from an existing snapshot aws ec2 create-volume \ --volume-type gp3 \ --snapshot-id snap-0abcdef1234567890 \ --availability-zone us-east-1a

🔗 Attaching a Volume to an Instance
aws ec2 attach-volume \ --volume-id vol-1234567890abcdef0 \ --instance-id i-1234567890abcdef0 \ --device /dev/sdf

💡 Post-Attachment Configuration (Instance-side):
  • Identify the Device: On Nitro instances, EBS volumes appear as NVMe devices (e.g., /dev/nvme1n1)
  • Make the Volume Available: sudo mkfs -t xfs /dev/nvme1n1 (⚠️ destroys existing data)
  • Mount the Volume: sudo mount /dev/nvme1n1 /mnt/data
🔌 Detaching a Volume
🔴 Critical Pre-Detachment Step: Unmounting
Before you can detach a volume from a running instance, you must unmount it from the operating system. Failure to do so can cause data corruption.
# Linux unmount sudo umount -d /dev/sdf # Detach from AWS aws ec2 detach-volume --volume-id vol-1234567890abcdef0

⚠️ Force Detach: The --force option is available as a last resort but can lead to data loss or file system corruption.

⚠️ Root Volume Consideration: The root volume of an instance cannot be detached while the instance is running. You must stop the instance first.

11.1.4 EBS Multi-Attach

io1/io2 Shared Block Storage
📖 Complete Theory: Shared Block Storage for Clustered Applications

Amazon EBS Multi-Attach is a feature that allows you to attach a single Provisioned IOPS SSD (io1 or io2) volume to multiple EC2 instances at the same time. Each attached instance has full read and write permissions to the shared volume.

11.1.5 EBS Encryption

Default Encryption
📖 Complete Theory: Encryption at Rest

EBS encryption is a critical security feature that protects your data at rest. AWS offers two primary mechanisms: per-volume encryption during creation and encryption by default, which is an account-level setting that automatically encrypts all new EBS volumes and snapshots.

🔐 EBS Encryption by Default
Encryption by default is a regional account setting that ensures all newly created EBS volumes and snapshots are automatically encrypted. Accounts created after August 2022 typically have this feature enabled by default.

Key Characteristics:
FeatureDescription
ScopeRegional setting — configured per AWS Region
Encryption MethodUses AWS Key Management Service (KMS)
Default KeyAWS-managed key (alias/aws/ebs) unless a custom key is specified
Existing VolumesUnaffected — only applies to newly created volumes
Performance ImpactMinimal latency impact; same IOPS performance

Commands to Manage Default Encryption:
# Enable encryption by default aws ec2 enable-ebs-encryption-by-default # View the current default KMS key aws ec2 get-ebs-default-kms-key-id # Set a custom KMS key as the default aws ec2 modify-ebs-default-kms-key-id --kms-key-id "arn:aws:kms:us-east-1:123456789012:key/..."
🔑 KMS Key Options:
Key TypeDescriptionUse Case

💡 How to Encrypt an Existing Unencrypted Volume:
  1. Create an encrypted snapshot copy of the volume
  2. Create a new encrypted volume from that snapshot
  3. Replace the original volume with the new encrypted one

⚠️ Important Notes:
  • Existing unencrypted volumes are not automatically encrypted
  • AWS-managed keys (alias/aws/ebs) are free to use
  • Customer-managed keys incur monthly and per-API costs
  • Encryption has minimal performance impact — same IOPS as unencrypted volumes

Amazon EBS is used for persistent, block-level storage for applications that require frequent updates and data persistence, such as the system drive for an EC2 instance or storage for a database application.

11.1.3 Review Questions

Q1: What is the prerequisite for attaching an EBS volume to an EC2 instance regarding the Availability Zone?
The EBS volume must be created in the same Availability Zone as the EC2 instance. EBS volumes cannot be attached to instances in different Availability Zones.
Q2: Why is it critical to unmount the volume before detaching it from a running instance?
Unmounting ensures the operating system has finished all read/write operations and flushed its file system caches. Failing to unmount can lead to data corruption, and the volume can become stuck in a busy state.
Q3: What is the risk of using the --force option when detaching a volume?
The --force option detaches the volume without giving the instance's operating system a chance to flush file system caches or metadata. This can lead to data loss or file system corruption. It should only be used as a last resort on failed instances.
Q4: Can you detach the root EBS volume from a running instance?
No. If an EBS volume is the root device of an instance, you must stop the instance before you can detach it.
Q5: On a Nitro-based EC2 instance, what is the challenge with device names like /dev/sdf?
On Nitro instances, EBS volumes are exposed as NVMe block devices with names like /dev/nvme1n1. The block device driver can assign these names in a different order than specified. For reliable identification, you should use the EBS volume ID.

11.1.4 Review Questions

Q1: What is Amazon EBS Multi-Attach and which volume types support it?
Amazon EBS Multi-Attach enables a single Provisioned IOPS SSD (io1 or io2) volume to be attached to multiple EC2 instances in the same Availability Zone. Each instance has full read and write permissions to the shared volume.
Q2: How many instances can a Multi-Attach volume be attached to?
A Multi-Attach volume can be attached to up to 16 Nitro-based instances that are in the same Availability Zone.
Q3: Why can't you use standard file systems like ext4 or XFS with Multi-Attach?
Standard file systems are not designed for simultaneous access by multiple servers. Using them with Multi-Attach can result in data corruption or data loss. You must use a clustered file system (like GFS2) or implement application-level write coordination.
Q4: What is the difference between io1 and io2 for Multi-Attach?
io2 offers 99.999% durability (100× better than io1's 99.8–99.9%), I/O fencing support via NVMe reservations (not supported on io1), and the ability to enable/disable Multi-Attach after creation. AWS recommends io2 for all new Multi-Attach workloads.

11.1.5 Review Questions

Q1: What is EBS encryption by default, and how does it affect new volumes?
EBS encryption by default is an account-level regional setting that automatically encrypts all newly created EBS volumes and snapshots in that Region. It does not affect existing volumes and ensures that encryption is applied without requiring explicit action during volume creation.
Q2: How does default encryption interact with custom KMS keys?
With default encryption enabled, you can still specify a custom KMS key when creating a volume. If you do not specify a key, the default KMS key is used. You can also change the default KMS key for your account using the modify-ebs-default-kms-key-id command.
Q3: What are the key options for encrypting EBS volumes?
You can use either the AWS-managed key (alias/aws/ebs), a Customer-Managed Key (CMK), or an Organization Shared Key. AWS-managed keys are free, while CMKs incur monthly and per-API costs.
Q4: How can you encrypt an existing unencrypted EBS volume?
To encrypt an existing unencrypted volume, you must create an encrypted snapshot copy of the volume, then create a new encrypted volume from that snapshot. The original volume remains unencrypted and must be replaced manually.
Q5: What is the performance impact of EBS encryption?
Encrypted EBS volumes have the same IOPS performance as unencrypted volumes with minimal impact on latency. The encryption process is handled transparently by the EBS service.

  • EBS provides persistent block storage for EC2 instances, independent of instance lifecycle.
