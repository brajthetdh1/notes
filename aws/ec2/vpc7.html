Q1: What is a VPC and how does it relate to EC2?

📝 Answer:
A Virtual Private Cloud (VPC) is a logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define. It is the fundamental networking container for EC2 instances, providing complete control over your virtual networking environment, including IP address ranges, subnets, route tables, and network gateways.
🔍 Detailed Explanation:

The VPC-EC2 Relationship:
A VPC serves as the network boundary for your EC2 instances. When you launch an EC2 instance, it must be placed into a subnet within a VPC. The VPC provides:
  • Network Isolation: Your EC2 instances run in a private, isolated network segment
  • IP Addressing: The VPC defines the IP address range (CIDR block) from which EC2 instances receive their private IP addresses
  • Connectivity Control: Through route tables and gateways, the VPC controls how EC2 instances communicate
  • Security Boundaries: Security Groups and Network ACLs control traffic to and from EC2 instances

VPC Component & How It Relates to EC2:
VPC ComponentHow It Relates to EC2
SubnetsEC2 instances are launched into specific subnets within the VPC
Route TablesControl how traffic from EC2 instances is routed (e.g., to the internet via IGW)
Security GroupsAct as virtual firewalls at the instance level, controlling inbound/outbound traffic
Internet GatewayEnables EC2 instances in public subnets to communicate with the internet
NAT GatewayEnables EC2 instances in private subnets to initiate outbound internet access

💡 Default VPC: Every AWS account has a default VPC in each Region with a pre-configured setup (public subnets, Internet Gateway, and route table) that allows you to launch EC2 instances immediately without any additional configuration.
❓ Q1 🌐 VPC 🖥️ EC2

Q2: Public IP vs Private IP vs Elastic IP

📝 Answer:
IP TypeScopePersistenceAssignmentUse Case
Private IPInternal to VPCPersists until terminationAssigned from subnet CIDRInternal communication
Public IPInternet-routableReleased on stop/startAssigned from AWS poolTemporary internet access
Elastic IPInternet-routablePersists until releasedAllocated to your accountStatic public endpoint
🔍 Detailed Explanation:

🔒 Private IP
  • Used for communication within your VPC
  • Assigned from subnet's CIDR block
  • Persistent: Remains until termination
  • Not reachable from the internet
  • No additional cost
🌍 Public IP
  • Assigned from Amazon's pool
  • Not associated with your account
  • Ephemeral: Released on stop
  • Changes on start (new IP assigned)
  • Available for IPv4 only
⭐ Elastic IP
  • Static public IPv4 address
  • Allocated to your account
  • Persistent: Survives stop/start
  • Can be reassigned
  • Charges apply

Q3: What is an ENI and why attach multiple ENIs?

📝 Answer:
An Elastic Network Interface (ENI) is a logical virtual network interface that represents a virtual network card. It includes attributes such as private IP addresses, Elastic IPs, security groups, and a MAC address, and can be attached to an EC2 instance.
🔍 Detailed Explanation:

Key ENI Attributes:
AttributeDescription
Primary Private IPv4The main private IP address from the subnet's range
Secondary Private IPv4sAdditional private IP addresses
IPv6 AddressIf the subnet has an IPv6 CIDR
Elastic IPCan be associated with each private IPv4 address
Security GroupsFirewall rules for the interface
MAC AddressA unique hardware identifier

Primary vs. Secondary ENIs:
FeaturePrimary ENISecondary ENIs
AttachmentAuto-attached at launchCreated and attached manually
Detachment❌ Cannot be detached✅ Can be attached/detached on demand
DeletionDeleted with the instancePersists independently
Public IPCan auto-assignCannot auto-assign

Why Attach Multiple ENIs:
Use CaseHow It Works
Management NetworkSeparate public-facing traffic from management/SSH traffic
Network AppliancesNAT servers, firewalls, load balancers with different interfaces
Dual-Homed ApplicationsWeb servers with one interface on web subnet, another on app subnet
Low-Budget HAIf an instance fails, attach its ENI to a standby instance
Multi-VPC ConnectivityAttach an ENI from a different VPC (same AZ)

⚠️ Source/Destination Check: The source/destination check flag is enabled by default. It must be disabled for instances that perform NAT, routing, or firewall services.

💡 ENI Limits: The number of ENIs an instance can have depends on the instance type. Larger instances support more ENIs.

Q4: What are ENA and EFA?

📝 Answer:
ENA (Elastic Network Adapter) and EFA (Elastic Fabric Adapter) are both high-performance network interfaces for EC2 instances. ENA is the standard high-performance network interface for general workloads, while EFA provides OS-bypass capabilities for HPC and ML workloads.
🔍 Detailed Comparison:
FeatureENAEFA
PerformanceUp to 100 GbpsUp to 100 Gbps with OS-bypass
OS-Bypass❌ No✅ Yes
IP Addressing✅ Yes✅ Yes (EFA with ENA) or ❌ No (EFA-only)
Use CasesGeneral-purpose networkingHPC, ML distributed training
LatencyLowUltra-low, consistent
Windows Support✅ Yes❌ No (OS-bypass not supported)
AttachmentHot attach supportedMust be attached to stopped instance

When to Use ENA:
  • General-purpose web servers and application servers
  • Databases and data processing workloads
  • Any workload that needs high network throughput without HPC-specific requirements

When to Use EFA:
  • HPC applications using MPI (Open MPI, Intel MPI)
  • ML distributed training using NCCL
  • Workloads requiring ultra-low, consistent latency
  • Applications that benefit from kernel bypass

EFA Types:
TypeDescriptionIP Assignment
EFA with ENASupports both ENA and EFA✅ Yes
EFA-onlyStandalone EFA device without IP❌ No

⚠️ Important EFA Limitations:
  • OS-bypass is not supported on Windows instances
  • EFA must be attached to a stopped instance
  • EFA OS-bypass traffic is not routable
  • Security group must allow all traffic for the EFA
❓ Q4 ⚡ ENA 🚀 EFA
❓

Q5: Can you move an Elastic IP from one instance to another?

📝 Answer:
Yes, an Elastic IP (EIP) can be moved from one EC2 instance to another. You can disassociate it from one instance and associate it with another instance at any time, either through the AWS Management Console, CLI, or API.
🔍 Detailed Explanation:

How to Move an Elastic IP:
  1. Disassociate the Elastic IP from the current instance
  2. Re-associate the Elastic IP with the new instance (automatically disassociates from old instance)

AWS CLI Commands:
# Method 1: Direct re-association aws ec2 associate-address \ --instance-id i-1234567890abcdef0 \ --allocation-id eipalloc-12345678 # Method 2: Explicit disassociate then reassociate aws ec2 disassociate-address --association-id eipassoc-12345678 aws ec2 associate-address --instance-id i-1234567890abcdef0 --allocation-id eipalloc-12345678

Important Considerations:
ConsiderationDetail
Network TrafficTraffic is automatically redirected without DNS updates
Instance StateCan be running or stopped
ChargesHourly charges apply to EIPs not associated with running instances
LimitEach EIP can be associated with one instance at a time
Primary ENICan associate with the primary ENI (eth0)
Same Region OnlyEIPs are Region-specific

💡 Why Move an Elastic IP?
  • Failover: Quickly redirect traffic to a standby instance during failures
  • Zero-Downtime Deployments: Move traffic to a new instance during updates
  • Instance Replacement: Maintain the same public endpoint when replacing instances
❓ Q5 ⭐ Elastic IP 🔄 move

Q6: What is a Bastion Host and why do you need one?

📝 Answer:
A Bastion Host (also called a jump host or jump server) is a dedicated EC2 instance that serves as a secure, controlled entry point for accessing other EC2 instances in private subnets. It acts as a gateway between the internet and your private instances, allowing SSH/RDP access without exposing private instances directly to the internet.
🔍 Detailed Explanation:

Why You Need a Bastion Host:
ReasonDescription
SecurityPrivate instances should not have public IPs; bastion is the only instance with public access
Audit TrailAll access to private instances can be logged and monitored
Controlled AccessSecurity groups can be tightly restricted (e.g., only specific IP ranges)
Centralized ManagementUse the bastion host for jump access to multiple instances

Q7: What is VPC Peering?

📝 Answer:
VPC Peering is a networking connection between two VPCs that enables you to route traffic between them using private IPv4 or IPv6 addresses. Instances in either VPC can communicate as if they are within the same network, making it a powerful tool for connecting EC2 instances across VPCs.
🔍 Detailed Explanation:

How VPC Peering Works:
A VPC peering connection is a one-to-one relationship between two VPCs. It allows traffic to flow between the VPCs using the AWS private network, without traversing the public internet.

FeatureDescription
TrafficUses private IP addresses (not public)
NetworkStays on the AWS global backbone (private, secure)
Transitivity❌ NOT transitive (VPC A peered with B and C does NOT allow B ↔ C)
ScalabilityOne VPC can peer with up to 125 VPCs
Cross-Region✅ Supported via Inter-Region VPC Peering
Overlapping CIDRs❌ Not allowed — CIDR blocks must not overlap

AWS CLI Example:
# Create VPC peering connection aws ec2 create-vpc-peering-connection \ --vpc-id vpc-12345678 \ --peer-vpc-id vpc-87654321 \ --peer-region us-west-2 # Accept the peering connection aws ec2 accept-vpc-peering-connection \ --vpc-peering-connection-id pcx-12345678 # Add route in VPC A to reach VPC B aws ec2 create-route \ --route-table-id rtb-12345678 \ --destination-cidr-block 10.1.0.0/16 \ --vpc-peering-connection-id pcx-12345678 # Add route in VPC B to reach VPC A aws ec2 create-route \ --route-table-id rtb-87654321 \ --destination-cidr-block 10.0.0.0/16 \ --vpc-peering-connection-id pcx-12345678

⚠️ Key Considerations:
  • No Overlapping CIDRs: VPCs with overlapping IP ranges cannot be peered
  • Non-Transitive: Peering is not transitive
  • Security Groups: Can reference the peer VPC as a source/destination
  • DNS Resolution: DNS hostnames resolve to private IPs only if DNS resolution is enabled
  • Cost: Charges apply for data transfer across peering connections

Key Takeaways

  • VPC is the fundamental networking container for EC2 instances, providing network isolation, IP addressing, connectivity control, and security boundaries.

  • Private IPs are persistent and used for internal communication; Public IPs are ephemeral and change on stop/start; Elastic IPs are static and persist until released.

  • ENIs decouple networking from compute — the primary ENI cannot be detached, but secondary ENIs can be attached/detached on demand.

  • ENA provides up to 100 Gbps for general workloads; EFA provides OS-bypass for HPC and ML workloads.

  • Elastic IPs can be moved between instances for failover and zero-downtime deployments.

  • Bastion Hosts provide a secure entry point to private instances — use Session Manager for better security.

  • VPC Peering connects two VPCs using private IPs — it is not transitive and requires non-overlapping CIDRs.

  • Source/destination check must be disabled for NAT, routing, and firewall instances.

  • ENI limits depend on instance type — larger instances support more ENIs.

  • EFA must be attached to a stopped instance and does not support Windows OS-bypass.
