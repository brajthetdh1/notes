7.Q1: Four Main Pricing Models

Q: What are the four main EC2 pricing models?

Answer: Amazon EC2 offers four main pricing models:

💰 On-Demand
Pay per second, no commitment
Short-term, burst workloads
📊 RIs
Up to 75% discount
1-3 year commitment
⚡ Spot
Up to 90% discount
Interruptible, fault-tolerant
📊 Savings Plans
Up to 72% discount
Hourly spend commitment

📌 1. On-Demand: Pay for compute capacity by the second (minimum 60 seconds) with no long-term commitments. Best for development, testing, short-term, and unpredictable workloads.
📌 2. Reserved Instances: A billing discount applied to On-Demand instances that match specific attributes in exchange for a 1- or 3-year commitment. Types: Standard (up to 75%) and Convertible (up to 66%).
📌 3. Spot Instances: Spare EC2 capacity offered at up to 90% discount. AWS can reclaim with a 2-minute notice. Best for fault-tolerant, stateless, and flexible workloads.
📌 4. Savings Plans: Flexible pricing model where you commit to a consistent hourly spend ($/hour) for 1- or 3-year terms. Types: Compute SP (66%), EC2 Instance SP (72%), Database SP (35%), SageMaker SP (64%).
💰 models 📊 On-Demand ⚡ Spot
⚖️

7.Q3: Standard vs Convertible RI

Q: What is the difference between Standard and Convertible Reserved Instances?

Answer: Standard RIs offer the highest discount (up to 75%) but lock you into a specific configuration. Convertible RIs offer a lower discount (up to 66%) but allow exchanges.

FeatureStandard RIConvertible RI
Max DiscountUp to 75%Up to 66%
Instance Family❌ Fixed✅ Can exchange
Region❌ Fixed❌ Fixed
OS❌ Fixed✅ Can exchange
Tenancy❌ Fixed✅ Can exchange
Resell on Marketplace✅ Yes❌ No

🔄 Exchange Rules
• Equal or greater value
• Region fixed
• Term alignment (longest)
• True-Up cost if higher value
• Retains expiration date
🎯 When to Choose
Standard: Stable workloads, max discount
Convertible: Evolving architectures, flexibility needed

7.Q4: Spot Instances

Q: What are Spot Instances and why are they cheaper?

Answer: Spot Instances are EC2 instances that use spare, unused compute capacity in the AWS cloud. They are offered at a steep discount (up to 90% off On-Demand) because AWS can reclaim the capacity when needed elsewhere.

💡 Why Spot Instances Are Cheaper:
  • Spare Capacity: AWS sells unused capacity
  • No Capacity Guarantee: AWS can reclaim when demand increases
  • Flexibility for AWS: Manage capacity efficiently with interruptible workloads

7.Q5: Spot Interruption Notice

Q: Can Spot Instances be terminated at any time? How much notice do you get?

Answer: Yes, Spot Instances can be interrupted (terminated, stopped, or hibernated) by AWS at any time. AWS provides a two-minute interruption notice via IMDSv2 and EventBridge, though this is on a "best effort" basis.

The Two-Minute Warning:
# IMDSv2 format {"action": "terminate", "time": "2026-08-02T10:30:00Z"}

⚠️ Important Notes:
  • Best Effort: Instance could be interrupted before the notice is available
  • Hibernation: No two-minute warning (process begins immediately)
  • Billing: If AWS interrupts, you are NOT charged for any partial hour of usage

ScenarioBilling
You terminateYou pay for any partial hour used
AWS interruptsNOT charged for partial hour
⏱️ 2-minute warning ⚠️ best effort 💰 no partial charges

7.Q6: Spot Fleet

Q: What is a Spot Fleet and how does it improve availability?

Answer: A Spot Fleet is a collection of Spot Instances (and optionally On-Demand Instances) that AWS launches based on criteria you specify. It improves availability by diversifying across multiple instance types and Availability Zones.

📊 Key Features
• Multiple instance types
• Multi-AZ distribution
• Mixed purchasing options
• Automated replacement
• Capacity Rebalancing
⚠️ Deprecation Notice
RequestSpotFleet is a legacy API with no planned investment.

Use instead:
• EC2 Fleet
• Auto Scaling Groups with Mixed Instances Policy

💡 How Spot Fleet Improves Availability:
  • Diversification: If one instance type or AZ has low capacity, others can be used
  • Automatic Replacement: When interrupted, fleet launches a replacement
  • Capacity Rebalancing: Proactively replaces instances at risk
  • On-Demand Baseline: Guarantees a minimum number of On-Demand instances
🚀 Spot Fleet 📊 mixed types 🔄 Capacity Rebalancing

7.Q7: Dedicated Hosts

Q: What are Dedicated Hosts and when would you use them?

Answer: Dedicated Hosts are physical EC2 servers fully dedicated to your use. You get the entire physical server with full control over instance placement, visibility into sockets and cores, and comprehensive BYOL support — billed per host.

FeatureDescription
Physical ServerEntire server dedicated to your account
Host VisibilitySee sockets, physical cores, and host ID
Placement ControlFull control via host affinity and auto-placement
BYOL SupportComprehensive — Windows Server, SQL Server, RHEL, SUSE
BillingPer host (regardless of number of instances)

🎯 When to Use Dedicated Hosts:
  • BYOL: Per-socket or per-core licenses (Windows Server, SQL Server)
  • License Audits: Need visibility into sockets and cores
  • Regulated Workloads: Full physical isolation required
  • SPLA Licensing: Service Provider License Agreement requires dedicated infrastructure

⚠️ Restrictions:
  • RHEL, SUSE Linux, SQL Server AMIs from AWS cannot be used
  • Auto Scaling only with launch template specifying host resource group
  • No RDS, No Free Tier, No Placement Groups
🏛️ Dedicated Host 🔑 BYOL 📊 per-host
💰

Answer: You can save up to 72% on EC2 costs by using EC2 Instance Savings Plans or Standard Reserved Instances. Both require a 1- or 3-year commitment.
