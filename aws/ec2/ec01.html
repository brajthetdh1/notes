Introduction

The Genesis of Cloud Computing
Before diving into EC2, it's essential to understand the paradigm shift that cloud computing introduced. In the traditional IT model, organizations had to:
  • Predict their computing needs months in advance
  • Procure expensive physical servers (often over-provisioning to handle peak loads)
  • Wait weeks or months for hardware delivery and setup
  • Manage the entire infrastructure lifecycle (power, cooling, maintenance, upgrades)
  • Accept high idle capacity (typically 70-80% of server resources went unused)

🚀 2006 Amazon EC2 was launched in August 2006 as AWS's first compute service, fundamentally changing this model. It introduced the concept of "compute as a utility" — similar to how you pay for electricity or water, you now pay for computing power on-demand, with no upfront investment, and scale according to your actual needs.

  • Ecosystem: Seamless integration with 200+ AWS services
  • Economies of Scale: AWS passes on savings from massive infrastructure investments to customers

Core Definition

B. "Elastic"
Elasticity is the most revolutionary aspect of EC2. It refers to the system's ability to:

1. Scale Out (Horizontal Scaling)
  • Add more instances when demand increases
  • Example: Your e-commerce site experiences 10x traffic during Black Friday — EC2 automatically launches 10x more instances to handle the load
2. Scale In (Horizontal Scaling)
  • Remove instances when demand decreases
  • Example: After the sale ends, EC2 gracefully terminates extra instances to save costs
3. Scale Up (Vertical Scaling)
  • Move to a larger instance type with more CPU and memory
  • Example: Your database instance needs more RAM — you change the type from r5.large to r5.xlarge
4. Scale Down (Vertical Scaling)
  • Move to a smaller instance type when requirements reduce

5. Automatic vs. Manual Elasticity
TypeDescriptionUse Case
Manual ScalingYou manually adjust the number or size of instancesPredictable workloads, dev/test
Scheduled ScalingScaling happens at predefined timesBatch processing at midnight
Dynamic ScalingScaling happens automatically based on CloudWatch metricsWeb apps with variable traffic
Predictive ScalingML predicts future demand and scales proactivelyWorkloads with weekly/seasonal patterns
The Elasticity Metaphor:
Think of a rubber band:
  • When you pull it (increased demand), it stretches (scales out)
  • When you release it (decreased demand), it returns to its original size (scales in)
  • The band never breaks because it's designed for flexibility

Core Definition

C. "Compute"
Compute represents the processing power — the ability to execute instructions, run applications, process data, and perform calculations. In EC2, compute encompasses:

1. Central Processing Unit (CPU)
  • The brain of the instance
  • Measured in vCPUs (virtual CPUs)
  • Different processor architectures:
    • x86_64: Intel Xeon and AMD EPYC (compatible with most software)
    • ARM (Graviton): AWS's custom silicon — better price/performance (up to 40% cheaper)
    • Apple Mac: For iOS/macOS development on mac1.metal
2. Memory (RAM)
  • Temporary storage for running processes
  • Measured in GiB (Gibibytes)
  • Ranges from 0.5 GiB to 24 TiB (24,576 GiB)
3. Networking
  • Data transfer between instances and the internet
  • Measured in Gbps (Gigabits per second)
  • Enhanced networking with ENA (Elastic Network Adapter)
  • Specialized HPC networking with EFA (Elastic Fabric Adapter)
4. Storage
  • EBS (Elastic Block Store) for persistent data
  • Instance Store for temporary, high-performance storage
5. GPU/Accelerators
  • Specialized compute for ML, video rendering, and scientific simulations
  • NVIDIA GPUs (A100, H100, L4, L40S)
  • AWS Inferentia (custom ML inference chips)
  • AWS Trainium (custom ML training chips)

Core Definition

D. "Cloud"
Cloud signifies the delivery model — resources are provided over the internet as a service. This includes:

1. Location Independence
  • You don't need to know which physical server your instance runs on
  • You select a Region (e.g., us-east-1) and Availability Zone (e.g., us-east-1a)
  • AWS manages the underlying hardware
2. Abstraction of Complexity
  • You don't manage physical servers, power, cooling, or networking cables
  • The hypervisor (Nitro) abstracts the hardware
  • You interact with EC2 through API calls, CLI, or Console
3. Ubiquitous Access
  • Access your instances from anywhere with an internet connection
  • HTTPS API endpoints available globally
4. Multi-Tenancy
  • Multiple customers share the same physical hardware
  • Complete isolation between instances (security)
5. Self-Service
  • Launch, manage, and terminate instances without human intervention
  • Programmatic control via SDKs and APIs
6. Measured Service
  • Pay exactly for what you consume:
    • Per second billing (minimum 60 seconds)
    • Per GB for data transfer
    • Per IOPS for provisioned storage

The Nitro System

The Engine Behind EC2
The AWS Nitro System is the underlying hardware and software platform that powers all modern EC2 instances. It represents a complete re-architecture of virtualization.

Why Nitro Exists:
Traditional hypervisors (Xen, KVM) share a physical server's resources in software, causing overhead. AWS designed Nitro to offload virtualization management to dedicated hardware, freeing up the CPU.

Components of the Nitro System:

The Virtualization Stack

How EC2 Works
Simplified Architecture Flow: +-----------------------+ | YOU (Customer) | | AWS Management | | Console / CLI / SDK | +-----------+-----------+ | v +-----------+-----------+ | EC2 API Service | | (ec2.amazonaws.com) | | - Authentication | | - Authorization | | - Request Routing | +-----------+-----------+ | v +-----------+-----------+ | Placement Service | | - Selects Region | | - Selects AZ | | - Checks Capacity | +-----------+-----------+ | v +-----------+-----------+ | Hypervisor (Nitro) | | - Allocates vCPU | | - Allocates Memory | | - Attaches Storage | +-----------+-----------+ | v +-----------+-----------+ | EC2 Instance | | (Running on Physical | | Host in AWS DC) | +-----------+-----------+
Step-by-Step Launch Process:
  1. Customer Request: Select AMI, Instance Type, networking, storage, Key Pair
  2. Authentication & Authorization: AWS validates IAM credentials and permissions
  3. Resource Allocation: Placement Service finds a physical host with capacity
  4. Virtualization: Nitro Hypervisor creates a VM, attaches volumes, configures networking
  5. Instance Boot: AMI boot volume is mounted, OS starts (1-5 minutes)
  6. Running State: Instance transitions to "running", CloudWatch collects metrics
  7. Billing Begins: Per second billing (minimum 60 seconds)

Security

The Shared Responsibility Model
EC2 security follows the Shared Responsibility Model, which clearly defines what AWS secures and what you secure.
SHARED RESPONSIBILITY MODEL +-----------------------------------------+ | CUSTOMER RESPONSIBILITY | | (Security IN the Cloud) | +-----------------------------------------+ | * Guest OS (patching, updates) | | * Applications and software | | * Data encryption (client-side) | | * Security Groups (firewall rules) | | * NACLs (subnet-level firewall) | | * IAM (users, groups, policies) | | * Key Pairs (SSH keys, certificates) | | * AMI management (custom images) | | * Application-level logging & auditing | +-----------------------------------------+ | | (Boundary) v +-----------------------------------------+ | AWS RESPONSIBILITY | | (Security OF the Cloud) | +-----------------------------------------+ | * Physical data centers | | * Hardware (servers, networking) | | * Hypervisor (Nitro) | | * EC2 API infrastructure | | * Global network security | | * Physical security (guards, cameras) | | * Compliance certifications | | * Environmental (power, cooling) | | * DDoS protection (AWS Shield) | | * Supply chain security | +-----------------------------------------+

Review Questions

Q1 – Q5
Q1: What does "Elastic" mean in EC2?
Answer: "Elastic" refers to the system's ability to dynamically scale compute resources up or down based on real-time demand. This includes horizontal scaling (adding/removing instances), vertical scaling (changing instance sizes), automatic scaling (using Auto Scaling Groups and CloudWatch), and scheduled scaling (time-based adjustments). The elasticity ensures you only pay for what you actually use, leading to significant cost savings.
Q2: What is the Nitro System and why is it important?
Answer: The AWS Nitro System is the hardware and software platform that powers all modern EC2 instances. It includes:
  • Nitro Hypervisor: Minimal virtualization overhead (<1% CPU)
  • Nitro Cards: Dedicated hardware for networking, storage, and security
  • Nitro Security Chip: Hardware-rooted security
  • Nitro Enclaves: Secure isolated compute environments
Importance: Near-bare-metal performance, enhanced security, high-speed networking (up to 200 Gbps), low latency storage, and support for future innovations (Graviton, AI/ML acceleration).
Q3: How is EC2 different from AWS Lambda?
Answer:
AspectEC2AWS Lambda
Compute ModelVirtual Server (IaaS)Serverless Function (FaaS)
ControlFull control over OS, networking, softwareLimited to code and runtime
StateStateful (can maintain persistent state)Stateless (ephemeral)
DurationRuns indefinitely (24/7)Maximum 15 minutes
PricingPer second + storage + data transferPer request + compute time (milliseconds)
Cold StartNo cold start100-300ms cold start latency
Use CaseLong-running apps, databases, batch jobsEvent-driven, microservices, APIs
When to choose EC2: Long-running applications, complex configurations, legacy software, regulatory compliance, custom OS.
When to choose Lambda: Event-driven workloads, APIs, serverless microservices, processing S3 events.
Q4: What is the Shared Responsibility Model for EC2?
Answer: The Shared Responsibility Model divides security responsibilities:
  • AWS: Physical security, hypervisor security, EC2 API infrastructure
  • Customer: Guest OS (patching, updates), applications, data encryption, Security Groups, IAM, Key Pairs, AMI management
Key Takeaway: AWS secures the cloud, but you are responsible for security in the cloud.
Q5: What are the different EC2 pricing models?
Answer: EC2 offers five primary pricing models:
  • On-Demand: Pay per second, no commitment (0% savings) — for unpredictable workloads
  • Reserved (RI): 1-3 year commitment (up to 72% savings) — for steady-state workloads
  • Savings Plans: Flexible compute commitment (up to 72% savings) — for consistent usage
  • Spot: Bid on spare capacity (up to 90% savings) — for fault-tolerant, batch jobs
  • Dedicated Hosts: Physical server dedicated to you (varies) — for BYOL, compliance

Review Questions

Q6 – Q10
Q6: How does EC2 provide high availability?
Answer: EC2 enables high availability through:
  • Multiple Availability Zones (AZs): Deploy across 3+ AZs per region
  • Auto Scaling Groups: Maintains desired instance count, replaces failed instances
  • Elastic Load Balancing (ELB): Distributes traffic across healthy instances
  • CloudWatch: Monitors instance health, triggers auto-recovery
  • EBS Snapshots: Point-in-time backups that can be restored in other AZs
  • Multi-Region Deployment: Global applications with Route 53 routing
Q7: What is the difference between stopping and terminating an EC2 instance?
Answer:
AspectStopTerminate
StateSTOPPED (still exists)TERMINATED (deleted)
EBS Root VolumePreservedDeleted (unless specified)
Instance IDPreservedDeleted
Private IPPreserved (in same VPC)Released
Public IPReleased (new IP on start)Released
Elastic IPRemains attachedRemains attached
Instance Store DataLostLost
BillingStops (no compute cost)Stops (permanently)
Can you start again?Yes (restart with same ID)No (must launch new instance)
Use Stop when: You need to save costs but keep the instance for future use, or you need to change the instance type.
Use Terminate when: You no longer need the instance and want to permanently delete it.
Q8: What is an AMI and how is it related to EC2?
Answer: AMI (Amazon Machine Image) is a template that contains the operating system, application server, and applications required to launch an EC2 instance.
  • Components: Root Volume, Block Device Mapping, Permissions
  • Types: Quick Start (AWS-provided), AWS Marketplace (third-party), Community (public), Custom (your own)
  • Relationship: Instances are launched from an AMI; instances can be converted to an AMI after customization
Analogy: An AMI is a blueprint; an instance is a running copy.
Q9: How can EC2 instances communicate with each other?
Answer: EC2 instances communicate using:
  • VPC Network: Private IPs within the same VPC
  • Security Groups: Reference each other via Security Group IDs
  • Load Balancers: ALB/NLB routes traffic between services
  • Elastic/Public IPs: Over the internet via TLS/HTTPS
  • VPC Peering / Transit Gateway: Connect VPCs across regions
  • Messaging Services: SQS, SNS, EventBridge for decoupled communication
Q10: What happens when you change the instance type of a running EC2 instance?
Answer:
  • Process: Stop → Change type → Start (cannot change while running)
  • Public IP: Changes (unless you have an Elastic IP)
  • Private IP: Remains the same (within VPC)
  • EBS Volumes: Preserved (data intact)
  • Instance Store: Data is lost (if any)
  • Instance ID: Remains the same
  • Limitations: Can only change within the same generation; cannot change architecture (x86 → ARM)
Best Practice: Always back up your data before changing instance type.

Practical Exercise

Launch Your First EC2 Instance
Objective: Launch a t3.micro instance, connect to it, and verify the basic configuration.

Steps:
  1. Access the EC2 Dashboard: AWS Console → Services → EC2
  2. Click "Launch Instance": Name it My-First-EC2
  3. Choose an AMI: Amazon Linux 2023 AMI (Free Tier Eligible)
  4. Choose Instance Type: t3.micro (Free Tier Eligible)
  5. Create or Select a Key Pair: ec2-demo-key (save the .pem file securely)
  6. Configure Networking: VPC: default, Subnet: default, Auto-assign public IP: Enabled
  7. Configure Storage: Root volume: 20GB gp3 (Free Tier: 30GB max)
  8. Configure Security Group: Allow SSH (port 22) from your IP, Allow HTTP (port 80) from anywhere
  9. Add User Data (Optional):
    #!/bin/bash dnf update -y dnf install -y httpd systemctl start httpd systemctl enable httpd echo "Hello from EC2!" > /var/www/html/index.html
  10. Launch the Instance: Review all settings and click "Launch Instance"
  11. Connect to the Instance:
    # For Linux/macOS: chmod 400 ec2-demo-key.pem ssh -i ec2-demo-key.pem ec2-user@<public-ip> # For Windows: Use PuTTY (convert .pem to .ppk)
  12. Verify the Instance:
    # Check OS version cat /etc/os-release # Check CPU info cat /proc/cpuinfo # Check memory free -m # Check disk df -h # Check if HTTP server is running curl http://localhost
  13. Terminate the Instance: EC2 Dashboard → Instances → Select → Instance State → Terminate

✅ Lab Verification Checklist:
  • □ Instance launched successfully (state: running)
  • □ Public IP address assigned
  • □ SSH connection successful
  • □ HTTP server accessible (if User Data used)
  • □ Instance metadata accessible (curl http://169.254.169.254/latest/meta-data/)
  • □ Instance terminated cleanly

Key Takeaways

  • EC2 is a virtual server in the cloud providing secure, resizable compute capacity.
  • Elasticity is the defining feature — automatically scale up/down based on demand.
  • The Nitro System provides near-bare-metal performance with hardware-level security.
  • Pricing models offer flexibility: On-Demand, Reserved, Spot, Savings Plans, and Dedicated Hosts.
  • Security follows the Shared Responsibility Model — AWS secures the cloud, you secure your configuration.
  • Instance types are categorized by workload: General, Compute, Memory, Storage, GPU, and specialized families.
  • High availability is achieved through multi-AZ deployments, Auto Scaling, and Load Balancing.
  • Storage options include EBS (persistent), Instance Store (ephemeral), and EFS (shared).
  • Networking is managed via VPC, Security Groups, NACLs, and Elastic IPs.
  • Automation is key — use User Data, AMIs, and Infrastructure as Code (CloudFormation/Terraform).
