3.2 AWS Identity and Access Management (IAM)

3.2.1 What is IAM?
AWS Identity and Access Management (IAM) is a foundational, no-cost AWS service that enables you to securely control access to your AWS resources. It serves as the gatekeeper for your AWS environment, providing the infrastructure necessary to manage authentication (who can sign in) and authorization (what permissions they have).

At its core, IAM acts as a comprehensive security hub, providing centralized control over user identities, groups, roles, and permissions across your entire AWS account. This service addresses one of the fundamental challenges in cloud computing: ensuring that the right individuals and applications have precisely the access they need to perform their tasks, and nothing more.

3.2.2 Understanding the Core IAM Entities

IAM is built around four principal entities that work together to define and enforce access control:

👤 IAM Users
Represents a specific person or application with permanent, long-term credentials (password or access keys). The Root User has complete access to all AWS services.
👥 IAM Groups
Collections of IAM users. Attach permissions to a group, and all users inherit those permissions. Simplifies management at scale.
🎭 IAM Roles
Identities that provide temporary credentials instead of long-term credentials. Can be assumed by AWS services (like EC2) or federated users.
📜 IAM Policies
JSON documents that define permissions. Specify what actions are allowed or denied on which resources. Attached to users, groups, or roles.

📌 Key Insight: AWS provides AWS managed policies for common job functions, and you can also create your own customer managed policies to implement the principle of least privilege.

3.2.3 The IAM Security Model

Authentication and Authorization
IAM operates on two core principles that work together to secure your AWS environment.

🔑 Authentication
Validates a user's identity. When you sign in with your username and password, or when an application presents its credentials, IAM checks these credentials against its database.
💡 Best Practice: AWS strongly recommends using Multi-Factor Authentication (MFA) for an extra layer of security.
📋 Authorization
Determines what an authenticated user is allowed to do. AWS uses an explicit deny, implicit deny model.
Model:
  • Default Deny: Users have no permissions by default
  • Explicit Allow: Permissions must be explicitly granted
  • Explicit Deny: Overrides any allow

Example: EC2 Instance Accessing S3 via IAM Role:
1. Administrator creates a role with necessary permissions and a trust policy allowing EC2 to assume it 2. EC2 instance is launched with the role attached 3. Application retrieves temporary credentials from instance metadata 4. Application makes authorized API requests to S3 using these credentials

3.2.4 IAM Roles and EC2

Using IAM roles is the secure way to grant permissions to applications running on EC2 instances. Instead of embedding long-term credentials (like access keys) into your application code or the instance, you use an IAM role to provide temporary credentials that are automatically rotated.

🔐 How It Works:
  1. Launch an EC2 instance with an IAM role attached
  2. AWS creates an instance profile that contains the role
  3. Applications running on the instance retrieve temporary credentials from the EC2 instance metadata service (IMDS)
  4. Applications make authenticated AWS API calls using these credentials

⚠️ Security Risk Avoided: Using IAM roles eliminates the security risk of managing long-term access keys on instances. It also removes the operational burden of credential distribution and rotation.

3.2.5 Best Practices for IAM Security

🔐 Secure Your Root User
The root user should only be used for account setup and tasks that specifically require root permissions.
📉 Implement Least Privilege
Granting only the permissions required to perform a task — the principle of least privilege.
👥 Use Groups for Permissions
Assign permissions to groups rather than individual users for scalable management.
🔑 Enable MFA
Multi-Factor Authentication adds an extra security layer for privileged users.
🎭 Use IAM Roles for EC2
Use IAM roles instead of storing access keys on EC2 instances.
🔍 Regularly Review Permissions
Remove unused credentials and review policies regularly.

Review Questions

Q1: What are the four main entities in IAM?
Answer: The four main entities are:
  • IAM Users — specific people or applications with long-term credentials
  • IAM Groups — collections of users for simplified permission management
  • IAM Roles — identities with temporary credentials that can be assumed by services or users
  • IAM Policies — documents that define permissions
Q2: Why should you use IAM Roles for EC2 instances instead of embedding access keys?
Answer: IAM Roles provide temporary credentials that are automatically rotated, eliminating the security risk of managing long-term access keys on instances. This also removes the operational burden of credential distribution and rotation.
Q3: What is the difference between authentication and authorization in IAM?
Answer: Authentication validates user identity through credentials (like username/password), while authorization determines what permissions an authenticated user has to access resources.
Q4: What is the principle of least privilege and why is it important?
Answer: The principle of least privilege means granting only the minimum permissions necessary to perform a task. This is crucial for security because it limits potential damage from compromised credentials, insider threats, or misconfigurations.
Q5: What is the difference between an IAM group and an IAM role?
Answer: An IAM group is a collection of IAM users with permanent permissions. An IAM role provides temporary credentials for AWS services or federated users. Groups are for human users, while roles are for services and temporary access.
