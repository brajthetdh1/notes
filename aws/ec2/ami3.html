4.3 Finding and Selecting an AMI

Finding the right AMI is a foundational skill in AWS, as the AMI determines the operating system, architecture, software, and configuration of every EC2 instance you launch. This section guides you through the process, from understanding key selection criteria to mastering the tools and methods available.

🎯

Before You Begin: Key Selection Criteria

Before you start searching, define your requirements based on the instance you plan to launch. Consider the following characteristics:

🌍 AWS Region
AMI IDs are unique to each Region. Find your AMI in the same Region where you plan to launch.
💻 Operating System
Linux (Amazon Linux, Ubuntu, RHEL), Windows Server, or macOS.
🏗️ Architecture
64-bit (x86_64), 64-bit ARM (arm64), or 32-bit (i386). Must match instance type.
💾 Root Volume Type
EBS-backed (persistent) vs. Instance Store-backed (ephemeral). EBS-backed is recommended.
👤 Provider
Amazon Web Services (AWS), AWS Marketplace vendors, Community, or your own Custom AMIs.
📦 Additional Software
Pre-installed software like SQL Server, application stacks, or licensed tools.

Finding an AMI in the AWS Management Console

The EC2 console offers two primary methods for discovering AMIs.

Method 1: The Launch Instance Wizard (Quick Start)
The fastest way to find a common AMI is during the Launch Instance wizard.
  1. Open the Amazon EC2 console at https://console.aws.amazon.com/ec2/.
  2. From the navigation bar, select the Region where you want to launch your instance.
  3. Click Launch Instance.
  4. In the Application and OS Images section, the Quick Start tab lists popular AMIs (Amazon Linux, Ubuntu, Windows Server).
💡 Pro Tip: Select the Free tier only checkbox to filter for AMIs eligible for the AWS Free Tier.

Method 2: The AMI Page (Search and Filter)
For more advanced discovery, use the AMI page.
  • From the EC2 console navigation pane, choose AMI.
  • Use the Public images filter to start searching among publicly available AMIs.
  • Use the search bar to apply specific filters:
    • Owner alias = amazon — AWS-provided AMIs
    • Platform = windows — Windows Server AMIs
    • Root device type = ebs — EBS-backed AMIs
  • Click the Show/Hide Columns (gear) icon to customize the table view.
  • Select an AMI to view its full details in the Details tab.

Finding an AMI with the AWS CLI

The AWS CLI is essential for automation. The primary command to use is describe-images.

Basic Command Syntax:
aws ec2 describe-images --owners [owner-id] --filters [filters] --query [query]

Example 1: Find AWS-Owned AMIs
aws ec2 describe-images --owners amazon

Example 2: Find EBS-Backed AMIs with a Specific OS
aws ec2 describe-images --owners amazon --filters "Name=platform,Values=windows" "Name=root-device-type,Values=ebs" --query 'Images[*].[ImageId,Name,CreationDate]' --output table

Example 3: Find the Latest Amazon Linux 2 AMI
aws ec2 describe-images --owners amazon --filters 'Name=name,Values=amzn2-ami-hvm-2.0.????????.?-x86_64-gp2' 'Name=state,Values=available' --query 'reverse(sort_by(Images, &CreationDate))[:1].ImageId' --output text

Example 4: Find the Latest Ubuntu 24.04 LTS AMI
aws ec2 describe-images --owners 099720109477 --filters 'Name=name,Values=ubuntu/images/hvm-ssd-gp3/ubuntu-noble-24.04-amd64-server-*' --query 'Images | sort_by(@, &CreationDate) | [-1].ImageId' --output text

Using SSM Parameter Store (Canonical/Ubuntu):
aws ssm get-parameters --names /aws/service/canonical/ubuntu/server/24.04/stable/current/amd64/hvm/ebs-gp3/ami-id --query 'Parameters[0].Value' --output text

Special Topics in AMI Selection

Launch Permissions & Allowed AMIs
AMI availability is controlled by launch permissions. An AMI can be:
  • Public: Accessible to all AWS accounts
  • Explicit: Shared with specific accounts
  • Implicit: Only the owner can launch it

💡 Allowed AMIs is a feature for administrators to control which AMIs are discoverable and usable within their accounts, improving security and compliance.

Identifying the AMI Provider
Always check the Owner alias to ensure you are using a trusted AMI:
amazon
✅ Verified — Amazon Linux, Windows
aws-marketplace
✅ From AWS Marketplace — commercial software
aws-backup-vault
✅ AMIs managed by AWS Backup
⚠️ Community AMIs
❌ NOT verified by AWS — never use in production without a thorough security review.

Summary: AMI Selection Strategy

  • Define Your Needs: List your requirements for Region, OS, architecture, and root volume type.

  • Start with Trusted Sources: Prefer AWS-provided AMIs (Owner: amazon) or AWS Marketplace AMIs (Owner: aws-marketplace).

  • Use the Console for Discovery: The EC2 console is best for exploring what's available.

  • Automate with the CLI: In scripts and Infrastructure as Code, use aws ec2 describe-images with careful filters to find the latest, up-to-date AMI.

Key Takeaways

  • AMI IDs are region-specific — always use an AMI from the same Region where you plan to launch.

  • The key selection criteria are: Region, Operating System, Architecture, Root Volume Type, Provider, and Additional Software.

  • Use the Launch Instance wizard for quick discovery of popular AMIs.

  • Use the AMI page for advanced search and filtering.

  • Use aws ec2 describe-images with --owners amazon and --filters for automation.

  • Community AMIs are not verified by AWS — use caution.

  • Some vendors provide SSM Parameter Store parameters for the latest AMI IDs (e.g., Canonical/Ubuntu).

Review Questions

Q1: What are the key criteria to consider when selecting an AMI?
Answer: The key criteria are Region (AMI IDs are region-specific), Operating System (e.g., Linux, Windows), Architecture (e.g., x86_64, arm64), Root Volume Type (EBS-backed vs Instance Store-backed), the Provider, and whether it has any Additional Software pre-installed.
Q2: How do you find an AMI owned by AWS using the CLI?
Answer: You use the describe-images command with the --owners amazon option. For example: aws ec2 describe-images --owners amazon. You can then combine it with --filters to narrow the results by OS or root device type.
Q3: Why is it important to use the same Region for the AMI and the instance?
Answer: An AMI is a regional resource. An AMI ID in one Region (e.g., us-east-1) is not valid in another (e.g., eu-west-1). If you try to launch an instance using an AMI ID from a different Region, the command will fail because the AMI does not exist there.
Q4: What is the difference between a Public AMI and a Community AMI?
Answer: A Public AMI is an AMI whose launch permissions are set to "public." Community AMIs are specifically public AMIs shared by other AWS users (not Amazon or verified vendors). They are accessible but unverified, meaning they could contain malicious software or be misconfigured.
Q5: How can you find the latest verified Ubuntu 24.04 LTS AMI using the AWS CLI?
Answer: You can use the describe-images command, filtering by Canonical's owner ID (099720109477) and the AMI name pattern for Ubuntu 24.04 (Noble):
aws ec2 describe-images --owners 099720109477 --filters 'Name=name,Values=ubuntu/images/hvm-ssd-gp3/ubuntu-noble-24.04-amd64-server-*' --query 'Images | sort_by(@, &CreationDate) | [-1].ImageId' --output text
Alternatively, use the SSM Parameter Store parameter for Canonical/Ubuntu.
Q6: What is the 'Allowed AMIs' feature used for?
Answer: It is a governance feature that allows administrators to control which AMIs are discoverable and usable for launching instances within their account. This helps enforce company policies by restricting users from using unapproved or unsupported images.
