Terraform Topics

Terraform Overview

Terraform is an Infrastructure as Code (IaC) tool that enables you to safely and predictably create, change, and improve infrastructure. It codifies APIs into declarative configuration files.

Key Features

  • Infrastructure as Code - Configuration files describe infrastructure
  • Execution Plans - Preview changes before applying
  • Resource Graph - Builds dependencies automatically
  • Change Automation - Apply complex changes safely

Benefits

  • Multi-cloud and hybrid cloud deployments
  • Version control for infrastructure
  • Collaboration and reuse
  • Consistency and reproducibility

Terraform Workflow 

1. Write Configuration
   └── Define resources in .tf files

2. Initialize
   └── terraform init (download providers/modules)

3. Plan
   └── terraform plan (review changes)

4. Apply
   └── terraform apply (provision infrastructure)

5. Manage State
   └── terraform state (inspect/modify state)

6. Destroy (optional)
   └── terraform destroy (clean up resources)

Supported Providers

  • AWS (Amazon Web Services)
  • Google Cloud Platform
  • Microsoft Azure
  • Kubernetes
  • MySQL, PostgreSQL
  • And 1600+ more...

File Structure

  • main.tf - Main configuration
  • variables.tf - Input variables
  • outputs.tf - Output values
  • terraform.tfvars - Variable values
  • versions.tf - Version constraints

Core Concepts

Understanding Terraform's core concepts is essential for effectively managing infrastructure as code.

Fundamental Concepts

Resources

Infrastructure components

Essential

The most important element in Terraform. Each resource block describes one or more infrastructure objects.

Type: Block
Purpose: Define infrastructure

Providers

Platform plugins

Essential

Plugins that interact with APIs to manage resources. Each provider adds a set of resource types and data sources.

Type: Plugin
Purpose: API integration

Variables

Input parameters

Essential

Parameters that allow users to customize Terraform configurations without modifying the source code.

Type: Input
Purpose: Customization

Outputs

Return values

Essential

Return values from a Terraform module that can be used by other configurations or displayed to users.

Type: Output
Purpose: Data exposure

Data Sources

External data

Intermediate

Allow Terraform to use information defined outside of Terraform, or defined by another Terraform configuration.

Type: Read-only
Purpose: Data lookup

State

Infrastructure mapping

Intermediate

Terraform must store state about your infrastructure to map real-world resources to your configuration.

Type: Metadata
Purpose: Resource tracking

Core Concepts Examples

Basic Terraform Configuration

# main.tf - Main configuration file
terraform {
  required_version = ">= 1.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 4.0"
    }
  }
}

# Configure the AWS Provider
provider "aws" {
  region = var.aws_region
}

# Create a VPC
resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  enable_dns_support   = true
  
  tags = {
    Name = "main-vpc"
    Environment = var.environment
  }
}

# Create a public subnet
resource "aws_subnet" "public" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = var.public_subnet_cidr
  availability_zone = var.availability_zone
  
  tags = {
    Name = "public-subnet"
  }
}

# Create an internet gateway
resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id
  
  tags = {
    Name = "main-igw"
  }
}

# Create a route table for public subnets
resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id
  
  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.main.id
  }
  
  tags = {
    Name = "public-rt"
  }
}

# Associate public subnet with route table
resource "aws_route_table_association" "public" {
  subnet_id      = aws_subnet.public.id
  route_table_id = aws_route_table.public.id
}

Variables and Outputs

# variables.tf - Input variables
variable "aws_region" {
  description = "AWS region to deploy resources"
  type        = string
  default     = "us-east-1"
}

variable "environment" {
  description = "Environment name (dev, staging, prod)"
  type        = string
  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}

variable "vpc_cidr" {
  description = "CIDR block for VPC"
  type        = string
  default     = "10.0.0.0/16"
}

variable "public_subnet_cidr" {
  description = "CIDR block for public subnet"
  type        = string
  default     = "10.0.1.0/24"
}

variable "availability_zone" {
  description = "Availability zone for resources"
  type        = string
  default     = "us-east-1a"
}

# outputs.tf - Output values
output "vpc_id" {
  description = "ID of the VPC"
  value       = aws_vpc.main.id
}

output "vpc_cidr_block" {
  description = "CIDR block of the VPC"
  value       = aws_vpc.main.cidr_block
}

output "public_subnet_id" {
  description = "ID of the public subnet"
  value       = aws_subnet.public.id
}

output "internet_gateway_id" {
  description = "ID of the internet gateway"
  value       = aws_internet_gateway.main.id
}

# terraform.tfvars - Variable values (optional)
aws_region        = "us-west-2"
environment       = "dev"
vpc_cidr          = "10.0.0.0/16"
public_subnet_cidr = "10.0.1.0/24"
availability_zone = "us-west-2a"

Data Sources and Locals

# data.tf - Data sources
# Get the current AWS region
data "aws_region" "current" {}

# Get available availability zones
data "aws_availability_zones" "available" {
  state = "available"
}

# Get AMI ID for Amazon Linux 2
data "aws_ami" "amazon_linux_2" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["amzn2-ami-hvm-*-x86_64-gp2"]
  }

  filter {
    name   = "virtualization-type"
    values = ["hvm"]
  }
}

# Get default VPC
data "aws_vpc" "default" {
  default = true
}

# locals.tf - Local values
locals {
  common_tags = {
    Environment = var.environment
    Project     = "terraform-demo"
    ManagedBy   = "terraform"
    Owner       = "devops-team"
  }
  
  instance_name = "${var.environment}-web-server"
  
  # Calculate subnet CIDR blocks dynamically
  private_subnet_cidrs = [for i in range(2) : cidrsubnet(var.vpc_cidr, 8, i + 1)]
  public_subnet_cidrs  = [for i in range(2) : cidrsubnet(var.vpc_cidr, 8, i + 101)]
}

# Using data sources and locals in resources
resource "aws_instance" "web" {
  ami           = data.aws_ami.amazon_linux_2.id
  instance_type = "t3.micro"
  subnet_id     = aws_subnet.public.id
  
  tags = merge(local.common_tags, {
    Name = local.instance_name
  })
}

resource "aws_subnet" "private" {
  count = length(local.private_subnet_cidrs)
  
  vpc_id            = aws_vpc.main.id
  cidr_block        = local.private_subnet_cidrs[count.index]
  availability_zone = data.aws_availability_zones.available.names[count.index]
  
  tags = merge(local.common_tags, {
    Name = "private-subnet-${count.index + 1}"
  })
}

  • Start simple with basic resources and gradually add complexity

  • Manage state properly, especially in team environments
  • Version control all your Terraform configurations

Configuration Syntax

Terraform uses the HashiCorp Configuration Language (HCL), which is designed to be both human-readable and machine-friendly.

HCL Syntax Elements

Blocks

Container for content

Basic

Blocks are containers for other content and represent configuration objects.

Syntax: block_type "label" { }
Examples: resource, variable, provider

Arguments

Name-value pairs

Basic

Arguments assign a value to a name and appear within blocks.

Syntax: name = value
Types: String, Number, Bool, List, Map

Expressions

References and functions

Intermediate

Expressions represent values, either directly or by referencing and combining other values.

Types: References, Functions, Operators
Usage: Dynamic values

Functions

Built-in operations

Intermediate

Built-in functions perform transformations and calculations on values.

Categories: String, Numeric, Collection, Encoding
Usage: Data transformation

Functions and Dynamic Values

# String functions
locals {
  upper_env   = upper(var.environment)
  lower_name  = lower("My-Project-Name")
  title_case  = title("hello world")
  trimmed_str = trimspace("  hello  ")
  substr      = substr("hello world", 0, 5)  # "hello"
}

# Numeric functions
locals {
  max_val    = max(5, 10, 3, 8)      # 10
  min_val    = min(5, 10, 3, 8)      # 3
  parsed_int = parseint("15", 10)    # 15
  abs_val    = abs(-5)               # 5
}

# Collection functions
locals {
  numbers = [1, 2, 3, 4, 5]
  
  # Transform collections
  doubled     = [for n in local.numbers : n * 2]           # [2, 4, 6, 8, 10]
  even_only   = [for n in local.numbers : n if n % 2 == 0] # [2, 4]
  list_length = length(local.numbers)                      # 5
  sorted_list = sort(local.numbers)                        # [1, 2, 3, 4, 5]
  
  # Map functions
  my_map = {
    "a" = 1
    "b" = 2
    "c" = 3
  }
  
  keys_list   = keys(local.my_map)        # ["a", "b", "c"]
  values_list = values(local.my_map)      # [1, 2, 3]
  lookup_val  = lookup(local.my_map, "b") # 2
}

# Encoding functions
locals {
  base64_encoded = base64encode("hello")
  base64_decoded = base64decode("aGVsbG8=")
  json_encoded   = jsonencode({name = "John", age = 30})
  yaml_encoded   = yamlencode({servers = ["web1", "web2"]})
}

# File functions
locals {
  file_content = file("${path.module}/config.json")
  template     = templatefile("${path.module}/user_data.tftpl", {
    username = "admin"
    port     = 8080
  })
}

# Date and time functions
locals {
  current_timestamp = timestamp()
  formatted_date    = formatdate("YYYY-MM-DD", local.current_timestamp)
  time_added        = timeadd(local.current_timestamp, "24h")
}

# Network functions
locals {
  cidr_host  = cidrhost("10.0.0.0/16", 5)     # "10.0.0.5"
  cidr_net   = cidrnetmask("10.0.0.0/16")     # "255.255.0.0"
  cidr_sub   = cidrsubnet("10.0.0.0/16", 8, 2) # "10.0.2.0/24"
}

# Type conversion functions
locals {
  str_to_list = split(",", "a,b,c,d")        # ["a", "b", "c", "d"]
  list_to_str = join("-", ["a", "b", "c"])   # "a-b-c"
  str_to_bool = tobool("true")               # true
  num_to_str  = tostring(42)                 # "42"
}

# Using functions in resources
resource "aws_security_group" "web" {
  name_prefix = "${replace(lower(var.project_name), " ", "-")}-"
  
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = [cidrsubnet(var.vpc_cidr, 8, 0)]
  }
  
  tags = {
    Name = format("%s-sg", var.project_name)
  }
}

Configuration Syntax Guidelines

  • Use consistent formatting with 2-space indentation
  • Group related resources together in files
  • Use descriptive names for resources and variables
  • Leverage functions for dynamic values and transformations
  • Validate inputs using variable validation blocks
  • Use locals for complex expressions and repeated values

State Management

Terraform state is used to track the resources Terraform manages. Proper state management is crucial for team collaboration and infrastructure reliability.

State Management Concepts

Local State

Default storage

Basic

State stored locally in a terraform.tfstate file. Suitable for individual use.

Storage: Local file
Use case: Single user

Remote State

Shared storage

Intermediate

State stored in remote backends like S3, Azure Storage, or Terraform Cloud for team collaboration.

Storage: Remote backend
Use case: Team collaboration

State Locking

Prevent conflicts

Intermediate

Prevents multiple users from modifying state simultaneously, which could cause conflicts.

Mechanism: Lock file
Backends: S3+DynamoDB, etc.

State Operations

Manual state management

Advanced

Commands to manually inspect, modify, and manage Terraform state when needed.

Commands: state, import, taint
Use case: Troubleshooting

Workspaces

Environment isolation

Intermediate

Isolate state files for different environments (dev, staging, prod) using the same configuration.

Isolation: State separation
Use case: Multi-environment

State Security

Protect sensitive data

Advanced

State files may contain sensitive information. Proper security measures are essential.

Protection: Encryption, access control
Best practice: Remote backend

# Create the S3 bucket for state storage (separate configuration)
resource "aws_s3_bucket" "terraform_state" {
  bucket = "my-company-terraform-state"
  
  # Prevent accidental deletion
  lifecycle {
    prevent_destroy = true
  }
  
  tags = {
    Name        = "Terraform State Storage"
    Environment = "Global"
  }
}

# Enable versioning on the S3 bucket
resource "aws_s3_bucket_versioning" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id
  
  versioning_configuration {
    status = "Enabled"
  }
}

# Enable server-side encryption
resource "aws_s3_bucket_server_side_encryption_configuration" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id
  
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
  }
}

# Create DynamoDB table for state locking
resource "aws_dynamodb_table" "terraform_state_locks" {
  name         = "terraform-state-locks"
  billing_mode = "PAY_PER_REQUEST"
  hash_key     = "LockID"
  
  attribute {
    name = "LockID"
    type = "S"
  }
  
  tags = {
    Name = "Terraform State Lock Table"
  }
}

Workspace Configuration

# Using workspaces for environment isolation
terraform {
  backend "s3" {
    bucket = "my-company-terraform-state"
    key    = "apps/web-app/terraform.tfstate"  # Base path
    region = "us-east-1"
    dynamodb_table = "terraform-state-locks"
    encrypt = true
  }
}

# Workspace-aware configuration
locals {
  # Environment-specific settings
  environment_settings = {
    dev = {
      instance_type = "t3.micro"
      instance_count = 1
      enable_monitoring = false
    }
    staging = {
      instance_type = "t3.small"
      instance_count = 2
      enable_monitoring = true
    }
    production = {
      instance_type = "t3.medium"
      instance_count = 3
      enable_monitoring = true
    }
  }
  
  # Current environment settings
  env = local.environment_settings[terraform.workspace]
}

# Create instances based on workspace
resource "aws_instance" "web" {
  count = local.env.instance_count
  
  ami           = data.aws_ami.ubuntu.id
  instance_type = local.env.instance_type
  monitoring    = local.env.enable_monitoring
  
  tags = {
    Name        = "${terraform.workspace}-web-${count.index + 1}"
    Environment = terraform.workspace
    Workspace   = terraform.workspace
  }
}

# Workspace-specific outputs
output "instance_ids" {
  description = "IDs of the EC2 instances"
  value       = aws_instance.web[*].id
}

output "workspace_name" {
  description = "Current Terraform workspace"
  value       = terraform.workspace
}

resource "aws_security_group" "web" {
  name_prefix = "${terraform.workspace}-web-"
  description = "Security group for ${terraform.workspace} web servers"

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = terraform.workspace == "production" ? ["0.0.0.0/0"] : ["10.0.0.0/8"]
  }

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = terraform.workspace == "production" ? ["203.0.113.0/24"] : ["10.0.0.0/8"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Environment = terraform.workspace
    Name        = "${terraform.workspace}-web-sg"
  }
}

State Operations and Commands

# State inspection and manipulation examples

# View current state
# terraform show

# View state in JSON format
# terraform show -json

# terraform state list

# terraform state show aws_instance.web[0]

# Remove resources from state (without destroying)
# terraform state rm aws_instance.old_instance

# Import existing infrastructure
# terraform import aws_instance.existing i-1234567890abcdef0

  }
}

# Move command to migrate state:
# terraform state mv aws_security_group.web_old aws_security_group.web_new

# Force replacement with -replace flag
# terraform apply -replace="aws_instance.web[0]"

# Replace multiple resources
# terraform apply -replace="aws_instance.web[0]" -replace="aws_instance.web[1]"

# State backup and restore
# Always backup state before operations:
# cp terraform.tfstate terraform.tfstate.backup

# For remote state, use:
# terraform state pull > state_backup.json

State Management Best Practices

  • Use remote state for team collaboration and backup
  • Enable state locking to prevent concurrent modifications
  • Secure state files with encryption and access controls
  • Use workspaces for environment isolation
  • Backup state regularly before major operations
  • Version state buckets to enable recovery
