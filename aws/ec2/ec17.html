6.4 Managing Instance States

Managing EC2 instance states is a core operational task that involves controlling the lifecycle of your virtual servers. Understanding how to properly start, stop, reboot, and terminate instances is essential for cost management, maintenance, and ensuring high availability.

This chapter covers the four primary instance management operations and their implications.
📊 management 🔄 states ⚡ EC2
📋

The Four Primary Operations

▶️ Start
Powers on a stopped instance
Resume work → Billing resumes
⏸️ Stop
Powers off a running instance
Cost savings → Billing stops (compute)
🔄 Reboot
Restarts without changing state
OS updates → Billing continues
🗑️ Terminate
Permanently deletes the instance
Remove resources → Billing stops permanently

Operation 1: Stop Instance

📖 Theory
Stopping an instance powers it down and releases the underlying physical resources (vCPUs, memory). The instance's EBS volumes remain intact, and the instance ID, private IP, and Elastic IP (if attached) are preserved.

What Happens During Stop:
Compute Resources
Released (vCPU, memory)
EBS Volumes
✅ Preserved (data persists)
Instance Store
❌ Data is lost
Public IP
Released (unless Elastic IP)
Private IP
✅ Preserved
Instance ID
✅ Preserved
Billing
⏸️ Stops for compute

When to Stop:
  • 💰 Cost Optimization: Save costs during off-hours
  • 🔧 Maintenance: OS updates or configuration changes
  • 📊 Instance Type Change: Change the instance type
  • 💾 Data Preservation: Pause work while keeping data intact

Operation 3: Reboot Instance

📖 Theory
A reboot restarts the instance's operating system without changing its underlying resources. Unlike stop/start, a reboot preserves the instance's IP addresses, instance store data, and does not move the instance to a different host.

What Happens During Reboot:
  • ✅ Physical Host: Unchanged
  • ✅ Compute Resources: Unchanged
  • ✅ EBS Volumes: Persist (data intact)
  • ✅ Instance Store: Persists (data intact)
  • ✅ Public IP: Unchanged
  • ✅ Private IP: Unchanged
  • ✅ Billing: Continues uninterrupted

When to Reboot:
  • 🔄 OS Updates: Apply kernel or OS updates
  • 🧹 Application Issues: Clear memory leaks
  • ⚡ Performance: Resolve degradation from long uptime

Using the AWS CLI:
aws ec2 reboot-instances --instance-ids i-1234567890abcdef0
🔄 Reboot
• Downtime: 2-5 minutes
• Physical Host: Unchanged
• Instance Store: Preserved
• IP Addresses: Unchanged
• Billing: Continuous
⏸️ Stop/Start
• Downtime: 5-15 minutes
• Physical Host: May change
• Instance Store: Lost
• IP Addresses: Public IP changes
• Billing: Pauses during stop
🔄 reboot ⚡ fast 💵 billing continues
🗑️

Operation 4: Terminate Instance

⚠️ WARNING: Termination is Permanent and Irreversible
Terminating an instance permanently deletes it and typically deletes its associated EBS root volume (unless DeleteOnTermination=false). Terminated instances cannot be recovered.

📖 Theory
Termination is the final operation in an instance's lifecycle. It permanently deletes the instance, releases all resources, and removes the instance ID from your account.

What Happens During Termination:
  • ❌ Compute Resources: Released permanently
  • ❌ EBS Root Volume: Deleted (unless DeleteOnTermination=false)
  • ✅ EBS Data Volumes: Preserved if DeleteOnTermination=false
  • ❌ Instance Store: Data lost
  • ❌ Public IP: Released
  • ❌ Private IP: Released
  • ❌ Instance ID: Permanently deleted
  • ❌ Billing: Stops permanently

When to Terminate:
  • 🧹 Resource Cleanup: Remove unused instances
  • 💰 Cost Control: Eliminate all charges
  • 📊 Auto Scaling: ASG automatically terminates instances

Key Takeaways

  • Stop an instance to save costs while preserving EBS data. The instance can be started again later.

  • Start an instance to resume operations after it has been stopped. A new public IP is assigned (unless an Elastic IP is attached).

  • Reboot an instance for OS updates or to resolve application issues. It preserves all data, IP addresses, and instance store data, and billing is uninterrupted.

  • Terminate an instance to permanently delete it and stop all charges. This action is irreversible.

  • Use termination protection on critical instances to prevent accidental deletion.

  • Monitor instance state using the console, CLI, or CloudWatch to ensure your operations are successful.

  • Auto Scaling Groups automatically manage start, stop, and terminate operations based on your configuration.

Review Questions

Q1: What is the difference between stopping and terminating an EC2 instance?
Answer: Stopping powers down the instance while preserving EBS volumes, instance ID, private IP, and Elastic IP. The instance can be started again. Terminating permanently deletes the instance and typically deletes the EBS root volume. Terminated instances cannot be recovered.
Q2: What happens to the data on an EBS volume when you stop an instance?
Answer: Data on EBS volumes is preserved when you stop an instance. The EBS volumes remain intact and can be accessed again when the instance is restarted.
Q3: Why would you choose to reboot an instance instead of stopping and starting it?
Answer: Rebooting is faster (2-5 minutes vs. 5-15 minutes), preserves the instance store, IP addresses, and does not move the instance to a different physical host. It is ideal for applying OS updates or clearing application issues without disrupting billing.
Q4: How can you prevent an instance from being accidentally terminated?
Answer: Enable termination protection on the instance. This can be done in the console under Instance Settings → Change termination protection, or via the CLI using aws ec2 modify-instance-attribute --disable-api-termination. With termination protection enabled, you must disable it before terminating.
Q5: What happens to a public IP address (non-Elastic) when you stop an instance?
Answer: When you stop an instance, its public IP address (non-Elastic) is released. When you start the instance again, it receives a new public IP address. If an Elastic IP is attached, it remains attached to the instance.
