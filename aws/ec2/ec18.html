6.4.1 Stop, Start, Reboot, Terminate

The four primary instance management operations — Stop, Start, Reboot, and Terminate — are the fundamental actions you can perform on an EC2 instance. This section provides a detailed, side-by-side comparison of these operations, including their effects, use cases, and step-by-step instructions.
📊 operations ⏸️ stop ▶️ start 🔄 reboot 🗑️ terminate
📋

Stop

📖 Complete Theory
Stop powers down your EC2 instance. The instance's EBS volumes persist, but any data on instance store volumes is lost. The physical host resources (vCPU and memory) are released to the AWS pool. Stopping an instance is reversible; you can start it again at any time.

🛠️ How to Stop:
# Console: EC2 Dashboard → Instances → Select → Instance State → Stop # CLI: aws ec2 stop-instances --instance-ids i-1234567890abcdef0 # Force stop (for hung instances) aws ec2 stop-instances --instance-ids i-1234567890abcdef0 --force

⚠️ Important Considerations:
⏱️ Minimum Billing
Charged for 60 seconds even if stopped immediately
🌐 Public IP
Released; new one assigned on start (unless Elastic IP)
💾 Instance Store
Data is permanently lost
🖥️ Physical Host
May change on next start
💰 EBS Billing
You continue to pay for EBS storage even while stopped

✅ When to Stop:
  • 💰 Cost Savings: Pause non-production instances during off-hours
  • 🔧 Maintenance: Perform updates that require the instance to be offline
  • 📊 Instance Type Change: Change the instance type (requires stopped state)
⏸️ stop 💾 EBS preserved 💰 cost savings
▶️

Start

📖 Complete Theory
Start powers on a stopped instance. The instance boots from its EBS root volume, and the underlying physical resources (vCPU, memory) are allocated. The instance resumes its previous state.

EFFECTS OF STARTING AN INSTANCE ┌─────────────────────────────────────────────────────────────────────────────────────┐ │ EFFECTS OF STARTING AN INSTANCE │ ├─────────────────────────────────────────────────────────────────────────────────────┤ │ │ │ ┌─────────────────────────────────────────────────────────────────────────────────┐│ │ │ BEFORE START (Stopped) ││ │ │ ┌─────────────────────────────────────────────────────────────────────────┐ ││ │ │ │ • Instance is powered off │ ││ │ │ │ • EBS volumes attached but not in use │ ││ │ │ │ • Private IP assigned but not routed │ ││ │ │ │ • No compute billing │ ││ │ │ └─────────────────────────────────────────────────────────────────────────┘ ││ │ └─────────────────────────────────────────────────────────────────────────────────┘│ │ │ │ │ ▼ (Start Initiated) │ │ ┌─────────────────────────────────────────────────────────────────────────────────┐│ │ │ AFTER START (Running) ││ │ │ ┌─────────────────────────────────────────────────────────────────────────┐ ││ │ │ │ • Instance is operational │ ││ │ │ │ ✅ EBS volumes reattached and accessible │ ││ │ │ │ ✅ New instance store (empty) │ ││ │ │ │ ✅ New public IP (non-Elastic) │ ││ │ │ │ ✅ Elastic IP remains attached │ ││ │ │ │ ✅ Private IP remains assigned │ ││ │ │ │ ✅ Instance ID persists │ ││ │ │ │ ✅ Billing resumes (compute) │ ││ │ │ └─────────────────────────────────────────────────────────────────────────┘ ││ │ └─────────────────────────────────────────────────────────────────────────────────┘│ │ │ └─────────────────────────────────────────────────────────────────────────────────────┘

🛠️ How to Start:
# Console: EC2 Dashboard → Instances → Select → Instance State → Start # CLI: aws ec2 start-instances --instance-ids i-1234567890abcdef0

⚠️ Important Considerations:
  • 🌐 New Public IP: The instance receives a new public IP (unless Elastic IP attached)
  • 🖥️ Physical Host: May be placed on a different host
  • 📋 User Data: Does NOT execute on start (only on first boot)
  • 💾 Instance Store: Previous data lost; new empty instance store provided
  • ⏱️ Boot Time: 1-5 minutes to boot from EBS volume

✅ When to Start:
  • 🔄 Resume Workloads: Continue work after a planned pause
  • 📊 Auto Scaling: ASG automatically starts instances
  • 🔄 Recovery: Recover after a system check failure
▶️ start 🔁 resume 💰 billing resumes
🔄

Reboot

📖 Complete Theory
Reboot restarts the instance's operating system. The instance remains on the same physical host, and all data on EBS and instance store volumes is preserved. Billing continues uninterrupted.

🛠️ How to Reboot:
# Console: EC2 Dashboard → Instances → Select → Instance State → Reboot # CLI: aws ec2 reboot-instances --instance-ids i-1234567890abcdef0

✅ When to Reboot:
  • 🔄 OS Updates: Apply kernel or OS updates
  • 🧹 Application Issues: Clear memory leaks, stale processes
  • ⚡ Performance: Resolve degradation after long uptime
  • ⚙️ Configuration Changes: Apply config changes requiring reboot
🔄 Reboot
• Downtime: 2-5 minutes
• Physical Host: Unchanged
• Instance Store: ✅ Preserved
• IP Addresses: Unchanged
• Billing: Continuous
⏸️ Stop/Start
• Downtime: 5-15 minutes
• Physical Host: May change
• Instance Store: ❌ Lost
• IP Addresses: Public IP changes
• Billing: Pauses during stop
🔄 reboot ⚡ fast 💵 billing continues
🗑️

Terminate

⚠️ WARNING: Termination is Permanent and Irreversible
Terminate permanently deletes the instance and typically deletes its associated EBS root volume. Terminated instances cannot be recovered. This is the final operation in an instance's lifecycle.

🛠️ How to Terminate:
# Console: EC2 Dashboard → Instances → Select → Instance State → Terminate # CLI: aws ec2 terminate-instances --instance-ids i-1234567890abcdef0

🛡️ Preventing Accidental Termination:
# Enable termination protection aws ec2 modify-instance-attribute \ --instance-id i-1234567890abcdef0 \ --disable-api-termination

✅ When to Terminate:
  • 🧹 Resource Cleanup: Remove unused instances
  • 💰 Cost Control: Eliminate all charges
  • 📊 Auto Scaling: ASG automatically terminates instances
  • 🔄 Infrastructure Refreshes: Blue/green deployments
🗑️ terminate ⚠️ permanent 🛡️ protection
📝

Key Takeaways

  • Stop is for cost savings and maintenance. It preserves EBS data and is reversible.

  • Start resumes a stopped instance. It may assign a new public IP.

  • Reboot is for OS updates and application issues. It preserves all data, IP addresses, and is fast.

  • Terminate is permanent and irreversible. Use it only when you are sure you no longer need the instance.

  • Use termination protection on critical instances to prevent accidental deletion.

  • Monitor instance state using aws ec2 describe-instances or CloudWatch.

  • Reboot is faster (2-5 minutes) than stop/start (5-15 minutes).

Review Questions

Q1: What is the primary difference between rebooting and stopping/starting an instance?
Answer: Rebooting restarts the operating system while keeping the instance on the same physical host and preserving all data (including instance store). Billing continues uninterrupted. Stopping and starting powers down the instance, may move it to a different physical host, loses instance store data, and pauses billing. Rebooting is also faster (2-5 minutes) compared to stopping and starting (5-15 minutes).
Q2: What happens to an Elastic IP when you stop an instance?
Answer: An Elastic IP remains attached to the instance when it is stopped. This ensures that you can maintain a stable public IP address even when the instance is powered off. When you start the instance again, the Elastic IP will still be attached.
Q3: How can you prevent an instance from being accidentally terminated?
Answer: Enable termination protection on the instance. This is done in the console under Instance Settings → Change termination protection, or via the CLI with aws ec2 modify-instance-attribute --disable-api-termination. With termination protection enabled, you must disable it before you can terminate the instance.
Q4: What happens to instance store data when you stop, reboot, and terminate an instance?
Answer:
  • Stop: Instance store data is lost
  • Reboot: Instance store data is preserved
  • Terminate: Instance store data is lost permanently
Q5: Why would you choose to stop an instance instead of terminating it?
Answer: You would stop an instance to save costs during periods of inactivity while preserving the instance's EBS data, configuration, and allowing for a quick restart. Stopping is reversible, whereas termination is permanent and irreversible. Stopping is also used for maintenance tasks or changing the instance type.
