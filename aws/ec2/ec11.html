6.1 EC2 Instance Lifecycle

📖 Complete Theory

The EC2 instance lifecycle describes the sequence of states that an EC2 instance transitions through from the moment it is launched until it is terminated. Understanding these states is fundamental to effectively managing your EC2 instances and predicting behavior, costs, and available operations at each stage.

Detailed Breakdown of Each State

1. Pending
The initial state immediately after you initiate a launch request. AWS is provisioning CPU, memory, storage, and networking.

What Happens: Physical resources allocated → AMI copied to root volume → Network attached → Instance boots → User Data scripts execute.

Characteristics: Duration 1-5 minutes, no billing, cannot connect.

2. Running
The fully operational state. Instance has completed boot and is ready to serve traffic.

Characteristics: Billed per second (min 60s), can connect via SSH/RDP/Session Manager, full management capabilities.

3. Stopping
A transient state when you initiate a stop request. The instance is performing an orderly shutdown.

What Happens: OS shut down → Processes terminated → Memory data lost → EBS volumes persist.

Characteristics: Duration 1-2 minutes, no compute billing, cannot connect, instance store data lost.

4. Stopped
The instance is shut down but the root EBS volume persists.

Characteristics: No compute billing, EBS storage costs continue, cannot connect, can modify most attributes.

5. Terminating
A transient state when you initiate a termination request. The instance is being permanently deleted.

Characteristics: No billing, cannot connect, cannot stop/revert, EBS volumes deleted (unless DeleteOnTermination=false).

6. Terminated
The instance has been permanently deleted.

Characteristics: No billing, cannot be recovered/restarted, appears in CloudTrail for auditing.

Key Takeaways

  • The EC2 instance lifecycle consists of six states: Pending, Running, Stopping, Stopped, Terminating, and Terminated.

  • Billing only occurs in the Running state, with a minimum charge of 60 seconds per start.

  • EBS volumes persist when instances are stopped and started. Instance store data is lost on stop/terminate.

  • You cannot change the instance type while running — you must stop the instance first.

  • Public IPs are released when an instance is stopped unless an Elastic IP is attached.

  • Termination is permanent and cannot be undone. Always use EBS snapshots for data you need to preserve.

  • CloudTrail records all state transitions, providing an audit trail for instance lifecycle events.

  • Use Auto Scaling to automate lifecycle management for large fleets.

Review Questions

Q1: What happens to the data on an EBS volume when you stop an EC2 instance?
Answer: When you stop an EC2 instance, all data on the EBS volumes (including the root volume) is preserved and persists after the instance is stopped. However, any data in the instance store (ephemeral storage) is lost because instance store volumes are physically attached to the host server and do not persist.
Q2: What is the difference between stopping and terminating an EC2 instance?
Answer: Stopping is a temporary action — the instance is shut down, but EBS volumes remain, and you can start it again later (billing stops for compute). Terminating permanently deletes the instance and usually deletes the associated EBS root volume (unless DeleteOnTermination=false), and the instance cannot be recovered.
Q3: Can you change the instance type of an EC2 instance while it is running?
Answer: No, you cannot change the instance type of a running EC2 instance. You must first stop the instance, change the instance type, and then start it again. This is because the instance type determines the underlying hardware allocation, which requires the instance to be stopped to modify.
Q4: What happens to an Elastic IP address when you stop an EC2 instance?
Answer: When you stop an EC2 instance that has an Elastic IP attached, the Elastic IP remains attached to the instance and is not released. However, if the instance has a public IP address (not Elastic), that public IP is released when the instance is stopped. When you start the instance again, it receives a new public IP address.
Q5: Can you recover a terminated EC2 instance?
Answer: No, a terminated EC2 instance cannot be recovered. The instance ID is permanently deleted, and all associated data (unless separately preserved via snapshots) is lost. To prevent data loss, you must ensure you have EBS snapshots or backups before termination.
Q6: What is the minimum billing duration for an EC2 instance?
Answer: EC2 instances are billed per second, with a minimum charge of 60 seconds (1 minute) per instance start. This minimum ensures that even if you terminate the instance within the first minute, you are charged for the full 60 seconds of compute time.
