14.2.1 EC2 System Log

Console Output
📖 Complete Theory: What Is the EC2 System Log?

The EC2 System Log, also known as console output, is a diagnostic tool that displays the text output that would normally appear on a physical monitor attached to a computer's display port. It provides visibility into your instance's boot process and system-level operations without requiring direct access to the instance itself.

EC2 SYSTEM LOG (CONSOLE OUTPUT) ┌─────────────────────────────────────────────────────────────────────────────────────┐ │ EC2 SYSTEM LOG (CONSOLE OUTPUT) │ ├─────────────────────────────────────────────────────────────────────────────────────┤ │ │ │ ┌─────────────────────────────────────────────────────────────────────────────────┐│ │ │ Linux Instances ││ │ │ ┌─────────────────────────────────────────────────────────────────────────┐ ││ │ │ │ • System boot messages │ ││ │ │ │ • Kernel logs and kernel version │ ││ │ │ │ • File system information │ ││ │ │ │ • cloud-init logs (bootstrap scripts execution) │ ││ │ │ │ • Command line parameters │ ││ │ │ │ • SSH host key fingerprints │ ││ │ │ └─────────────────────────────────────────────────────────────────────────┘ ││ │ └─────────────────────────────────────────────────────────────────────────────────┘│ │ │ │ ┌─────────────────────────────────────────────────────────────────────────────────┐│ │ │ Windows Instances ││ │ │ ┌─────────────────────────────────────────────────────────────────────────┐ ││ │ │ │ • Last three system event log errors │ ││ │ │ │ • System initialization status │ ││ │ │ └─────────────────────────────────────────────────────────────────────────┘ ││ │ └─────────────────────────────────────────────────────────────────────────────────┘│ │ │ └─────────────────────────────────────────────────────────────────────────────────────┘

🛠️ How to Access:
# AWS Management Console # EC2 → Instances → Select instance → Actions → Monitor and troubleshoot → Get System Log # AWS CLI aws ec2 get-console-output --instance-id i-1234567890abcdef0 # Get latest output (truncated) aws ec2 get-console-output --instance-id i-1234567890abcdef0 --latest --output text # Boto3 (Python SDK) import boto3 ec2 = boto3.client('ec2') response = ec2.get_console_output(InstanceId='i-1234567890abcdef0', Latest=True) print(response['Output'])

💡 Key Insight: The console output is generated at the infrastructure level, independent of your instance's network configuration. It works even when SSH is broken or the instance is unreachable.
📝 Review Questions
Q1: What is the EC2 System Log and why is it important?
The EC2 System Log (console output) is a diagnostic record of the instance's boot process. It is important because it provides visibility into what happens when an instance starts, making it invaluable for troubleshooting boot failures, kernel panics, and OS-level issues.
Q2: How can you access the EC2 System Log using the CLI?
Use aws ec2 get-console-output --instance-id <instance-id>. Add the --latest flag to retrieve the most recent output, and --output text to view the decoded output directly in your terminal.
Q3: What information does the console output include for Windows instances?
For Windows instances, the console output includes the last three system event log errors, which help diagnose system-level issues.
Q4: Can the EC2 System Log help verify the execution of user data scripts?
Yes, the console output includes cloud-init logs, which show the execution of user data scripts. You can view these logs in the system log to confirm that your bootstrap scripts were executed correctly.

14.2.2 EC2 Serial Console

BIOS-level Access
📖 Complete Theory: The Last Resort for Troubleshooting

The EC2 Serial Console is a powerful troubleshooting feature that provides text-based, BIOS-level access to your EC2 instance. Unlike SSH, which relies on a functioning operating system and network stack, the Serial Console connects to the instance's serial port before the operating system boots.

EC2 SERIAL CONSOLE ARCHITECTURE ┌─────────────────────────────────────────────────────────────────────────────────────┐ │ EC2 SERIAL CONSOLE ARCHITECTURE │ ├─────────────────────────────────────────────────────────────────────────────────────┤ │ │ │ ┌─────────────────────────────────────────────────────────────────────────────────┐│ │ │ YOUR LAPTOP ││ │ │ └─ AWS Management Console or CLI ││ │ └─────────────────────────────────────────────────────────────────────────────────┘│ │ │ │ │ ▼ (HTTPS / TLS) │ │ ┌─────────────────────────────────────────────────────────────────────────────────┐│ │ │ AWS SYSTEMS MANAGER SERVICE ││ │ │ └─ Acts as a proxy for serial communication ││ │ └─────────────────────────────────────────────────────────────────────────────────┘│ │ │ │ │ ▼ (Outbound HTTPS) │ │ ┌─────────────────────────────────────────────────────────────────────────────────┐│ │ │ EC2 INSTANCE (Nitro-based) ││ │ │ ┌─────────────────────────────────────────────────────────────────────────┐ ││ │ │ │ BIOS / UEFI Boot (Serial Console) │ ││ │ │ │ └─ Pre-OS bootloader: GRUB or systemd-boot │ ││ │ │ │ └─ Kernel boot messages │ ││ │ │ │ └─ Emergency shell / recovery mode (if the OS fails to boot) │ ││ │ │ └─────────────────────────────────────────────────────────────────────────┘ ││ │ └─────────────────────────────────────────────────────────────────────────────────┘│ │ │ └─────────────────────────────────────────────────────────────────────────────────────┘

🏗️ Key Characteristics:
  • Instance Types: Primarily available on Nitro-based instance types
  • Architecture: x86_64 and ARM (Graviton) supported
  • Access: Through AWS Management Console or CLI via SSM
  • Use Cases: Boot failures, kernel panics, lost root password, broken SSH config
🛠️ Common Fixes via Serial Console:

Fixing a Bad /etc/fstab Entry:
# In emergency shell mount -o remount,rw / vi /etc/fstab # Add '#' at the start of the bad line reboot

Resetting a Lost Root Password:
# Interrupt boot → GRUB → single-user mode mount -o remount,rw / passwd reboot

💡 Key Insight: The Serial Console works at the BIOS/UEFI level, providing access before the operating system boots. It is the ultimate troubleshooting tool for instances that are completely unreachable via SSH or RDP.

📝 Review Questions
Q1: What is the EC2 Serial Console and why is it useful?
The EC2 Serial Console provides BIOS-level, text-based access to your instance, enabling you to troubleshoot issues even when the OS isn't fully booted or networking is down. It is essential for diagnosing boot failures, kernel panics, and other OS-level problems.
Q2: What are the prerequisites for using the EC2 Serial Console?
The prerequisites are: a compatible Nitro-based instance type; the Serial Console must be enabled at the account level in the specific Region; and you must have IAM permissions to access the serial console.
Q3: How can you fix a bad /etc/fstab entry using the Serial Console?
Access the instance via the Serial Console, and when the boot drops to an emergency shell, remount the root as read-write (mount -o remount,rw /), edit /etc/fstab to comment out or fix the problematic entry, and then reboot the instance.

14.2.3 EC2Rescue

Recovery Tool
📖 Complete Theory: EC2Rescue

EC2Rescue is an open-source diagnostic and troubleshooting tool that helps you identify and remediate common issues on EC2 Linux and Windows instances. It is available for Linux as a Python-based framework ec2rl and for Windows Server.

🧠 What is EC2Rescue?
EC2Rescue serves as a diagnostic framework for executing modular scripts to analyze and fix issues on EC2 instances. The Linux version contains over 100 modules — YAML files containing either a BASH or Python script with associated metadata.

🔍 Common Use Cases:
Use CaseDescription
Diagnosing SSH failuresIdentifies and fixes OpenSSH configuration issues
Gathering system logsCollects syslog, package manager logs, and boot logs
Diagnosing kernel parametersIdentifies problematic kernel parameters
Repairing boot issuesFixes fstab entries, kernel panics, and GRUB misconfigurations
Windows password resetRegenerates Windows Administrator passwords via SSM
🛠️ Running EC2Rescue:
# Manual: On a Running Instance ./ec2rl run # Run all modules sudo ./ec2rl run # With root privileges ./ec2rl run --only-modules=dig # Run specific module sudo ./ec2rl run --remediate # Auto-fix identified issues ./ec2rl list # View available modules # View results cat /var/tmp/ec2rl/{timestamp}/mod_out/run/dig.log

📋 Three Ways to Run EC2Rescue:
  1. Manual (Running Instance): Install and run directly on a running instance
  2. Rescue Instance (Offline Volume): Attach root volume to a helper instance
  3. Automated via SSM Runbook: AWSSupport-ExecuteEC2Rescue

⚠️ Limitations of AWSSupport-ExecuteEC2Rescue:
  • Does not support instances with encrypted root volumes
  • Requires a VPC available to create a temporary environment

📝 Review Questions
Q1: What is EC2Rescue and what problem does it solve?
EC2Rescue is an open-source tool that automates the diagnosis and remediation of common EC2 issues, such as SSH connectivity, boot failures, kernel parameters, and resource utilization.
Q2: What are the two main ways to run EC2Rescue?
Manually from the command line (e.g., ./ec2rl run or via a helper instance) or automatically via Systems Manager Automation using the AWSSupport-ExecuteEC2Rescue runbook.
Q3: What is the limitation of the AWSSupport-ExecuteEC2Rescue runbook?
It does not support instances with encrypted root volumes.
Q4: How do you view the results of an EC2Rescue module?
Results are saved in /var/tmp/ec2rl/ (e.g., /var/tmp/ec2rl/{timestamp}/mod_out/run/dig.log).

SAW Runbooks & CloudWatch

⚙️ AWS Support Automation Workflows (SAW):

SAW are curated Systems Manager automation runbooks that provide self-service diagnosis and remediation. They leverage AWS's experience from resolving recurring customer issues.

AWSSupport-TroubleshootSSH
Installs EC2Rescue and fixes SSH issues, even if SSM Agent is not installed
AWSSupport-ResetAccess
Generates and adds a new SSH key pair (Linux) or enables password decryption (Windows)
AWSPremiumSupport-TroubleshootEC2DiskUsage
Analyzes EBS volume usage and automates extension of partitions and file systems
AWSSupport-ExecuteEC2Rescue
Automates the entire rescue instance workflow

🔗 AWS Systems Manager (SSM) Session Manager:

While primarily an access tool, Session Manager is a critical troubleshooting tool because it allows you to connect to instances without open inbound ports, SSH keys, or a public IP address.

  • Access Without Network: Connect to instances unreachable via SSH/RDP
  • One-Click Access: Start a session directly from the console
  • Port Forwarding: Debug application-level issues
  • Logging: Sessions logged to S3 or CloudWatch

Key Takeaways

  • EC2 Console Output is the "black box" of your instance — always check it first when troubleshooting boot issues. It works even when SSH is broken.

  • EC2 Serial Console provides BIOS-level access before the OS boots. Use it to fix bad fstab entries, reset passwords, and observe kernel panics.

  • EC2Rescue is an open-source automated recovery tool with over 100 diagnostic modules. Run it manually (./ec2rl run) or via SSM Automation.

  • SAW Runbooks (AWSSupport-*) are curated Systems Manager automations for common issues like SSH connectivity, disk usage, and access recovery.

  • SSM Session Manager provides secure access without SSH keys, inbound ports, or public IPs — essential for troubleshooting unreachable instances.

  • CloudWatch Metrics provide system-level visibility even when you can't log in. Enable detailed monitoring and install the CloudWatch Agent.

  • AWSSupport-ExecuteEC2Rescue automates the entire rescue workflow but does not support encrypted root volumes.

  • The Serial Console must be enabled at the account level per Region before use.

  • The console output is base64-encoded — command-line tools decode it automatically.

  • EC2Rescue modules are YAML files containing BASH or Python scripts stored in /var/tmp/ec2rl/.
