6.4.2 Changing Instance Type

Stop → Change → Start
Changing the instance type of an EC2 instance is a common operation for scaling your infrastructure up or down to meet changing performance or cost requirements. This process is known as "resizing" an instance and allows you to adjust the compute resources (vCPUs and memory) available to your application without losing your data or configuration.
📊 resize 🔄 stop → change → start ⚡ scaling
📖

The Core Prerequisite

You must stop your EBS-backed instance before you can change its instance type.

⚠️ Hard Requirement: The option to change the instance type is grayed out in the console while the instance is running. This downtime is necessary to detach the instance from its underlying hardware and reattach it to a new configuration.

💡 Key Benefit: Your EBS volumes and data are preserved throughout this process. However, your public IP will change unless an Elastic IP is attached.
📖 prerequisite ⏸️ stop required 💾 EBS preserved
🔍

Compatibility: Before You Change

Before you proceed, it is critical to verify that your desired new instance type is compatible with your current instance's configuration. If they are not compatible, the change request will fail, or the instance may not start correctly.

🏗️ Architecture
Must match processor architecture (x86 → x86, ARM → ARM)
⚠️ Cannot switch between Intel and Graviton
🔄 Virtualization Type
Must match (PV or HVM)
⚠️ Cannot change from PV to HVM
💾 EBS Volume Limit
New type must support same number of attached EBS volumes
🌐 Enhanced Networking
Drivers (ENA) must be installed
⚠️ If missing, change will fail
💿 NVMe Support
OS must support NVMe for Nitro instances
Use UUIDs, not device names
🔐 NitroTPM
Target must also support NitroTPM

💡 Best Practice: Before changing, take a snapshot of your EBS volumes or create an AMI as a precaution.
🔍 compatibility 🏗️ architecture 🌐 ENA drivers
🖥️

Step-by-Step: Console

Method 1: Using the AWS Management Console

  1. Back Up Your Data (Optional but Recommended): Take a snapshot of your EBS volumes or create an AMI as a precaution.

  2. Stop the Instance: Open the Instances page → Select your instance → Instance state → Stop instance. Confirm. Wait for the instance to stop.

  3. Change the Instance Type: With the instance selected, go to Actions → Instance settings → Change instance type.

  4. Select the New Type: Choose your desired instance type from the dropdown. Click Apply.

  5. Start the Instance: Once the change is applied, start the instance again by choosing Instance state → Start instance.

Step-by-Step: CLI

Method 2: Using the AWS CLI
The CLI approach allows you to script this process for automation.

Step 1: Stop the instance
aws ec2 stop-instances --instance-ids i-1234567890abcdef0

Step 2: Confirm the instance is stopped
aws ec2 describe-instances --instance-ids i-1234567890abcdef0 --query 'Reservations[0].Instances[0].State.Name'
✅ Expected output: "stopped"

Step 3: Change the instance type
aws ec2 modify-instance-attribute \ --instance-id i-1234567890abcdef0 \ --instance-type "{\"Value\": \"t3.small\"}"
💡 Note: This command produces no output if successful.

Step 4: Start the instance
aws ec2 start-instances --instance-ids i-1234567890abcdef0
💻 CLI ⚙️ modify-instance-attribute 🤖 automation

Important Considerations

⏱️ Downtime
Instance unavailable during stop, change, and restart process
🌐 Public IP
Public IP released on stop; new IP assigned on start (unless Elastic IP)
💾 Instance Store
Data on instance store volumes is LOST when stopped
📊 Auto Scaling Groups
Stopping an instance in an ASG may mark it unhealthy and trigger termination. Suspend scaling processes first.
⚡ Spot Instances
Cannot change the instance type of a Spot Instance
⚠️ considerations ⏱️ downtime 💾 instance store

Key Takeaways

  • Changing the instance type is a Stop → Change → Start process. The instance must be stopped first.

  • EBS volumes and data are preserved throughout the process.

  • Public IP is released on stop; a new one is assigned on start (unless Elastic IP is attached).

  • Instance store data is lost when the instance is stopped.

  • Check compatibility before changing: architecture, virtualization type, drivers, NVMe support, and EBS volume limits.

  • For instances in Auto Scaling Groups, suspend scaling processes before stopping to prevent termination.

  • Spot Instances cannot have their instance type changed.

  • Always back up (snapshot or AMI) before making changes.

Review Questions

Q1: Is it possible to change an EC2 instance type without terminating the instance?
Answer: Yes, it is possible to change the instance type of an EBS-backed instance without terminating it. The process is a Stop → Change → Start sequence. You must stop the instance, change its type, and then start it again. This preserves your data and configurations.
Q2: What is the most important prerequisite before changing an EC2 instance type?
Answer: The most critical prerequisite is to stop the instance. You cannot change the instance type of a running instance. Additionally, you must ensure the new instance type is compatible with your current instance configuration, including architecture, virtualization type, and drivers.
Q3: What happens to my EBS volumes and data when I change the instance type?
Answer: Your EBS volumes and the data on them are preserved. The process only changes the compute resources (vCPUs and memory). The EBS volume sizes and configurations remain unaffected. The EBS volumes are detached from the old hardware and reattached to the new hardware.
Q4: My instance currently uses a public IP address. What will happen to it when I change the instance type?
Answer: If your instance has a public IPv4 address that is not an Elastic IP, it will be released when you stop the instance. When you start the instance again, it will be assigned a new public IPv4 address. If you need to retain the same public IP, you must attach an Elastic IP to the instance.
Q5: What should you do to ensure an instance in an Auto Scaling Group is not terminated during a type change?
Answer: You should suspend the scaling processes for the Auto Scaling Group before stopping the instance. The service might mark the stopped instance as unhealthy and terminate it to launch a replacement. Suspending the processes prevents this and allows you to complete the type change safely.
Q6: Can I change the instance type of a Spot Instance?
Answer: No, you cannot change the instance type of a Spot Instance. This operation is not supported for Spot Instances.
Q7: What are the key compatibility factors to check before changing the instance type?
Answer: Key factors include:
  • CPU Architecture: x86 vs ARM (cannot switch)
  • Virtualization Type: PV vs HVM
  • Enhanced Networking Drivers: ENA/ixgbevf must be installed
  • NVMe Support: Required for Nitro instances
  • EBS Volume Limit: New type must support the same number of volumes
  • NitroTPM: Target must also support this feature
