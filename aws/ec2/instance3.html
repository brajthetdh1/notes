7.4 Dedicated Hosts and Dedicated Instances

📖 Complete Theory

Dedicated Hosts and Dedicated Instances are two AWS offerings that provide physical isolation for your EC2 workloads. Both ensure that your instances run on hardware dedicated to your use, but they serve fundamentally different use cases and offer different levels of control and billing models.
🏛️ dedicated 🔒 physical isolation 📊 BYOL
🔑

The Core Difference

Full Server vs. Dedicated VM

The primary distinction is what you are paying for and controlling:
  • 🖥️ Dedicated Host: You get an entire physical server. You pay for the whole host, can see its sockets and cores, and control exactly how instances are placed on it.

  • 📦 Dedicated Instance: You get a VM running on hardware dedicated to your account. You pay per instance and have no visibility or control over the underlying physical server.

7.4.1 Dedicated Hosts

📖 What They Are
A Dedicated Host is a physical EC2 server fully dedicated to your use. You have complete control over the host and can run instances on it, manage placement, and see the physical hardware specifications (sockets, cores).

Key Capabilities:
🏷️ BYOL Support
Comprehensive support for per-socket, per-core, or per-VM licenses (Windows Server, SQL Server, RHEL, SUSE)
📍 Host Affinity
Pin instances to a specific host to ensure they always run on the same physical server
👁️ Visibility
See socket count, physical core count, and host ID
🎯 Placement Control
Control exactly how instances are placed on the physical server

Pricing:
  • On-Demand Dedicated Hosts: Billed per host per second (minimum 60 seconds)
  • Dedicated Host Reservations: Up to 70% discount — All Upfront, Partial Upfront, or No Upfront

Restrictions:
  • ❌ No RDS — Amazon RDS instances are not supported
  • ❌ No Windows/RHEL Marketplace AMIs
  • ❌ No Placement Groups
  • ❌ No Free Tier
🖥️ Dedicated Host 🔑 BYOL 📊 per-host
📦

7.4.2 Dedicated Instances

📖 What They Are
A Dedicated Instance is an EC2 instance running on hardware dedicated to your account. Unlike a Dedicated Host, you do not have visibility or control over the underlying physical server.

Key Characteristics:
🔒 Physical Isolation
Instance runs on hardware dedicated to your account
🚫 No Host Visibility
You cannot see sockets, cores, or host ID
🚫 No Placement Control
You cannot control which host the instance runs on
💰 Billed Per Instance
You pay per instance, not per host
📋 Capacity Reservations
You can reserve capacity in a specific Availability Zone

BYOL Support:
Dedicated Instances provide partial BYOL support:
✅ Microsoft SQL Server
With License Mobility through Software Assurance
✅ Windows VDA
Windows Virtual Desktop Access licenses
❌ Other BYOL licenses
Not supported

Decision Framework

🔒 Physical isolation only (no BYOL)
→ Dedicated Instance — Lower cost, simpler management
👁️ Need to see sockets/cores for licensing
→ Dedicated Host — Required for per-socket/per-core license compliance
🏷️ Bringing Windows Server licenses
→ Dedicated Host — Per-socket licensing requires host visibility
📊 Bringing SQL Server licenses
→ Dedicated Host — Per-core licensing requires host visibility
🎯 Need placement control
→ Dedicated Host — Host affinity and auto-placement features
📋 Need capacity reservations
→ Dedicated Instance — Dedicated Hosts don't support capacity reservations

Key Takeaways

  • Dedicated Host = Full physical server with host visibility, placement control, and comprehensive BYOL support. Billed per host.

  • Dedicated Instance = Isolated VM on dedicated hardware, without host visibility or placement control. Billed per instance.

  • Choose Dedicated Hosts when you need to bring your own per-socket or per-core licenses (Windows Server, SQL Server), pass license audits, or need placement control.

  • Choose Dedicated Instances when you just need physical isolation from other customers, use AWS-provided licenses, and don't need host visibility.

  • Performance, security, and physical characteristics are identical between Dedicated Instances and instances running on Dedicated Hosts. The difference is in control, visibility, and billing.

  • Dedicated Host Reservations offer up to 70% discount compared to On-Demand Dedicated Hosts.

  • Dedicated Instances support capacity reservations; Dedicated Hosts do not.

Review Questions

Q1: What is the primary difference between a Dedicated Host and a Dedicated Instance?
Answer: A Dedicated Host gives you a full physical server with control over placement, visibility into sockets and cores, and comprehensive BYOL support — all billed per host. A Dedicated Instance is a VM running on dedicated hardware but with no host visibility or placement control, billed per instance.
Q2: Which option should you choose if you need to bring your own SQL Server licenses with per-socket licensing?
Answer: You should choose a Dedicated Host. Dedicated Hosts provide full BYOL support, including visibility into socket counts, which is required to demonstrate license compliance for per-socket licensing.
Q3: What licenses can be used with Dedicated Instances?
Answer: Dedicated Instances have partial BYOL support:
  • ✅ Microsoft SQL Server with License Mobility through Software Assurance
  • ✅ Windows Virtual Desktop Access (VDA) licenses
  • ❌ Other BYOL licenses are not supported
Q4: How is billing different between Dedicated Hosts and Dedicated Instances?
Answer: Dedicated Hosts are billed per host — you pay for the entire physical server regardless of how many instances you run on it. Dedicated Instances are billed per instance — you pay for each VM individually.
Q5: Can you use Auto Scaling Groups with Dedicated Hosts?
Answer: Yes, Auto Scaling Groups are supported when using a launch template that specifies a host resource group.
