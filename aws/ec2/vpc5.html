9.4 Enhanced Networking

📖 Complete Theory: High-Performance Network Virtualization

Enhanced Networking is an AWS technology that provides significantly higher network performance for EC2 instances compared to traditional virtualized networking. It uses Single Root I/O Virtualization (SR-IOV), a method of device virtualization that allows network devices to bypass the hypervisor and communicate directly with the instance's operating system.

The Core Benefit: Bypassing the Hypervisor
Traditional virtualized networking sends every packet through the hypervisor's virtual switch, which consumes CPU cycles and adds latency. SR-IOV presents the physical network card directly to the instance's OS, enabling:
  • Higher bandwidth: Up to 100 Gbps on supported instance types
  • Lower latency: Consistently lower latency between instances
  • Higher PPS performance: Critical for network-intensive applications
  • Lower CPU utilization: Reduces CPU load for network processing

💡 This technology is available at no additional charge, making it a cost-effective way to boost network performance for suitable workloads.

Benefits:
  • Network-intensive applications: Allocate more queues for maximum vCPU utilization
  • CPU-intensive applications: Operate with fewer queues to preserve CPU cycles

9.4.1 Review Questions

Q1: What is the Elastic Network Adapter (ENA) and what is its primary benefit?
ENA is a high-performance network interface for EC2 instances that enables Enhanced Networking using SR-IOV technology. It provides higher bandwidth (up to 100 Gbps), lower latency, higher PPS performance, and lower CPU utilization compared to traditional virtualized networking.
Q2: What is the ENA queue allocation feature announced in May 2025?
ENA queue allocation allows you to dynamically allocate ENA network queues across ENIs from the instance's total queue pool. This provides granular control over network resources, enabling more queues for network-intensive workloads and fewer queues for CPU-intensive workloads.
Q3: Which instance types use ENA for enhanced networking?
All Nitro-based instances use ENA. Additionally, some Xen-based instances support ENA: H1, I3, G3, m4.16xlarge, P2, P3, P3dn, and R4.
Q4: How can you verify if ENA enhanced networking is enabled on your Linux instance?
Use modinfo ena to check if the ENA module is available, and ethtool -i eth0 to verify if your network interface uses the ena driver.
Q5: What are the prerequisites for installing or upgrading the ENA driver?
Prerequisites include: creating a backup AMI for rollback, ensuring internet connectivity, and using a compatible operating system version. On Windows, PowerShell 3.0 or later is required.

9.4.2 Elastic Fabric Adapter (EFA)

HPC and ML Workloads
📖 Complete Theory: The OS-Bypass Network Interface

The Elastic Fabric Adapter (EFA) is a specialized network interface for Amazon EC2 instances that accelerates High-Performance Computing (HPC) and machine learning (ML) applications. EFA enables you to achieve the application performance of an on-premises HPC cluster, with the scalability, flexibility, and elasticity provided by the AWS Cloud.

The Core Innovation: OS-Bypass
Traditionally, HPC applications use MPI to interface with the system's network transport. With an EFA, HPC applications use MPI or NCCL to interface with the Libfabric API, which bypasses the operating system kernel and communicates directly with the EFA device.

EFA OS-BYPASS ARCHITECTURE ┌─────────────────────────────────────────────────────────────────────────────────────┐ │ Traditional HPC Stack (ENA) │ │ ┌─────────────────────────────────────────────────────────────────────────┐ │ │ │ Application (MPI) │ │ │ │ └─ TCP/IP Stack │ │ │ │ └─ ENA Driver │ │ │ │ └─ Network Hardware │ │ │ └─────────────────────────────────────────────────────────────────────────┘ │ │ │ │ EFA HPC Stack │ │ ┌─────────────────────────────────────────────────────────────────────────┐ │ │ │ Application (MPI/NCCL) │ │ │ │ └─ Libfabric API (OS-BYPASS) │ │ │ │ └─ EFA Device │ │ │ │ └─ Network Hardware │ │ │ └─────────────────────────────────────────────────────────────────────────┘ │ │ ✅ Bypasses kernel → Lower latency, higher throughput │ └─────────────────────────────────────────────────────────────────────────────────────┘

aws ec2 create-network-interface \ --subnet-id subnet-0abcdef1234567890 \ --interface-type efa \ --description "my efa"

aws ec2 attach-network-interface \ --network-interface-id eni-0abcdef1234567890 \ --instance-id i-1234567890abcdef0 \ --device-index 1

EFA in AWS ParallelCluster:
EFA can be enabled in AWS ParallelCluster by adding enable_efa = true to the queue section. A cluster placement group should be used to minimize latencies between instances.

9.4.2 Review Questions

Q1: What is the Elastic Fabric Adapter (EFA) and what is its primary purpose?
EFA is a specialized network interface for EC2 instances that accelerates HPC and ML applications. It provides OS-bypass capabilities, allowing applications to communicate directly with the network hardware, resulting in lower latency and higher throughput compared to standard TCP transport.
Q2: What are the different types of EFA interfaces?
There are three types: ENA (standard IP networking), EFA with ENA (IP networking + OS-bypass), and EFA-only (OS-bypass only, no IP address). EFA-only interfaces were introduced in October 2024 to address IP address and routing challenges for large AI/ML clusters.
Q3: Which libraries and interfaces does EFA support?
EFA supports Open MPI 4.0.2+, Intel MPI 2019 Update 5+, NVIDIA NCCL 2.4.2+, NVIDIA NIXL 1.0.0+, and AWS Neuron SDK 2.3+.
Q4: What are the limitations of EFA?
Key limitations include: OS-bypass is not supported on Windows instances; EFA must be attached to a stopped instance; EFA OS-bypass traffic is not routable; the security group must allow all traffic for the EFA.
Q5: When should you choose EFA over ENA?
Choose EFA when running HPC or distributed ML workloads that rely on MPI-style communication and require very low latency and consistent communication between nodes. ENA is sufficient for general-purpose, high-bandwidth networking.

Key Takeaways

  • Enhanced Networking uses SR-IOV to provide higher bandwidth (up to 100 Gbps), lower latency, and higher PPS performance compared to traditional virtualized networking.

  • Elastic Network Adapter (ENA) is the primary mechanism for enhanced networking on modern Nitro-based instances and is available at no additional charge.

  • The Intel 82599 VF interface is a legacy mechanism for older instance types, supporting up to 10 Gbps.

  • ENA queue allocation (May 2025) allows flexible distribution of network queues across ENIs, enabling optimization for network-intensive or CPU-intensive workloads.

  • Elastic Fabric Adapter (EFA) provides OS-bypass capabilities for HPC and ML workloads, requiring attachment to stopped instances.

  • EFA-only interfaces (October 2024) decouple EFA from ENA, enabling large AI/ML clusters without IPv4 address constraints.

  • Most modern AMIs (Amazon Linux 2, AL2023, Ubuntu 14.04+) include ENA drivers by default.

  • Back up your instance before enabling enhanced networking, as incompatible configurations may render the instance unreachable.

  • EFA supports Open MPI, Intel MPI, NVIDIA NCCL, NVIDIA NIXL, and AWS Neuron SDK.

  • Windows does not support EFA OS-bypass capabilities — if attached, it functions as a standard ENA.
