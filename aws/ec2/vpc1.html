9.1 Amazon Virtual Private Cloud (VPC)

📖 Complete Theory: Your Private Network in the Cloud

Amazon Virtual Private Cloud (Amazon VPC) is a foundational AWS service that enables you to provision a logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define. This virtual network closely resembles a traditional network you'd operate in your own data center, but with the benefits of AWS's scalable infrastructure.

The Core Concept: Total Network Control
At its heart, Amazon VPC gives you complete control over your virtual networking environment. You are empowered to define your own private IP address space, design the network topology, and manage all aspects of network connectivity and security.

🏗️

Core Components of a VPC

A VPC is composed of several key components that work together to create a functional and secure network.

🧱 Subnets
A subnet is a segment of a VPC's IP address range where you can place groups of isolated resources. Subnets allow you to divide your VPC into smaller, manageable sections. Crucially, a subnet must reside in a single Availability Zone.

🌍 Public Subnet
Resources in a public subnet, such as web servers, can be directly accessible from the internet. This is achieved by associating the subnet with a route table that has a route to an Internet Gateway.
🔒 Private Subnet
Resources in a private subnet, such as databases, are not directly accessible from the internet. They are isolated for security and can only access the internet via a NAT Gateway.

🗺️ Route Tables
Route tables control the traffic routing within your VPC. They contain a set of rules, called routes, that determine where network traffic is directed. A route specifies a destination and a target. Each subnet must be associated with a route table.

🌐 Gateways
  • Internet Gateway (IGW): A horizontally scaled, redundant VPC component that allows communication between your VPC and the internet.
  • NAT Gateway: Enables instances in a private subnet to initiate outbound traffic to the internet without exposing them to inbound traffic.

🔗 Connecting VPCs and On-Premises
  • VPC Peering: A networking connection between two VPCs that enables routing traffic between them using private IP addresses. Not transitive.
  • VPN Connection: Extend your corporate data center to your VPC.
  • VPC Endpoints: Privately connect your VPC to supported AWS services (S3, DynamoDB) without internet access.

🔐 Security Layers
  • Security Groups: Stateful virtual firewalls at the instance level. If you allow an incoming request, the response is automatically allowed.
  • Network ACLs: Stateless firewalls at the subnet level. Require explicit rules for both inbound and outbound traffic.

9.1.1 What is a VPC?

📖 Complete Theory: Your Private Network in the Cloud

A Virtual Private Cloud (VPC) is a logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define. Think of it as your own private data center inside AWS — you have complete control over your virtual networking environment, including selecting your own IP address ranges, creating subnets, and configuring route tables and network gateways.

The Core Concept: Total Network Control
Your VPC closely resembles a traditional network that you might operate in your own data center, but with the benefits of using AWS's scalable infrastructure. This isolation is the key — your VPC is completely separate from other AWS customers' networks.

Default VPC:
When you create an AWS account, AWS automatically creates a default VPC in each Region, pre-configured with:
  • A default subnet in each Availability Zone
  • An internet gateway attached to the VPC
  • A route in the main route table that sends all traffic (0.0.0.0/0) to the internet gateway
This allows you to immediately launch and connect to EC2 instances without any additional network configuration.

Q1: What is an Amazon VPC?
An Amazon VPC is a logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define. It gives you complete control over your virtual networking environment, including selecting your own IP address ranges, creating subnets, and configuring route tables and network gateways.
Q2: What is a default VPC and how is it configured?
A default VPC is automatically created in each AWS Region. It is pre-configured with a default subnet in each Availability Zone, an internet gateway attached, and a route that sends all traffic (0.0.0.0/0) to the internet gateway. Q3: What are subnets and how do they relate to Availability Zones?
A subnet is a range of IP addresses in your VPC where you can place groups of isolated resources. Each subnet must reside in a single Availability Zone. This design enables you to build fault-tolerant systems by distributing resources across multiple Availability Zones.
Q4: What is the difference between a Security Group and a Network ACL?
A Security Group is a stateful firewall at the instance level — if you allow an incoming request, the response is automatically allowed. A Network ACL is a stateless firewall at the subnet level — it requires explicit rules for both inbound and outbound traffic.

9.1.2 VPC Components

Subnets, Route Tables, IGW, NAT
📖 Complete Theory: Building Blocks of Your Virtual Network

A Virtual Private Cloud (VPC) is composed of several interconnected components that work together to create a secure, functional, and customizable network environment. The four components we will explore — Subnets, Route Tables, Internet Gateways (IGW), and NAT Gateways — form the foundation of a well-architected AWS network.

🧱 Subnets: Dividing Your Network
A subnet is a logical segment of a VPC's IP address range, a subdivision of the larger VPC. This allows you to group and organize your resources based on their role, security requirements, or other operational needs.

Key Characteristics of Subnets:
CharacteristicDescription
Availability Zone (AZ)Each subnet must reside entirely within a single AZ. This design is crucial for fault tolerance.
CIDR BlockYou define a unique, non-overlapping range of IP addresses for each subnet from your VPC's overall CIDR block.
TypeSubnets are categorized as public or private based on their routing configuration.

Public vs. Private Subnets:
Subnet TypeConnectivityRoute TableKey Use Cases
🌍 Public SubnetDirect internet access (bi-directional)Has a route to an Internet Gateway (IGW) for internet traffic (0.0.0.0/0 → IGW)Hosting web servers, load balancers, bastion hosts
🔒 Private SubnetNo direct internet access (cannot receive inbound traffic from the internet)Routes traffic to a NAT Gateway for outbound-only accessHosting application servers, databases, internal resources

💡 Note: The terms "public" and "private" are determined by routing, not by the subnet's IP range. It's the route table configuration that makes a subnet public or private.

🗺️ Route Tables: Directing the Traffic
Route tables are the traffic directors of your VPC. They contain a set of rules, known as routes, that determine where network traffic from your subnets and gateways is directed.

Core Concepts:
  • Routes: Each route specifies a destination and a target.
  • Main Route Table: Automatically associated with any subnet that doesn't have a custom route table.
  • Custom Route Tables: Create custom route tables and associate them with specific subnets for precise control.
  • Local Route: Every route table automatically contains a "local" route that allows traffic to flow between all resources within the VPC.

Common Route Configurations:
Subnet TypeRoute ConfigurationPurpose
Public SubnetDestination: 0.0.0.0/0, Target: Internet GatewayAllows resources to both send and receive traffic from the internet
Private SubnetDestination: 0.0.0.0/0, Target: NAT GatewayAllows outbound traffic while preventing inbound connections from the internet

IGW & NAT Gateway Deep Dive

🌐 Internet Gateway (IGW): The Door to the Internet
An Internet Gateway (IGW) is a horizontally scaled, redundant, and highly available VPC component that enables communication between your VPC and the public internet.

Key Functions of an Internet Gateway:
  • Provides a Target: It provides the target (like igw-xxxxxxxx) for the default route (0.0.0.0/0) in a route table associated with a public subnet.
  • Performs NAT: It performs Network Address Translation (NAT) for instances that have been assigned public IP addresses (either a dynamic public IPv4 or an Elastic IP).

Requirements for Internet Access via IGW:
For an EC2 instance to have internet access via an IGW, it must meet two conditions:
  1. It must be in a subnet that has a route table with a route to the IGW (i.e., a public subnet).
  2. It must have a public IP address (either assigned automatically at launch or an Elastic IP).
⚠️ Without both of these, the instance cannot directly communicate with the internet.

🌐 NAT Gateway: Secure Outbound Access for Private Subnets
A NAT Gateway is a fully managed AWS service that enables instances in a private subnet to initiate outbound traffic to the internet while preventing the internet from initiating connections to those instances.

Key Functions of a NAT Gateway:
  • ✅ Enables Outbound Internet Access: Allows private instances to access the internet for essential tasks like downloading updates.
  • 🛡️ Protects Private Instances: Private instances are not directly exposed to the internet and do not need public IP addresses.

How a NAT Gateway Works:
  • Placement: Must be created in a public subnet.
  • Elastic IP: Associated with an Elastic IP (EIP), a static public IP address.
  • Routing: A route in the private subnet's route table sends all internet-bound traffic (0.0.0.0/0) to this NAT Gateway.
  • Traffic Flow: The NAT Gateway translates the instance's private IP to its own Elastic IP. Responses are translated back and forwarded to the instance.

💡 Key Insight: Instances in a private subnet do not need public IPs, relying on the NAT Gateway's Elastic IP for outbound internet access. This enhances security by keeping them isolated from direct internet exposure.

9.1.2 Review Questions

Q1: What is a subnet, and what is its relationship to an Availability Zone?
A subnet is a range of IP addresses within your VPC where you can place groups of resources. A subnet must reside in a single Availability Zone (AZ). By creating subnets in different AZs, you can design fault-tolerant and highly available systems.
Q2: What is the difference between a public subnet and a private subnet?
A public subnet has a route table that directs all internet-bound traffic (0.0.0.0/0) to an Internet Gateway (IGW), allowing resources to communicate directly with the internet. A private subnet does not have a route to an IGW; instead, it may route outbound traffic to a NAT Gateway for secure, outbound-only internet access, while preventing inbound connections from the internet.
Q3: What is the purpose of a route table?
A route table contains rules (routes) that determine where network traffic is directed. Each route specifies a destination (e.g., 0.0.0.0/0 for the internet) and a target (e.g., an Internet Gateway). Each subnet must be associated with a route table to control its traffic flow.
Q4: What is the role of an Internet Gateway (IGW)?
An Internet Gateway is a highly available VPC component that allows communication between your VPC and the internet. It serves as a target for internet-routable traffic in your route tables and performs Network Address Translation (NAT) for instances that have been assigned public IP addresses.
Q5: Why must a NAT Gateway be placed in a public subnet, and what is its purpose?
A NAT Gateway must be placed in a public subnet so it can use the Internet Gateway (IGW) to communicate with the internet. It enables instances in a private subnet to initiate outbound traffic to the internet (e.g., for software updates) while preventing the internet from initiating connections to those private instances, thus ensuring they remain secure and isolated.

Key Takeaways

  • VPC is your private, isolated network within the AWS Cloud, giving you complete control over IP addressing, subnets, and routing.

  • Subnets segment your VPC into isolated sections, each tied to a single Availability Zone for fault tolerance. A public subnet has a route to the internet, while a private subnet does not.

  • Route tables are sets of rules (routes) that direct network traffic. Each subnet must be associated with a route table.

  • An Internet Gateway (IGW) provides a target for internet-routable traffic and enables bi-directional communication between your VPC and the internet.

  • A NAT Gateway is placed in a public subnet and uses an Elastic IP. It allows instances in private subnets to access the internet for outbound traffic only.

  • Security Groups are stateful firewalls at the instance level — if you allow an incoming request, the response is automatically allowed.

  • Network ACLs are stateless firewalls at the subnet level — they require explicit rules for both inbound and outbound traffic.

  • VPC Peering connects two VPCs using private IP addresses, but is not transitive.

  • VPC Endpoints enable private connectivity to AWS services (S3, DynamoDB) without using an internet gateway.
