P1.1 Enable MFA on the Root Account

📖 Theory
The AWS root account has unrestricted access to all resources in your AWS account. If compromised, an attacker can delete all your resources, incur massive charges, and steal your data. Multi-Factor Authentication (MFA) adds an extra layer of security by requiring a time-based one-time password (TOTP) in addition to your password. This is the single most important security step you can take.

⚠️ Critical Security Warning: The root account should never be used for daily operations. It should only be used for tasks that specifically require root access (e.g., closing the account, changing support plans, or recovering IAM permissions).

🛠️ Step-by-Step Instructions
  1. Sign in to the AWS Console at https://console.aws.amazon.com/ as the root user.
  2. Navigate to IAM Dashboard → click your account name → Security credentials.
  3. In the MFA section, click Add MFA or Assign MFA.
  4. Choose Authenticator app (Google Authenticator, Microsoft Authenticator, Authy, or 1Password).
  5. Scan the QR code or manually enter the setup key in your authenticator app.
  6. Enter two consecutive 6-digit codes from your authenticator app.
  7. Click Assign MFA.

P1.2 Create an IAM Admin User

📖 Theory
An IAM (Identity and Access Management) user represents a person or application that interacts with AWS. By creating an IAM admin user, you:
  • Follow the principle of least privilege by not using the root account
  • Enable auditability (each action is traceable to a specific user)
  • Allow individual credentials (no sharing of passwords)
  • Enable fine-grained permissions

📌 Best Practice: Even for administrative users, you should always require MFA for login.

🛠️ Step-by-Step Instructions
  1. In the IAM Dashboard, click Users → Create user.
  2. User name: Enter admin-user (or your preferred name).
  3. Select "Provide user access to the AWS Management Console".
  4. Set a Custom password.
  5. Click Next.
  6. Permissions: Select "Attach policies directly".
  7. Search for and select AdministratorAccess.
  8. Click Next, review, and click Create user.
  9. Save the console sign-in URL along with the username and password.

P1.3 Generate Access Key ID and Secret Access Key

📖 Theory
Access Keys are long-term credentials used for programmatic access to AWS (via CLI, SDKs, or API calls). Each IAM user can have up to two active access keys at a time, allowing for zero-downtime rotation.

  • Access Key ID: A unique identifier (like a username)
  • Secret Access Key: A private key (like a password) that is never shared

⚠️ Critical Security Warning: The Secret Access Key is only displayed once during creation. If lost, you must delete the key and create a new one. Never share or commit these keys to code repositories.

🛠️ Step-by-Step Instructions
  1. In IAM, click Users → select admin-user.
  2. Open the Security credentials tab.
  3. Scroll to Access keys and click Create access key.
  4. Select "Command Line Interface (CLI)" as the use case.
  5. Click Next → Create access key.
  6. Immediately download the .csv file or copy both values to a secure location.

P1.4 Install and Configure AWS CLI

📖 Theory
The AWS Command Line Interface (AWS CLI) is a unified tool that allows you to interact with AWS services directly from your terminal. It provides the same functionality as the console but with the power of automation and scripting.

Installation Options:
  • Windows: MSI installer (recommended)
  • macOS: Official .pkg installer or brew install awscli
  • Linux: curl installer for x86_64 or ARM/aarch64

🛠️ Step-by-Step Instructions
Option A: Windows
# Download and run the MSI installer from: https://awscli.amazonaws.com/AWSCLIV2.msi
Option B: macOS (.pkg)
curl "https://awscli.amazonaws.com/AWSCLIV2.pkg" -o "AWSCLIV2.pkg" sudo installer -pkg AWSCLIV2.pkg -target /
Option C: macOS (Homebrew)
brew install awscli
Option D: Linux (x86_64)
# Install unzip sudo apt update && sudo apt install unzip -y # Download and install curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip" unzip awscliv2.zip sudo ./aws/install
Verify Installation:
aws --version
Expected Output:

P1.5 Set Up CloudWatch Billing Alarm ($5)

📖 Theory
CloudWatch Billing Alarms help you monitor your AWS spending and avoid unexpected charges. By setting up a billing alarm, you can receive email notifications when your estimated charges exceed a specific threshold.

📌 Important: Billing alarms are region-independent and must be set up in the us-east-1 (N. Virginia) region because billing metrics are published there by default.

🛠️ Step-by-Step Instructions
  1. Navigate to CloudWatch → set region to us-east-1.
  2. Click Alarms → Create alarm.
  3. Select Billing as the metric source.
  4. Under Billing metrics, select EstimatedCharges.
  5. Threshold: Greater than 5 USD.
  6. Create a new SNS topic: BillingAlarmTopic.
  7. Enter your email address and click Create topic.
  8. Confirm the subscription in the email you receive.
  9. Name the alarm: BillingAlarm-Threshold5.
  10. Click Create alarm.

Troubleshooting Common Issues

"aws: command not found"
CLI not installed or not in PATH. Reinstall or add to PATH manually.
"Invalid access key"
Access Key ID or Secret Access Key is incorrect. Regenerate keys.
"Access denied"
IAM user does not have AdministratorAccess policy. Attach the policy.
"Region not found"
Default region is not set correctly. Use aws configure set region us-east-1.
Billing alarm not triggering
Ensure you are in us-east-1 region. Check SNS subscription confirmation.
MFA setup failed
Ensure time on your mobile device is synchronized. Use Time Sync in authenticator app.

Key Takeaways

  • MFA on root account is non-negotiable. It is the single most important security control.

  • Never use root account for daily tasks. Always create IAM users with appropriate permissions.

  • Access keys are long-term credentials. Store them securely and rotate them regularly.

  • The AWS CLI is your primary tool for automation and infrastructure as code.

  • Billing alarms are essential for cost control — always set one up.

  • Test your configuration after every setup step to catch issues early.

  • Document your setup. Keep a record of usernames, ARNs, and configurations.
