6.Q1: Stop vs Terminate

Q: What is the difference between stopping and terminating an EC2 instance?

Answer: Stopping powers down the instance while preserving its configuration and EBS volumes, allowing you to start it again later. Terminating permanently deletes it and its associated resources (unless explicitly preserved). Termination is irreversible.

Elastic IP✅ Remains attached❌ Disassociated
Compute Billing❌ Stops❌ Stops permanently

6.Q2: User Data

Q: What is User Data and when is it executed?

Answer: User Data is a script or configuration that runs automatically when an EC2 instance launches for the first time. It is used to bootstrap instances — installing software, applying configurations, and preparing the instance for use without manual intervention.

Key Characteristics:
  • Runs only on first boot (not on subsequent starts or reboots)
  • Can be up to 16 KB in size
  • Executes as root (Linux) or Administrator (Windows)
  • Supports shell scripts (Linux) or PowerShell scripts (Windows)
  • Can be passed as plain text or base64-encoded

6.Q3: Instance Metadata

Q: What is Instance Metadata and how do you access it?

Answer: Instance Metadata is data about your EC2 instance that is available to applications running on the instance itself. It includes information like the instance ID, public IP, private IP, security groups, and more. It is accessed via the Instance Metadata Service (IMDS) at the IP address 169.254.169.254.

Identity Documentinstance-identity/document (JSON)

🛠️ How to Access Metadata (IMDSv2):
# Step 1: Get a session token TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600") # Step 2: Use the token to access metadata INSTANCE_ID=$(curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id) echo "Instance ID: $INSTANCE_ID"

6.Q4: IMDSv1 vs IMDSv2

Q: What is the difference between IMDSv1 and IMDSv2?

Answer: IMDSv1 and IMDSv2 are two versions of the Instance Metadata Service. IMDSv2 adds security enhancements to prevent Server-Side Request Forgery (SSRF) attacks, making it the recommended version for all new and existing workloads.

FeatureIMDSv1IMDSv2
AuthenticationNo authentication required✅ Session token required
Request MethodGET request only✅ PUT for token, then GET
Token TTLN/A✅ Configurable (60-21600s)
SSRF Protection❌ Vulnerable✅ Protected
Default in New InstancesDeprecated✅ Recommended
FlexibilitySimple, less secureSlightly more complex, highly secure

⚠️ Why IMDSv2 is More Secure:
  • Session Token Required: Prevents SSRF attacks
  • Token TTL: Limits exposure window
  • PUT Request: Cannot be easily forged
  • AWS Recommended: For all new and existing workloads

⚙️ Enforcing IMDSv2:
# During Launch aws ec2 run-instances \ --image-id ami-0abcdef1234567890 \ --instance-type t3.micro \ --metadata-options "HttpTokens=required,HttpEndpoint=enabled" # Modifying an Existing Instance aws ec2 modify-instance-metadata-options \ --instance-id i-1234567890abcdef0 \ --http-tokens required \ --http-endpoint enabled
🛡️ IMDSv2 🔐 security 🔄 SSRF protection

6.Q5: Public IP on Stop/Start

Q: What happens to the Public IP when you stop and start an instance?

Answer: When you stop and start an EC2 instance, the public IP address (non-Elastic) is released and a new one is assigned. The private IP address remains the same because the Elastic Network Interface (ENI) is preserved.

IP TypeDuring StopAfter Start
Public IP (non-Elastic)❌ Released✅ New public IP assigned
Elastic IP (if attached)✅ Remains attached✅ Remains attached (same IP)
Private IP✅ Preserved✅ Same private IP
IPv6 IP✅ Preserved (if assigned)✅ Same IPv6 IP

🛠️ How to Test This:
# Record the current public IP OLD_IP=$(aws ec2 describe-instances --instance-ids i-1234567890abcdef0 --query 'Reservations[0].Instances[0].PublicIpAddress' --output text) echo "Old IP: $OLD_IP" # Stop the instance aws ec2 stop-instances --instance-ids i-1234567890abcdef0 aws ec2 wait instance-stopped --instance-ids i-1234567890abcdef0 # Start the instance aws ec2 start-instances --instance-ids i-1234567890abcdef0 aws ec2 wait instance-running --instance-ids i-1234567890abcdef0 # Record the new public IP NEW_IP=$(aws ec2 describe-instances --instance-ids i-1234567890abcdef0 --query 'Reservations[0].Instances[0].PublicIpAddress' --output text) echo "New IP: $NEW_IP"

6.Q6: EC2 Instance Connect

Q: What is EC2 Instance Connect and why is it more secure than opening port 22?

Answer: EC2 Instance Connect is a browser-based or CLI-based service that allows you to securely connect to your Linux instances without managing SSH keys or opening inbound port 22. It provides a temporary SSH key that is automatically injected into the instance's ~/.ssh/authorized_keys file for the duration of the session.

FeatureTraditional SSHEC2 Instance Connect
Inbound Port 22✅ Required❌ Not required (can be closed)
SSH Key Management✅ Required (long-term)❌ Not required (temporary keys)
IAM Integration⚠️ Limited✅ Full IAM policy integration
Audit Logging⚠️ Manual or third-party✅ Automatic CloudTrail logging
SecurityRelies on key managementIAM-based access control
Connection MethodSSH client (terminal)Browser or CLI

🛡️ Why EC2 Instance Connect is More Secure:
  • No Port 22 Open: Reduces attack surface; eliminates SSH brute-force attacks
  • No SSH Key Management: Eliminates risk of leaked or stolen SSH keys
  • Temporary Access: Keys valid for only 60 seconds
  • IAM Integration: Access control managed centrally
  • Auditable: All connections logged in CloudTrail
  • Instance-Specific: Each connection scoped to a specific instance

🛠️ IAM Permissions for EC2 Instance Connect:
{ "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Action": "ec2-instance-connect:SendSSHPublicKey", "Resource": "*" }, { "Effect": "Allow", "Action": "ec2:DescribeInstances", "Resource": "*" } ] }

6.Q7: Changing Instance Type

Q: Can you change the instance type of a running instance?

Answer: No, you cannot change the instance type of a running EC2 instance. The instance must be stopped first. The process is a three-step sequence: Stop → Change → Start.

🔐 Core Security Principles:
  • Use IMDSv2 for metadata access — session tokens prevent SSRF attacks
  • Use EC2 Instance Connect instead of opening port 22 — eliminates SSH key management
  • Never use root user for daily tasks — create IAM users with least privilege
  • Enable termination protection on critical instances
  • Always back up (snapshots/AMIs) before making changes
