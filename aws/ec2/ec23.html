7.1 On-Demand Instances

On-Demand Instances are the most straightforward and flexible pricing model for Amazon EC2. They function like a utility: you provision compute capacity and pay only for the time you use it, with no long-term commitment.
💰 On-Demand ⚡ flexible 📊 pay-as-you-go
📖

The Flexible Baseline

The defining feature of On-Demand Instances is flexibility. This model gives you complete control over the instance lifecycle. You can launch, stop, hibernate, start, reboot, or terminate an instance at any time, paying solely for the capacity you consume. It serves as the baseline against which all other pricing models are compared.

Billing and Pricing Dynamics:
  • ⏱️ Per-Second Billing: On-Demand Instances are billed by the second, with a minimum charge of 60 seconds for each instance start.
  • 📊 Fixed Rates: The price per second for a running On-Demand Instance is fixed for a given instance type and region.
  • 💰 Cost Implications: This flexibility comes at a premium; On-Demand is the most expensive EC2 pricing option over time. It is not cost-efficient for workloads that run continuously 24/7.

Account Quotas

Your ability to launch On-Demand Instances is governed by vCPU-based quotas set per AWS account per region.

📋 Quota Types
AWS groups instance families into quota types. The "Running On-Demand Standard instances" quota covers general-purpose families like A, C, D, H, I, M, R, T, and Z.
🔢 Default Limits
By default, you can run up to 5 vCPUs for Standard instances. Specialized families (e.g., P, G, Inf) often start with a quota of 0 vCPUs.
📈 Quota Management
These quotas can be increased via a Service Quota request if you need to launch larger workloads.

💡 Example: If your account has a default quota of 5 vCPUs for standard instance families, you could run a single m5.large (2 vCPUs) or five t2.micro (1 vCPU each) instances.

When to Use On-Demand Instances

On-Demand's flexibility makes it the ideal choice for specific scenarios.

📋 Short-Term Workloads
Development, testing, early-stage experiments, ad-hoc batch jobs
⚡ Burst Capacity
Scale beyond reserved capacity during traffic spikes
🔒 Guaranteed Availability
Critical applications, stateful workloads, synchronous tasks

💡 Key Insight: Unlike Spot Instances, On-Demand capacity is highly reliable and not subject to interruption by AWS. This makes it essential for customer-facing production systems, brokers, and long-running tasks that must not be interrupted.

Pros and Cons

✅ Advantages
  • Ultimate Flexibility: No long-term commitments. Start/stop at any time.
  • Instant Capacity: Instances available immediately after launch.
  • Simple Billing: Fixed rate for exact seconds running (1-min minimum).
  • Low Management Overhead: No need to forecast usage or plan commitments.
❌ Disadvantages
  • Highest Unit Cost: Most expensive option vs Reserved or Spot.
  • No Long-Term Discounts: 24/7 running is significantly more expensive.
  • Unpredictable Bills: Variable usage makes budgeting difficult.
  • Risk of Overprovisioning: Easy to leave instances running and overspend.

Key Takeaways

  • On-Demand Instances are the most flexible EC2 pricing model — launch, stop, start, reboot, or terminate at any time with no long-term commitment.

  • Billing is per-second with a 60-second minimum charge for each instance start.

  • On-Demand is the most expensive pricing model over time — it serves as the baseline against which all other models are compared.

  • vCPU-based quotas limit how many On-Demand instances you can run per account and region (default: 5 vCPUs for standard families).

  • Best for short-term, unpredictable workloads, burst capacity, and applications requiring guaranteed availability.

  • Not cost-efficient for steady-state workloads that run 24/7 — use Reserved Instances or Savings Plans instead.

  • Quotas can be increased via Service Quota requests.

Review Questions

Q1: What is the billing granularity for On-Demand Instances?
Answer: On-Demand Instances are billed by the second, with a 60-second minimum charge for each instance start. This means if you run an instance for 90 seconds, you are billed for exactly 90 seconds.
Q2: What are the primary advantages of using On-Demand Instances?
Answer: The primary advantages are flexibility and ease of use. You have complete control over the instance lifecycle, can launch or terminate instances at any time, and have no long-term commitments. This makes it ideal for unpredictable, short-term, or experimental workloads.
Q3: What is the biggest disadvantage of On-Demand Instances?
Answer: The biggest disadvantage is the cost. Compared to other models like Reserved Instances or Spot Instances, On-Demand is the most expensive way to run compute in EC2. It is not cost-efficient for steady-state workloads that run continuously.
Q4: What is the difference between an On-Demand Instance and a Reserved Instance?
Answer: An On-Demand Instance requires no commitment; you pay a higher rate for the flexibility of paying as you go. A Reserved Instance requires a 1- or 3-year commitment but offers a significant discount (up to 75%) compared to On-Demand pricing, making it the better choice for steady-state workloads.
Q5: What are "vCPU-based quotas" for On-Demand Instances?
Answer: vCPU-based quotas are limits set by AWS per account and region, defining the maximum number of vCPUs you can run across your On-Demand Instances. For example, your account may have a default quota of 5 vCPUs for standard instance families, meaning you could run a single m5.large (2 vCPUs) or five t2.micro (1 vCPU each) instances.
Q6: Why would an application that runs continuously 24/7 be a poor fit for On-Demand?
Answer: Because the high per-second cost of On-Demand accumulates over time. For a server that runs constantly, the cost savings from a 1- or 3-year commitment (like Savings Plans or Reserved Instances) are significant and should be leveraged instead of paying the full On-Demand rate.
