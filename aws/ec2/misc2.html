10.2 Key Pairs

📖 Complete Theory: Your SSH Credentials for EC2

An Amazon EC2 Key Pair is a foundational security component for connecting to your EC2 instances. It is a set of credentials based on public-key cryptography that proves your identity when connecting to an instance.

What is a Key Pair?
A key pair consists of two parts:
  • Public Key: Stored by AWS and placed on your EC2 instance at launch (typically in ~/.ssh/authorized_keys)
  • Private Key: Stored on your local computer — the "secret" you use to prove your identity

⚠️ Critical Security Warning:
  • Amazon EC2 does not store a copy of your private key. It is provided to you only once, at the moment of creation.
  • You cannot recover the private key if it is lost or deleted.
  • Anyone who possesses your private key can connect to any instances that use that key pair.

RSA vs ED25519
📖 Complete Theory: RSA vs. ED25519

Amazon EC2 supports SSH-2 RSA keys for both Linux and Windows instances, and ED25519 keys exclusively for Linux instances. Windows instances do not support ED25519 keys.

Creating Key Pairs

Console & CLI
🛠️ Creating Key Pairs Using AWS Console
  1. Open the EC2 console → Network & Security → Key Pairs
  2. Click Create key pair
  3. Name: Enter a descriptive name (up to 255 ASCII characters)
  4. Key pair type: RSA or ED25519
  5. Private key file format: pem (OpenSSH) or ppk (PuTTY)
  6. Click Create key pair

⚠️ Critical: Your browser will automatically download the private key file. This is your only opportunity to save it — AWS does not store a copy.

# Set file permissions (Linux/macOS) chmod 400 your-key-pair.pem

🛠️ Creating Key Pairs Using AWS CLI
# Basic RSA key pair aws ec2 create-key-pair \ --key-name my-key-pair \ --key-type rsa \ --key-format pem \ --query "KeyMaterial" \ --output text > my-key-pair.pem # ED25519 key pair aws ec2 create-key-pair \ --key-name my-ed25519-key \ --key-type ed25519 \ --key-format pem \ --query "KeyMaterial" \ --output text > my-ed25519-key.pem

Command Options:
OptionDescription
--key-nameName for the key pair
--key-typersa (default) or ed25519
--key-formatpem (default) or ppk (for PuTTY)
--query "KeyMaterial"Extracts only the private key material

💡 Note: You can have up to 5,000 key pairs per AWS Region.

Importing Public Keys

🔧 Using Third-Party Tools and Importing Public Keys

Instead of using AWS to generate the key pair, you can create it locally and import the public key.

Generating a Key Pair Locally (Linux/macOS):
# RSA 2048-bit ssh-keygen -t rsa -b 2048 -f my-key-pair # ED25519 ssh-keygen -t ed25519 -f my-key-pair

Importing the Public Key:
aws ec2 import-key-pair \ --key-name my-imported-key \ --public-key-material fileb://my-key-pair.pub

Requirements for Imported Keys:
RequirementDetails
Supported TypesRSA (Linux & Windows), ED25519 (Linux only)
Supported FormatsOpenSSH public key format, RFC 4716, Base64 encoded DER (RSA only)
Supported Lengths1024, 2048, 4096 bits

💡 Note: If you import an RSA key, AWS calculates the fingerprint using MD5 (imported keys use MD5, while AWS-created RSA keys use SHA-1).

10.2.1 Review Questions

Q1: What are the two key pair types supported by Amazon EC2, and which OS supports each?
EC2 supports RSA (2048-bit SSH-2 RSA) for both Linux and Windows instances, and ED25519 exclusively for Linux instances. ED25519 keys are not supported on Windows instances.
Q2: What are the two private key file formats you can choose when creating a key pair?
The two formats are pem (compatible with OpenSSH, used on Linux/macOS terminal) and ppk (compatible with PuTTY, used on Windows). The default is pem.
Q3: Why is it critical to save the private key file immediately after creation?
AWS does not store a copy of your private key. You are only given the opportunity to download it once, at the moment of creation. If you lose it, you cannot recover it and must create a new key pair.
Q4: What command would you use to create an ED25519 key pair with the AWS CLI?
aws ec2 create-key-pair \ --key-name my-ed25519-key \ --key-type ed25519 \ --key-format pem \ --query "KeyMaterial" \ --output text > my-ed25519-key.pem
Q5: What are the supported lengths for RSA keys, and which is the default?
Supported lengths are 1024, 2048, and 4096 bits. The default is 2048. Amazon EC2 does not accept DSA keys.

10.2.2 Managing Key Pairs

📖 Complete Theory: Managing Key Pairs

Managing EC2 key pairs is a continuous process that involves security hygiene, organizational governance, and operational responsiveness. Once your keys are created, the real work of managing them begins — ensuring they are properly organized, securely distributed, and promptly decommissioned when no longer needed.

📋 Listing and Describing Key Pairs
AWS CLI:
# List all key pairs aws ec2 describe-key-pairs # Filter by a specific name aws ec2 describe-key-pairs --key-names "my-key-pair" # Get detailed information including tags aws ec2 describe-key-pairs --key-pair-ids key-0123456789EXAMPLE

Boto3 (Python SDK):
import boto3 ec2 = boto3.client('ec2') response = ec2.describe_key_pairs() for key in response['KeyPairs']: print(f"Name: {key['KeyName']}, Fingerprint: {key['KeyFingerprint']}")

🏷️ Tagging Key Pairs for Organization
Tags help you classify and manage your key pairs effectively. Common tagging patterns:

EnvironmentProduction, Development, StagingSeparate workloads by environment

🔄 Key Rotation
Key rotation is a security best practice that limits the exposure window of compromised credentials. Research shows that 95% of successful data breaches involve compromised credentials.

⚠️ Note: Rotating key pairs is about generating a new key and replacing the old public key on instances. AWS does not support directly updating the key pair associated with a running instance through the console.

Zero-Downtime Rotation Workflow:
  1. Generate a new key pair in AWS or locally
  2. Add the new public key to ~/.ssh/authorized_keys on each instance
  3. Verify connectivity using the new private key
  4. Remove the old public key from authorized_keys
  5. Delete the old key pair from your AWS account

Key Management Best Practices

🔐 Security Best Practices for Key Management

Store private keys securely: Never commit private keys to version control; use password managers or AWS Secrets Manager
Restrict file permissions: chmod 600 or chmod 400 on private key files prevents unauthorized reading
Use individual keys per user: Avoid sharing key pairs; individual keys enable accountability and access revocation
Rotate keys regularly: Limit exposure window; recommended: every 90 days or annually
Delete unused keys: Old keys represent a security risk if rediscovered
Enable CloudTrail logging: Audit all key pair operations for compliance and incident response
Use region-specific keys: Keys are regional; you may need the same key in multiple regions through import

🗑️ Deleting Key Pairs
Deleting a key pair removes the public key from your AWS account. It does not automatically remove the public key from running instances — the key remains in ~/.ssh/authorized_keys until you manually remove it.

When to Delete:
  • The key pair is no longer associated with any instances
  • The key has been rotated and replaced
  • Team members who held the private key have left the organization
  • The key is believed to be compromised

AWS CLI Delete:
aws ec2 delete-key-pair --key-name my-key-pair

Boto3 Delete:
import boto3 ec2 = boto3.client('ec2') ec2.delete_key_pair(KeyName='my-key-pair')

10.2.2 Review Questions

Q1: How do you view all key pairs in your AWS account using the CLI?
You can use aws ec2 describe-key-pairs to list all key pairs in the current region. For detailed information including tags, use aws ec2 describe-key-pairs --key-pair-ids key-0123456789EXAMPLE.
Q2: Why should you tag key pairs, and what are some common tags?
Tags help classify and manage key pairs at scale. Common tags include Environment (Production, Development), Team (DevOps, Security), ManagedBy (Terraform, Ansible), RotatedDate, and Expiration.
Q3: What is the recommended process for rotating key pairs without downtime?
Generate the new key pair, add the new public key to ~/.ssh/authorized_keys, verify connectivity with the new key, remove the old public key, then delete the old key pair from AWS. This ensures no access gap during rotation.
Q4: Does deleting a key pair from AWS automatically remove it from running instances?
No. Deleting a key pair only removes the public key from your AWS account. The public key remains in the ~/.ssh/authorized_keys file on each running instance until you manually remove it.
Q5: What is the recommended approach for managing SSH keys across multiple users?
Each user should have their own individual SSH key pair. The public keys should be added to instances' ~/.ssh/authorized_keys files. This provides individual accountability and allows precise access revocation when users leave the organization.

Key Takeaways

  • Key pairs consist of a public key (stored by AWS) and a private key (stored by you). AWS does not store a copy of your private key.

  • RSA keys work on both Linux and Windows; ED25519 keys are Linux-only and offer better performance and security.

  • Private keys must be downloaded immediately after creation — they cannot be recovered if lost.

  • Importing public keys allows you to use keys generated with third-party tools (ssh-keygen).

  • Tagging key pairs with metadata (Environment, Team, ManagedBy) enables effective organization and automation at scale.

  • Key rotation is a security best practice that requires adding the new key before removing the old one to avoid access gaps.

  • Deleting a key pair from AWS does not remove it from running instances — you must also remove it from ~/.ssh/authorized_keys.

  • Individual keys per user is the recommended approach — sharing keys reduces accountability and complicates access revocation.

  • Set restrictive permissions on private key files: chmod 400 or chmod 600.

  • Automation tools like Ansible can handle key rotation, discovery, and distribution across large fleets with zero downtime.
