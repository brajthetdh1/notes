6.2 Launching an Instance

Launching an EC2 instance is the process of creating and provisioning a virtual server in the AWS cloud. The EC2 Launch Instance wizard is a web-based form that provides all the fields for configuring and launching your instance. It simplifies the process by providing default values for the instance configuration fields.

Core Concepts

When launching an EC2 instance, you need to understand the key components that define your virtual server.

🖼️ AMI
Operating System + pre-installed software
📊 Instance Type
CPU, memory, storage, networking capacity
🔑 Key Pair
SSH/RDP credentials
🌐 Network
VPC, Subnet, Security Group
💾 Storage
EBS root volume + data volumes

1. Amazon Machine Image (AMI)
The AMI determines the operating system and pre-installed software your instance starts with. AWS offers AMIs for Amazon Linux, Ubuntu, macOS, RHEL, and Windows Server. The AWS Marketplace also allows vendors to publish their own AMIs.

2. Instance Type
The instance type defines the hardware configuration: CPU, memory, storage, and networking capacity. There are over 750 instance types grouped into families. For simple demos and free-tier accounts, t2.micro is commonly used (1 vCPU, 1 GiB RAM).

3. Key Pair
A key pair is a set of security credentials used to prove your identity when connecting to your instance. The public key is stored on your instance, while the private key remains on your local computer. This is the only chance you have to save the private key file.

4. Network Configuration
Includes VPC and Subnet. Default VPC and public subnets automatically assign a public IP address. Security groups act as a firewall controlling inbound and outbound traffic.

5. Storage
An Amazon EBS volume is a storage device that functions like a physical hard drive. Each instance comes with a root volume that stores the AMI containing the operating system.

Step 1: Select a Region
Select the desired AWS Region from the top navigation bar. This determines where your instance will be physically hosted.

Step 2: Navigate to EC2 Console
From the AWS Management Console, search for EC2 and open the EC2 service. From the EC2 Dashboard, choose Launch instance.

Step 3: Name Your Instance
Under Name and tags, enter a descriptive name like My first EC2 instance.

Step 4: Choose an AMI
The Quick Start tab displays popular options like Amazon Linux, Ubuntu, and Windows Server. A common free-tier choice is Amazon Linux 2023 AMI.

Step 5: Choose an Instance Type
For simple demos and free-tier accounts, t2.micro is frequently used (1 vCPU, 1 GiB RAM).

Step 6: Create or Select a Key Pair
Either select an existing key pair or create a new one. AWS does not retain a copy of the private key — save it securely and back it up.

Step 7: Configure Network Settings
Select a VPC and subnet. Configure a security group. For SSH access, add an inbound rule for TCP port 22 and limit the source to your client IP.

Step 8: Configure Storage
Specify the root EBS volume size and type. 8 GiB is common for a basic Ubuntu instance.

Step 9: Launch the Instance
Review the configuration and choose Launch instance.

Launching an Instance: CLI

For automation, the AWS CLI provides a repeatable and scalable way to launch instances.

Minimum Parameters Required:
  • --image-id — The ID of the AMI to launch
  • --instance-type — The instance type (e.g., t2.micro)
  • --subnet-id — The ID of the subnet
  • --security-group-ids — The security group ID(s)
  • --key-name — The name of the key pair

Basic Command Example:
aws ec2 run-instances \ --image-id ami-xxxxxxxxxxxxxxxxx \ --instance-type t2.micro \ --key-name YourKeyPair \ --subnet-id subnet-xxxxxxxxxxxxxxxxx \ --security-group-ids sg-xxxxxxxxxxxxxxxxx \ --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=YourInstanceName}]'

Prerequisites for CLI Launch:
  • The AWS CLI must be installed and configured with appropriate credentials
  • The IAM user must have sufficient permissions (e.g., AmazonEC2FullAccess IAM policy)
  • A key pair must exist in the target Region

How to Find Your Instance

After launching, locate your instance in the EC2 console:

  1. Open the Instances page.
  2. In the Name column, find your instance by the name you gave it.
  3. Note the Instance ID — a unique identifier beginning with i- followed by 17 alphanumeric characters.

View Instance Configuration:
Select the instance ID link to open the instance details page where you can review its configuration, including:
  • Instance type
  • Public IPv4 address
  • Owner (your AWS account number)
  • Launch time
  • Instance state — should be Running

Key Takeaways

  • AMI and Instance Type are the two primary decisions when launching an instance — the AMI defines the OS and software, while the instance type defines the hardware resources.

  • Key Pair is critical for secure SSH access. The private key is only available for download once — store it securely.

  • Security Groups act as firewalls. Restrict inbound traffic to only what is strictly necessary — avoid 0.0.0.0/0 for SSH in production environments.

  • Network Configuration includes VPC, subnet, and security group settings. Default VPC and public subnets are suitable for test instances.

  • The Launch Instance Wizard provides default values for most configuration fields, allowing for quick launches.

  • Use the AWS CLI for repeatable, automated, and scalable instance launches.

Review Questions

Q1: What is the minimum set of parameters required to launch an EC2 instance using the AWS CLI?
Answer: The minimum required parameters are: --image-id (AMI ID), --instance-type (e.g., t2.micro), --subnet-id (subnet ID), --security-group-ids (security group ID), and --key-name (key pair name).
Q2: Why is it important to store the private key file securely after creating a key pair?
Answer: The private key is required to securely connect to your EC2 instance via SSH. AWS does not retain a copy of the private key — you can only download it during creation. If someone else gets hold of your private key, they can access your instance.
Q3: What is the difference between a VPC and a subnet in the context of launching an EC2 instance?
Answer: A VPC (Virtual Private Cloud) is a virtual network within the AWS Cloud dedicated to your AWS account. A subnet is a range of IP addresses within a VPC. When you launch an instance, you choose a subnet within your VPC. A default subnet is typically a public subnet, meaning it automatically assigns a public IP address and provides internet access.
Q4: What are the first steps you should take in the AWS Console to launch an EC2 instance?
Answer: First, select your desired AWS Region from the top navigation bar. Then, navigate to the EC2 Console (search for "EC2" or select it from services), and from the Instances page, click the Launch instances button. The EC2 launch wizard will guide you through the remaining configuration steps.
Q5: What does the "State" of an instance indicate after it's launched?
Answer: The instance state shows the current status of the instance in its lifecycle. After launch, the instance first appears with state pending and transitions to running after boot is complete. When an instance is in the running state, it is ready for use and you can connect to it.
