4.3.2 Using AWS CLI (aws ec2 describe-images)

The aws ec2 describe-images command is the most powerful tool for programmatically discovering and selecting AMIs. It provides granular control over the search process, making it essential for automation, Infrastructure as Code, and DevOps pipelines.
💻 CLI 📋 describe-images 🤖 automation
🔧

Command Overview

The describe-images command lists the AMIs available to you, including public images, private images you own, and images shared with you by other AWS accounts. When you run it, you must specify the Region where you want to search, as AMI IDs are unique to each Region.

Basic Syntax:
aws ec2 describe-images \ --region <region> \ --owners <owner-ids> \ --filters <filters> \ --query <query-expression> \ --output <format>

Parameters:
--region
Specifies which AWS Region to search
Example: --region us-east-1
--owners
Filters images by owner account
Example: --owners amazon
--filters
Narrows results by specific attributes
Example: --filters "Name=platform,Values=windows"
--query
Extracts specific fields using JMESPath
Example: --query 'Images[0].ImageId'
--output
Formats the output (json, text, table)
Example: --output table

Filtering Results

The --filters parameter allows you to narrow your search to specific AMI attributes. Multiple filters are combined with an AND operation, while multiple values within a single filter are combined with OR.

Essential Filters:
name
String with wildcards (*)
ubuntu/images/hvm-ssd-gp3/*
platform
windows (omit for Linux)
architecture
x86_64, arm64, i386
root-device-type
ebs, instance-store
state
available, pending, failed
owner-alias
amazon, aws-marketplace
ena-support
true, false
virtualization-type
hvm, paravirtual
tag:Key
Key-value pair

💡 Note on Filter Values: Filter values are case-sensitive. You can use wildcards (*) to match patterns in the name filter.

Practical Examples

Example 1: Describe a Specific AMI by ID
aws ec2 describe-images \ --region us-east-1 \ --image-ids ami-1234567890EXAMPLE

Example 2: Find AWS-Provided Windows AMIs
aws ec2 describe-images \ --owners amazon \ --filters "Name=platform,Values=windows" "Name=root-device-type,Values=ebs"

Example 3: Find the Latest Ubuntu 24.04 LTS AMI
aws ec2 describe-images \ --owners 099720109477 \ --filters "Name=name,Values=ubuntu/images/hvm-ssd-gp3/ubuntu-noble-24.04-amd64-server-*" "Name=state,Values=available" \ --query 'sort_by(Images, &CreationDate)[-1].ImageId' \ --output text \ --region us-east-1

Example 4: Find the Latest RHEL 9 AMI
aws ec2 describe-images \ --owners amazon \ --filters "Name=name,Values=RHEL-9*-x86_64-*" "Name=state,Values=available" \ --query 'sort_by(Images, &CreationDate)[-1].[ImageId,Name,CreationDate]' \ --output table \ --region us-east-1

Example 5: Find Debian 13 Images
aws ec2 describe-images \ --owners 136693071363 \ --filters "Name=name,Values=debian-13-*" "Name=state,Values=available" \ --query 'sort_by(Images, &CreationDate)[-1].[ImageId,Name,CreationDate]' \ --output table \ --region eu-north-1

Example 6: Include Deprecated AMIs
aws ec2 describe-images \ --owners amazon \ --filters "Name=name,Values=RHEL-*" \ --query 'Images[*].[ImageId,Name]' \ --output table \ --include-deprecated

Embedding AMI Discovery in run-instances

The true power of describe-images emerges when you embed it directly into the instance launch process:
aws ec2 run-instances \ --image-id "$(aws ec2 describe-images \ --owners 099720109477 \ --filters \ "Name=name,Values=ubuntu/images/hvm-ssd-gp3/ubuntu-noble-24.04-amd64-server-*" \ --query 'sort_by(Images, &CreationDate)[-1].ImageId' \ --output text \ --region us-east-1)" \ --instance-type t3.medium \ --key-name MyKeyPair \ --security-group-ids sg-12345678

💡 This pattern ensures you always launch with the latest official AMI, eliminating manual updates to AMI IDs in your automation scripts.

Best Practices

  • 🔒 Always Specify the Owner: Use --owners amazon, a specific AWS account ID (like Canonical's 099720109477), or aws-marketplace to ensure you are only viewing official images.

  • 📋 Use Precise Name Filters: AMI names follow predictable patterns. Use name patterns with * wildcards to target exactly what you need.

  • ✅ Filter by State: Add "Name=state,Values=available" to ensure you only receive launchable AMIs.

  • 📊 Always Use --query: Limit the response data to reduce payload size and make the output easier to parse.

  • 🔄 Cache AMI IDs in Scripts: If you are launching hundreds of instances, embed the describe-images command to fetch the latest AMI each time.

Key Takeaways

  • aws ec2 describe-images is the primary CLI command for programmatically finding AMIs.

  • Always specify the Region — AMI IDs are unique to each Region.

  • Use --owners to filter by provider (e.g., amazon, 099720109477 for Canonical).

  • Use --filters with specific attributes: name, platform, architecture, root-device-type, and state.

  • Use --query with sort_by and [-1] to find the latest AMI.

  • Embed describe-images in run-instances to always use the latest official AMI.

  • Always filter by state=available to ensure the AMI is launchable.

  • Use --include-deprecated to find legacy AMIs.

Review Questions

Q1: What command is used to find AMIs programmatically?
Answer: The command is aws ec2 describe-images. It is the primary CLI command for discovering and selecting AMIs.
Q2: How do you filter results to only show AWS-provided AMIs?
Answer: Use the --owners amazon parameter. This filters the results to only show AMIs owned by Amazon (e.g., Amazon Linux, Windows).
Q3: What is the owner ID for Canonical's official Ubuntu AMIs?
Answer: Canonical's official Ubuntu AMIs are published under owner ID 099720109477.
Q4: How can you find the latest Ubuntu 24.04 LTS AMI using the CLI?
Answer: Use the following command:
aws ec2 describe-images \ --owners 099720109477 \ --filters "Name=name,Values=ubuntu/images/hvm-ssd-gp3/ubuntu-noble-24.04-amd64-server-*" "Name=state,Values=available" \ --query 'sort_by(Images, &CreationDate)[-1].ImageId' \ --output text \ --region us-east-1
Q5: Why is it a best practice to always specify the owner when using describe-images?
Answer: Specifying the owner (e.g., --owners amazon or --owners 099720109477) ensures you are only viewing official, verified images from trusted providers. This is essential for security and reliability, as it filters out potentially unsafe Community AMIs.
Q6: How can you ensure you always launch with the latest official AMI?
Answer: Embed the describe-images command directly in your run-instances command using command substitution:
--image-id "$(aws ec2 describe-images ... --query 'sort_by(Images, &CreationDate)[-1].ImageId' --output text)"
This pattern fetches the latest AMI ID at launch time, eliminating manual updates.
