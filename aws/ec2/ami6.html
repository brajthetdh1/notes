4.5.1 Sharing AMIs Across Accounts

Sharing an AMI across AWS accounts allows you to grant launch permissions to other accounts without creating a copy, thereby maintaining centralized management and reducing storage costs. This section covers the mechanisms, permissions, and special considerations for cross-account AMI sharing.
🔑 sharing 🌍 cross-account 💰 cost-effective
📊

Key Characteristics

CharacteristicDescription
OwnershipSource account retains ownership; the AMI remains in source account
CostNo additional storage costs; no data transfer fees for sharing
ManagementCentralized control; can revoke permissions at any time
LimitsMaximum of 1,000 AMI launches per account, per Region
PermissionsOnly launch permissions are granted; storage access may require additional permissions

Snapshot Permissions for Shared AMIs

When you share an AMI, you are granting launch permissions — but the destination account also needs access to the underlying EBS snapshots to launch instances.

⚠️ The Error You May See:
"You do not have permission to access the storage of this AMI"

✅ Solution: Add Snapshot Permissions
  • When sharing the AMI, always select the option to add 'Create volume' permission to associated snapshots
  • If already shared without permissions: Remove the existing sharing, then re-share with snapshot permissions

📌 Note: This requirement applies to non-AWS Marketplace AMIs. For AWS Marketplace AMIs, you cannot share them directly — you must launch an instance and create a new AMI from it.
⚠️ snapshot permissions 📸 Create volume ❌ error
🔐

Sharing Encrypted AMIs

For an encrypted AMI to be shareable, the destination account must have access to the AWS KMS customer-managed key used to encrypt the snapshots.

🏠 Source Account
• Navigate to KMS console
• Add destination account as principal
• Add key policy statements for:
kms:Encrypt, kms:Decrypt, kms:ReEncrypt*, kms:GenerateDataKey*, kms:DescribeKey
🎯 Destination Account
• Create IAM policy to allow access to source KMS key
• Include actions: kms:Encrypt, kms:Decrypt, kms:ReEncrypt*, kms:GenerateDataKey*, kms:DescribeKey
• Include kms:CreateGrant, kms:ListGrants, kms:RevokeGrant

⚠️ Important: Replace KEY_ARN with the ARN of your AWS KMS key in both source and destination policies.

Copying an AMI: CLI Examples

Basic Cross-Region Copy:
aws ec2 copy-image \ --source-image-id ami-1234567890abcdef0 \ --source-region us-east-1 \ --name "my-web-ami-v1.0-eu" \ --description "Copy of AMI for EU deployment" \ --region eu-west-1

Copy with Tags:
aws ec2 copy-image \ --source-image-id ami-1234567890abcdef0 \ --source-region us-east-1 \ --name "my-web-ami-v1.0-eu" \ --region eu-west-1 \ --tag-specifications 'ResourceType=image,Tags=[{Key=Environment,Value=Production},{Key=Version,Value=v1.0}]'

Copy with Encryption:
aws ec2 copy-image \ --source-image-id ami-1234567890abcdef0 \ --source-region us-east-1 \ --name "my-web-ami-v1.0-eu" \ --region eu-west-1 \ --encrypted \ --kms-key-id arn:aws:kms:eu-west-1:123456789012:key/abcd1234-5678-90ef-ghij-klmnopqrstuv

Time-Based Copy (15 min to 48 hours):
aws ec2 copy-image \ --source-image-id ami-1234567890abcdef0 \ --source-region us-east-1 \ --name "my-ami" \ --region eu-west-1 \ --copy-image-timeout-minutes 120

💡 Key Points:
  • Additional charges apply for time-based copies
  • Completion duration applies to all snapshots associated with the AMI
  • There are quotas for time-based copies (capped by cumulative snapshot copy throughput)

Important Considerations

📋 Launch Permissions
Amazon does NOT copy launch permissions from the source AMI to the new AMI. You must apply them after the copy completes.
🏷️ Tags
Only user-defined tags are copied if specified. System tags (aws: prefix) are NOT copied.
⏳ Time-Based Copies
Specify completion time window (15 min to 48 hours). Additional charges apply.
🌍 Source-Destination
Region → Region, Outpost, Local Zone
Local Zone → Same Local Zone, parent Region
Outpost → Cannot be copied

⚠️ AWS Marketplace AMIs: Cannot be directly copied across accounts. Instead, launch an instance and create a new AMI from that instance in the target account.

Key Takeaways

  • Sharing AMIs grants launch permissions without creating a copy, maintaining centralized management and cost-effectiveness.

  • When sharing an AMI, always add Create volume permission to the associated snapshots, or the destination account will receive a "storage access" error.

  • Encrypted AMIs require KMS key policy updates in both the source and destination accounts.

  • Copying AMIs across Regions is essential for global deployment and disaster recovery.

  • Launch permissions are NOT copied when you copy an AMI — you must reapply them.

  • Time-based copies allow you to guarantee completion within a specified window, but additional charges apply.

  • AWS Marketplace AMIs cannot be directly copied across accounts; instead, launch an instance and create a new AMI.

  • Instance store-backed AMIs require additional S3 permissions for copying.

Review Questions

Q1: What is the difference between sharing an AMI and copying an AMI?
Answer: Sharing grants launch permissions to another account without creating a copy — the AMI remains in the source account with no additional storage costs. Copying creates an independent duplicate in the destination Region or account, incurring storage costs, and the destination account owns the copy. Sharing is preferred for centralized management, while copying is necessary for global deployment.
Q2: What error occurs if a destination account tries to launch from a shared AMI without snapshot permissions?
Answer: The destination account will receive the error: "You do not have permission to access the storage of this AMI". To resolve this, the source account must re-share the AMI with the option to add Create volume permission to the associated snapshots selected.
Q3: Can you copy an AWS Marketplace AMI to another account?
Answer: No. You cannot directly copy an AWS Marketplace AMI across accounts. Instead, launch an instance using the AMI, then create a new AMI from that instance in the target account.
Q4: What permissions are required for copying an encrypted AMI to another Region?
Answer: For encrypted AMIs, the destination account must have access to the source AWS KMS key for decryption during the copy process. The source account must update the KMS key policy to grant the destination account permissions for kms:Decrypt, kms:ReEncrypt*, kms:GenerateDataKey*, and kms:DescribeKey. The destination account also needs an IAM policy allowing it to use the KMS key.
Q5: What happens to launch permissions when you copy an AMI to a different Region?
Answer: Launch permissions are not copied from the source AMI to the new AMI. After the copy completes, you must explicitly set the launch permissions (e.g., making it private, sharing it, or making it public) for the new AMI in the destination Region.
Q6: How can you ensure an AMI copy completes within a specific timeframe?
Answer: You can enable a time-based copy by specifying a completion duration (minimum 15 minutes, maximum 48 hours, in 15-minute increments) in the console or using the --copy-image-timeout-minutes parameter in the CLI. Additional charges apply for time-based copies.
