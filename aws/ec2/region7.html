2.3 Edge Locations and Content Delivery

Edge Locations are a critical component of AWS's global infrastructure, designed to bring AWS services closer to end-users. This chapter explores what Edge Locations are, how they function, and the services that leverage them for content delivery and application acceleration.

2.3.1 What are Edge Locations?

An Edge Location (also known as a Point of Presence or PoP) is a physical site deployed by AWS in major cities and highly populated areas across the globe. Unlike Regions, which are complete data center clusters, Edge Locations are smaller facilities designed for a specific purpose: caching content and delivering it to users with the lowest possible latency.

How Edge Locations Work

Edge Locations function as a distributed cache layer. Here is the step-by-step process when a user requests content:

📋 Step-by-Step Process:
  1. User Request: A user in London visits a website hosted on an EC2 instance in us-east-1 (N. Virginia).
  2. DNS Routing: The user's DNS resolver returns the IP address of the nearest Edge Location (in this case, one in London), not the origin server in the US.
  3. Cache Check: The Edge Location checks if it has a cached copy of the requested content (e.g., images, CSS, JS files).
  4. Cache Hit: If the content is in the cache, it is served directly to the user with low latency.
  5. Cache Miss: If the content is not in the cache, the Edge Location fetches it from the origin server (in us-east-1), caches a copy, and then delivers it to the user.

💡 Result: This dramatically reduces the geographical distance data must travel, improving load times and the overall user experience.

2.3.2 Regional Edge Caches

A Second Layer of Caching
In addition to the primary Edge Locations, AWS operates Regional Edge Caches. These are a mid-tier caching layer located between your origin servers and the Edge Locations.

Why Regional Edge Caches Exist:
  • 📊 Large Cache Size: Edge Locations have limited cache capacity. As content becomes less popular, it might be evicted from an Edge Location.
  • ⚠️ The "Miss" Problem: If content is evicted from an Edge Location, the next user request would result in a "cache miss," requiring a request all the way back to the origin server.

How They Solve It:
Regional Edge Caches act as a 'backup' cache. They have a larger cache footprint than a single Edge Location. If a user requests content that has been evicted from their local Edge Location, the Edge Location can fetch it from the nearest Regional Edge Cache (which is closer than the origin), rather than traveling all the way to the origin server.

2.3.3 AWS Services Using Edge Locations

Several AWS services are built on and utilize the global network of Edge Locations.

1. Amazon CloudFront
AWS's primary CDN service. Uses 410+ Edge Locations to securely deliver content with low latency. Supports Cache Policies, CloudFront Functions, Lambda@Edge, and integrates with WAF & Shield.
2. Amazon Route 53
AWS's highly available DNS service. Uses Edge Locations to provide fast, authoritative DNS responses to end users worldwide, reducing overall load time.
3. AWS Global Accelerator
Networking service that improves application availability and performance. Provides static IP addresses (anycast) and routes traffic over the optimized AWS global network.

📌 Key Insight: AWS Global Accelerator provides static IP addresses (anycast) that serve as a fixed entry point. When a user connects, it routes traffic to the optimal endpoint based on client location, health, and application health — all over the AWS global network.

Key Takeaways

  • Edge Locations are AWS's global network of caching sites, designed to deliver content and services to users with minimal latency.

  • They are not full Regions. They are smaller and primarily used for caching, DNS resolution, and networking services.

  • Amazon CloudFront is the primary service using Edge Locations, functioning as a global CDN.

  • Regional Edge Caches are a mid-tier layer that provides an additional, larger cache between the Edge Location and the origin server, improving performance for less popular content.

  • Static IPs and Anycast are used by services like Global Accelerator to provide a fixed, globally routable entry point to your applications.

  • The global edge network consists of over 410 Points of Presence (PoPs) across 90+ cities and 48 countries.

  • Edge Functions (CloudFront Functions and Lambda@Edge) allow running code at the edge for custom content delivery logic.

Review Questions

Q1: What is the primary difference between an Edge Location and an Availability Zone?
Answer: An Availability Zone (AZ) is a fully isolated data center within an AWS Region. It's where you host your primary infrastructure like EC2 instances, RDS databases, and EBS volumes. It is a failure domain and is fundamental to achieving high availability. An Edge Location, on the other hand, is a smaller caching site used by services like CloudFront. It is not a place to host your primary resources; rather, its purpose is to deliver cached content and perform DNS resolution to end-users with low latency.
Q2: What is the purpose of a Regional Edge Cache?
Answer: A Regional Edge Cache sits between the Edge Locations and your origin server. It provides a larger caching layer than any single Edge Location. When content is evicted from a local Edge Location, the Regional Edge Cache can serve that content to the Edge Location, preventing a request from having to go all the way back to the origin server. This significantly reduces latency and load on the origin.
Q3: How does Amazon CloudFront handle a user request when the content is not in the cache?
Answer: When a user makes a request and the content is not available in the closest Edge Location (a "cache miss"), the request is forwarded to the nearest Regional Edge Cache. If the content is available there, it is served back to the Edge Location and then to the user. If the content is also not in the Regional Edge Cache, CloudFront makes a request to the origin server, fetches the content, caches it at both the Regional Edge Cache and the Edge Location, and finally delivers it to the user.
Q4: Besides CloudFront, what other AWS services use Edge Locations?
Answer: Two other key services that use Edge Locations are:
  • Amazon Route 53: The DNS service uses Edge Locations to perform fast, low-latency DNS resolution for end users.
  • AWS Global Accelerator: This service uses Edge Locations as entry points for its static IP addresses, using them to inspect incoming traffic and route it over the optimized AWS global network to the user's application endpoints.
Q5: What is a "Point of Presence" (PoP)?
Answer: A Point of Presence (PoP) is the physical location where AWS deploys its Edge infrastructure. The terms "Edge Location" and "PoP" are often used interchangeably. A PoP contains multiple servers and is part of the AWS global edge network. The network currently consists of over 410 PoPs worldwide.
