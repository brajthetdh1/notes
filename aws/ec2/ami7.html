P2.2 Connect via SSM Session Manager

📖 Theory: What is SSM Session Manager?
AWS Systems Manager Session Manager is a fully managed service that provides secure, browser-based or CLI-based shell access to your EC2 instances without needing to open inbound ports or manage SSH keys.

Key Benefits:
  • 🔑 No SSH Keys: No key pair management required
  • 🚫 No Open Ports: No inbound ports need to be open
  • 📋 Auditable: All sessions are logged in CloudTrail
  • 🔒 Secure: Uses IAM for authentication and authorization

🔄 How It Works:
  1. EC2 Instance has SSM Agent pre-installed (Amazon Linux 2023)
  2. Instance has IAM Role with AmazonSSMManagedInstanceCore policy
  3. User initiates session (console or CLI)
  4. Session Manager establishes secure tunnel (no open ports needed)
  5. User gets shell access to the instance

Method 1: Using the AWS Management Console
Navigate to AWS Systems Manager → Session Manager → Start session

Method 2: Using the AWS CLI
aws ssm start-session --target i-1234567890abcdef0

✅ Verification Checklist
  • □ SSM session opened successfully
  • □ Shell prompt displays (sh-4.2$ or similar)
  • □ You can run commands in the session
  • □ whoami returns ssm-user

P2.3 Update System Packages

sudo dnf update -y
📖 Theory: DNF Package Manager
DNF (Dandified YUM) is the next-generation package manager for RPM-based Linux distributions, including Amazon Linux 2023.

CommandPurpose
sudo dnf updateUpdate all packages
sudo dnf upgradeUpgrade to latest versions
sudo dnf install <package>Install a package
sudo dnf remove <package>Remove a package
sudo dnf search <keyword>Search for packages
sudo dnf list installedList installed packages

🛠️ Step-by-Step Instructions
# Check current package count sudo dnf list installed | wc -l # Check for available updates sudo dnf check-update # Update all packages sudo dnf update -y # Check the kernel version uname -r # Check the OS version cat /etc/os-release

✅ Verification Checklist
  • □ sudo dnf update -y completed without errors
  • □ All packages were updated successfully
  • □ Kernel version is current
  • □ No security updates are pending

P2.4 Install Apache (httpd)

Enable on Boot
📖 Theory: Apache HTTP Server
Apache HTTP Server (httpd) is one of the most popular web servers in the world. It is open-source, reliable, and highly configurable.

Why Install Apache in the AMI?
  • 🚀 Ready to Serve: Instances launched from this AMI will have a web server ready immediately
  • ✅ Consistency: Every instance will have the exact same configuration
  • ⚡ Faster Scaling: Auto Scaling groups can launch fully functional instances quickly

🛠️ Step-by-Step Instructions
# Install Apache sudo dnf install httpd -y # Check Apache version httpd -v # Start Apache service sudo systemctl start httpd # Verify Apache is running sudo systemctl status httpd # Enable Apache to start on boot sudo systemctl enable httpd # Verify enablement sudo systemctl is-enabled httpd

Configure Firewall:
# Allow HTTP and HTTPS sudo firewall-cmd --permanent --add-service=http sudo firewall-cmd --permanent --add-service=https sudo firewall-cmd --reload

Create a Test Web Page:
# Create index.html echo "<h1>Hello from Golden AMI!</h1>" | sudo tee /var/www/html/index.html # Test locally curl http://localhost

SSM session fails

dnf update fails
Check internet connectivity via NAT/IGW
Apache won't start
Check logs: sudo journalctl -u httpd -f
Firewall blocking traffic
Verify security group has HTTP inbound rule
Apache not responding on public IP
Ensure public IP is assigned and security group allows port 80
