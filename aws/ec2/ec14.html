Steps 1-4: Region, Console, Name, AMI

Step 1: Select a Region
Select a Region from the top navigation bar. This determines where your instance will be physically hosted.

💡 Tip: Choose the Region closest to you or your users for better latency. For free-tier testing, us-east-1 (N. Virginia) is a common choice.

Step 2: Open the EC2 Console
In the AWS Console search bar, type "EC2" and open the EC2 service. From the EC2 Dashboard, click Launch instance.

Step 3: Name Your Instance
Under Name and tags, enter a descriptive name like My first EC2 instance.

Step 4: Choose an AMI
The AMI determines the operating system and pre-installed software. The Quick Start tab displays popular options.

Common Free-Tier AMIs:
  • Amazon Linux 2023 (recommended for learning AWS)
  • Ubuntu Server 22.04 LTS
  • Windows Server 2022 Base
💡 Note: AMI IDs are region-specific. You may see different IDs depending on your selected Region.

Steps 5-6: Instance Type & Key Pair

Step 5: Choose an Instance Type
Instance types define the hardware configuration: CPU, memory, storage, and networking capacity.

Instance TypevCPUsMemoryFree Tier

⚠️ Important: Only one t2.micro or t3.micro instance is free per month (750 hours) under the AWS Free Tier.

Step 6: Create or Select a Key Pair
A key pair enables secure SSH access to Linux instances without passwords.

How to Create a New Key Pair:
  1. Under Key pair, select Create a new key pair
  2. Enter a name (e.g., ec2-demo-key)
  3. Choose key pair type: ED25519 (Linux) or RSA (Linux & Windows)
  4. Choose private key file format: .pem (OpenSSH) or .ppk (PuTTY)
  5. Click Create key pair

Step 7: Configure Network Settings

The network configuration includes VPC, Subnet, and Security Group settings.

Default Settings (Good for Testing):
  • VPC: Default VPC
  • Subnet: Default subnet (public subnet with internet access)
  • Auto-assign public IP: Enabled

Security Group Configuration (Critical):
A security group acts as a firewall controlling inbound and outbound traffic.

💡 For SSH access, add an inbound rule:
  • Type: SSH
  • Protocol: TCP
  • Port Range: 22
  • Source: Your local IP address or range (not 0.0.0.0/0 in production)

Steps 8-9: Storage & Launch

Step 8: Configure Storage
EC2 instances typically attach to an EBS volume configured in this section.

Default Settings:
  • Root Volume Size: 8 GiB (enough for a basic Linux instance)
  • Volume Type: gp2 or gp3 (SSD)

💡 Tip: For learning and testing, the default storage settings are sufficient. You can increase the root volume size if needed.

Step 9: Review and Launch
Review the configuration in the Summary panel.

  • Ensure you've selected a key pair (if you plan to connect via SSH).
  • Verify the security group rules.
  • Click Launch instance.

✅ A Success banner confirms the launch.

Finding Your Instance:
  1. From the success banner, choose Instances in the breadcrumb.

Terminating Your Instance (Clean Up)

⚠️ WARNING: Terminating an instance is permanent and irreversible. The instance and its data (unless separately backed up) are lost.

How to Terminate:
  1. Select the checkbox next to your instance.
  2. Click Instance State → Terminate (delete) instance.
  3. Confirm by clicking Terminate (delete).
  4. Monitor the state change from shutting-down to terminated.

📌 Why Terminate? AWS charges for running instances (even idle ones). Always terminate instances you no longer need to avoid unnecessary costs.

Stop vs Terminate (Quick Recap):
  • Stop: Pauses the instance, preserves EBS data, and can be restarted later. Billing stops for compute but continues for storage.
  • Terminate: Permanently deletes the instance and its data. Use when you no longer need the instance.
🗑️ terminate ⚠️ permanent 💰 avoid charges

Key Takeaways

  • Region Selection is the first and most important step — it determines where your instance physically resides.

  • AMI and Instance Type are the two primary decisions: AMI defines the OS and software, while the instance type defines the hardware.

  • Key Pair is essential for SSH access. The private key is only available for download once — store it securely.

  • Security Groups act as firewalls. Restrict inbound traffic to only what is strictly necessary.

  • Termination is Permanent — always double-check before terminating, and ensure you have backups if needed.

  • The Launch Wizard simplifies the process by providing default values, making it easy for beginners to launch their first instance.

Review Questions

Q1: What are the first two steps to launch an EC2 instance from the console?
Answer: Select your desired AWS Region from the top navigation bar, then navigate to the EC2 Console and click the Launch instance button from the EC2 Dashboard or the Instances page.
Q2: Why is it important to save the private key file securely after creating a key pair?
Answer: The private key is required to securely connect to your EC2 instance via SSH. AWS does not retain a copy of the private key — you can only download it during creation. If you lose it, you cannot retrieve it and must create a new key pair.
Q3: How can you prevent unauthorized SSH access to your EC2 instance?
Answer: Restrict the inbound SSH rule in your security group to your specific IP address or IP range. Avoid using 0.0.0.0/0 (anywhere) for SSH in production environments.
Q4: What should you do to avoid ongoing charges after testing an EC2 instance?
Answer: Terminate the instance when you no longer need it. While stopping the instance stops compute charges, EBS storage charges continue. Termination is the only way to avoid all charges for the instance.
Q5: What is the difference between the instance ID and the instance name?
Answer: The instance ID (e.g., i-01aeed690c9fb5322) is a unique identifier automatically assigned by AWS when the instance is launched. The instance name is an optional tag that you can assign for easier identification in the console. The instance name is not used by AWS for internal identification.
