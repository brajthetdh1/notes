3.3 AWS CLI Installation and Configuration

The AWS Command Line Interface (AWS CLI) is a powerful, unified tool that enables you to interact with AWS services directly from your terminal. It provides the same functionality as the AWS Management Console but with the speed and scriptability of the command line.

Whether you are automating deployments, managing infrastructure, or simply performing quick queries, the AWS CLI is indispensable.

This chapter provides a comprehensive guide to installing and configuring the AWS CLI version 2, the current recommended version. Version 1 is effectively deprecated — always use version 2 for the latest features and security updates.

3.3.1 Installing the AWS CLI

Installing on Windows
The simplest and most reliable method for installing the AWS CLI on Windows is using the official MSI installer.

📥 Step 1: Download
Download the MSI file from the official AWS documentation page.
▶️ Step 2: Run
Double-click the downloaded .msi file and follow the installation wizard.
🤫 Step 3: Silent Install (Optional)
For unattended installations, run with Administrator prompt.

Silent Installation Command:
msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi /qn
🪟 Windows 📦 MSI 🤫 silent install
🍎

Installing on macOS

There are two primary methods to install the AWS CLI on macOS:

📦 Official .pkg Installer
Download the package from AWS using curl and run the installer.
🍺 Homebrew
If you use Homebrew, install with a single command.

Official .pkg Installer:
curl "https://awscli.amazonaws.com/AWSCLIV2.pkg" -o "AWSCLIV2.pkg" sudo installer -pkg AWSCLIV2.pkg -target /

Homebrew Installation:
brew install awscli
🍎 macOS 📦 .pkg 🍺 Homebrew
🐧

Installing on Linux

The installation process on Linux involves downloading a zip file and running the installer. The process is similar for most distributions.

Step 1: Install unzip (if not already installed)
# For Debian/Ubuntu sudo apt update && sudo apt install unzip -y # For Amazon Linux/RHEL/CentOS sudo yum install unzip -y

Step 2: Download the installer
# For x86_64 architectures (most standard systems) curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip" # For ARM/aarch64 architectures (including AWS Graviton) curl "https://awscli.amazonaws.com/awscli-exe-linux-aarch64.zip" -o "awscliv2.zip"

Step 3: Unzip and Install
unzip awscliv2.zip sudo ./aws/install

Alternative: Ubuntu Snap
sudo snap install aws-cli --classic
🐧 Linux 📦 zip 🔄 snap
✅

Verifying the Installation

After installation, open a new terminal window and run the following command to confirm that the AWS CLI is installed correctly and accessible in your PATH:
aws --version
Expected Output:
aws-cli/2.27.50 Python/3.10.6 Windows/10 exe/AMD64

⚠️ Troubleshooting: If you see a "command not found" error, the installation may have failed or the AWS CLI was not added to your system's PATH. Ensure you have closed and reopened your terminal after installation.

3.3.2 Prerequisites and Creating Access Keys

Before you can configure the AWS CLI, you need to obtain programmatic credentials, known as Access Keys. This is a crucial step to ensure secure authentication with your AWS account.

⚠️ Important Security Note: Do not use your AWS root user credentials for day-to-day CLI tasks. Instead, create an IAM user with specific, least-privilege permissions.

Steps to create an Access Key for an IAM User:
  1. Sign in to the AWS Management Console and navigate to the IAM service.
  2. In the left navigation pane, select Users and choose your IAM username.
  3. Open the Security credentials tab.
  4. Click Create access key.
  5. Select the appropriate use case (e.g., Command Line Interface) and confirm.
  6. Optionally, add a description tag.
  7. Click Create access key.

After creation, you will be presented with:
  • Access Key ID (e.g., AKIAIOSFODNN7EXAMPLE)
  • Secret Access Key (e.g., wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY)

⚠️ Security Best Practices:
  • Immediately copy or download the .csv file containing the access key details. This is the only time the Secret Access Key will be available.
  • Treat them like passwords. Never commit them to your codebase or share them publicly.
  • If a key is accidentally exposed, delete it immediately and create a new one.
  • Rotate your access keys regularly to reduce risk.
🔑 access keys 👤 IAM user 🔒 security
⚙️

3.3.3 Configuring the CLI with aws configure

Once you have your access keys, you can use the aws configure command to set up your default profile.

Run the command:
aws configure

Enter your credentials:
AWS Access Key ID [None]: AKIAIOSFODNN7EXAMPLE AWS Secret Access Key [None]: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY Default region name [None]: us-east-1 Default output format [None]: json

Configuration Value Details:
ValueDescription
Access Key IDThe Access Key ID obtained from IAM
Secret Access KeyThe Secret Access Key obtained from IAM
Default region nameThe AWS Region to use by default (e.g., us-east-1, eu-west-1)
Default output formatjson is most comprehensive; text and table also available

3.3.4 Where AWS CLI Stores Credentials

The values you provide are stored in two separate files within the .aws directory in your user's home folder.

Operating SystemCredentials FileConfig File
macOS/Linux~/.aws/credentials~/.aws/config
Windows%USERPROFILE%\.aws\credentials%USERPROFILE%\.aws\config

📂 File Contents:
  • Credentials File: Stores the aws_access_key_id and aws_secret_access_key.
  • Config File: Stores the region and output (and any other configuration profiles).
📂 files 🔑 credentials ⚙️ config
👤

3.3.5 Working with Multiple Profiles

If you manage multiple AWS accounts, different projects, or separate environments, you can configure multiple named profiles.

Create a new named profile:
aws configure --profile <profile-name>
Example:
aws configure --profile dev-account

Use a specific profile:
  • Command-line option: Add --profile <profile-name> to any command.
    • aws s3 ls --profile dev-account

  • Environment variable: Set the AWS_PROFILE environment variable for an entire terminal session.
    • # macOS/Linux export AWS_PROFILE=dev-account # Windows setx AWS_PROFILE dev-account

Verify Your Configuration:
aws sts get-caller-identity
Expected Output:
{ "UserId": "AIDA...", "Account": "123456789012", "Arn": "arn:aws:iam::123456789012:user/your-username" }

Review Questions

Q1: How do I install the AWS CLI on my macOS or Linux machine?
Answer: The installation method depends on your operating system:
  • macOS: Either download the official .pkg installer using curl or use brew install awscli (Homebrew).
  • Linux: Use curl to download the appropriate zip file for your architecture (x86_64 or aarch64), unzip it, and run sudo ./aws/install.
Always verify your installation by running aws --version.
Q2: How do I create access keys for an IAM user to use with the AWS CLI?
Answer: You create access keys in the IAM console. Navigate to Users, select your user, go to the Security credentials tab, and click Create access key. You'll be prompted to choose a use case (e.g., Command Line Interface). After creation, you can view the Access Key ID and Secret Access Key — download immediately as it is the only time it will be displayed. For production, AWS IAM Identity Center is the recommended alternative.
Q3: What does aws configure do, and what information is required?
Answer: The aws configure command sets up your default AWS credentials and configuration settings. It prompts you for:
  • AWS Access Key ID
  • AWS Secret Access Key
  • Default region name (e.g., us-east-1)
  • Default output format (e.g., json)
This information is stored in ~/.aws/credentials and ~/.aws/config.
Q4: What are named profiles, and how do I create one?
Answer: Named profiles are used to manage configurations for different AWS accounts, roles, or projects. You create a new named profile using aws configure --profile <profile-name>. You can then use this profile by adding --profile <profile-name> to your aws commands or by setting the AWS_PROFILE environment variable.
Q5: How can I verify that my AWS CLI is configured and authenticated correctly?
Answer: You can verify your configuration using aws sts get-caller-identity. This will return details like the account number and the Amazon Resource Name (ARN) of the user or role you are currently authenticated as. You can also run aws s3 ls to list your S3 buckets and test basic permissions.
