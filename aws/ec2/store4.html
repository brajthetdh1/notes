11.4 Amazon Elastic File System (EFS)

📖 Complete Theory: Scalable Shared File Storage

Amazon Elastic File System (Amazon EFS) is a fully managed, serverless, and elastic file system that provides scalable, shared storage for use with AWS Cloud services and on-premises resources. It is built on the Network File System (NFS) protocol, allowing multiple EC2 instances (or other compute resources) to access the same file system simultaneously.

Conceptual Difference:
EBS is like a dedicated hard drive attached to a single server.
EFS is like a shared network drive that many servers can access at the same time.
📁 EFS 📊 shared file storage 🔄 NFS protocol
🏗️

Core Architecture

Regional, Multi-AZ by Default
EFS is a regional service, which means that by default, a file system is redundantly stored across multiple Availability Zones (AZs) within an AWS Region. This architecture ensures high availability and durability for your data.

11.4.1 What is EFS?

Shared, Scalable File Storage
📖 Complete Theory: Serverless Shared Storage for the Cloud

Amazon Elastic File System (Amazon EFS) is a fully managed, serverless, and elastic file system designed for use with AWS Cloud services and on-premises resources. It provides a simple, scalable, and highly available shared file storage solution that can be mounted on multiple EC2 instances simultaneously, enabling concurrent read and write access from thousands of compute nodes.

📝 Review Questions
Q1: What is Amazon EFS and what protocol does it use?
Amazon EFS is a fully managed, serverless, and elastic file system that provides shared, scalable storage. It uses the NFS (Network File System) protocol and is POSIX-compliant.
Q2: How is EFS different from EBS?
EBS is a block storage volume attached to a single EC2 instance, providing low-latency, high-performance storage. EFS is a shared file system that can be concurrently mounted by thousands of instances across multiple AZs, providing shared access and elastic scaling.
Q3: What does "serverless" mean in the context of EFS?
Serverless means there is no need to provision or manage storage capacity. EFS automatically scales storage up and down as you add or remove files, and AWS handles all the underlying infrastructure management.
Q4: Why would you use EFS over S3?
EFS provides a file system interface (POSIX/NFS) with shared file semantics (locking, permissions), making it ideal for applications that require traditional file system behavior and concurrent write access from multiple compute nodes. S3 is an object storage service better suited for storing blobs, backups, and static assets.
Q5: What are the storage classes offered by EFS and when would you use each?
EFS offers three storage classes: EFS Standard for frequently accessed data; EFS Infrequent Access (IA) for data accessed only a few times per quarter; and EFS Archive for cold, rarely accessed data. EFS Lifecycle Management can automatically tier data between these classes.

11.4.2 EFS Storage Classes

Standard, Infrequent Access, Archive
📖 Complete Theory: Optimizing Cost with Automatic Tiering

Amazon EFS offers three storage classes that allow you to optimize costs based on how frequently your files are accessed. The key insight is that most storage cost is wasted on cold data — files that are rarely touched — yet are sitting in high-performance storage and generating unnecessary charges.

📝 Review Questions
Q1: What are the three EFS storage classes and when would you use each?
The three storage classes are EFS Standard (frequently accessed active data), EFS Infrequent Access (IA) (data accessed a few times per quarter with up to 95% lower cost), and EFS Archive (cold, rarely-accessed data with up to 97% lower cost).
Q2: What is the prerequisite for using EFS Archive?
To use EFS Archive, the file system must use the Elastic Throughput mode and the General Purpose performance mode. It is not available with Provisioned Throughput or in China Regions.
Q3: What are the access charges associated with IA and Archive storage?
Both IA and Archive have per-access read/write fees. Archive has a 3× higher request charge than IA, reflecting its deeper cost optimization for truly cold data. These charges should be factored into cost decisions.

11.4.3 EFS Lifecycle Policies

Automated Storage Tiering
📖 Complete Theory: Automated Storage Tiering

EFS Lifecycle Policies are the core mechanism that enables Amazon EFS to automatically and transparently move your files between storage classes based on access patterns. This is the "set and forget" capability that makes EFS cost-optimized without requiring manual data management.

EFS LIFECYCLE POLICIES - HOW THEY WORK ┌─────────────────────────────────────────────────────────────────────────────────────┐ │ STEP 1: File Created/Updated in Standard │ │ └─ Timer starts tracking last access time │ │ │ │ │ ▼ │ │ STEP 2: Transition to IA (e.g., AFTER_30_DAYS) │ │ └─ If file has not been accessed in Standard for 30 days │ │ └─ File moves to IA storage (lower cost) │ │ │ │ │ ▼ │ │ STEP 3: Transition to Archive (e.g., AFTER_90_DAYS) │ │ └─ If file has not been accessed in Standard for 90 days │ │ └─ File moves to Archive storage (lowest cost) │ │ │ │ │ ▼ │ │ STEP 4: Transition Back to Standard (Intelligent-Tiering) │ │ └─ If file is accessed in IA or Archive, move back to Standard │ │ └─ Ensures active files get sub-millisecond latency performance │ └─────────────────────────────────────────────────────────────────────────────────────┘

The Three Lifecycle Policies:
📤 Transition to IA
  • Moves files from Standard to IA
  • Options: 1, 7, 14, 30, 60, 90 days
  • Default: 30 days
  • Tracks last access time in Standard
📤 Transition to Archive
  • Moves files from Standard/IA to Archive
  • Options: 1–365 days
  • Default: 90 days
  • Requires Elastic Throughput
📥 Transition to Standard
  • Moves files back to Standard
  • Intelligent-Tiering
  • Option: AFTER_1_ACCESS
  • Prevents unbounded access charges

💡 How the Timer Works: The timer tracks the last time a file was accessed while in Standard storage. Metadata operations such as ls do NOT count as file access events. Only actual data reads/writes reset the timer.
🛠️ AWS CLI Configuration:
aws efs put-lifecycle-configuration \ --file-system-id fs-0abc123def456789 \ --lifecycle-policies '[ {"TransitionToIA": "AFTER_30_DAYS"}, {"TransitionToArchive": "AFTER_90_DAYS"}, {"TransitionToPrimaryStorageClass": "AFTER_1_ACCESS"} ]'

Default Configuration:
PolicyDefault Setting
Transition into IAAFTER_30_DAYS
Transition into ArchiveAFTER_90_DAYS
Transition to StandardNone (disabled)

📝 Review Questions
Q1: How does EFS Lifecycle Management automate storage tiering?
EFS Lifecycle Management uses three lifecycle policies: Transition to IA moves files to IA after a period of no access (default 30 days), Transition to Archive moves files to Archive after a longer period (default 90 days), and Transition to Standard moves files back to Standard when accessed (Intelligent-Tiering).
Q2: What is EFS Intelligent-Tiering and why is it important?
EFS Intelligent-Tiering is a lifecycle policy that automatically moves files back to EFS Standard when they are accessed in IA or Archive storage. This prevents performance degradation and unbounded access charges for files whose access patterns change and become active again.
Q3: What is the prerequisite for using EFS Archive?
To use EFS Archive, the file system must use the Elastic Throughput mode and the General Purpose performance mode. It is not available with Provisioned Throughput or in China Regions.

11.4.4 Mounting EFS on EC2 Instances (NFS)

📖 Complete Theory: Connecting to Shared Storage

Mounting an Amazon EFS file system to an EC2 instance connects your instance to a shared, scalable file system. Once mounted, the EFS file system appears as a local directory, and any data written to it is accessible from other EC2 instances that have the same file system mounted, enabling seamless data sharing across a distributed fleet.

🛠️ Prerequisites:
PrerequisiteDescription
Same VPCThe EC2 instance and the EFS file system must be in the same VPC
Security Group AccessAllow inbound NFS traffic on port 2049
Mount TargetsEFS must have a mount target in the same AZ as your instance
DNS SettingsVPC must have DNS Resolution and DNS Hostnames enabled
Linux InstanceEFS uses NFS — not supported natively on Windows

🛠️ Step-by-Step: Mounting an EFS File System

Step 1: Install the mount helper
sudo dnf install -y amazon-efs-utils

Step 2: Create a mount directory
sudo mkdir /mnt/efs

Step 3: Mount the file system
# With TLS encryption (recommended) sudo mount -t efs -o tls fs-xxxxxxxxxxxxxxxxx:/ /mnt/efs # Standard NFS mount sudo mount -t nfs -o nfsvers=4.1,rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvport fs-xxxxxxxxxxxxxxxxx.efs.region.amazonaws.com:/ /mnt/efs
Step 4: Verify the mount
df -h /mnt/efs

Step 5: Make the mount persistent
echo "fs-xxxxxxxxxxxxxxxxx:/ /mnt/efs efs _netdev,noresvport,tls 0 0" | sudo tee -a /etc/fstab

💡 Key Options Explained:
  • _netdev — Mounts after network is available
  • noresvport — Survives network reconnections
  • tls — Encrypts data in transit

📝 Review Questions
Q1: What protocol does Amazon EFS use for mounting on EC2 instances?
Amazon EFS uses the Network File System (NFS) protocol, specifically versions 4.0 and 4.1. NFSv4.1 is recommended for most Linux instances.
Q2: How can you mount an EFS file system with encryption in transit?
Use the EFS mount helper (amazon-efs-utils) and add the -o tls option: sudo mount -t efs -o tls fs-xxxxxxxxxxxxxxxxx:/ /mnt/efs.
Q3: What is the security requirement regarding security groups for an EFS mount?
The security group attached to the EC2 instance must have an inbound rule allowing NFS traffic on TCP port 2049 from the security group associated with the EFS mount target.
Q4: How can you ensure an EFS file system is automatically remounted after an EC2 instance reboot?
Add an entry to the /etc/fstab file with the _netdev and noresvport options.

Key Takeaways

  • Amazon EFS is a fully managed, serverless, and elastic file system that uses the NFS protocol to provide shared storage accessible by multiple EC2 instances simultaneously.

  • EFS is a regional service — data is stored across multiple Availability Zones for high availability (or One Zone for dev/test).

  • Three storage classes: EFS Standard (sub-ms latency), EFS Infrequent Access (IA) (up to 95% lower cost), and EFS Archive (up to 97% lower cost).

  • Lifecycle Management automates tiering — Transition to IA (default 30 days), Transition to Archive (default 90 days), and Intelligent-Tiering (move back to Standard on access).

  • EFS Archive requires Elastic Throughput — not available with Provisioned Throughput.

  • Mount targets provide NFS endpoints in your VPC, allowing EC2 instances to connect.

  • Install amazon-efs-utils for simplified mounting and TLS encryption of data in transit.

  • Security group requirement: Allow inbound NFS traffic on port 2049 from the EFS mount target's security group.

  • Intelligent-Tiering prevents unbounded access charges by moving files back to Standard when they become active again.

  • EFS vs EBS vs S3: EFS = shared file system (multi-instance), EBS = single-instance block storage, S3 = object storage.
