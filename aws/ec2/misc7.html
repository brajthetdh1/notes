10.6 AWS Systems Manager (SSM)

📖 Complete Theory: A Unified Management Hub

AWS Systems Manager (SSM) is a powerful, unified management service that provides a central place to view and control your AWS infrastructure. It simplifies resource and application management, shortens the time to detect and resolve operational problems, and makes it easier to operate and manage your EC2 instances and other AWS resources at scale.

Key Capabilities:
  • Operations Management: Gain visibility into your resources, aggregate operational data, and analyze it for insights
  • Application Management: Discover, visualize, and manage your applications and their dependencies
  • Change Management: Request, approve, implement, and track changes to your environment
  • Node Management: Manage your EC2 instances and on-premises servers as managed nodes
  • Patch Management: Automate the process of patching your managed nodes with security-related updates
  • Automation: Automate common maintenance and deployment tasks
  • Session Manager: Securely connect to your instances without opening inbound ports or managing SSH keys
⚙️ SSM 📊 unified management 🔄 automation
🏗️

Core Components

1. SSM Agent
The SSM Agent is a software component that runs on EC2 instances and enables them to be managed by Systems Manager. It processes requests from the Systems Manager service and runs commands, applies patches, and sends inventory data back to the service.
  • Installation: Pre-installed on many AMIs, including Amazon Linux, Amazon Linux 2, Windows Server, and Ubuntu
  • Communication: Communicates with the Systems Manager service over HTTPS, using the IAM role attached to the instance
  • Management: You can configure the agent's behavior, including logging and proxy settings

2. Managed Nodes
A managed node is any EC2 instance or on-premises server that is configured to be managed by Systems Manager.
  • Node Status: View the status of all managed nodes (online or offline) in the Systems Manager console
  • Inventory: Collect and aggregate metadata about your managed nodes

3. Documents
SSM Documents are the core of Systems Manager automation. They define the actions that Systems Manager performs on your managed nodes.
  • Command Documents: Define a sequence of commands to run
  • Policy Documents: Define a configuration to be enforced
  • Automation Documents: Define a workflow to automate a specific task
💡 AWS provides a library of pre-built documents for common tasks, and you can also create your own custom documents.

10.6.1 SSM Session Manager

Secure Remote Access
📖 Complete Theory: The Modern Way to Connect

AWS Systems Manager Session Manager is a fully managed feature that provides secure, auditable, and interactive shell access to your EC2 instances, edge devices, on-premises servers, and virtual machines — without the need to open inbound ports, maintain bastion hosts, or manage SSH keys.

🔑 Key Benefits:
  • ✅ No Open Inbound Ports: Close SSH/RDP ports, dramatically reducing attack surface
  • ✅ No SSH Key Management: Permissions managed centrally through IAM policies
  • ✅ No Bastion Hosts: Eliminates another potential attack surface
  • ✅ Centralized Access Control: IAM policies control exactly who can start sessions
  • ✅ Auditable Sessions: Session activity automatically logged in S3 or CloudWatch Logs
  • ✅ Works in Private Subnets: No public IP required

📝 Review Questions
Q1: What is AWS Systems Manager Session Manager and what problem does it solve?
Session Manager is a fully managed feature that provides secure shell access to EC2 instances without opening inbound ports, managing SSH keys, or maintaining bastion hosts. It solves the security and operational problems of traditional SSH/RDP access.
Q2: Why is Session Manager considered more secure than traditional SSH access?
Session Manager is more secure because it does not require open inbound ports (eliminating a major attack surface), uses IAM-based authentication (centralized, auditable), and does not require SSH key distribution (reducing the risk of compromised keys).
Q3: What are the prerequisites for using Session Manager with an EC2 instance?
The prerequisites are: the SSM Agent must be installed, the instance must have an IAM role with the AmazonSSMManagedInstanceCore policy attached, and the instance must have outbound HTTPS (port 443) connectivity to Systems Manager endpoints.
Q4: Can Session Manager connect to instances in private subnets without public IP addresses?
Yes. Because the connection is initiated outbound from the instance, Session Manager can connect to instances in private subnets, provided they have outbound internet access or VPC endpoints for Systems Manager.
Q5: How can you log and audit Session Manager sessions?
Session activity is logged via AWS CloudTrail for API calls. You can also configure Session Manager to store session logs in Amazon S3 or Amazon CloudWatch Logs for debugging and compliance.

Run Command

Automating Tasks with Run Command

Run Command lets you remotely run commands (shell scripts, PowerShell, etc.) on one or more managed nodes without having to log in to each one.

Prerequisites:
  • The EC2 instance must have the SSM Agent installed
  • The instance must have an IAM role with the AmazonSSMManagedInstanceCore policy attached

Running a Command (CLI):
# Run a shell script on a Linux instance aws ssm send-command \ --document-name "AWS-RunShellScript" \ --parameters "commands=sudo yum update -y" \ --targets "Key=instanceids,Values=i-1234567890abcdef0"

Common Use Cases:
  • Installing software
  • Applying security patches
  • Running diagnostic scripts
  • Configuration management

10.6.2 SSM Parameter Store

Secrets Management
📖 Complete Theory: Centralized Configuration and Secrets Management

AWS Systems Manager Parameter Store is a secure, hierarchical key-value store within AWS Systems Manager. It is designed to provide a centralized, secure place for managing configuration data and secrets for your applications and infrastructure.

🔑 Key Capabilities:

Hierarchical Storage:
Parameter Store allows you to organize parameters using a hierarchical path structure, similar to a file system. For example:
/myapp/production/database/host /myapp/production/database/port /myapp/staging/database/host

Three Parameter Types:

StringNoneNon-sensitive config (URLs, feature flags)
StringListNoneComma-separated lists
SecureString✅ KMS encryptedSensitive info (passwords, API keys)

Standard and Advanced Tiers:

Public Parameters:
A unique feature of Parameter Store is the ability to access Public Parameters — official, read-only parameters provided by AWS, such as the latest AMI IDs for Amazon Linux. This allows you to automate instance launches with the most up-to-date images.

💡 Recommended Strategy: Use Parameter Store for cost-effective, hierarchical configuration data and Secrets Manager for database credentials and other secrets that require automatic rotation and cross-account/cross-region access.
📝 Review Questions
Q1: What is AWS Systems Manager Parameter Store and what is its primary purpose?
Parameter Store is a secure, hierarchical key-value store designed to centrally manage configuration data and secrets. Its primary purpose is to provide a unified place for applications and infrastructure to retrieve settings like feature flags, environment variables, and encrypted credentials.
Q2: What are the three parameter types in Parameter Store, and when would you use each?
The three types are String (plain text config like URLs), StringList (comma-separated lists), and SecureString (sensitive data). SecureString parameters are encrypted with KMS to protect sensitive information.
Q3: What is the key difference between Parameter Store and AWS Secrets Manager regarding automatic rotation?
AWS Secrets Manager has built-in support for automatic secret rotation. Parameter Store does not natively support automatic rotation.
Q4: What are the limits and costs associated with the Standard and Advanced tiers?
The Standard tier is free and allows up to 10,000 parameters with a 4 KB size limit. The Advanced tier costs $0.05 per parameter per month and supports up to 100,000 parameters with an 8 KB size limit.
Q5: What is a Public Parameter in Parameter Store and how is it useful?
A Public Parameter is a read-only parameter provided by AWS that contains official data, such as the latest AMI IDs for Linux. It is useful for automating instance launches with the most up-to-date images without having to manually look up or hard-code AMI IDs.
Q6: What is a recommended strategy for using Parameter Store and Secrets Manager together?
A common and recommended practice is to use Parameter Store for cost-effective, hierarchical configuration data and Secrets Manager for database credentials and other secrets that require automatic rotation and cross-account/cross-region access.

  • Session Manager provides secure, auditable shell access without open inbound ports, SSH keys, or bastion hosts — IAM is the control plane.

  • Prerequisites for SSM: SSM Agent installed, IAM role with AmazonSSMManagedInstanceCore, outbound HTTPS connectivity.

  • Session Manager works in private subnets — instances do not need public IP addresses.

  • Run Command enables remote execution of scripts and commands across fleets of instances.

  • Parameter Store Standard tier is free for up to 10,000 parameters — highly cost-effective for configuration data.

  • Public Parameters provide official AWS data (like latest AMI IDs) for automation.

  • Parameter Store vs Secrets Manager: Use Parameter Store for hierarchical config (free tier), Secrets Manager for automatic rotation and cross-account secrets.

  • Session Manager sessions are auditable via CloudTrail and can be logged to S3 or CloudWatch Logs.
