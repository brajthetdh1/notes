Spring Cloud LoadBalancer: Complete Client-Side Load Balancing Guide

Client-Side vs Server-Side Load Balancing

Client-Side Load Balancing

  • Location: Load balancing logic resides in the client application
  • Knowledge: Client knows all available service instances
  • Decision: Client chooses which instance to call
  • Dependency: Requires service discovery (Eureka, Consul, etc.)
  • Performance: Eliminates extra network hop
  • Complexity: More logic in client, but better performance

Architecture:
Client → [Load Balancer] → Chooses Instance → Service Instance

Server-Side Load Balancing

  • Location: Dedicated load balancer (hardware or software)
  • Knowledge: Load balancer knows service instances
  • Decision: Load balancer routes requests
  • Dependency: Centralized load balancer component
  • Performance: Additional network hop introduced
  • Complexity: Simpler clients, but single point of failure

Architecture:
Client → Load Balancer → Routes Request → Service Instance

Architectural Comparison


// Client-Side Load Balancing Architecture
[Order Service]                          [Payment Service Instances]
     |                                              |
     |--- Knows all Payment Service instances ------|
     |--- Chooses instance using algorithm ---------|
     |--- Direct call to chosen instance -----------> Instance 1 (192.168.1.10:8080)
     |--- Or --> Instance 2 (192.168.1.11:8080)
     |--- Or --> Instance 3 (192.168.1.12:8080)

// Server-Side Load Balancing Architecture  
[Order Service]        [Load Balancer]           [Payment Service Instances]
     |                       |                              |
     |-- Request to LB ----->|                              |
     |                       |-- Routes to instance ------->| Instance 1
     |<-- Response ----------|<-- Response ----------------|
                            |
     |-- Request to LB ----->|
     |                       |-- Routes to instance ------->| Instance 2
     |<-- Response ----------|<-- Response ----------------|

Key Difference: Client-side eliminates the load balancer hop, 
giving better performance and reducing single points of failure.

Fundamental Difference: Client-side load balancing moves the routing decision to the client, which knows all available service instances and chooses one directly. Server-side load balancing uses a central component that all clients call, which then routes to service instances.

Spring Cloud LoadBalancer: Primary Role

Core Responsibility: Spring Cloud LoadBalancer provides client-side load balancing capabilities for Spring Boot applications in a microservices architecture. It integrates with service discovery to automatically distribute requests among available service instances.

Key Responsibilities

  • Service Instance Selection: Choose from available instances
    Round Robin, Random, Custom algorithms
  • Integration with Service Discovery: Works with Eureka, Consul, etc.
    Auto-discovers service instances
  • Load Balancing Algorithms: Various strategies for instance selection
    RoundRobin, Random, Weighted, Custom
  • Health Checking: Avoid unhealthy instances
    Integrates with health indicators

Spring Cloud LoadBalancer vs Netflix Ribbon

Transition Reason: Spring Cloud replaced Netflix Ribbon with Spring Cloud LoadBalancer as the default because Ribbon entered maintenance mode and Spring team wanted a solution with better Spring integration, modern reactive support, and active development.

Netflix Ribbon (Legacy)

  • Status: Maintenance mode (no active development)
  • Reactive Support: Limited reactive programming support
  • Spring Integration: Good, but not native Spring solution
  • Configuration: Complex configuration patterns
  • Blocking I/O: Primarily designed for blocking operations
  • Dependencies: Part of Netflix OSS (aging ecosystem)
implementation 'org.springframework.cloud:spring-cloud-starter-netflix-ribbon'

Spring Cloud LoadBalancer (Current)

  • Status: Actively developed by Spring team
  • Reactive Support: First-class reactive programming support
  • Spring Integration: Native Spring solution with better integration
  • Configuration: Spring Boot auto-configuration friendly
  • Blocking & Reactive: Supports both blocking and non-blocking I/O
  • Dependencies: Part of Spring Cloud ecosystem
implementation 'org.springframework.cloud:spring-cloud-starter-loadbalancer'

Fundamental Interface: ReactorLoadBalancer

Core Interface: ReactorLoadBalancer<T> is the fundamental interface in Spring Cloud LoadBalancer that defines the load-balancing algorithm. It's a reactive interface that chooses service instances from available options.

ReactorLoadBalancer Interface Structure


// Core LoadBalancer interface
public interface ReactorLoadBalancer {
    
    // Choose a service instance from available instances
    Mono> choose(Request request);
    
    // Default implementation for request
    default Mono> choose() {
        return choose(Request.EMPTY);
    }
}

// Response wrapper containing chosen instance
public class Response {
    private final T server;  // The chosen service instance
    private final boolean hasServer;
    
    public Response(T server) {
        this.server = server;
        this.hasServer = server != null;
    }
    
    public T getServer() { return server; }
    public boolean hasServer() { return hasServer; }
}

// ServiceInstance - represents a discoverable service instance
public interface ServiceInstance {
    String getInstanceId();      // Unique instance identifier
    String getServiceId();       // Service name (e.g., "payment-service")
    String getHost();           // Host address
    int getPort();              // Port number
    boolean isSecure();         // HTTPS?
    URI getUri();               // Full URI
    Map getMetadata();  // Additional metadata
    String getScheme();         // http or https
}

RoundRobinLoadBalancer

// Round Robin implementation - cycles through instances
public class RoundRobinLoadBalancer implements ReactorLoadBalancer {
    
    private final ObjectProvider serviceInstanceListSupplierProvider;
    private final String serviceId;
    private final AtomicInteger position;  // Tracks current position
    
    public RoundRobinLoadBalancer(
            ObjectProvider serviceInstanceListSupplierProvider,
            String serviceId) {
        this(serviceInstanceListSupplierProvider, serviceId, new AtomicInteger(0));
    }
    
    @Override
    public Mono> choose(Request request) {
        ServiceInstanceListSupplier supplier = serviceInstanceListSupplierProvider.getIfAvailable();
        return supplier.get(request).next()
            .map(instances -> processInstanceResponse(supplier, instances));
    }
    
    private Response processInstanceResponse(
            ServiceInstanceListSupplier supplier,
            List instances) {
        
        if (instances.isEmpty()) {
            return new EmptyResponse();
        }
        
        // Round Robin logic
        int pos = Math.abs(this.position.incrementAndGet());
        ServiceInstance instance = instances.get(pos % instances.size());
        
        return new DefaultResponse(instance);
    }
}

public class RandomLoadBalancer implements ReactorLoadBalancer {
    
    private final ObjectProvider serviceInstanceListSupplierProvider;
    private final String serviceId;
    private final Random random;
    
    public RandomLoadBalancer(
            ObjectProvider serviceInstanceListSupplierProvider,

        this.serviceId = serviceId;
        this.random = new Random();
    }
    
    @Override
    public Mono> choose(Request request) {
        ServiceInstanceListSupplier supplier = serviceInstanceListSupplierProvider.getIfAvailable();
        return supplier.get(request).next()
            .map(instances -> processInstanceResponse(instances));
    }
    
    private Response processInstanceResponse(List instances) {
        if (instances.isEmpty()) {
            return new EmptyResponse();
        }
        
        // Random selection logic
        int index = random.nextInt(instances.size());
        ServiceInstance instance = instances.get(index);
        
        return new DefaultResponse(instance);
    }
}

Custom LoadBalancer Implementation


// Complete custom load balancer implementation
@Component
public class CustomLoadBalancer implements ReactorLoadBalancer {
    
    private final ObjectProvider serviceInstanceListSupplierProvider;
    private final String serviceId;
    private final MeterRegistry meterRegistry;
    
    public CustomLoadBalancer(
            ObjectProvider serviceInstanceListSupplierProvider,
            String serviceId,
            MeterRegistry meterRegistry) {
        this.serviceInstanceListSupplierProvider = serviceInstanceListSupplierProvider;
        this.serviceId = serviceId;
        this.meterRegistry = meterRegistry;
    }
    
    @Override
    public Mono> choose(Request request) {
        ServiceInstanceListSupplier supplier = serviceInstanceListSupplierProvider.getIfAvailable();
        
        return supplier.get(request).next()
            .map(instances -> {
                // Filter out unhealthy instances
                List healthyInstances = instances.stream()
                    .filter(instance -> isHealthy(instance))
                    .collect(Collectors.toList());
                
                if (healthyInstances.isEmpty()) {
                    meterRegistry.counter("loadbalancer.no_healthy_instances", "service", serviceId)
                                .increment();
                    return new EmptyResponse();
                }
                
                // Custom selection logic - could be based on:
                // - Geographic proximity
                // - Current load
                // - Instance capabilities
                // - Cost optimization
                ServiceInstance selected = selectInstance(healthyInstances, request);
                
                meterRegistry.counter("loadbalancer.instance_selected", 
                    "service", serviceId,
                    "instance", selected.getInstanceId())
                    .increment();
                
                return new DefaultResponse(selected);
            });
    }
    
    private boolean isHealthy(ServiceInstance instance) {
        // Check health status from metadata or external health check
        return !"DOWN".equals(instance.getMetadata().get("status"));
    }
    
    private ServiceInstance selectInstance(List instances, Request request) {
        // Example: Stickiness based on request header
        if (request.getContext() instanceof HttpHeaders) {
            HttpHeaders headers = (HttpHeaders) request.getContext();
            String sessionId = headers.getFirst("X-Session-Id");
            if (sessionId != null) {
                // Sticky session - always return same instance for same session
                int hash = Math.abs(sessionId.hashCode());
                return instances.get(hash % instances.size());
            }
        }
        
        // Fallback to round robin
        int index = ThreadLocalRandom.current().nextInt(instances.size());
        return instances.get(index);
    }
}

    public Mono<Object> aggregateData(String userId) {
        WebClient userClient = serviceClients.get("user-service");
        WebClient orderClient = serviceClients.get("order-service");

                    int pos = Math.abs(position.getAndIncrement());
                    ServiceInstance instance = instances.get(pos % instances.size());
                    
                    return new DefaultResponse(instance);
                });
        }

// Sticky session implementation
public class StickySessionLoadBalancer implements ReactorLoadBalancer<ServiceInstance> {
    
    private final String serviceId;
    private final ServiceInstanceListSupplier supplier;
    private final Map<String, ServiceInstance> stickyInstances = new ConcurrentHashMap<>();
    
    public StickySessionLoadBalancer(ServiceInstanceListSupplier supplier, String serviceId) {
        this.supplier = supplier;
        this.serviceId = serviceId;
    }
    
    @Override
    public Mono<Response<ServiceInstance>> choose(Request request) {
        return supplier.get().next().map(instances -> {
            if (instances.isEmpty()) {
                return new EmptyResponse();
            }
            
            // Extract session ID from request (simplified)
            String sessionId = extractSessionId(request);
            
            if (sessionId != null) {
                // Try to use sticky instance
                ServiceInstance stickyInstance = stickyInstances.get(sessionId);
                if (stickyInstance != null && instances.contains(stickyInstance)) {
                    return new DefaultResponse(stickyInstance);
                }
            }
            
            // Fallback to round robin
            ServiceInstance instance = instances.get(ThreadLocalRandom.current().nextInt(instances.size()));
            
            if (sessionId != null) {
                stickyInstances.put(sessionId, instance);
            }
            
            return new DefaultResponse(instance);
        });
    }
    
    private String extractSessionId(Request request) {
        // Extract from request context, headers, etc.
        if (request.getContext() instanceof HttpHeaders) {
            HttpHeaders headers = (HttpHeaders) request.getContext();
            return headers.getFirst("X-Session-ID");
        }
        return null;
    }
}

public class HealthAwareLoadBalancer implements ReactorLoadBalancer<ServiceInstance> {
    
    private final String serviceId;
    private final ServiceInstanceListSupplier supplier;
    private final HealthCheckService healthCheckService;
    private final Map<String, Boolean> instanceHealth = new ConcurrentHashMap<>();
    
    public HealthAwareLoadBalancer(ServiceInstanceListSupplier supplier, 
                                  String serviceId,
                                  HealthCheckService healthCheckService) {
        this.supplier = supplier;
        this.serviceId = serviceId;
        this.healthCheckService = healthCheckService;
    }
    
    @Override
    public Mono<Response<ServiceInstance>> choose(Request request) {
        return supplier.get().next().map(instances -> {
            List<ServiceInstance> healthyInstances = instances.stream()
                .filter(instance -> isHealthy(instance))
                .collect(Collectors.toList());
            
            if (healthyInstances.isEmpty()) {
                return new EmptyResponse();
            }
            
            // Use round robin among healthy instances
            int index = ThreadLocalRandom.current().nextInt(healthyInstances.size());
            return new DefaultResponse(healthyInstances.get(index));
        });
    }
    
    private boolean isHealthy(ServiceInstance instance) {
        String instanceKey = instance.getHost() + ":" + instance.getPort();
        return instanceHealth.computeIfAbsent(instanceKey, 
            key -> healthCheckService.checkHealth(instance));
    }

// Custom implementation for weighted load balancing
@Component
public class WeightedServiceInstanceListSupplier 
    implements ServiceInstanceListSupplier {
    
    private final ServiceInstanceListSupplier delegate;
    
    public WeightedServiceInstanceListSupplier(
            ServiceInstanceListSupplier delegate) {
        this.delegate = delegate;
    }
    
    @Override
    public String getServiceId() {
        return delegate.getServiceId();
    }
    
    @Override
    public Flux<List<ServiceInstance>> get() {
        return delegate.get().map(this::applyWeighting);
    }
    
    private List<ServiceInstance> applyWeighting(
            List<ServiceInstance> instances) {
        
        // Filter instances with weight > 0
        List<ServiceInstance> weightedInstances = instances.stream()
            .filter(instance -> {
                String weight = instance.getMetadata().get("weight");
                return weight != null && Integer.parseInt(weight) > 0;
            })
            .collect(Collectors.toList());
            
        // Expand list based on weights for weighted round-robin
        List<ServiceInstance> expandedList = new ArrayList<>();
        for (ServiceInstance instance : weightedInstances) {
            int weight = Integer.parseInt(instance.getMetadata().get("weight"));
            for (int i = 0; i < weight; i++) {
                expandedList.add(instance);
            }
        }
        
        return expandedList.isEmpty() ? instances : expandedList;

@Component
public class ManualLoadBalancer {
    
    private final DiscoveryClient discoveryClient;
    private final Map<String, AtomicInteger> positionMap = new ConcurrentHashMap<>();
    
    public ManualLoadBalancer(DiscoveryClient discoveryClient) {
        this.discoveryClient = discoveryClient;
    }
    
    // Round-robin load balancing
    public Optional<ServiceInstance> chooseInstance(String serviceId) {
        List<ServiceInstance> instances = discoveryClient.getInstances(serviceId);
        if (instances.isEmpty()) {
            return Optional.empty();
        }
        
        int pos = positionMap.computeIfAbsent(serviceId, k -> new AtomicInteger(0))
                           .getAndUpdate(i -> (i + 1) % instances.size());
        
        return Optional.of(instances.get(pos));
    }
    
    // Weighted load balancing based on instance metadata
    public Optional<ServiceInstance> chooseWeightedInstance(String serviceId) {
        List<ServiceInstance> instances = discoveryClient.getInstances(serviceId);
        if (instances.isEmpty()) {
            return Optional.empty();
        }
        
        // Calculate total weight
        int totalWeight = instances.stream()
            .mapToInt(instance -> 
                Integer.parseInt(instance.getMetadata()
                    .getOrDefault("weight", "1")))
            .sum();
        
        // Select instance based on weight
        int randomWeight = new Random().nextInt(totalWeight);
        int currentWeight = 0;
        
        for (ServiceInstance instance : instances) {
            int weight = Integer.parseInt(instance.getMetadata()
                .getOrDefault("weight", "1"));
            currentWeight += weight;
            if (randomWeight < currentWeight) {
                return Optional.of(instance);
            }
        }
        
        return Optional.of(instances.get(0)); // Fallback
    }
    
    // Health-aware instance selection
    public Optional<ServiceInstance> chooseHealthyInstance(String serviceId) {
        List<ServiceInstance> instances = discoveryClient.getInstances(serviceId)
            .stream()
            .filter(instance -> {
                // Custom health check logic
                String status = instance.getMetadata().get("status");
                return !"DOWN".equals(status) && !"OUT_OF_SERVICE".equals(status);
            })
            .collect(Collectors.toList());
            
        return instances.isEmpty() ? Optional.empty() : chooseInstance(serviceId);
    }
    
    // Manual service call with load balancing
    public <T> T callWithLoadBalancing(String serviceId, 
                                      String path, 
                                      Object request, 
                                      Class<T> responseType) {
        
        ServiceInstance instance = chooseInstance(serviceId)
            .orElseThrow(() -> new ServiceUnavailableException(serviceId));
        
        String url = String.format("http://%s:%s%s", 
            instance.getHost(), instance.getPort(), path);
            
        RestTemplate restTemplate = new RestTemplate();
        return restTemplate.postForObject(url, request, responseType);
    }
}

Custom Weighted Load-Balancing Strategy

Weighted Distribution: Custom weighted load balancing allows you to distribute traffic unevenly across service instances based on factors like instance capacity, performance, or custom metrics.

Weighted Load Balancer

@Component
public class WeightedLoadBalancer implements ReactorServiceInstanceLoadBalancer {
    
    private final ObjectProvider<ServiceInstanceListSupplier> supplierProvider;
    private final String serviceId;
    private final AtomicInteger position;
    
    public WeightedLoadBalancer(ObjectProvider<ServiceInstanceListSupplier> supplierProvider,
                               String serviceId) {
        this.supplierProvider = supplierProvider;
        this.serviceId = serviceId;
        this.position = new AtomicInteger(new Random().nextInt(1000));
    }
    
    @Override
    public Mono<Response<ServiceInstance>> choose(Request request) {
        ServiceInstanceListSupplier supplier = supplierProvider.getIfAvailable();
        return supplier.get(request).next()
            .map(instances -> processInstanceResponse(instances, request));
    }
    
    private Response<ServiceInstance> processInstanceResponse(
            List<ServiceInstance> instances, Request request) {
        
        if (instances.isEmpty()) {
            return new EmptyResponse();
        }
        
        // Calculate weights based on instance metadata
        List<WeightedInstance> weightedInstances = instances.stream()
            .map(this::createWeightedInstance)
            .collect(Collectors.toList());
        
        // Calculate total weight
        int totalWeight = weightedInstances.stream()
            .mapToInt(WeightedInstance::getWeight)
            .sum();
        
        // Select instance based on weighted random
        int randomWeight = new Random().nextInt(totalWeight);
        int currentWeight = 0;
        
        for (WeightedInstance weightedInstance : weightedInstances) {
            currentWeight += weightedInstance.getWeight();
            if (randomWeight < currentWeight) {
                return new DefaultResponse(weightedInstance.getInstance());
            }
        }
        
        // Fallback to first instance
        return new DefaultResponse(instances.get(0));
    }
    
    private WeightedInstance createWeightedInstance(ServiceInstance instance) {
        // Get weight from metadata or calculate dynamically
        int weight = getInstanceWeight(instance);
        return new WeightedInstance(instance, weight);
    }
    
    private int getInstanceWeight(ServiceInstance instance) {
        // Priority 1: Explicit weight from metadata
        String weightStr = instance.getMetadata().get("weight");
        if (weightStr != null) {
            return Integer.parseInt(weightStr);
        }
        
        // Priority 2: Weight based on instance type
        String instanceType = instance.getMetadata().get("instance-type");
        if ("large".equals(instanceType)) return 3;
        if ("medium".equals(instanceType)) return 2;
        if ("small".equals(instanceType)) return 1;
        
        // Priority 3: Dynamic weight based on current load
        String currentLoad = instance.getMetadata().get("current-load");
        if (currentLoad != null) {
            int load = Integer.parseInt(currentLoad);
            return Math.max(1, 10 - load); // Higher load = lower weight
        }
        
        return 1; // Default weight
    }
    
    private static class WeightedInstance {
        private final ServiceInstance instance;
        private final int weight;
        
        // constructor, getters
    }
}

Zone Affinity Load Balancer

Zone Preference: Zone affinity load balancing prefers instances in the same availability zone to reduce latency and cross-zone data transfer costs, with fallback to other zones when necessary.

Zone-Aware Implementation


@Component
public class ZoneAffinityLoadBalancer implements ReactorServiceInstanceLoadBalancer {
    
    private final ObjectProvider<ServiceInstanceListSupplier> supplierProvider;
    private final String serviceId;
    private final String currentZone;
    
    public ZoneAffinityLoadBalancer(ObjectProvider<ServiceInstanceListSupplier> supplierProvider,
                                   String serviceId) {
        this.supplierProvider = supplierProvider;
        this.serviceId = serviceId;
        this.currentZone = determineCurrentZone();
    }
    
    @Override
    public Mono<Response<ServiceInstance>> choose(Request request) {
        ServiceInstanceListSupplier supplier = supplierProvider.getIfAvailable();
        return supplier.get(request).next()
            .map(instances -> processInstanceResponse(instances, request));
    }
    
    private Response<ServiceInstance> processInstanceResponse(
            List<ServiceInstance> instances, Request request) {
        
        if (instances.isEmpty()) {
            return new EmptyResponse();
        }
        
        // Group instances by zone
        Map<String, List<ServiceInstance>> instancesByZone = instances.stream()
            .collect(Collectors.groupingBy(instance -> 
                instance.getMetadata().getOrDefault("zone", "unknown")));
        
        // Strategy 1: Prefer same-zone instances
        List<ServiceInstance> sameZoneInstances = instancesByZone.get(currentZone);
        if (sameZoneInstances != null && !sameZoneInstances.isEmpty()) {
            // Use round-robin within same zone
            int pos = Math.abs(new Random().nextInt(sameZoneInstances.size()));
            return new DefaultResponse(sameZoneInstances.get(pos));
        }
        
        // Strategy 2: Fallback to nearest zone
        String nearestZone = findNearestZone(instancesByZone.keySet());
        if (nearestZone != null) {
            List<ServiceInstance> nearestZoneInstances = instancesByZone.get(nearestZone);
            int pos = Math.abs(new Random().nextInt(nearestZoneInstances.size()));
            return new DefaultResponse(nearestZoneInstances.get(pos));
        }
        
        // Strategy 3: Fallback to any available instance
        int pos = Math.abs(new Random().nextInt(instances.size()));
        return new DefaultResponse(instances.get(pos));
    }
    
    private String determineCurrentZone() {
        // Method 1: From environment variable
        String zone = System.getenv("ZONE");
        if (zone != null) return zone;
        
        // Method 2: From configuration
        zone = System.getProperty("zone");
        if (zone != null) return zone;
        
        // Method 3: From cloud platform metadata
        try {
            // AWS Availability Zone
            zone = fetchAwsAvailabilityZone();
            if (zone != null) return zone;
        } catch (Exception e) {
            // Ignore and continue
        }
        
        return "default-zone"; // Fallback
    }
    
    private String fetchAwsAvailabilityZone() {
        // AWS EC2 metadata service
        try {
            URL url = new URL("http://169.254.169.254/latest/meta-data/placement/availability-zone");
            HttpURLConnection connection = (HttpURLConnection) url.openConnection();
            connection.setRequestMethod("GET");
            connection.setConnectTimeout(1000);
            connection.setReadTimeout(1000);
            
            try (BufferedReader reader = new BufferedReader(
                new InputStreamReader(connection.getInputStream()))) {
                return reader.readLine();
            }
        } catch (Exception e) {
            return null;
        }
    }
    
    private String findNearestZone(Set<String> availableZones) {
        // Simple implementation - in real scenario, use latency measurements
        // or predefined zone proximity mapping
        
        Map<String, Integer> zoneProximity = Map.of(
            "us-east-1a", 1, "us-east-1b", 2, "us-east-1c", 3,
            "us-west-1a", 4, "us-west-1b", 5, "eu-west-1a", 6
        );
        
        return availableZones.stream()
            .min(Comparator.comparingInt(zone -> 
                zoneProximity.getOrDefault(zone, Integer.MAX_VALUE)))
            .orElse(null);
    }
}

    public Mono<Response<ServiceInstance>> choose(Request request) {

            .flatMap(instances -> filterHealthyInstances(instances))
            .map(healthyInstances -> selectInstance(healthyInstances, request));

    private Mono<List<ServiceInstance>> filterHealthyInstances(List<ServiceInstance> instances) {
        List<Mono<ServiceInstance>> healthMonos = instances.stream()

                .filter(HealthyInstance::isHealthy)
                .map(HealthyInstance::getInstance)
                .onErrorResume(e -> Mono.empty())) // Skip unhealthy instances
            .collect(Collectors.toList());
        
        return Mono.zip(healthMonos, objects -> 
            Arrays.stream(objects)
                .map(obj -> (ServiceInstance) obj)
                .collect(Collectors.toList()));
    }
    
    private Response<ServiceInstance> selectInstance(List<ServiceInstance> instances, Request request) {
        if (instances.isEmpty()) {
            return new EmptyResponse();
        }
        
        // Round-robin selection
        int pos = Math.abs(new Random().nextInt(instances.size()));
        return new DefaultResponse(instances.get(pos));
    }

            List<ServiceInstance> instances, Request request) {
        
        // Filter by version if specified in request
        String targetVersion = extractTargetVersion(request);
        if (targetVersion != null) {
            instances = instances.stream()
                .filter(instance -> targetVersion.equals(
                    instance.getMetadata().get("version")))
                .collect(Collectors.toList());
        }
        
        // Prefer instances with specific tags
        List<ServiceInstance> preferredInstances = instances.stream()
            .filter(instance -> {
                String tags = instance.getMetadata().get("tags");
                return tags != null && tags.contains("premium");
            })
            .collect(Collectors.toList());
        
        if (!preferredInstances.isEmpty()) {
            instances = preferredInstances;
        }
        
        // Select based on capacity
        return selectByCapacity(instances);
    }
    
    private String extractTargetVersion(Request request) {
        if (request instanceof DefaultRequest) {
            Object context = ((DefaultRequest<?>) request).getContext();
            if (context instanceof HttpHeaders) {
                return ((HttpHeaders) context).getFirst("X-API-Version");
            }
        }
        return null;
    }
    
    private Response<ServiceInstance> selectByCapacity(List<ServiceInstance> instances) {
        // Select instance with highest capacity
        Optional<ServiceInstance> bestInstance = instances.stream()
            .max(Comparator.comparingInt(instance -> 
                Integer.parseInt(instance.getMetadata()
                    .getOrDefault("capacity", "1"))));
        
        return bestInstance.map(DefaultResponse::new)
            .orElse(new EmptyResponse());
    }
}

Handling No Available Service Instances

Fallback Strategies


@Component
public class FallbackAwareLoadBalancer implements ReactorServiceInstanceLoadBalancer {
    
    private final FallbackService fallbackService;
    private final CircuitBreaker circuitBreaker;
    
    @Override
    public Mono<Response<ServiceInstance>> choose(Request request) {
        ServiceInstanceListSupplier supplier = // get supplier
        return supplier.get(request).next()
            .map(instances -> {
                if (instances.isEmpty()) {
                    // Strategy 1: Execute fallback immediately
                    if (request.supportsFallback()) {
                        executeFallback(request);
                        return new FallbackResponse();
                    }
                    
                    // Strategy 2: Throw specific exception
                    throw new NoAvailableInstancesException("No instances available for service");
                }
                return new DefaultResponse(selectInstance(instances));
            })
            .onErrorResume(NoAvailableInstancesException.class, e -> {
                // Strategy 3: Return fallback response
                return Mono.just(new FallbackResponse());
            });
    }
    
    private void executeFallback(Request request) {
        // Execute business logic fallback
        fallbackService.executeFallback(request);
    }

@Component
public class HeaderBasedRoutingTransformer implements LoadBalancerRequestTransformer {
    
    @Override
    public HttpRequest transformRequest(HttpRequest request, ServiceInstance instance) {
        // Copy headers from original request to load-balanced request
        HttpHeaders headers = request.headers();
        
        ClientRequest.Builder builder = ClientRequest.from(request);
        
        // Preserve tracing headers
        copyHeaderIfPresent(headers, builder, "X-B3-TraceId");
        copyHeaderIfPresent(headers, builder, "X-B3-SpanId");
        copyHeaderIfPresent(headers, builder, "X-Request-Id");
        
        // Add custom routing headers
        String canaryHeader = headers.getFirst("X-Canary-Version");
        if (canaryHeader != null) {
            builder.header("X-Canary", canaryHeader);
        }
        
        return builder.build();
    }
    
    private void copyHeaderIfPresent(HttpHeaders source, ClientRequest.Builder target, String headerName) {
        String value = source.getFirst(headerName);
        if (value != null) {
            target.header(headerName, value);
        }
    }
}

@Component

        String contextPath = instance.getMetadata().get("context-path");
        if (contextPath != null) {

                    .url(newUri)
                    .build();
            } catch (URISyntaxException e) {
                // Log error and return original request
                return request;
            }
        }
        
        return request;
    }

Request-Level Instance Caching

Caching Implementation


@Component
public class CachingLoadBalancer implements ReactorServiceInstanceLoadBalancer {
    
    private final ObjectProvider<ServiceInstanceListSupplier> supplierProvider;
    private final String serviceId;
    private final Cache<String, List<ServiceInstance>> instanceCache;
    private final Cache<String, ServiceInstance> stickySessionCache;
    
    public CachingLoadBalancer(ObjectProvider<ServiceInstanceListSupplier> supplierProvider,
                              String serviceId) {
        this.supplierProvider = supplierProvider;
        this.serviceId = serviceId;
        this.instanceCache = Caffeine.newBuilder()
            .expireAfterWrite(10, TimeUnit.SECONDS) // Cache for 10 seconds
            .maximumSize(100)
            .build();
        this.stickySessionCache = Caffeine.newBuilder()
            .expireAfterWrite(30, TimeUnit.MINUTES) // Longer cache for sticky sessions
            .maximumSize(1000)
            .build();
    }
    
    @Override
    public Mono<Response<ServiceInstance>> choose(Request request) {
        // Try to get from cache first
        List<ServiceInstance> cachedInstances = instanceCache.getIfPresent(serviceId);
        if (cachedInstances != null && !cachedInstances.isEmpty()) {
            return Mono.just(selectFromCached(cachedInstances, request));
        }
        
        // Cache miss - fetch from supplier and cache
        ServiceInstanceListSupplier supplier = supplierProvider.getIfAvailable();
        return supplier.get(request).next()
            .doOnNext(instances -> instanceCache.put(serviceId, instances))
            .map(instances -> selectInstance(instances, request));
    }
    
    private Response<ServiceInstance> selectFromCached(
            List<ServiceInstance> instances, Request request) {
        
        // Sticky session support
        String sessionId = extractSessionId(request);
        if (sessionId != null) {
            ServiceInstance stickyInstance = stickySessionCache.getIfPresent(sessionId);
            if (stickyInstance != null && instances.contains(stickyInstance)) {
                return new DefaultResponse(stickyInstance);
            }
        }
        
        // Regular selection from cached instances
        ServiceInstance selected = selectInstance(instances, request);
        
        // Cache for sticky sessions
        if (sessionId != null) {
            stickySessionCache.put(sessionId, selected);
        }
        
        return new DefaultResponse(selected);
    }
    
    private String extractSessionId(Request request) {
        if (request instanceof DefaultRequest) {
            Object context = ((DefaultRequest<?>) request).getContext();
            if (context instanceof HttpHeaders) {
                return ((HttpHeaders) context).getFirst("X-Session-Id");
            }
        }
        return null;
    }
    
    // Refresh cache periodically
    @Scheduled(fixedRate = 10000) // Every 10 seconds
    public void refreshCache() {
        instanceCache.invalidate(serviceId);
    }
}

Performance Benefits

  • Reduced Discovery Calls: Minimize calls to service discovery
    Cache instances for 5-30 seconds
  • Faster Instance Selection: No network calls for instance lookup
    In-memory cache access
  • Sticky Sessions: Maintain session affinity

  • Reduced Load: Less pressure on service registry

Trade-off: Caching improves performance but may temporarily route to unavailable instances. Balance cache TTL with freshness requirements.

public class CustomRetryPolicy implements LoadBalancedRetryPolicy {

    }

        return currentAttempts < getMaxRetries();
    }

        return context.getLastException() instanceof SocketTimeoutException;

    @Override
    public void close(LoadBalancerContext context) {
        // Cleanup
    }
    
    @Override
    public void registerThrowable(LoadBalancerContext context, Throwable throwable) {
        currentAttempts++;
    }

        // Service-specific retry configuration
        switch (serviceId) {
            case "payment-service": return 2;
            case "inventory-service": return 3;

        }

Netflix Ribbon Limitations & Spring Cloud LoadBalancer Evolution

Historical Context: Netflix Ribbon was the original client-side load balancer in Spring Cloud, but several critical limitations led to the development of Spring Cloud LoadBalancer as its modern replacement.

Netflix Ribbon Limitations

  • Maintenance Mode: Entered maintenance mode in 2016
    No active development or new features
  • Blocking Architecture: Built on blocking I/O model
    Not suitable for reactive applications
  • Complex Configuration: Overly complex configuration model
    Required extensive XML/Java configuration
  • Tight Coupling: Deep integration with Netflix OSS stack
    Hard to use without Eureka, Hystrix
  • Limited Extensibility: Difficult to customize and extend
    Rigid architecture with limited hooks

Spring Cloud LoadBalancer Advantages

  • Active Development: Actively maintained by Spring team
    Regular updates and new features
  • Reactive Support: Native reactive programming support
    Works seamlessly with WebFlux
  • Simplified Configuration: Spring Boot auto-configuration
    Minimal configuration required
  • Modular Design: Pluggable components and strategies
    Easy to customize and extend
  • Standalone Operation: Works without external dependencies
    No mandatory Eureka dependency

BlockingLoadBalancerClient vs ReactiveLoadBalancer

BlockingLoadBalancerClient

  • Architecture: Traditional blocking I/O model
  • Use Case: Servlet-based applications (Spring MVC)
  • Thread Model: One thread per request
  • Integration: Works with RestTemplate
  • Performance: Good for low-concurrency scenarios
  • Simplicity: Easier to understand and debug

Best For: Traditional Spring MVC applications with moderate load

ReactiveLoadBalancer

  • Architecture: Non-blocking reactive model
  • Use Case: Reactive applications (WebFlux)
  • Thread Model: Event-loop, few threads handle many requests
  • Integration: Works with WebClient
  • Performance: Excellent for high-concurrency scenarios
  • Scalability: Better resource utilization

Best For: High-performance reactive applications and microservices

Common Configuration Pitfalls and Mistakes

Configuration Mistakes

  • Missing @LoadBalanced: Forgetting to annotate RestTemplate/WebClient builder
    @Bean + @LoadBalanced required for auto-configuration
  • Incorrect Service Names: Case sensitivity and naming mismatches
    user-service vs USER-SERVICE vs UserService
  • Discovery Client Missing: Not including spring-cloud-starter-loadbalancer
    Required dependency: spring-cloud-starter-loadbalancer
  • Port Configuration: Wrong server port in instance metadata
    server.port vs management.server.port confusion
  • Health Check Misconfiguration: Instances marked down incorrectly
    /actuator/health returning DOWN status

Architecture Mistakes

  • Mixed Client Types: Using RestTemplate and WebClient inconsistently
    Choose one: blocking (MVC) or reactive (WebFlux)
  • Direct URL Calls: Bypassing load balancer with hardcoded URLs
    Use http://service-name not http://host:port
  • Cache Configuration: Service instance cache causing stale data
    spring.cloud.loadbalancer.cache.enabled=true
  • Timeout Settings: Inadequate timeouts for service discovery
    Configure appropriate connection and read timeouts
  • Load Balancer Selection: Wrong load balancing algorithm for use case
    RoundRobin vs Random vs Custom strategies

@Component
public class InstanceAvailabilityHealthIndicator implements HealthIndicator {
    
    private final DiscoveryClient discoveryClient;
    private final Set<String> criticalServices;
    
    public InstanceAvailabilityHealthIndicator(DiscoveryClient discoveryClient) {
        this.discoveryClient = discoveryClient;
        this.criticalServices = Set.of("user-service", "payment-service", "inventory-service");
    }
    
    @Override
    public Health health() {
        Map<String, Object> details = new HashMap<>();
        boolean allHealthy = true;
        
        for (String service : criticalServices) {
            List<ServiceInstance> instances = discoveryClient.getInstances(service);
            boolean serviceHealthy = !instances.isEmpty();
            allHealthy = allHealthy && serviceHealthy;
            
            details.put(service, Map.of(
                "available", serviceHealthy,
                "instanceCount", instances.size(),
                "instances", instances.stream()
                    .map(ServiceInstance::getUri)
                    .map(URI::toString)
                    .collect(Collectors.toList())
            ));
        }
        
        return allHealthy ? 
            Health.up().withDetails(details).build() :
            Health.down().withDetails(details).build();
    }
}

Client-Side vs Server-Side Load Balancing Impact

Client-Side Load Balancing

  • Location: Load balancing logic in client application
  • Performance: Lower latency - direct service-to-service calls
  • Scalability: Scales with client applications
  • Complexity: More complex client implementation
  • Failure Detection: Faster - client directly observes service health
  • Cost: No additional infrastructure cost

Architecture:
Client App → [Load Balancer Logic] → Service Instances

Server-Side Load Balancing

  • Location: Dedicated load balancer (hardware/software)
  • Performance: Higher latency - extra network hop
  • Scalability: Load balancer becomes bottleneck
  • Complexity: Simpler clients, complex infrastructure
  • Failure Detection: Slower - health checks have delay
  • Cost: Additional infrastructure and maintenance

Architecture:
Client App → Load Balancer → Service Instances

When to Use Client-Side
  • Microservices architectures with service discovery
  • High-performance, low-latency requirements
  • Dynamic environments with frequent scaling
  • Cost-sensitive deployments
  • Teams comfortable with distributed systems complexity
When to Use Server-Side
  • Traditional monolithic applications
  • Simple infrastructure requirements
  • Static environments with infrequent changes
  • Teams preferring operational simplicity
  • Legacy systems without service discovery

Modern Recommendation: For microservices architectures, client-side load balancing (like Spring Cloud LoadBalancer) is generally preferred due to better performance, scalability, and cost-effectiveness. Server-side load balancing is better suited for traditional applications or as a complement for north-south traffic.
